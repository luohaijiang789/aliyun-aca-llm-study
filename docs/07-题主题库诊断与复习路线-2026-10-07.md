# 题主题库诊断与 ACA V2.4 复习路线

> 2026-10-07 核对。考试依据是仓库内的[官方大纲 PDF](../resources/官方-考试大纲-V2.4.pdf)，题库数据来自当日 Mac 微信小程序「题主」界面。用户确认这两套为真题资料；题主界面未提供官方原题来源证明，故保留来源说明并单独核对参考答案。

> 本文是 10 月 7 日的早期诊断。两套完整模拟卷完成后的成绩、错因和冲刺路线见[两套模拟卷通关手册](08-两套模拟卷通关手册.md)。

## 先记住考试到底考什么

认证是**阿里云大模型工程师 ACA**，不是 ACE。官方定位是企业 AI 通识和业务应用：理解大模型的能力边界，面对具体任务能判断该优化输入、接入知识库、调用工具、微调、协作 Agent，还是保留人工确认。大纲明确不要求写代码，也不考模型训练和协议实现细节。

| 模块 | 官方权重 | 对应 50 题的分值 | 复习重点 |
|---|---:|---:|---|
| 增强大模型应用的能力 | 22% | 22 分 | RAG 质量链路、知识库与工具选型、MCP 作用 |
| 提示词工程 | 20% | 20 分 | 目标、背景、约束、示例、格式、评价标准；复杂任务先规划 |
| 大模型概念 | 18% | 18 分 | 生成能力、幻觉、知识时效、上下文限制、人工边界 |
| 大模型 Agent | 16% | 16 分 | 从问答到任务、Skill、自检、阶段检查、高风险确认 |
| 大模型微调 | 12% | 12 分 | 何时适用、与 RAG 的边界、五步基本流程 |
| 大模型安全合规 | 12% | 12 分 | 数据与权限、来源和审计、人工复核 |

考试 **60 分钟，50 题，35 单选 + 15 多选，每题 2 分，80 分及格**。上表每模块的分值由官方权重直接对应，但每模块具体单选和多选各有多少题，官方大纲没有给出。

另外显示错题本 53 题、收藏夹 45 题。「必刷题」和「6月更新 V2.4」是章节/标签，可能与单选、多选分类重叠，不能把它们相加算总题量。上述正确率是该题库的历史作答数据，不等于正式考试预测分数。

我抽看了新版题开头、中段、后段和末尾，以及普通多选和必刷题。**这是抽样观察，不是对 1062 题逐题审校。** 实际题目出现以下问法：

1. **场景选型**：内部资料答错、要实时路线或业务动作时，应先判断资料解析、RAG、工具调用各自负责什么。
2. **原因定位**：输出不满足字数、参数表格读错、多个工单串扰时，找直接原因和最先要修的环节。
3. **能力边界**：大模型负责理解意图与决定何时调工具，地图等外部服务负责返回实时数据和执行确定操作。
4. **方法复用**：Skill 固化章节结构、处理规则和检查步骤，不把某一次报告的事实内容写成永久模板。
5. **自检与安全**：检查项要能核对实际状态，不能把“待审批”写成“已签署”；高风险动作保留人工确认。
6. **概念辨析**：单选和多选都出现；多选需要逐项判断每个选项是否满足题干条件。

题库也有与当前 ACA 重点不一致的内容：普通多选开头出现扩散模型数学基础，「必刷题」开头出现复杂投资多 Agent 策略规划。它们不能仅凭「必刷」标签升级为官方高频考点。新版题末尾还见到标题标为单选、题干却问“哪些设计更合适”的写法；这类题应核对解析和题型，不宜死背答案。题库自称 V2.4 也不代表每题都与官方大纲一致。

### 整库导出的可行性

截至本次检查，小程序的题库页、题库中心和个人设置没有看到「导出题库」入口；公开搜索也没有找到可核实的题主开放 API 文档。这只能说明**目前没有可用的官方批量获取路径**，不能证明后台绝无接口。购买订阅提供了应用内阅读权限，并不能据此推定可以直接调用未公开的后台接口或批量复制整库。若题主客服提供正式导出文件或开放 API 文档，可再按其授权范围整理成可检索的学习资料。

## 一张业务选型卡

| 题干真正缺的是什么 | 优先想到 | 排除误区 |
|---|---|---|
| 任务说不清、输出要求不明确 | 优化提示词 | 先说明目标、背景、约束、示例、格式和评价标准 |
| 企业内部、私域、经常更新的资料 | RAG／知识库 | 微调不能方便地保持事实更新与来源可查 |
| 实时信息、精确计算、查询系统或执行动作 | 工具调用 | 不能让模型仅靠记忆编造实时结果或精算结果 |
| 长期稳定的格式、风格、分类行为；轻量模型能力 | 先试提示词，再考虑微调 | 微调不是补新知识的首选 |
| 需要跨步骤规划、查资料、调用工具并检查结果 | Agent | Agent 是任务编排；资料和动作仍分别依靠知识库、工具 |
| 医疗、金融、合同、对外发布等高风险决定或动作 | 人工确认／复核 | AI 可以起草，最终责任仍在人 |

**顺口记：说不清先改输入；查资料用 RAG；要实时、算准、做动作就调工具；稳行为才考虑微调；多步任务让 Agent 协作；高风险留人工。** 这是按官方大纲整理的记忆法，不是逐题标准答案。复杂业务题可以同时使用多种手段，要看题目问的是“主要解决哪个问题”。

## 先补最可能拉分的地方

1. **优先补多选**：你在题主的多选正确率为 53.58%，明显低于单选的 73.44%。先刷多选中的六大官方模块题，逐个选项写出“为什么对/错”；不要假设少选有部分分，官方 PDF 未说明多选的部分给分规则。
2. **先刷新版，再刷错题**：把「6月更新 V2.4」剩余题按官方六模块标注；优先复盘已做的 50 题中答错的题。错题本的 53 题也按“概念不清／场景选错／读题失误／题库疑似错误”分类。
3. **核对题库而不是背题库**：碰到扩散模型推导、训练参数、MCP 报文等，与大纲“不考实现细节”相冲突时，降为低优先级。遇到答案可疑时，以官方大纲和课程为准，记录争议，不机械记忆。
4. **用一套 50 题自测验收**：按正式时长做一次 35 单选 + 15 多选的模拟。目标先达到 80 分，再争取稳定高于 85 分；按模块检查失分，别只看总正确率。仓库的[自建 50 题](../quiz/README.md)可用来检查知识，不应当作官方原题。
