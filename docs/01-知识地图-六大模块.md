## M1 · 大模型概念（18%）

> 📜 **官方原文要点**：理解大模型是什么、能做什么、**不能直接替人决定什么**；理解**基于上下文生成内容**的方式与由此带来的**幻觉、训练数据时间范围和上下文限制**；掌握**能力边界判断**——什么时候适合生成、总结、分析，什么时候需要知识库、工具或人工确认。

### 考点清单

**A. 定义与本质**
- [ ] 大模型的定义：**大规模参数 + 海量数据预训练**的深度神经网络
- [ ] 「大」体现在：参数量、训练数据量、算力规模
- [ ] 大模型 ≠ 搜索引擎：本质是**概率预测下一个 token**，不是检索事实库

**B. 训练三阶段（必考）**
- [ ] 预训练 Pre-training：大规模无监督/自监督，学通用知识 → 得到基座模型
- [ ] 监督微调 SFT：高质量标注数据有监督训练 → 学会遵循指令
- [ ] 对齐偏好 RLHF：人类反馈强化学习 → 输出符合人类价值观

**C. 工作原理**
- [ ] **分词 Tokenization**：文本被分成 token；中文字符与 token 数量没有固定比例，具体由分词器决定
- [ ] **自回归生成**：逐 token 生成，每次预测依赖前文
- [ ] **注意力机制 Attention**：Q/K/V，捕捉长距离依赖 —— ⚠️ 官方未列考点，**了解即可，不考推导**
- [ ] **Transformer 架构**：编码器/解码器结构
- [ ] **MoE 架构**：混合专家，稀疏激活 —— ⚠️ 官方未列考点，**了解即可，不考结构细节**

**D. 四大特点**
- [ ] 涌现能力 / 泛化性 / 上下文学习（ICL）/ 多任务适配
- [ ] **官方三大局限**：**幻觉、训练数据时间范围、上下文限制**

**E. 模型分类**
- [ ] 按模态：语言模型 / 视觉模型 / 多模态
- [ ] 按开源：闭源 vs 开源
- [ ] 按规模与用途：通用基座 vs 垂直领域

**F. 阿里云产品矩阵**
- [ ] **通义千问 Qwen**：基础语言大模型
- [ ] **通义万相**：视觉生成（文生图 / 图生视频）
- [ ] **百炼平台**：一站式大模型服务与应用开发平台
- [ ] 能区分语言生成、视觉生成与应用平台；具体 Qwen 型号能力随版本变化，以当期官方产品说明为准，不背未经核实的型号清单

## M2 · 提示词工程（20%）

> 📜 **官方原文要点**：**好答案来自好输入**。掌握如何说明**目标、背景、角色、约束、示例、输出格式和评价标准**；面对**复杂任务**先列计划和关键信息、确认后再生成；面对**翻译、改写、总结、分类**补充**受众、目的、术语和不可改写信息**。

### 考点清单

**A. 提示词基础**
- [ ] 提示词的构成：指令 / 上下文 / 输入数据 / 输出格式
- [ ] 好提示词的特征：明确、具体、有约束、给示例

**B. 核心技巧（必考）**
- [ ] **角色设定**：给模型一个身份
- [ ] **Few-shot**：给示例（0-shot / 1-shot / few-shot 区别）
- [ ] **思维链 CoT**：让模型"一步步思考"
- [ ] **任务拆解**：复杂任务拆成子任务
- [ ] **输出格式约束**：JSON / 表格 / 指定字数
- [ ] **限定条件**：范围、语气、禁止项

**C. 优化方法论**
- [ ] 迭代式优化：写 → 测 → 分析缺陷 → 改
- [ ] 常见失败模式：指令模糊、缺少上下文、任务过载、格式没约束

**D. 业务场景应用**
- [ ] 批量文本分析、信息提取、内容生成、翻译、图表分析

## M3 · 增强大模型应用的能力（22%）

> 📜 **官方原文要点**：**查企业资料用 RAG，需要实时数据、确定性计算或业务动作时用工具**；理解 RAG 的**解析、切分、检索、重排序和评测**会影响答案质量；了解 **MCP 的作用，不要求掌握协议细节**。

> V2.4 新增：**RAG 评测归因**、**向量检索**

### 考点清单

**A. RAG 检索增强生成（核心）**
- [ ] RAG 定义：先检索外部知识，再拼进提示词让模型回答
- [ ] 解决什么：**知识缺失**（私域/最新信息）+ **幻觉**
- [ ] 完整流程：文档切分 → 向量化 → 存入向量库 → 召回 → 重排 → 拼上下文 → 生成
- [ ] **向量检索**（V2.4 新增）： embedding、相似度计算（余弦/欧氏）、ANN 近似检索
- [ ] **RAG 评测归因**（V2.4 新增）：回答不好时如何定位是**检索错了**还是**生成错了**
- [ ] 切分策略 chunking：固定长度 / 语义切分，chunk size 与 overlap 的权衡

**B. 工具调用**
- [ ] 工具解决什么：需要**实时数据、确定性计算或业务动作**（联网、计算、调外部系统）
- [ ] 与 RAG 的区别：**查企业资料用 RAG**；**做动作靠工具**

**C. API 调用**
- [ ] 通过 API 让大模型自动化处理任务
- [ ] 常见参数：`temperature`、`top_p`、`max_tokens` 的作用
- [ ] **真题补充**：上万份材料的批量任务应程序化调用 API、做限流/重试/结果核验；ACA 不要求现场编写代码
- [ ] **真题补充**：结构化销量/库存/排行优先用受控查询或 NL2SQL，非结构化文档问答用 RAG

## M4 · 大模型 Agent（16%）⭐ 本次升级重点

> 📜 **官方原文要点**：**Agent 的价值是把「回答问题」推进到「完成任务」**。掌握如何给 Agent 明确**目标、资料来源、工具边界和阶段检查点**；理解 **Skill 用来固化重复工作方法**，**自检清单要具体、可核对、有证据**；**高风险动作必须人工确认**。

> V2.4 新增全部集中在这里：桌面 Agent、知识库应用、MCP、Skill 编排、自检闭环

### 考点清单

**A. Agent 基础**
- [ ] 定义：能**自主感知 → 思考 → 行动**完成目标的系统
- [ ] 三大核心能力（必考）：
  - **感知 Perception**：获取环境信息与用户输入
  - **思考 Reasoning**：分析、规划、决策（CoT / ReAct / ToT）
  - **行动 Action**：调用工具、与外部交互
- [ ] **ReAct 范式**：Reasoning + Acting 交替循环

**B. 工具调用（V2.4 新增）**
- [ ] Function Calling / Tool Use：模型输出结构化调用请求 → 执行 → 结果回灌
- [ ] **MCP**（官方归在 M3 增强应用）：标准化模型与外部数据源/工具的连接方式
  - ⚠️ 官方要求**只了解作用**，**不考协议细节**

**C. 桌面 Agent（V2.4 新增）**
- [ ] 本地安装与运行形态
- [ ] 与云端 Agent 的区别：能操作本地文件/终端
- [ ] 具体桌面 Agent 产品名和下载入口按当前官方课程核对；考试重点是本地文件/终端能力及权限边界

**D. 知识库接入（V2.4 新增）**
- [ ] Agent + RAG = 能查私域知识的执行体

**E. Skill 编排（V2.4 新增）**
- [ ] Skill 定义：把一套**固化的工作方法**封装成可复用单元
- [ ] 与 Prompt 的区别：Skill 含流程 + 工具 + 约束，可反复调用
- [ ] 编排：多个 Skill 组合完成复杂任务

**F. 自检闭环（V2.4 新增）**
- [ ] 定义：Agent 执行后**自我检查结果**，不达标则重试/修正
- [ ] 为什么需要：降低单次生成的不可靠性
- [ ] 实现方式：结果校验规则、反思提示、多轮重试上限

**G. Multi-Agent**
- [ ] 多智能体协作：角色分工、任务分发、结果汇总
- [ ] 认识 ModelScope-Agent 等名称可能作为多步骤任务选项出现；重点是角色分工、协调、交接和适用范围
- [ ] **真题补充**：隔离不同工单上下文；跨会话只复用确认过的关键事实；Skill 正文按需加载，避免工具与日志挤占上下文

## M5 · 大模型微调（12%）

> 📜 **官方原文要点**：**微调不是万能按钮**。微调适合**稳定行为、格式、风格、分类能力，或支持轻量模型部署**；基本流程为**定义目标、准备样本、选择基模、控制数据质量、评估效果**；能区分**「查知识用 RAG，做动作靠工具，稳行为才考虑微调」**。

### 考点清单

**A. 微调的本质**
- [ ] 定义：在预训练基座上，用**特定领域数据**继续训练，改变模型行为/风格/格式
- [ ] 解决什么：稳定行为、格式、风格、分类和轻量部署；可能记住训练样本事实，但不适合维护频繁更新、需引用的知识

**B. 何时用微调（必考决策点）**
- [ ] ✅ 需要固定格式/风格/语气
- [ ] ✅ 领域术语与表达习惯强特殊
- [ ] ❌ 只是缺知识 → 用 RAG
- [ ] ❌ 只是回答不好 → 先优化提示词

**C. 微调方式**
- [ ] 全参数微调 vs **高效微调 PEFT** —— ⚠️ 官方「不考模型训练细节」，**了解即可**
- [ ] **LoRA / QLoRA**：参数高效微调术语；第一套 Q28 已考适用场景，知道资源受限时的用途，不背矩阵推导
- [ ] **蒸馏**：小模型学习大模型行为，可探索降推理成本/延迟；具体准确率与时延目标必须实测
- [ ] 数据要求：质量 > 数量，需清洗与标注（对应官方「控制数据质量」）

**D. 流程**
- [ ] **官方五步**：定义目标 → 准备样本 → 选择基模 → 控制数据质量 → 评估效果；上线泛化差时查样本覆盖、过拟合和独立评测

## M6 · 大模型安全合规（12%）

> 📜 **官方原文要点**：安全合规的核心是**让 AI 在边界内工作**。掌握**内容安全、数据安全、权限控制、生成内容标识、来源留存、审计追踪和人工复核**；遇到**医疗、金融、合同、对外发布**等高风险场景，**AI 可以辅助整理和起草，但不能替代最终责任人**。

### 考点清单

**A. 风险来源**
- [ ] **数据安全**：训练/推理数据泄露、敏感信息入参
- [ ] **内容安全**：有害内容生成、越狱 Jailbreak、提示词注入
- [ ] **幻觉风险**：虚假信息误导决策
- [ ] **合规风险**：未备案上线、跨境数据流动
- [ ] **知识产权**：训练数据版权、生成物归属

**B. 治理与防控**
- [ ] 输入侧：内容过滤、敏感词、意图识别
- [ ] 模型侧：对齐训练、安全护栏 Guardrails
- [ ] 输出侧：结果审核、水印/标识
- [ ] 管理侧：权限控制、审计日志、数据最小化

**C. 法规（国内，需核实具体条文）**
- [ ] 《生成式人工智能服务管理暂行办法》
- [ ] 《互联网信息服务算法推荐管理规定》
- [ ] 《数据安全法》《个人信息保护法》
- [ ] **大模型应用备案**要求

- 剩下 Agent（16%）拿 60% → 约 10 分 → **累计 ~81 分，过线**
- Agent 每多对 1 题 = 多 2 分缓冲，是拉开差距的地方
