## M1 · 大模型概念（18%）

### 考点清单

**A. 定义与本质**
- [ ] 大模型的定义：**大规模参数 + 海量数据预训练**的深度神经网络
- [ ] 「大」体现在：参数量、训练数据量、算力规模
- [ ] 大模型 ≠ 搜索引擎：本质是**概率预测下一个 token**，不是检索事实库

**B. 训练三阶段（必考）**
- [ ] 预训练 Pre-training：大规模无监督/自监督，学通用知识 → 得到基座模型
- [ ] 监督微调 SFT：高质量标注数据有监督训练 → 学会遵循指令
- [ ] 对齐偏好 RLHF：人类反馈强化学习 → 输出符合人类价值观

**C. 工作原理**
- [ ] **分词 Tokenization**：文本切分为 token（中文 1 字 ≈ 1~2 token）
- [ ] **自回归生成**：逐 token 生成，每次预测依赖前文
- [ ] **注意力机制 Attention**：Q/K/V，捕捉长距离依赖（V2.4 强化图文）
- [ ] **Transformer 架构**：编码器/解码器结构
- [ ] **MoE 架构**：混合专家，稀疏激活（V2.4 强化）

**D. 四大特点**
- [ ] 涌现能力 / 泛化性 / 上下文学习（ICL）/ 多任务适配
- [ ] 局限：幻觉、知识时效性、无真实世界 grounding

**E. 模型分类**
- [ ] 按模态：语言模型 / 视觉模型 / 多模态
- [ ] 按开源：闭源 vs 开源
- [ ] 按规模与用途：通用基座 vs 垂直领域

**F. 阿里云产品矩阵**
- [ ] **通义千问 Qwen**：基础语言大模型
- [ ] **通义万相**：视觉生成（文生图 / 图生视频）
- [ ] **百炼平台**：一站式大模型服务与应用开发平台
- [ ] 待补充：百炼的具体能力边界、Qwen 各版本定位（Qwen3.8-Max / Flash / VL）

## M3 · 增强大模型应用的能力（22%）

> V2.4 新增：**RAG 评测归因**、**向量检索**

### 考点清单

**A. RAG 检索增强生成（核心）**
- [ ] RAG 定义：先检索外部知识，再拼进提示词让模型回答
- [ ] 解决什么：**知识缺失**（私域/最新信息）+ **幻觉**
- [ ] 完整流程：文档切分 → 向量化 → 存入向量库 → 召回 → 重排 → 拼上下文 → 生成
- [ ] **向量检索**（V2.4 新增）： embedding、相似度计算（余弦/欧氏）、ANN 近似检索
- [ ] **RAG 评测归因**（V2.4 新增）：回答不好时如何定位是**检索错了**还是**生成错了**
- [ ] 切分策略 chunking：固定长度 / 语义切分，chunk size 与 overlap 的权衡

**B. 插件机制**
- [ ] 插件解决什么：模型**能力边界不足**（联网、计算、调外部系统）
- [ ] 与 RAG 的区别：RAG 补**知识**，插件补**能力**

**C. API 调用**
- [ ] 通过 API 让大模型自动化处理任务
- [ ] 常见参数：`temperature`、`top_p`、`max_tokens` 的作用
- [ ] 待补充：阿里云百炼 API 的具体调用形态与参数命名

## M4 · 大模型 Agent（16%）⭐ 本次升级重点

> V2.4 新增全部集中在这里：桌面 Agent、知识库应用、MCP、Skill 编排、自检闭环

### 考点清单

**A. Agent 基础**
- [ ] 定义：能**自主感知 → 思考 → 行动**完成目标的系统
- [ ] 三大核心能力（必考）：
  - **感知 Perception**：获取环境信息与用户输入
  - **思考 Reasoning**：分析、规划、决策（CoT / ReAct / ToT）
  - **行动 Action**：调用工具、与外部交互
- [ ] **ReAct 范式**：Reasoning + Acting 交替循环

**B. 工具调用（V2.4 新增）**
- [ ] Function Calling / Tool Use：模型输出结构化调用请求 → 执行 → 结果回灌
- [ ] **MCP 协议**（V2.4 新增）：Model Context Protocol，标准化模型与外部数据源/工具的连接方式

**C. 桌面 Agent（V2.4 新增）**
- [ ] 本地安装与运行形态
- [ ] 与云端 Agent 的区别：能操作本地文件/终端
- [ ] 待补充：阿里云/通义对应的桌面 Agent 产品名称

**D. 知识库接入（V2.4 新增）**
- [ ] Agent + RAG = 能查私域知识的执行体

**E. Skill 编排（V2.4 新增）**
- [ ] Skill 定义：把一套**固化的工作方法**封装成可复用单元
- [ ] 与 Prompt 的区别：Skill 含流程 + 工具 + 约束，可反复调用
- [ ] 编排：多个 Skill 组合完成复杂任务

**F. 自检闭环（V2.4 新增）**
- [ ] 定义：Agent 执行后**自我检查结果**，不达标则重试/修正
- [ ] 为什么需要：降低单次生成的不可靠性
- [ ] 实现方式：结果校验规则、反思提示、多轮重试上限

**G. Multi-Agent**
- [ ] 多智能体协作：角色分工、任务分发、结果汇总
- [ ] 待补充：ModelScope-Agent 框架细节

## M5 · 大模型微调（12%）

### 考点清单

**A. 微调的本质**
- [ ] 定义：在预训练基座上，用**特定领域数据**继续训练，改变模型行为/风格/格式
- [ ] 解决什么：**特定的输出格式或行文风格**（不是补知识）

**B. 何时用微调（必考决策点）**
- [ ] ✅ 需要固定格式/风格/语气
- [ ] ✅ 领域术语与表达习惯强特殊
- [ ] ❌ 只是缺知识 → 用 RAG
- [ ] ❌ 只是回答不好 → 先优化提示词

**C. 微调方式**
- [ ] 全参数微调 vs **高效微调 PEFT**
- [ ] **LoRA / QLoRA**：低秩适配，只训练少量参数，显存友好
- [ ] 数据要求：质量 > 数量，需清洗与标注

**D. 流程**
- [ ] 数据准备 → 选择基座 → 配置超参 → 训练 → 评测 → 部署
