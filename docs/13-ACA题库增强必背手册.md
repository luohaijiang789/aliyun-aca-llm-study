# ACA 题库增强必背手册

> 基于两套模拟卷与顺序题 1～150 汇总。用途是闭卷背诵与场景判断；官方范围仍以 V2.4 考试大纲为准。

## 一、先背这张总决策表

| 题干真正缺什么 | 首选手段 | 不要误选 |
|---|---|---|
| 指令不清、格式不稳、语气不对 | Prompt | 直接微调 |
| 企业资料、内部制度、频繁更新知识 | RAG/知识库 | 把最新知识全做进微调 |
| 实时数据、精确计算、数据库查询、业务动作 | 工具/API | 仅靠 RAG 或 Prompt |
| 长期稳定分类、风格、行为；Prompt 反复调整仍不稳 | 微调 | 先忽略数据与评测 |
| 多步骤自主规划并调用工具执行 | Agent | 简单固定流程也强上 Agent |
| 医疗、金融、合同、对外发布 | 人工确认/复核 | 让模型直接拍板 |

**总口诀：先提示，缺知检索；实时工具，稳定微调；多步 Agent，高险人工。**

## 二、M1 大模型概念：必须脱口而出的 16 句

1. 大模型能力来自**数据、参数、算力和训练方法**共同作用。
2. 大模型基于上下文进行概率生成，可能出现**幻觉**。
3. 模型训练数据有时间边界，不能天然知道最新事实。
4. 上下文窗口有限，长输入需要裁剪、摘要或检索。
5. AI 可以辅助分析与起草，不能替代高风险场景最终责任人。
6. Transformer 用自注意力捕捉长距离依赖。
7. 自回归是根据已有序列逐步预测下一个 token。
8. Token 不等于汉字；子词分词也不是中文必按单字切分。
9. 监督学习用标签，无监督学习不用标签，强化学习用奖励信号。
10. 训练集学习参数，验证集选模型，测试集做最终评估。
11. 交叉验证轮换训练/验证划分，降低一次划分的偶然性。
12. 分类常看 Accuracy、Precision、Recall、F1、AUC；回归常看 MSE。
13. ASR 是语音转文本，TTS 是文本转语音，声纹识别判断说话人。
14. GAN 是生成器和判别器对抗；扩散模型是逐步加噪与去噪。
15. 多模态的核心难点是表示差异、语义对齐和时空同步。
16. 模型更大不等于更安全、更实时、更准确或更适合所有业务。

### M1 必背公式

- `Precision = TP / (TP + FP)`：查准率，预测为正的有多少是真正。
- `Recall = TP / (TP + FN)`：查全率，真正为正的找回多少。
- `F1 = 2PR / (P + R)`：Precision 与 Recall 的调和平均。

### M1 一眼排错

- “模型会主动上网获取最新信息” → 错。
- “测试集可以参与调参” → 错。
- “网络越深效果必然越好” → 错。
- “量子计算是当前大模型成功的主要原因” → 错。
- “TensorFlow、NumPy、Matplotlib 都是深度学习框架” → 错；TensorFlow 才是框架，NumPy 是数值计算库，Matplotlib 是绘图库。

## 三、M2 提示词工程：必须脱口而出的 12 句

1. Prompt 改输入，不改模型权重。
2. 提示词核心是目标、背景、角色、约束、示例、输出格式、评价标准。
3. 角色提示要写身份、专业、目标、受众、语气和边界。
4. Few-shot 用少量高质量示例对齐任务和格式。
5. Few-shot 示例质量、数量、顺序和边界覆盖都会影响结果。
6. 正反例可以同时使用，但错误示例必须明确标注“不要这样做”。
7. CoT 适合数学、逻辑、规划等多步推理。
8. CoT 不保证事实正确，也不是步骤越长越好。
9. 多轮对话需要显式携带历史或使用外部记忆。
10. 长历史应按相关性保留、摘要和检索，不能无差别全部塞入。
11. 列表记忆不会随每次请求自动清空，是否清理由应用控制。
12. 提示词优化应使用固定评测集，写→测→分析→改，一次尽量只改一个因素。

### M2 题干触发词

| 触发词 | 立即想到 |
|---|---|
| 语气、格式、受众、字数 | Prompt |
| 给 2～5 个例子 | Few-shot |
| 逐步分析、推理链 | CoT |
| 之前说过、持续对话 | 记忆/上下文 |
| 稳定分类、长期行为 | 微调 |
| 最新事实、企业文件 | RAG/工具 |

## 四、M3 增强应用：必须脱口而出的 18 句

1. RAG 是先检索外部证据，再把证据放入上下文生成。
2. RAG 全链路：解析、清洗、切分、索引、查询、召回、过滤、重排、生成、引用、评估。
3. Chunk 太小易丢上下文，太大易带噪声并占窗口。
4. 滑窗和重叠可以保留跨边界信息，但会增加冗余。
5. Embedding/BGE 用于向量表示和语义检索，不直接负责生成答案。
6. 相似度阈值越高通常召回越少；过高会漏掉相关内容。
7. Top-K 越大候选越多，但噪声、成本和上下文占用也增加。
8. Rerank 重新评估候选相关性和顺序，不产生新知识。
9. Multi-Query 用多个相关查询扩大召回面。
10. Decomposition 将复杂问题拆成多个可检索子问题。
11. Step-back 先提出更高层问题，补充背景。
12. RAG-Fusion 对多路检索结果融合排序。
13. CRAG 评估检索质量，低置信时纠正或补充检索。
14. 有正确候选但排序靠后属于重排问题。
15. 正确证据已进入上下文但回答仍错属于生成忠实度问题。
16. 知识库没有内容时应补库或拒答，不能只调阈值。
17. 企业知识用 RAG；实时数据、计算和动作使用工具/API。
18. 引用来源能提高可追溯性，但引用存在不等于结论一定正确。

### M3 四个高级检索法口诀

**多问扩面，拆问解难，退步找背景，低分再纠正。**

- 多问：Multi-Query。
- 拆问：Decomposition。
- 退步：Step-back。
- 纠正：CRAG。

## 五、M4 Agent：必须脱口而出的 14 句

1. Agent 把“回答问题”推进到“完成任务”。
2. 强 Agent 信号是自主规划、调用工具、跨步骤执行和反馈调整。
3. Agent 闭环：目标→规划→记忆→工具→执行→观察→校验→继续/停止。
4. 单 Agent 适合目标单一、流程清晰和上下文集中。
5. 多 Agent 适合并行、专业分工和独立复核。
6. 多 Agent 的额外代价是通信、状态同步、冲突和成本。
7. 多 Agent 必须明确角色边界、共享状态、交接协议和冲突处理。
8. 强制所有 Agent 使用同一逻辑不能真正解决冲突。
9. 工具调用需要用途说明、参数 schema、调用入口、返回结构和权限边界。
10. ModelScope-Agent 题库定位是任务拆解、依赖编排、工具选择和参数抽取。
11. MetaGPT 用角色与标准化文档模拟软件团队。
12. AutoGen 侧重多智能体对话与协同推理。
13. AgentScope 侧重多 Agent 对话、分布式协作和仿真。
14. 高风险工具动作必须在执行前确认，并保留审计记录。

### M4 选型表

| 瓶颈 | 补什么 |
|---|---|
| 缺知识 | RAG |
| 缺实时/计算/动作 | 工具 |
| 缺稳定行为 | 微调 |
| 缺重复方法 | Skill/工作流 |
| 缺长任务控制 | 记忆、检查点、监控 |
| 缺专业并行/独立复核 | 多 Agent |

## 六、M5 微调：必须脱口而出的 16 句

1. 预训练学习通用语言模式，通常依赖海量无标注数据。
2. SFT 用高质量指令数据做任务适配。
3. RLHF 用人类偏好和奖励信号做偏好对齐。
4. 微调适合长期稳定分类、格式、风格、领域行为和轻量部署。
5. 最新知识、实时数据和企业文档通常不是微调的首选。
6. 微调前先确认 Prompt 和 RAG 是否已经能解决问题。
7. 微调准备要明确目标、基线、数据、资源和验收指标。
8. 基础设施关注 GPU、显存、存储和网络，UI 美观无关。
9. 数据质量、覆盖和标注一致性通常比盲目增加数据量更重要。
10. 梯度下降的目标是最小化损失函数。
11. 学习率控制参数更新步长；调度器动态调整学习率。
12. 权重初始化影响收敛稳定性和速度。
13. Batch Normalization 稳定中间分布、改善梯度传播。
14. L1/L2、Dropout、早停都能抑制过拟合。
15. 对抗训练主要提高模型对扰动和攻击的鲁棒性。
16. 剪枝、量化、蒸馏、缓存可降低推理成本或时延，但不保证效果提升。

### M5 三阶段口诀

**预训练学通用，SFT 学任务，RLHF 学偏好。**

### M5 五项准备口诀

**目标—基线—数据—资源—验收。**

## 七、M6 安全合规：必须脱口而出的 16 句

1. 安全合规的核心是让 AI 在边界内工作。
2. 七项治理：内容安全、数据安全、权限控制、生成内容标识、来源留存、审计追踪、人工复核。
3. 内容安全处理违法有害、越狱、提示词注入和不当输出。
4. 数据安全处理采集、输入、存储、训练和使用中的数据风险。
5. 权限控制决定谁能访问哪些数据、调用哪些工具、执行哪些动作。
6. 生成内容标识只说明“这是 AI 生成”，不保证内容真实。
7. 来源留存回答“依据从哪里来”。
8. 审计追踪回答“谁在何时做了什么”。
9. 人工复核负责高风险场景最终拍板。
10. 医疗、金融、合同、对外发布属于高风险场景。
11. 个人信息处理遵循目的明确、最小必要、告知同意和安全保护。
12. 使用在线模型前检查服务条款、隐私政策、数据保存和使用方式。
13. 工具和 Agent 增加输入校验、越权、误操作、注入和数据泄漏风险。
14. 安全评测闭环：定义风险→构建基准→执行评测→修复→回归→监控。
15. 未完成合规手续或严重违规可能导致限制服务、整改或下架；题库高频口径是应用下架。
16. RLHF 可以改善偏好与安全表现，但不能替代权限、审核和合规治理。

### M6 七项治理口诀

**内数权，标源审人。**

- 内：内容安全。
- 数：数据安全。
- 权：权限控制。
- 标：生成内容标识。
- 源：来源留存。
- 审：审计追踪。
- 人：人工复核。

## 八、20 组最容易混淆的对比

| A | B | 一句话区分 |
|---|---|---|
| Prompt | 微调 | 改输入 vs 改参数 |
| RAG | 微调 | 补外部知识 vs 改稳定行为 |
| RAG | 工具 | 查资料 vs 查实时/计算/动作 |
| 工具调用 | MCP | 调一个工具的机制 vs 标准化连接和发现工具的协议层 |
| Skill | Agent | 固化方法 vs 自主规划执行主体 |
| 单 Agent | 多 Agent | 集中处理 vs 专业分工/并行/复核 |
| 训练集 | 验证集 | 学参数 vs 选模型调参 |
| 验证集 | 测试集 | 开发期选择 vs 最终评估 |
| 多分类 | 多标签 | 选一个类别 vs 可同时多个标签 |
| Precision | Recall | 预测为正有多准 vs 真正为正找回多少 |
| 清洗 | 特征工程 | 修数据问题 vs 构造更有用表示 |
| 自注意力 | 自回归 | 关系建模机制 vs 逐步生成方式 |
| ASR | TTS | 语音转文本 vs 文本转语音 |
| ASR | 声纹识别 | 识别说什么 vs 识别谁在说 |
| GAN | 扩散 | 对抗生成 vs 逐步去噪 |
| 召回 | 重排 | 找候选 vs 给候选重新排序 |
| 相似度阈值 | Top-K | 最低相关门槛 vs 最多返回数量 |
| 来源留存 | 审计追踪 | 答案依据 vs 操作过程 |
| 生成内容标识 | 事实核验 | 标明 AI 生成 vs 判断真假 |
| 事前确认 | 事后审计 | 执行前阻断风险 vs 执行后追溯 |

## 九、绝对化表述排错表

看到以下词先提高警惕：**完全、始终、所有、仅需、自动、无需人工、越大越好、一定、从不**。

它们不一定百分之百错误，但在 ACA 场景题中经常把有条件成立的结论夸大成无条件结论。正确选项通常会包含：按场景、结合评测、在权限范围内、必要时人工复核、根据反馈动态调整。

## 十二、考前 10 分钟只看这里

1. 先提示，缺知 RAG，实时工具，稳定微调，多步 Agent，高险人工。
2. 训练学、验证选、测试判；P 查准、R 查全、F1 两者调和。
3. Prompt 改输入，微调改参数；Few-shot 给样例，CoT 给步骤。
4. RAG：解析切分、索引召回、过滤重排、生成引用、评估归因。
5. 多问扩面，拆问解难，退步找背景，低分再纠正。
6. Agent：目标规划、记忆工具、执行观察、校验停止。
7. 多 Agent：角色、共享、交接、冲突。
8. 预训练学通用，SFT 学任务，RLHF 学偏好。
9. 微调前：目标、基线、数据、资源、验收。
10. 安全七项：内数权，标源审人；高风险由人拍板。
