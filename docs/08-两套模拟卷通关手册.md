| 第二套 | 29/35 | 8/15 | 37/50 | 74/100 |

## 3. 一张表判断业务场景

先圈出题干的**目标、输入类型、时效、动作、风险、限制条件**，再选能直接解决根因的手段。多种手段可以组合，人工确认是高风险动作前的门槛，不是排在最后的技术方案。

| 题干真正缺什么 | 首选思路 | 排除什么 |
|---|---|---|
| 目标、背景、约束或输出格式说不清 | 明确提示词；给参考样例、禁止事项、核验标准 | 单靠加知识库无法修复含糊指令 |
| 企业制度、合同条款、内部文档中的事实 | 检索增强 RAG，并保留引用与版本 | 仅靠训练记忆答最新、需溯源的事实 |
| 数据库中的订单量、销售额、库存、排名 | 有权限的查询/指标服务或受控 NL2SQL，计算由数据库执行 | 把结构化聚合强行当普通文档语义检索 |
| 今天的天气/价格，精确金额，提交/修改/发送 | 调实时接口、计算工具或业务工具 | 要求模型凭记忆或文本推理保证结果 |
| 稳定的分类、格式、口吻；有足够高质量样本 | 先试提示词/输出校验，仍不稳再评估微调 | 把微调用成频繁更新的知识库 |
| 多步骤、需根据中间结果决定下一步 | Agent 编排任务、数据和工具，设检查点 | 简单单轮问答过度上 Agent |
| 付款、医疗建议、合同、对外发布等高风险 | 最小权限、核验依据、**执行前人工确认**和记录 | Agent 无人审批直接执行 |

这不是“固定顺序六选一”。一道题同时出现最新政策和发送通知时，可能同时需要 RAG、工具、Agent 与人工确认。先判断题干究竟问**信息来源、结果生成、流程编排，还是执行权限**。

## 4. 六模块必记卡

### 概念（18%）

- 大模型根据上下文预测 token，能生成连贯内容，但会受训练知识截止、上下文窗口、幻觉影响；遇到实时或内部事实需外部数据，遇到不确定事实需核验。
- 预训练主要建立广泛表示和基础能力；SFT 用示范数据增强指令遵循；偏好对齐调整回答倾向。阶段会影响知识与行为，不能说后两者“绝对不增加知识”。
- 温度升高通常增加随机性；`max_tokens` 是输出 token 上限，提高上限**不保证**实际更长。不要背题库中的具体默认参数值。
- 图文、语音可出现在业务题里，但以大纲列出的应用和风险判断为复习重点；具体产品型号能力随版本变化，低优先级。

### 提示词（20%）

- 写清**目标、背景/受众、角色、可用材料、不可变约束、示例、输出格式、评价标准**。合同/翻译类题特别保留姓名、数字、日期、术语与原意。
- 复杂任务先拆解或列计划、关键事实，再生成；对数字、事实、出处、格式逐项核对。提示词能改善表达与流程，不能创造缺失事实或代替权限校验。
- 多选里“增加华丽措辞、擅自润色事实、放宽所有限制”通常越过题干目标。给例子要说明例子是格式参考还是事实依据。

### 增强应用：RAG 与工具（22%）

- RAG 五个检查点：**解析 → 切分 → 检索 → 重排序 → 评测/归因**。还要关注版本、权限、引用能否对应原文。
- **PDF/表格内容根本没被解析**：先查解析与入库；**内容已入库但搜不到**：查切分、关键词/向量召回、元数据；**候选有正确段却排得太低**：查重排；**正确证据已给模型但答案编造**：查生成约束、引用核验。不要一见错答就重训模型。
- 文档问答可用 RAG；结构化表的过滤、排序、统计由查询服务/SQL/工具完成。NL2SQL 是把自然语言转成受约束查询的办法，必须处理权限、可执行范围与结果核验。
- 来源归因问“回答依据哪份资料”；审计问“谁在何时调用了什么、改了什么”。两者都可能需要。

### Agent、MCP、Skill（16%）

- Agent 从回答问题推进到完成任务。规划时明确**目标、资料来源、工具边界、阶段检查点**；基于中间结果继续或停止。简单任务无需为了“智能”而加多步自治。
- MCP 的重点是连接外部能力的标准化方式；工具提供具体查询/计算/动作；Skill 固化可重复的步骤、约束与检查方法。这三个不是同义词。
- 自检必须可核对、有证据：例如打开生成的网页核对图表与原始数值、对文件逐项检查、在提交前校验目标对象。只检查代码语法或让模型说“我检查过了”不够。
- 风险动作（付款、发布、发送合同、删除）需授权范围和人工确认；失败时应停下、报告原因，不能编造成功状态或自动扩大权限。

### 微调（12%）

- 记五步：**定目标、备样本、选基础模型、控数据质量、评估效果**。要看样本覆盖、标注一致性、独立评测与业务指标。
- 优先用于稳定行为、格式、风格、分类，或配合轻量部署；更新频繁且需引用的企业事实更适合外部检索。两者可以组合。
- LoRA 等训练方法的实现细节不在官方主考范围；只需能辨识“训练阶段调整”与“推理时检索/调用”的区别。

### 安全合规（12%）

- 七项治理：**内容安全、数据安全、权限控制、生成内容标识、来源留存、审计追踪、人工复核**。
- 机密数据先看授权、最小必要、隔离/脱敏；外部检索资料须防提示词注入与来源污染。注入可能同时造成内容失真、越权操作或数据泄露，不能机械归为单一风险。
- 医疗、金融、合同、对外发布等高风险场景，AI 可辅助整理起草，最终责任和关键动作必须落在人与组织治理上。人工复核可设置在对外发布**之前**；人工确认是高风险动作执行前明确授权。

## 5. 两套卷对应的补分顺序

1. **先修多选判断**。第一套 11 道多选错题中，记录显示 10 道含多选干扰项；第二套多选仍错 7 道。每个选项单独问：①它直接满足题干要求吗？②有题干未给的前提吗？③是否扩大权限或越过人工？④是否使用“必然/绝不/准确预测”等过度断言？只有独立成立才勾选。不要因为某项“总体有益”就勾。
2. **接着修数据类型与 RAG 故障定位**。第一套 Q6/Q19/Q23，第二套 Q1/Q28、Q6/Q27、Q44/Q50；重做时解释为什么选择解析、切分、检索、重排、生成，或为什么应由数据库/工具计算。
3. **再修安全与流程边界**。第一套 Q47/Q50 特别要区分低风险核对、高风险付款、操作权限；第二套 Q49 练长链路中的验证与纠偏。
4. **最后补低优先级术语**。第一套 Q28 的 LoRA、第二套 Q13/Q37/Q38 的多模态/产品能力，不要按题主答案字母背；掌握概念即可。

## 6. 七天冲刺安排

| 天 | 做什么 | 当天验收 |
|---|---|---|
| 1 | 读本手册第 2～4 节；重做两卷技术选型错题 | 能口头解释 RAG、查询工具、微调、Agent 的边界 |
| 2 | 做 [专项练习](../quiz/07-两卷错因专项练习.md) 的 RAG/数据题；回读增强应用资料 | 错题能定位到 RAG 五环节 |
| 3 | 做提示词与多选；每项写一句勾选/排除理由 | 无“听起来有用就勾”的选项 |
| 4 | 学 Agent、MCP、Skill、自检及高风险审批 | 能写出四要素和执行前确认点 |
| 5 | 复习概念、微调、安全七项；重做专项错题 | 不混淆训练/推理、来源/审计 |
| 6 | 限时 60 分钟完成一份**未见过**的 50 题卷，按模块记录错误 | 总分目标 ≥88，多选 ≥11/15 |
| 7 | 只补错因，做第二份未见过的限时卷；考前扫必记卡 | 连续两次达标，再安排正式考试更稳妥 |

已见过的两套题适合复盘，不适合作为新的通过概率测试。若官方模拟自测可用，按其页面的实际及格线和题量判断；**不要将正式考试 50 题/80 分直接套到模拟自测**。多选是否部分得分应以考试页面规则为准，目前官方大纲未给出细则。
