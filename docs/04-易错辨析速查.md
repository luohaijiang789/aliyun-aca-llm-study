# 04 · 易错辨析速查

> 专治「看着都会、一选就错」。每行都是一组**出题人最爱混淆**的概念。
> 用法：考前 24h 快速过一遍，任何一条卡壳就回 `01-知识地图` 补。
> 📜 术语与判据以 [`00-考试大纲-V2.4-官方原文.md`](00-考试大纲-V2.4-官方原文.md) 为准：官方统一用「**工具 / 工具调用**」，大纲全文未出现其他旧称。

> 两套真题资料中出现的遗漏考点见[100 题索引](09-两套真题100题考点索引.md)和[六模块复习卡](10-六模块真题复习卡.md)。以下速查补上最易混的四组。

## 真题新增辨析

| 容易混淆 | 判断关键 | 相关题 |
|---|---|---|
| 结构化销量排行 vs 文档问答 | 前者用有权限的查询/指标服务或受控 NL2SQL；后者用 RAG。推荐算法不是销量统计的必备条件 | 第二套 Q6、Q44、Q50 |
| OCR/解析 vs 召回 vs 生成 | 库里没有文本先查解析；有文本没找到查切分/检索；候选有但排低查重排；证据进上下文仍编造查生成约束 | 第二套 Q27、Q29；第一套 Q36 |
| LoRA/蒸馏 vs 业务目标 | LoRA 是高效微调的办法；蒸馏可帮助做小模型。都要评测，无法单独保证准确率和极端时延指标 | 第一套 Q4、Q28 |
| Agent、MCP、Skill 与多 Agent | Agent 编排任务，工具执行能力，MCP 提供连接方式，Skill 复用方法；多 Agent 是角色分工与协作 | 两套多题，第二套 Q18、Q33、Q46 |

## 一、训练三阶段

| 阶段 | 数据类型 | 是否监督 | 产出 | 常见错选 |
|---|---|---|---|---|
| 预训练 Pre-training | 大规模语料 | 自监督为主 | 建立基础表示与生成能力 | 被说成专门学习某企业指令 ❌ |
| 监督微调 SFT | 高质量「指令-回答」对 | ✅ 有监督 | 会遵循指令的助手 | 被说成「对齐价值观」❌ |
| 对齐偏好 RLHF | 人类偏好排序数据 | ✅ 强化学习 | 输出更符合人类偏好 | 被说成「学知识」❌ |

**易错点**：
- 广泛知识主要来自**预训练**；微调重点调整目标任务的行为，也可能让模型记住训练样本事实，不适合负责频繁更新、需要引用的企业知识。
- 偏好对齐主要调整**输出倾向**，不要用绝对的“完全不增加知识”作判断。

---

## 二、⭐ RAG vs 工具（最高频、必考）

> 官方原文（考试内容 3）：**「查企业资料用 RAG，需要实时数据、确定性计算或业务动作时用工具。」**

| 维度 | **RAG（接入知识库）** | **工具（工具调用）** |
|---|---|---|
| 官方判据 | 查**企业资料 / 私域知识** | **实时数据 / 确定性计算 / 业务动作** |
| 补的是 | **知识**（静态、可更新） | **能力**（模型本身做不到的事） |
| 典型场景 | 内部制度、产品手册、历史工单 | 查天气股价、精确计算、下单发信、改系统状态 |
| 数据时效 | 改库即生效 | 调用即取当下结果 |
| 常见错选 | 被拿去干「查实时股价 / 自动下单」❌ | 被拿去干「查公司制度」❌ |

**一句话**：**查企业资料 → RAG；要实时、要精确算、要真的动手 → 工具。**

---

## 三、⭐ 微调 vs RAG

> 官方原文（考试内容 4）：**「查知识用 RAG，做动作靠工具，稳行为才考虑微调。」** 且「**微调不是万能按钮**」。

| 维度 | RAG | 微调 |
|---|---|---|
| 补的是 | **知识**（企业资料 / 私域知识） | **行为**：稳定格式、风格、分类能力、轻量部署 |
| 数据 | 外部知识库（改库即更新） | 标注样本（需重训才更新） |
| 知识可更新 | ✅ 改库即生效 | ❌ 需重训，且易过时 |
| 典型错选 | 被当成「改风格」❌ | 被当成「补知识」❌ |

**易错点**：
- 「模型不知道公司内部资料 → 微调」是**最高频错项**，正解是 **RAG**。
- 「输出格式不统一 → RAG」也是错的，正解是**提示词强约束**，不行再**微调**。
- 两者**可以组合**：RAG 补知识 + 微调定风格。

---

## 四、⭐ 来源留存 vs 审计追踪

> 官方原文（考试内容 6）七项治理：内容安全、数据安全、权限控制、生成内容标识、**来源留存**、**审计追踪**、人工复核。

| 维度 | 来源留存 | 审计追踪 |
|---|---|---|
| 查的是 | AI 回答的**依据**（引了哪份资料、哪条数据） | **人**做了什么（谁、何时、做了什么操作） |
| 回答的问题 | 「这个答案从哪来？」 | 「这件事是谁干的？」 |
| 典型用途 | 引用归因、可追溯核验、降低幻觉影响 | 责任界定、合规检查、事后追溯 |
| 常见错选 | 被当成「查操作日志」❌ | 被当成「查引用出处」❌ |

**一句话**：**来源留存查「依据」，审计追踪查「人」。**

---

## 五、⭐ 人工确认 vs 人工复核

| 维度 | **人工确认** | **人工复核** |
|---|---|---|
| 出现在 | **Agent 执行前** | 安全合规治理项（考试内容 6） |
| 性质 | **动作门槛**：高风险动作必须经人点头才能执行 | **合规治理措施**：可在发布前审核产出，也可事后复盘 |
| 官方原文 | 考试内容 5：「**高风险动作必须人工确认**」 | 考试内容 6：七项治理之一 |
| 典型场景 | 自动下单、对外发文、改数据库前让人确认 | 对 AI 生成内容做审核、留痕 |
| 常见错选 | 被当成「事后检查」❌ | 被当成「执行前拦截」❌ |

**一句话**：**人工确认是执行前的闸门，人工复核是合规治理的环节。**

---

## 六、⭐ Skill vs 提示词

> 官方原文（考试内容 5）：**「Skill 用来固化重复工作方法」**；**「自检清单要具体、可核对、有证据」**。

| 维度 | 提示词（优化输入） | Skill |
|---|---|---|
| 形态 | 单次指令 | 可复用的**方法包**（步骤 + 工具 + 约束） |
| 解决什么 | 这一次说清楚 | **重复工作方法的固化** |
| 是否可复用 | 每次重写 | ✅ 固化后反复调用 |
| 常见错选 | 被当成「沉淀工作方法」❌ | 被当成「只是一句提示词」❌ |

**易错点**：问「把一套重复的工作方法沉淀下来」→ 选 **Skill**，不是「多写几条提示词」。

---

## 七、Agent 三能力

| 能力 | 干什么 | 典型技术 |
|---|---|---|
| 感知 Perception | 获取输入与环境信息 | 多模态输入、工具返回结果 |
| 思考 Reasoning | 分析、规划、决策 | CoT、ReAct、ToT、规划分解 |
| 行动 Action | 执行、调用工具 | Function Calling、MCP、API |

**易错点**：
- 「调用外部 API」属于**行动**，不是感知。（感知是"接收"，行动是"出手"）
- ReAct = **Reasoning + Acting 交替**，不是纯推理。
- 官方给 Agent 的四要素：**目标、资料来源、工具边界、阶段检查点**（考试内容 5）。

---

## 八、MCP / Skill / 工具 / Function Calling

| 概念 | 层级 | 一句话 |
|---|---|---|
| Function Calling | 模型能力 | 模型输出结构化的「我要调这个函数 + 参数」 |
| **工具（工具调用）** | 应用形态 | 把一个外部能力包装成模型可调用的成品（联网、计算、业务动作） |
| **MCP** | 协议标准 | 标准化模型与外部数据源 / 工具**怎么连** |
| **Skill** | 流程封装 | 把一套**工作方法**（步骤 + 工具 + 约束）固化成可复用单元 |

**易错点**：
- 官方统一说法是「**工具 / 工具调用**」，全文未出现其他旧称。
- MCP 是**协议**，不是工具本身。问「标准化连接方式」选 MCP。⚠️ 官方要求**只了解作用，不考协议细节**。
- Skill ≠ 提示词。提示词是单次指令，Skill 是**可复用、含流程与工具**的方法包。

## 九、自检闭环

| 说法 | 判断 |
|---|---|
| 「Agent 执行完自己检查结果，不合格就重试」 | ✅ 正解 |
| 「人工审核 Agent 的每一步输出」 | ❌ 这是人工流程，不是自检闭环 |
| 「让模型多生成几次选最好的」 | ⚠️ 这是 best-of-N 采样，不等于自检闭环（自检需有**校验标准**） |

**官方要求**：自检清单要**具体、可核对、有证据**（考试内容 5）。

## 十、安全合规

| 风险类型 | 例子 | 典型治理 |
|---|---|---|
| 数据安全 | 敏感信息被带入提示词、训练数据泄露 | 脱敏、数据最小化、权限控制 |
| 内容安全 | 生成有害内容、越狱、提示词注入 | 输入过滤 + 输出审核 + 安全护栏 |
| 幻觉 | 编造事实、虚假引用 | RAG 归因、**来源留存**、人工复核 |
| 合规 | 未备案上线、跨境数据 | 备案、合规审查 |
| 知识产权 | 训练数据版权、生成物归属 | 授权链路、生成内容**标识** |

**易错点**：
- 「提示词注入」从低信任输入进入，可能导致内容失真、越权工具调用或数据泄露；按后果同时考虑内容、权限和数据安全。
- 「幻觉」的治理首选 **RAG + 引用归因**，不是「加大模型参数」。
- 官方高风险四类场景：**医疗、金融、合同、对外发布** —— 一律「AI 可以辅助整理和起草，但**不能替代最终责任人**」。

## 十一、生成与采样参数

| 参数 | 作用 | 调大的效果 |
|---|---|---|
| `temperature` | 控制采样随机性 | 更有创意、更不稳定 |
| `top_p` | 核采样，从累积概率前 p 的候选里选 | 类似 temperature |
| `max_tokens` | 生成长度上限 | 允许更长输出，但不保证实际变长 |

**易错点**：需要**稳定、确定性**输出（如格式化抽取）时，应**调低** temperature，不是调高。
⚠️ 参数**默认值**不在官方大纲内，不必背数字；只考**作用方向**。

## 十二、概念判断题常设陷阱

| 陷阱 | 正解 |
|---|---|
| 「大模型能实时获取最新信息」 | ❌ 知识截止于训练数据，需 **RAG / 工具** |
| 「大模型理解语义」 | ⚠️ 本质是**基于上下文预测下一个 token**，表现为理解 |
| 「参数越大效果一定越好」 | ❌ 还取决于数据质量、对齐、架构 |
| 「多模态 = 一个模型搞定所有模态」 | ⚠️ 六大模块中**无多模态**，不必深究 |
| 「微调能让模型学会新知识」 | ❌ **查知识用 RAG，稳行为才考虑微调** |
| 「Agent 一定比提示词好」 | ❌ 简单任务用 Agent 是过度设计 |
| 「Agent 可以全自动执行高风险操作」 | ❌ **高风险动作必须人工确认** |
| 「效果不好就该微调」 | ❌ **微调不是万能按钮**，先优化输入 |

## 十三、第三套新增高频辨析

### 1. 知识缺失 vs 解析损坏 vs 切分不当

| 判断问题 | 知识缺失 | 解析损坏 | 切分不当 |
|---|---|---|---|
| 原文件里有内容吗 | 没有或版本旧 | 有 | 有 |
| 入库文本里有内容吗 | 没有 | 缺字段、错行列、OCR 错 | 有但上下文被拆散 |
| 首选修复 | 补/更新知识条目 | 修解析、OCR、表格结构 | 按章节/条款/API 小节切分 |
| 不要先做 | 调 Top-K、重排 | 换向量模型 | 整文合并或无限增大 Chunk |

### 2. 术语表 vs CoT vs 自检

- **术语表**提供唯一标准答案，适合固定译法。
- **CoT**帮助多步推理，但不能创造标准译法。
- **自检**发现与已有标准的偏差，前提是标准已提供。

### 3. Skill vs 知识库 vs 微调

| 对象 | 保存/改变什么 | 典型用途 |
|---|---|---|
| Skill | 步骤、模板结构、规则、检查项 | 重复报告流程、跨项目个人日志 |
| 知识库 | 制度、事实、资料、版本 | 公司规程、活动规则、产品手册 |
| 微调 | 模型稳定行为 | 高频分类、固定语气、领域意图 |

### 4. 信息抽取 vs 数值预测

从报告提取定价策略属于语言理解；根据历史销量“精确预测”未来数值属于统计建模与不确定性评估。大模型能辅助解释和生成特征，不能因会读报告就推导出精确未来。

### 5. 真实引用 vs 模型生成引用

真实引用来自给定权威资料或检索结果，并能回到原文核查；要求模型“为关键事实生成来源”会制造虚假出处。找不到依据时应删除、标记不确定或补查资料，不能改成模糊说法掩盖问题。
