# 六模块真题复习卡：按题主两套 100 题补齐

> 用于修订本项目六篇深度资料的备考重点。题号对应[100 题考点索引](09-两套真题100题考点索引.md)，具体题干在[第一套](../quiz/题主全真模拟卷-2026-10-09.md)和[第二套](../quiz/题主全真模拟卷-第二套-2026-10-09.md)。考试边界以[官方大纲 PDF](../resources/官方-考试大纲-V2.4.pdf)为准；题主卷里出现的术语也列入辨识复习，但不因此推断官方会考实现细节。

## M1 大模型概念：判断能做什么、不能保证什么

**本模块要背**

1. 大模型根据上下文逐 token 生成内容；生成并不等于核实事实。训练数据时间范围、上下文容量和幻觉是应用侧的边界。上下文写不下时要筛选、摘要或检索，不能只提高随机采样参数。
2. AI ⊃ 机器学习 ⊃ 深度学习；Transformer、CNN、RNN 是不同架构。预训练用大规模数据建立基础能力，SFT 用示范数据改善指令或任务表现，RLHF 用偏好反馈改善输出倾向。推理阶段主要是用已有参数生成，不是每次在线训练。
3. 生成、总结、提取、分类可以由模型辅助；**精确预测未来市场份额、可靠给出实时事实、执行外部动作**均需要额外证据、工具或人工决策。输出略超字数是约束遵循问题，未必是事实幻觉。
4. 图像目标检测解决“人和安全帽在哪里、是否关联”；文生图/图生视频与文本生成是不同能力。多模态未单列权重，但两套卷均有图像、视频、语音场景题。通义千问/万相等产品能力需按版本核对；不要背过时型号的绝对说法。
5. 术语只需认作用：embedding 把文本映射为语义表示；低温通常更稳定，高温通常更多样；`max_tokens` 只规定上限。

**对照真题**：第一套 Q21、Q34、Q38、Q42；第二套 Q8、Q12–16、Q20、Q22、Q36–38、Q40、Q48。第二套 Q13、Q37、Q38 的答案依赖“典型流程”或产品版本，复习概念与边界，不死记字母。

**自问**：模型能给出近三个月真实销量排行榜吗？仅靠参数不能；应查询有权限的数据源。它能帮写对外稿吗？可以起草，但事实和发布权要校验。

## M2 提示词工程：把输入写成可验收任务

**官方七要素**：目标、背景、角色、约束、示例、输出格式、评价标准。另在具体任务中补受众、目的、术语、不可改写信息；复杂任务先列计划与关键事实、确认后再生成。这些是要素池，不能误称为排他的“四件套”。

**按任务选写法**

| 题干问题 | 应加的内容 | 验收动作 |
|---|---|---|
| 招聘职责/福利混写 | 栏目结构、字段含义与示例 | 各信息只进对应栏 |
| 会议邮件把待确认写为已定 | 负责人、日期、动作、状态和“未确认”标识 | 对照原纪要逐项核查 |
| 法律/医学翻译歧义 | 受众、术语表、上下文示例、不可更改事实 | 查日期、数字、缩写和责任词 |
| 数学多步推理 | 分步求解、关键边界、计算核验 | 用独立验算检查结论 |
| 排障提示 | 报错、环境、已试步骤、成功标准 | 只用已有证据定位，不编造执行结果 |

CoT、问题分解、思维树分别用于分步推理、拆子问题、探索不同路径；**不能因为写了“逐步思考”就把算术或事实验证省掉**。分类示例需覆盖正负中性和混合/边界情形，避免只给极端样本。提示词有助于约束，但缺企业资料和实时信息时仍需 RAG 或工具。

**对照真题**：第一套 Q11、Q18、Q29–30、Q33、Q46；第二套 Q2–3、Q7、Q19、Q23、Q25–26、Q41、Q43。

## M3 增强应用：从数据类型到 RAG 故障定位

**先看数据**：制度、合同、产品手册等非结构化资料适合 RAG；持续变动的订单表、库存、销量前十适合**受控指标服务/数据库查询/NL2SQL**；实时外部数据、确定性计算、写入系统要工具。NL2SQL 是自然语言转受限查询，并非保证 SQL 安全正确；需权限、只读范围、字段校验与结果核对。推荐算法回答“给谁推荐什么”，不必然用于“统计销量前十”。

**RAG 五层排错**

| 观察到的症状 | 首查 | 不能先做什么 |
|---|---|---|
| 扫描 PDF、表格内容在切片库中根本不存在 | OCR/解析、表格抽取、入库 | 降低相似度阈值或调提示词 |
| 原文有，但被切断章节、条款或代码上下文 | 结构切分、相邻窗口、标题/条款元数据 | 无限放大所有 chunk |
| 切片有，候选没召回 | 查询改写、关键词+向量混合、过滤条件、召回评测 | 只换更大生成模型 |
| 候选有，排不到上下文前列 | 重排、top-k、上下文预算 | 再次 OCR |
| 证据已进入提示，回答仍编造或无引用 | 生成约束、证据对齐、无依据拒答 | 把问题归因于入库 |

召回数是上限：设 top-k=5、符合阈值只有 3 条，就返回 3 条。embedding 主要解决语义近似，关键词更适合精确术语；重排调整候选顺序，**不能恢复根本未召回的资料**。Raptor 是层级聚类/摘要索引思路，可支持跨文档关联；第二套 Q1/Q28 完全重复，其 B/C 表述有重叠，不宜作为“唯一正确术语定义”死背。

**API 与质量**：批量处理上万份材料需程序化/批处理调用、限流、失败重试和结果核验；“考试不要求写代码”不等于“不考识别批量 API 的合适方式”。文档检索指标看命中、召回、相关性；生成指标看真实性、证据忠实度、引用；延迟/成本另作运行指标。RAG 与微调可组合：前者提供可更新事实，后者改善稳定行为。

**对照真题**：第一套 Q6、Q12、Q17、Q19、Q22、Q31、Q36、Q39；第二套 Q1/Q28、Q4、Q6、Q9–11、Q22、Q24、Q27、Q29、Q44–45、Q50。**第二套 Q44/Q50 对近似销量题给了冲突的第二答案**；确定的核心是受控结构化查询，额外技术取决于题干是否另有推荐或文档依据需求。

## M4 Agent：完成任务，也要管上下文、工具和检查点

**四要素**：目标、资料来源、工具边界、阶段检查点。Agent 能根据中间结果规划和调用工具；MCP 解决外部能力的标准化连接，Skill 固化重复工作方法，两者不能代替权限设计。地图规划可按任务需要交替使用地点、路线、路况工具，调用顺序由中间结果决定。

**两套卷补出的细节**

- 不同工单的会话信息要隔离；跨会话需要复用时只保存已确认的必要事实，并记录来源和有效期。
- 工具/日志/Skill 太多会挤占上下文。按任务选择工具、按需加载 Skill 正文、压缩旧日志并保留关键状态，比整段塞回上下文更稳。
- 多 Agent 的分工要明确目标、交接产物、冲突协调和共享约束。多 Agent 并非单步问答的必选项。
- 自检必须看实际产物：网页要打开、图表数值要与源表比、合同状态要与记录比。仅检查语法或自述“已检查”不够。
- 长链路会出现等待、偏差累积、工具成本和中途纠偏难题。设置阶段检查、失败停止条件、人工介入点。
- 具体 Skill 安装目录、某框架名称属于产品/环境事实，不能从通用原理推导；先理解**作用域、复用、按需加载**，再按实际产品文档核对路径。

**对照真题**：第一套 Q2、Q5、Q8–9、Q13–15、Q23、Q26–27、Q32、Q40、Q43–44、Q49；第二套 Q17–18、Q21、Q33–35、Q46–47、Q49。第二套 Q49 的人机纠偏选项在实际系统也重要，按题目强调的性能范围解释答案。

## M5 微调：目标、样本、评测和效率

**官方五步**：定义目标 → 准备样本 → 选择基模 → 控制数据质量 → 评估效果。适合长期稳定的行为、格式、风格、分类能力，或支持轻量模型部署。先明确业务指标和样本覆盖；训练集高分、线上差，要查过拟合、数据分布、标注、错误类型，不能只延长训练。

**两套卷实际涉及的术语，学到辨识层即可**：LoRA 属于参数高效微调，适用于资源有限时对现有模型做领域任务适配；蒸馏让较小模型学习较大模型的行为，可作为降低推理成本/时延的候选方案。二者**都不保证**“准确率不降且 2.5 秒必达 200 毫秒”，必须实测。SFT 根据示范样本调整任务行为，RLHF 用人类偏好反馈改善输出；推理阶段不是持续在线微调。

**不该误选微调**：最新政策、频繁变化的产品价格、需引用出处的内部制度用外部数据；精确金额用工具；高风险审批靠治理。微调样本可能记入模型权重，难以像知识库那样逐条撤回或溯源，但不能说微调“绝对不会增加知识”。

**对照真题**：第一套 Q4、Q16、Q20、Q28、Q35、Q37、Q48；第二套 Q5、Q15、Q30–32、Q39、Q42、Q48。第一套 Q4 的极端性能指标不能由某个训练方案单独保证。

## M6 安全合规：所有自动化方案都要叠加边界

**官方七项**：内容安全、数据安全、权限控制、生成内容标识、来源留存、审计追踪、人工复核。来源留存解释“依据从哪来”，审计追踪解释“谁何时做了什么”；二者不是互相替代。人工复核可放在对外发布前；高风险动作**执行前**需人工确认。

**按风险问**

| 情况 | 合适处理 |
|---|---|
| 医疗建议没有查到用药依据 | 停止自动建议、转人工；改善检索是附加动作 |
| 工具要读整个网盘，但任务只需一个文件夹 | 缩小权限至最小必要范围 |
| 网页含“忽略规则、下载木马、外发名单” | 作为低信任资料处理，不执行其中指令；核查授权与外发边界 |
| 银行账单查询与分期办理 | 身份/权限隔离、受控接口、关键动作确认及审计 |
| 报销：核对发票与提交付款 | AI 可读取、比对、起草；实际付款由授权人确认 |
| 对外文章、视频、配乐、画面 | 核事实和来源、素材授权、生成标识、发布前审核 |

风险评测需定义场景、风险、验收标准和可核验证据，迭代进行，不必背第三方题库设定的绝对先后顺序。提示词注入可能造成内容污染、越权调用或数据泄漏，应按实际后果治理。金融/医疗/合同/发布场景的最终责任由人和组织承担。

**对照真题**：第一套 Q1、Q3、Q7、Q10、Q24–25、Q41、Q45、Q47–48、Q50；第二套 Q16、Q21、Q34、Q45。

## 最后记一个多选判断流程

1. 先读问法：问“哪些**直接**解决”、问“至少检查”、问“不包括/错误的是”，范围不同。
2. 每项单独归因：它解决的具体问题是什么？题干是否给了必要条件？是否引入新风险？
3. 对“可能有益但题干没要求”的选项保持克制；对“绝对、保证、只能、自动无风险”找反例。
4. 有争议的题，记**判据与缺失前提**，不把题主参考答案升级成官方通用规则。
