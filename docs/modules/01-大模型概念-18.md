## 三、逐考点详解

### M1-K01 · 大模型定义与"大"的体现 🟢`[A]`

**是什么**：大模型（Large Model / 大语言模型 LLM）是指**参数规模巨大、在海量数据上训练**而成的深度学习模型，能够理解和生成自然语言，并完成问答、写作、推理、摘要等多种任务。

**为什么**：之所以强调"大"，是因为**规模本身带来了能力变化**——不是简单地"更快的老模型"，而是能力边界被拓宽（这也是 M1-K08 涌现能力的前提）。

"大"体现在三个维度（**记忆核心**）：

| 维度 | 含义 |
|---|---|
| **参数量大** | 模型内部可学习的权重数量巨大，是承载知识/模式的"容量" |
| **训练数据量大** | 覆盖海量文本，模型才具备通用语言与世界知识 |
| **算力投入大** | 训练和推理都需要大量计算资源，这是"大"的成本面 |

**易错点**：
- ❌ 把"大"理解成"**能处理无限长输入**"——上下文长度有上限，且以 Token 计（见 M1-K03）。
- ❌ 认为"参数大 = **推理时所有参数都参与计算**"——MoE 架构下是稀疏激活（见 M1-K07）。
- ❌ 认为"大"保证"**回答一定正确**"——规模不消除幻觉（见 M1-K11）。

**记忆法**：**「参、数、算」** —— 参数多、数据多、算力多。看到"大"先想这三件事。

### M1-K02 · 训练三阶段：预训练 → SFT → RLHF 🟢`[A]`

**是什么**：一个可对话、好用的大模型，通常经历三个阶段：

| 阶段 | 全称 | 做的事 | 产出 |
|---|---|---|---|
| ① **预训练** | Pre-training | 在海量无标注文本上做"预测下一个 Token"的自监督学习 | **基座模型**（有知识、会续写，但不听指令） |
| ② **SFT** | Supervised Fine-Tuning 监督微调 | 用"指令-回答"示例数据训练 | 会**遵循指令**、按格式回答 |
| ③ **RLHF** | Reinforcement Learning from Human Feedback 人类反馈强化学习 | 用人类偏好反馈调整输出倾向 | 回答**更符合人类价值观与偏好**（有用、无害、诚实） |

**为什么**：三个阶段解决的是**三个不同的问题**——有没有知识 / 听不听话 / 讨不讨人喜欢。缺任一步都不行：只有预训练的模型会"续写"而不是"回答"；没有 RLHF 则可能输出有害或啰嗦的内容。

**易错点**（高频考题）：
- ❌ **顺序颠倒**：必须是 预训练 → SFT → RLHF，SFT 不可能在预训练之前。
- ❌ 认为 **RLHF 用来"注入新知识"**——新知识靠预训练/继续预训练/微调数据，RLHF 只调**输出倾向**。
- ❌ 认为 **SFT 负责对齐价值观**——那是 RLHF 的活；SFT 主要解决"听指令、按格式输出"。
- ❌ 把这里的"微调（SFT）"和 M5 模块的"业务微调"混为一谈——SFT 是**训练流程里的一个阶段**，M5 微调是**使用方为垂直领域做的适配**。

**记忆法**：**「先有料、再听话、后讨喜」** = 预训练（有料）→ SFT（听话）→ RLHF（讨喜）。

### M1-K03 · 分词 Tokenization 🟢`[A]`（V2.4 强化交互演示）

**是什么**：模型不能直接读字符串，输入文本会先被切分成一个个 **Token**（词元），再映射成数字 ID 送进模型。这是模型处理文本的**最小基本单位**。

**为什么**：
- 模型的所有"账"都按 Token 记：**上下文长度以 Token 计，调用量/计费也按 Token 计**。
- 分词粒度直接决定效率和成本：切得太碎 → 同样一段话占更多 Token → 更快撞上上下文上限、成本更高。

**要点**：
- 中文、英文**都会被切分**，不存在"中文按字、英文按词"这种简单规则。
- 一个英文单词**可能被拆成多个 Token**（尤其生僻词、专业词、长复合词），不是"一个单词 = 一个 Token"。
- 分词在**训练和推理阶段都需要**，且**必须用同一套词表/分词器**，否则语义对不上。
- 数字、标点、空格、代码块同样会占 Token。

**易错点**：
- ❌ "Token 就是字数/字符数"——两者不是一回事，不能简单按字数换算。
- ❌ "一个汉字 = 一个 Token"——只是粗略直觉，不同分词器粒度不同，**不要拿换算比例当考点硬记**。
- ❌ "分词只在训练时做"——推理时同样必须做。

**记忆法**：Token = 模型的**"计数单位"**，记住三句话：**输入要切、长度按它算、花费按它计**。

### M1-K04 · 自回归生成（文字接龙） 🟢`[A]`（V2.4 强化交互演示）

**是什么**：主流大语言模型采用**自回归（Auto-regressive）**方式生成文本：每次基于"已有内容"预测**下一个最可能的 Token**，把这个 Token 拼到已有内容后面，再预测下一个，如此循环直到结束。

**为什么**：这解释了大模型行为的很多"直觉现象"：
- **输出是逐字"蹦"出来的**（流式输出）——因为本来就是一个一个 Token 生成的。
- **输出越长越慢、越贵**——每个新 Token 都要重新算一遍。
- **前面写错了后面容易被带偏**——生成依赖已生成的历史（错误会累积）。
- **同一个问题每次答案可能不同**——每一步都是概率采样。
- 所谓"**文字接龙**"演示，就是把这个过程可视化出来。

**易错点**：
- ❌ 认为模型"先在脑子里打完草稿再一次性输出"——不是，是逐步生成。
- ❌ 认为模型"从数据库里检索出答案再念出来"——不是检索，是**基于概率逐 Token 预测**。
- ❌ 认为"输出长度不影响耗时"——影响，而且影响明显。

**记忆法**：**「接龙」**——你出上句，它接下一个字，接完再接下一个。

### M1-K05 · 注意力机制 🟢`[A]`（V2.4 强化：注意力溯源演示）

**是什么**：注意力机制（Attention）让模型在处理某个 Token 时，能够**动态地关注上下文中与它相关的其他 Token**，并按相关性分配权重。

通俗拆解（不必记公式，理解即可）：
- 每个 Token 会生成三种向量：**Query（我要找什么）**、**Key（我是什么）**、**Value（我能提供什么）**。
- 用 Query 去和所有 Key 算匹配度 → 得到**注意力权重** → 按权重把各 Token 的 Value 加权汇总。
- 结果：当前位置的表示里，**混入了它真正需要的上下文信息**。

**为什么**：
- 解决**长距离依赖**问题：句首的"那款蓝牙耳机"能被句尾的"它"正确关联上。
- 支持**并行计算**（相对 RNN 逐词串行），是训练超大模型的前提。
- V2.4 新增的**注意力溯源**演示：可以追溯"模型生成这个词时，究竟关注了输入里的哪些部分"，用于**提升可解释性**、定位问题（如回答被无关上下文干扰）。

**易错点**：
- ❌ 把"注意力"当成"模型的记忆/数据库"——它不是查表，是**相关性加权计算**。
- ❌ 认为"注意力权重高 = 事实正确"——注意力只说明**关注了哪里**，不代表答案对。
- ❌ 把注意力机制和 MoE 混淆：**注意力**决定"看上下文的哪些 Token"；**MoE 路由**决定"用模型的哪些参数/专家"。一个在**输入侧**，一个在**模型结构侧**。

**记忆法**：注意力 = **"看谁重要就多看谁一眼"**；溯源 = **"回看它刚才看的是谁"**。

### M1-K06 · Transformer 架构 🟡`[B]`

**是什么**：Transformer 是以**自注意力（Self-Attention）**为核心构建的神经网络架构，由多层注意力 + 前馈网络堆叠而成，是当前主流大模型的架构基础。

**为什么**：
- **可并行**：不像 RNN 必须逐词串行处理，Transformer 能同时处理整段序列 → 训练效率大幅提升 → 才可能把模型"做大"（承接 M1-K01）。
- **扩展性好**：层数、宽度、注意力头数等可以按规模扩展，支撑不同规模的模型系列。

常见形态（了解即可，不考实现）：
- **Encoder-only**：擅长理解类任务（如分类、向量表示）。
- **Encoder-Decoder**：擅长序列到序列（如翻译）。
- **Decoder-only**：擅长生成，主流对话大模型多采用此类。

**易错点**：
- ❌ 认为 "Transformer = 大模型"——Transformer 是**架构**，大模型是**规模 + 训练**的结果。
- ❌ 认为有了 Transformer 就不需要分词/不需要训练三阶段——架构只是底座，其余环节一个不少。

**记忆法**：**架构是骨架，规模是肌肉，训练三阶段是教育经历。**

### M1-K07 · MoE 架构 🟢`[A]`（V2.4 强化图文说明）

**是什么**：MoE = **Mixture of Experts（混合专家）**。模型内部包含多个"专家"子网络和一个**路由/门控（Router / Gate）**，每次处理输入时由路由挑选**少量相关专家**参与计算。

**为什么**（这是出题最爱问的"好处"）：
- **参数总量可以做得很大**（知识容量大、表达能力强），但**单次推理只激活一部分专家** → 推理算力/成本增长远低于参数量增长。
- 即：**"大模型能力 + 小模型开销"** 的折中方案。
- 核心关键词是**稀疏激活（Sparse Activation）**：总参数 ≠ 每次推理都用上的参数。

**易错点**：
- ❌ 认为 MoE 模型"每次推理都用全部参数"——恰恰相反，只激活被路由选中的部分专家。
- ❌ 把 MoE 和**量化**混为一谈——量化是降低数值精度来省显存/提速，不改"用哪些参数"；MoE 是改"用哪些专家"。
- ❌ 把 MoE 和**注意力**混为一谈——见 M1-K05 易错点。
- ❌ 认为 MoE 能解决幻觉/时效问题——不能，MoE 是**效率与容量**层面的架构设计。

**记忆法**：MoE = **"大医院分诊"**——专家很多，但你看病只挂对应那一个科室的号。关键词：**多专家 + 路由 + 稀疏激活**。

### M1-K08 · 涌现能力 🟡`[B]`

**是什么**：当模型的规模（参数量、数据量、算力）**跨过某个阈值后，突然表现出小模型不具备的能力**，这类能力称为涌现能力（Emergent Abilities）。

典型例子（理解即可）：多步推理、复杂指令遵循、上下文学习、思维链推理等——这些**不是被显式训练出来的任务**，而是随规模增长"冒出来"的。

**为什么**：它解释了"为什么一定要做大"——不是线性变好，而是到某个量级**解锁新能力**。这也是 M1-K01"大"的意义所在。

**易错点**：
- ❌ 认为"涌现 = 参数越大各项能力都平滑变好"——涌现强调的是**跃迁/突变**式出现，不是平滑线性提升。
- ❌ 认为"涌现能力是工程师写规则写进去的"——不是，不是显式编程或标注出来的。
- ❌ 认为"涌现 = 模型无所不能"——涌现不消除幻觉与时效限制。

**记忆法**：**"量变到质变，突然就会了"**。

---

### M1-K09 · 上下文学习 ICL 🟡`[B]`

**是什么**：**In-Context Learning（上下文学习）**：**不更新模型参数**，只在输入的上下文中给出若干示例（few-shot / 零示例 zero-shot），模型就能"照着样子"完成新任务。

**为什么**：这是大模型相对传统模型的重大差异——传统模型换个任务往往要重新训练；大模型**换个提示就能换任务**。它也是 **M2 提示词工程**成立的根本前提。

**易错点**：
- ❌ 认为 ICL "训练/更新了模型参数"——**完全没有**，参数一动不动，只是把它放进上下文里"临时"引导。
- ❌ 认为 ICL 把知识"永久存进模型"——关掉会话就没了，**不会沉淀**。
- ❌ 把 ICL 与 **RAG** 混同：ICL 是在提示里塞**示例**，RAG 是检索**外部知识**（属 M3）。
- ❌ 把 ICL 与 **微调** 混同：微调改参数（属 M5），ICL 不改参数。

**记忆法**：**"给几个例子，现学现用，用完就忘"**。

### M1-K10 · 大模型四大特点 🔴`[C]`

> ⚠️ **可信度 `[C]`**：课时1「认识大模型」必然讲大模型特点（故列为课程覆盖），但**"四大特点"的具体四项表述未获官方确认**，以下为行业通用表述，**待与官方 V2.4 大纲 PDF 核对**。若官方表述不同，以官方为准，但**掌握方向一致**。

常用四项（备考按此理解）：

| 特点 | 含义 |
|---|---|
| ① **强大的语言理解与生成能力** | 能理解复杂指令、语境、指代，并生成连贯自然的长文本 |
| ② **通用性与泛化能力** | 一个模型应对写作、摘要、翻译、推理、代码等多类任务，而非单一专用 |
| ③ **上下文学习能力（ICL）** | 见 M1-K09：给示例即可适配新任务，不改参数 |
| ④ **涌现能力** | 见 M1-K08：规模过阈值后出现小模型没有的能力 |

**易错点**：
- ❌ 把"**不会产生幻觉 / 永远正确**"当成特点——那是**误解**，规模再大也有幻觉与时效问题。
- ❌ 把"**能实时联网获取最新信息**"当成特点——原生大模型不具备，要靠 RAG/插件/工具（M3/M4）。
- ❌ 把"**具备自主意识和主观判断**"当成特点——没有，输出本质是概率生成。

**记忆法**：**「懂、广、学、涌」** —— 懂语言、广通用、学上下文、涌能力。

### M1-K11 · 模型局限：幻觉 / 时效 🟡`[B]`

**是什么**（两类最常被考的局限）：

| 局限 | 表现 | 典型场景 |
|---|---|---|
| **幻觉（Hallucination）** | 生成**看似合理但与事实不符**的内容：编造不存在的法条、文献、数据、API | 问"某法规第 X 条怎么规定的"，模型一本正经给出不存在的条款 |
| **知识时效性** | 模型的知识停留在**训练数据截止时点**，不知道之后发生的事 | 问"昨天的发布会发布了什么"，模型答不上来或瞎编 |

其他常见局限：上下文长度有限、复杂精确计算不可靠、对长文本中间部分容易"忽略"、输出不稳定（同一问题多次结果不同）。

**为什么**：这是**选型题的判断依据**——凡是"缺最新/私域知识"的问题 → 走 RAG（M3）；凡是"缺实时外部能力" → 走插件/工具（M3/M4）；凡是"缺固定风格/格式" → 走微调（M5）。**局限决定了增强手段。**

**易错点**：
- ❌ 把两者混为一谈：**编造不存在的东西 = 幻觉**；**不知道新近发生的事 = 时效**。题干里出现"不存在的/杜撰的"→ 幻觉；出现"最新的/上周的/今天的"→ 时效。
- ❌ 认为"换个更大的模型就能彻底消除幻觉"——只能缓解，不能根除。
- ❌ 认为"微调可以解决时效性问题"——微调成本高且知识同样会过期，时效问题首选 RAG。

**记忆法**：**「编的是幻觉，缺的是时效」**。

### M1-K12 · 模型分类（按模态 / 开源 / 用途） 🟡`[B]`

**是什么**：分类是**维度**问题，不同维度可以叠加，一个模型可同时属于多个类别。

| 维度 | 典型类别 |
|---|---|
| **按模态** | 语言/文本模型、视觉生成模型、语音模型、多模态模型（同时处理多种输入输出） |
| **按开放性** | 开源模型（权重开放可下载部署） / 闭源模型（以 API 形式提供服务） |
| **按用途** | 通用基座模型 / 垂直领域模型 / 专用能力模型（如 embedding 向量模型、重排序模型） |

**为什么**：分类决定**选型与部署方式**——开源可私有化部署（数据不出域），闭源走 API（省心、免运维）；通用基座适合做底座，垂直模型适合特定行业。

**易错点**：
- ❌ 认为"开源 = 一定能商用、一定免费"——开源是**权重可得**，商用要看具体许可协议。
- ❌ 认为分类是互斥的——同属多个维度很正常。
- ⚠️ **多模态**：V2.4 已将「多模态大模型」作为**独立模块移除**，本模块**不将其作为独立考区**；它只作为"按模态分类"中的一个类别名称出现。

**记忆法**：分类三问：**处理什么（模态）？拿不拿得到（开源）？干什么用（用途）？**

### M1-K13 · 典型应用场景（课时2） 🟢`[A]`

**是什么**（官方课时2「大模型的典型应用场景」的四类典型）：

| 场景类别 | 在做什么 | 例子 |
|---|---|---|
| **文本生成与创作** | 从无到有产出内容 | 写营销文案、写周报、写故事、生成代码 |
| **文本润色与转换** | 对已有文本做改写/转换 | 润色语病、风格改写、翻译、口语转书面语、格式转换 |
| **文本摘要与信息提取** | 压缩 + 抽关键信息 | 长文要点总结、会议纪要、从合同里提取甲乙方/金额/期限 |
| **信息推理与表格解读** | 基于给定数据做推断/计算式理解 | 读销售报表给结论、对比多方案、按表格内容回答追问 |

**为什么**：这是**场景归类题**的答题依据。做题方法是**看"输入→输出"发生的变化**：
- 原来没有、现在生成了 → **生成创作**
- 原来有、只是换了个说法/语种/风格 → **润色转换**
- 原来很长、现在变短或抽出字段 → **摘要与信息提取**
- 原来是一堆数据、现在给出结论/判断 → **信息推理与表格解读**

**易错点**：
- ❌ 把"长文压成 300 字要点"当成"润色转换"——**长度被压缩 = 摘要**，不是润色。
- ❌ 把"从合同中提取金额和期限"当成"信息推理"——**抽字段 = 信息提取**；只有"基于数据给出判断/结论"才算推理。
- ❌ 把"把中文翻译成英文"当成"生成创作"——**已有内容换个形式 = 转换**。

**记忆法**：**「造、改、抽、断」** —— 造（生成）、改（润色转换）、抽（摘要提取）、断（推理判断）。

## 四、易错辨析表（本模块内）

| 易混对 | 关键区别 | 一句话判据 |
|---|---|---|
| **预训练 vs SFT vs RLHF** | 学知识 / 学听指令 / 学对齐偏好 | 顺序**永不动摇**：预训练 → SFT → RLHF |
| **SFT vs 业务微调（M5）** | SFT 是训练流程的**阶段**；业务微调是使用方为**垂直领域**做的适配 | 问"流程第几步"→SFT；问"我该怎么改善垂直领域表现"→M5 |
| **幻觉 vs 知识时效** | 编造不存在的 / 不知道新发生的 | "杜撰的"→幻觉；"最新/上周/今天"→时效 |
| **Token vs 字数** | Token 是模型切分后的单位，不等于字符数 | 记：**长度按 Token 算、花费按 Token 计** |
| **注意力 vs MoE 路由** | 注意力：看**输入里哪些 Token**；MoE：用**模型里哪些专家** | 一个在输入侧，一个在结构侧 |
| **MoE vs 量化** | MoE：只激活部分专家；量化：降低数值精度 | 问"只激活一部分参数"→MoE |
| **涌现 vs ICL** | 涌现：**规模到阈值后能力突然出现**；ICL：**给示例临时学会任务** | "突然会了"→涌现；"照例子做"→ICL |
| **ICL vs RAG vs 微调** | ICL：提示里给**示例**（不改参数）；RAG：检索**外部知识**（M3）；微调：**改参数**（M5） | 看有没有改参数、有没有外部检索 |
| **生成创作 vs 润色转换** | 从无到有 / 已有换个形式 | 输入原本**有没有**这段内容 |
| **摘要提取 vs 信息推理** | 压缩 + 抽字段 / 基于数据下结论 | 输出是**要点/字段**→提取；输出是**判断/结论**→推理 |
| **通义千问 vs 通义万相 vs 百炼** | 语言模型 / 视觉生成 / 平台 | 说话→千问；画图→万相；搭应用→百炼 |
| **"大" vs "不会错"** | "大"指参数/数据/算力规模，不代表正确性 | 规模再大也有幻觉与时效问题 |

## 七、一句话总览（考前 30 秒过一遍）

> **"大"在参数/数据/算力 → 预训练学知识、SFT 学听话、RLHF 学讨喜 → 输入先切成 Token → 逐 Token 接龙生成 → 靠注意力找关联、靠 MoE 省算力 → 规模够了涌现新能力、给示例就能现学（ICL）→ 但会编（幻觉）、会过时（时效）→ 对应四类场景：造、改、抽、断 → 阿里云：千问说话、万相画图、百炼搭台。**
