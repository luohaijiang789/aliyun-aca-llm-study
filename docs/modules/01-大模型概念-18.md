## 三、⭐ 三大局限专章（官方点名的必考）

> **官方原文**：理解大模型**基于上下文生成内容**的基本方式，以及由此带来的**幻觉、训练数据时间范围和上下文限制**。

**一句话总纲**：三个局限都出在同一件事上——模型**只会依据当下上下文做概率预测**，它既不查证事实、也不自动更新知识、还不能无限装内容。

### 3.1 局限一：幻觉（Hallucination）🟢`[A]`

| 项目 | 内容 |
|---|---|
| **表现** | 生成**看似合理但与事实不符**的内容：杜撰不存在的法条条款、文献、数据、案例、API、链接，且语气自信、格式工整 |
| **成因** | 模型的目标是在给定上下文下预测"**最可能的下一个 Token**"，而不是"经验证为真的答案"；训练语料本身的错误与缺失也会带来偏差 |
| **后果** | 错误的决策依据；对外发布事故；法律与合规风险（尤其医疗、金融、合同场景） |
| **缓解手段** | ① 接入**知识库（RAG）**，让答案有据可依；② 要求给出**来源引用**并抽检；③ **关键结论保留人工确认**；④ **优化输入**（限定范围、允许回答"不知道"、要求不确定时说明） |

**易错**
- ❌ "换个更大的模型就能彻底消除幻觉"——只能**缓解**，不能根除。
- ❌ "要求模型再检查一遍就一定正确"——模型对自己的错误同样会自信地肯定。

### 3.2 局限二：训练数据时间范围 🟢`[A]`

| 项目 | 内容 |
|---|---|
| **表现** | 模型的知识停留在**训练数据的截止时点**：对之后发生的事件、新发布的政策法规、最新价格/库存/版本答不上来，或给出**过时答案** |
| **成因** | 知识来自训练时见过的数据；训练完成后模型**不会自动更新**，也不具备天然的"今天"概念 |
| **后果** | 信息过期导致决策错误；与新续 happening 的政策/流程冲突 |
| **缓解手段** | ① 需要查企业资料或最新文档 → **接入知识库（RAG）**；② 需要**实时数据**（天气、股价、库存、物流）→ **调用工具**；③ 对带时效的信息**标注日期并人工核实** |

**易错**
- ❌ "微调可以解决时效性问题"——微调成本高，且喂进去的知识**同样会过期**；要持续拿最新资料，首选 **RAG**。
- ❌ 把"答不上来"当成幻觉——**时间范围是"缺"，幻觉是"编"**，见 3.4 判据表。

### 3.3 局限三：上下文限制 🟢`[A]`

| 项目 | 内容 |
|---|---|
| **表现** | 模型一次能接收并处理的 Token 总量有**上限**（输入 + 输出合计）；超出后内容会被**截断**或被挤出有效范围；超长文档一次投喂时，模型可能"看不见"中间或开头的信息；长对话中前面说过的内容也可能不被重视 |
| **成因** | 上下文窗口有限；注意力计算与显存开销随长度增长，做不到无限扩展 |
| **后果** | 遗漏关键信息、前后答复不一致、长文档问答质量骤降 |
| **缓解手段** | ① **拆分处理**：分段摘要 → 再汇总；② 用**检索/知识库**只把相关片段放进上下文；③ **精简对话**，必要时开新会话并重新给出关键信息；④ 把最重要的事实放在**当前问题附近**而不是几千字之前 |

**易错**
- ❌ "上下文长度按字数算"——以 **Token** 计（见背景知识 M1-K13）。
- ❌ "只要模型支持长上下文，就可以把整本手册全塞进去并期待全部记住"——能装下不等于能同等重视每一段。

### 3.4 三大局限判据表（做题时按关键词秒判）

| 题干关键词 | 属于哪项局限 | 首选对策 |
|---|---|---|
| "**不存在的**""**杜撰的**""**查无此项**""编造的条款/文献/数据" | **幻觉** | 接知识库 + 要引用 + 人工核实 |
| "**最新的**""**最近**""**本周/本月发布的**""**实时**价格/库存" | **训练数据时间范围** | 接知识库（查资料）/ 调工具（取实时数据） |
| "**超长**文档""**几十万字**一次喂进去""**前面说过的内容**被忽略了" | **上下文限制** | 拆分分段 / 检索取相关片段 / 精简上下文 |

> **记忆法**：**「编的是幻觉，缺的是时间，塞不下的是上下文」**。

## 四、⭐ 能力边界判断专章（官方点名的核心考法）

> **官方原文**：掌握**能力边界判断**：什么时候适合**生成、总结、分析**，什么时候需要**知识库、工具或人工确认**。
> **官方原文（全局）**：考试重点是**理解大模型能力边界**，并能在业务场景中选择合适的方法：**优化输入、接入知识库、调用工具、使用微调、协作 Agent，或保留人工确认**。

### 4.1 判断三问（场景题的固定解题路径）

```
第 1 问：这件事要的事实，模型"肚子里"有吗？
        └─ 要的是企业私有/内部/指定资料 → 接【知识库/RAG】
        └─ 要的是最新发生的 / 会变的（价格、库存、天气、政策）→ 接【知识库】或直接【调工具】取实时数据
第 2 问：这件事需要"做动作"或"算准"吗？
        └─ 查库存、下订单、发通知、写库、算税额/利息 → 【调用工具】（确定性交给业务系统）
        └─ 多步骤、要串起若干工具与流程才能交付 → 【协作 Agent】
第 3 问：这件事错了谁负责？风险高不高？
        └─ 医疗、金融、合同、对外发布等高风险 → 【保留人工确认】
        └─ AI 可以辅助整理和起草，但【不能替代最终责任人】
三问都否 → 就是纯文字活（写、改、缩、归类、分析）→ 直接让模型【生成 / 总结 / 分析】，
           若效果不稳，先【优化输入】
```

### 4.2 能力边界判断主表 ⭐

| # | 任务特征 | 典型例子 | 推荐手段 | 官方依据 |
|:---:|---|---|---|---|
| 1 | 纯文字产出，不依赖外部事实 | 写营销文案、写周报、起标题、写邮件草稿 | **直接生成** | 「什么时候适合**生成**」 |
| 2 | 已有材料要压缩 / 抽字段 | 长文要点、会议纪要、从合同里提甲乙方/金额/期限 | **直接总结 / 信息提取** | 「适合**总结**」 |
| 3 | 基于给定材料谈看法、对比、归纳 | 对已有调研材料做 SWOT、对比多方案优劣 | **直接分析**（给足材料） | 「适合**分析**」 |
| 4 | 输出质量不稳、口径不对 | 格式跑偏、风格不符、要点漏项 | 先**优化输入**（目标/背景/角色/约束/示例/输出格式/评价标准） | 「**优化输入**」 |
| 5 | 需要企业私有/内部文档知识 | 问员工手册、产品手册、内部 SOP | **接入知识库** | 「**接入知识库**」 |
| 6 | 需要最新/会变化的信息 | 今天的股价、当前库存、最新政策原文 | **接入知识库**（文档）／**调用工具**（实时数据） | 「**调用工具**」 |
| 7 | 需要确定性计算或执行业务动作 | 算税额/利息、查订单、下单、发邮件、改数据库 | **调用工具** | M3 原文「需要实时数据、**确定性计算或业务动作**时用工具」 |
| 8 | 需要稳定行为：格式/风格/分类能力/轻量部署 | 固定话术风格、稳定 JSON 结构、工单分类 | **使用微调** | M5 原文「微调适合稳定行为、格式、风格、分类能力…」 |
| 9 | 多步骤、要把问答推进为交付结果 | 查资料 → 写报告 → 发邮件 → 回写系统 | **协作 Agent** | M4 原文「把『回答问题』推进到『完成任务』」 |
| 10 | 高风险领域与最终决策 | 医疗建议、金融授信、合同条款定稿、对外发布内容 | **保留人工确认** | M6 原文「AI 可以辅助整理和起草，但**不能替代最终责任人**」 |

### 4.3 「不能直接替人决定什么」清单

> **官方原文**：理解大模型是什么，**能做什么，不能直接替人决定什么**。

**核心理解**：大模型产出的是**候选与参考**，不是**决定**。决定权、签字权、发布权、追责主体始终是人。

| 大模型的角色（✅ 可以做） | 不能直接替人决定的事项（❌ 需要人拍板） |
|---|---|
| 生成草稿、提纲、候选方案 | 决定采用哪一版、对外发不发 |
| 整理与归纳资料、给出要点 | 判断是否足以支撑结论、是否采纳结论 |
| 起草合同条款、标出风险点 | 决定签约与否、接受哪份条款 |
| 辅助分析数据与给出假设 | 决定授信额度、投资决策、诊断结论 |
| 生成代码、SQL、测试用例（本认证不考代码） | 决定直接上线到生产环境 |

**四条记忆锚点**
1. **AI 可以辅助整理和起草，但不能替代最终责任人。**
2. 高风险动作（医疗、金融、合同、对外发布）**必须人工确认**。
3. 输出带概率性：**同一问题多次答案可能不同**，因此不能作为唯一依据。
4. 幻觉与时间范围限制意味着：**未经核实的模型输出不能当事实直接使用**。

| M1 的判断结果 | 落入模块 |
|---|---|

| 这件事缺知识 / 缺实时数据 / 缺动作能力 | **M3 增强大模型应用的能力**（知识库 / 工具 / MCP） |

| 这件事要多步骤交付 | **M4 大模型 Agent** |
| 这件事风险高，必须有兜底 + 留痕 + 复核 | **M6 大模型安全合规** |

## 六、逐考点详解

### M1-K01 · 大模型定义与"大"在哪里 🟢`[A]`

**是什么**：大模型（Large Model，大语言模型 LLM）指**参数规模巨大、在海量数据上训练**而成的深度学习模型，能理解并生成自然语言，完成问答、写作、摘要、推理等多种任务。

"大"体现在三个维度（**记忆核心**）：

| 维度 | 含义 |
|---|---|
| **参数量大** | 模型内部可学习权重的数量巨大，是承载知识与模式的"容量" |
| **训练数据量大** | 覆盖海量文本，模型才具备通用语言与世界知识 |
| **算力投入大** | 训练与推理都需要大量计算资源，这是"大"的成本面 |

**为什么**：规模带来的是**能力边界被拓宽**，不是"相同能力跑得更快"。

**易错点**
- ❌ 把"大"理解成"能处理无限长输入"——上下文长度有上限（见 M1-K07）。
- ❌ 认为"大 = 一定正确"——规模不消除幻觉（见 M1-K05）。
- ❌ 认为"大 = 会自动获取最新信息"——知识停在训练数据截止时点（见 M1-K06）。

**记忆法**：**「参、数、算」** = 参数多、数据多、算力多。

---

### M1-K02 · 大模型能做什么：生成 / 总结 / 分析 🟢`[A]`

> **官方原文**：掌握能力边界判断：什么时候适合**生成、总结、分析**，什么时候需要知识库、工具或人工确认。

**三种"放心交给模型"的典型任务**

| 能力 | 在做什么 | 例子 | 不放心时要补什么 |
|---|---|---|---|
| **生成** | 从目标出发产出草稿与候选 | 写文案、写周报、写邮件、拟提纲 | 事实准确性要求高 → 接知识库 + 给来源要求 |
| **总结** | 压缩与提炼已有材料 | 长文要点、会议纪要、通话小结 | 材料超出上下文 → 先拆分/检索（M1-K07） |
| **分析** | 基于**给定材料**归纳、对比、推断 | 对调研材料做对比表、提炼风险点、归纳用户反馈主题 | 结论要对外负责 → 保留人工确认 |

**共同前提**：三类任务都必须**把材料与要求放进上下文**（M1-K04），因为模型只能"基于上下文生成"。

**易错点**
- ❌ 认为"分析 = 模型自己知道答案"——模型分析的是**喂进去的材料**，材料不含的信息它只能用先验猜测（易产生幻觉）。
- ❌ 认为"只要一句『帮我分析』就够了"——不给材料、不给评价标准，输出不可控（属 M2 优化输入）。

**记忆法**：**「造、缩、判」** —— 生成=造，总结=缩，分析=判（**判要人复核**）。

### M1-K03 · 不能直接替人决定什么 🟢`[A]`

> **官方原文**：理解大模型是什么，能做什么，**不能直接替人决定什么**。

**是什么**：大模型可以**产出候选与参考**，但**不承担最终决定权、签字权、发布权与责任**。

**为什么**：三条死因决定了它不能拍板

| 原因 | 说明 | 对应局限 |
|---|---|---|
| 输出有**幻象风险** | 看似合理的内容可能与事实不符 | M1-K05 |
| 知识有**时间范围** | 不了解训练截止后发生的事 | M1-K06 |
| 输出带**概率性** | 同一问题多次回答可能不同，且天然没有"责任主体" | — |

**典型表现**：它可以写合同条款草稿，但不能替法务决定"签不签"；可以给出融资方案对比，但不能替管理层决定"投不投"；可以起草对外公告，但不能替责任人决定"发不发"。

**官方配套规则**
- 高风险场景（**医疗、金融、合同、对外发布**）：**AI 可以辅助整理和起草，但不能替代最终责任人**（M6 原文）。
- Agent 场景下：**高风险动作必须人工确认**（M4 原文）。

**易错点**
- ❌ 认为"提示词写得足够好，就可以免除人工确认"——再好的提示词也无法消除幻觉与时间范围限制。
- ❌ 认为"模型给出理由充分 = 结论可靠"——**有理由不等于有事实**，理由本身也可能是生成出来的。
- ❌ 认为"不能直接决定"= "不能参与"——恰恰相反，辅助整理、起草、分析正是它最合适的角色。

**记忆法**：**「决定权在人，参考稿在 AI」**。

### M1-K04 · 基于上下文生成内容 🟢`[A]`

> **官方原文**：理解大模型**基于上下文生成内容**的基本方式，以及由此带来的幻觉、训练数据时间范围和上下文限制。

**是什么**：模型每一次输出，都是**依据当前上下文**（系统说明 + 历史对话 + 你本次提供的材料 + 已生成的部分）预测"下一个最可能的 Token"，并把生成结果拼回上下文继续预测，直到结束。

**由此推出四条重要结论**（考试常在这里设陷阱）

| 结论 | 含义 |
|---|---|
| **给它什么，它才有什么** | 模型不会主动去查缺失的材料；材料不在上下文里就只能靠先验猜 → 幻觉风险 |
| **上下文质量决定输出质量** | 材料杂乱、要求含糊 → 输出必然不稳（这正是 M2 提示词工程存在的理由） |
| **上下文装不下就用不上** | 长度以 Token 计且有上限 → 上下文限制（M1-K07） |
| **输出天然带概率性** | 每次刷新可能不同；越长越慢越贵，前面的错误可能被带偏 |

**缓解思路**：把**真实的、相关的、最新的**材料放进上下文——放不下就用**检索（知识库）挑相关片段**，查实时数据就**调工具**。这三句话就是 M3 的入口。

**易错点**
- ❌ 认为模型"从数据库检索后再念出来"——原生大模型不检索，是**基于上下文的概率生成**。
- ❌ 认为"只要问得足够具体，就不需要知识库"——再具体的问法，也变不出模型没见过的事实。

**记忆法**：**「上下文是模型的全部世界」**。

### M1-K09 · 典型应用场景（课时2） 🟢`[A]`

| 场景类别 | 在做什么 | 例子 |
|---|---|---|
| **文本生成与创作** | 从无到有产出内容 | 写营销文案、写周报、写故事、写邮件草稿 |
| **文本润色与转换** | 对已有文本做改写 / 转换 | 润色语病、风格改写、翻译、口语转书面语、格式转换 |
| **文本摘要与信息提取** | 压缩 + 抽关键信息 | 长文要点总结、会议纪要、从合同里提取甲乙方/金额/期限 |
| **信息推理与表格解读** | 基于给定数据做推断 / 计算式理解 | 读销售报表给结论、对比多方案、按表格内容回答追问 |

**归类方法：看"输入 → 输出"发生的变化**
- 原来没有、现在生成了 → **生成创作**
- 原来有、只是换了个说法/语种/风格 → **润色转换**
- 原来很长、现在变短或抽出字段 → **摘要与信息提取**
- 原来是一堆数据、现在给出结论/判断 → **信息推理与表格解读**

**易错点**
- ❌ 把"长文压成 300 字要点"当成润色转换——**长度被压缩 = 摘要**。
- ❌ 把"从合同中提取金额和期限"当成信息推理——**抽字段 = 信息提取**；只有基于数据下结论才算推理。
- ❌ 把"中文翻译成英文"当成生成创作——**已有内容换形式 = 转换**。

**记忆法**：**「造、改、抽、断」** = 造（生成）、改（润色转换）、抽（摘要提取）、断（推理判断）。

### M1-K12 · 训练三阶段：预训练 → SFT → RLHF 🟡`[B]`

| 阶段 | 做的事 | 产出 |
|---|---|---|

### M1-K13 · 分词 Tokenization 🟡`[B]` ⚠️ **官方未列考点**

- Token 是模型处理文本的**最小基本单位**；**上下文长度以 Token 计、调用量与成本按 Token 计**。
- 中英文**都会被切分**；一个英文单词**可能被拆成多个 Token**；训练与推理都要分词，且必须用**同一套分词器/词表**。
- **易错**：❌ "Token = 字数/字符数"；❌ "一个汉字 = 一个 Token"（不同分词器粒度不同，不要背换算比例）；❌ "分词只在训练时做"。
- **为何只需了解**：它在考试中的唯一作用，是支撑"上下文限制"这条真实考点。

### M1-K14 · 注意力机制 🟡`[B]` ⚠️ **官方未列考点**

- 处理某个 Token 时，动态计算它与上下文中其他 Token 的**相关权重**并按权重汇总信息 → 解决长距离依赖（如"它"指代"蓝牙耳机"）。
- **易错**：❌ 把注意力当成"记忆/数据库"（它是相关性加权计算）；❌ 认为"注意力权重高 = 事实正确"（只说明关注了哪里）；❌ 与 MoE 路由混淆——**注意力决定看哪些 Token（输入侧），MoE 路由决定用哪些专家（结构侧）**。

### M1-K15 · Transformer 架构 🟡`[B]`

- 以**自注意力**为核心的神经网络架构，可**并行**处理整段序列（不同于 RNN 逐词串行），是当代大模型的架构底座。
- **易错**：❌ "Transformer = 大模型"——架构是骨架，**规模 + 训练**才是"大"。

### M1-K16 · MoE 架构 🟡`[B]` ⚠️ **官方未列考点**

- **Mixture of Experts**：多专家 + 路由，**稀疏激活**——参数总量大，但单次推理只激活少量专家 → "大容量 + 低推理开销"。
- **易错**：❌ 认为每次推理用全部参数（恰恰相反）；❌ 与**量化**混淆（量化降精度，MoE 选专家）；❌ 认为 MoE 能解决幻觉/时效（它是效率与容量层面的设计）。

### M1-K17 · 涌现能力 🟡`[B]`

- 规模跨过阈值后**突然出现**小模型不具备的能力（如多步推理、复杂指令遵循），**非显式训练所得**。
- **易错**：❌ 认为是"平滑线性提升"（强调跃迁）；❌ 认为"涌现 = 无所不能"（不消除幻觉与时效）。

### M1-K18 · 上下文学习 ICL 🟡`[B]`

- **不更新参数**，只在输入中给若干示例（few-shot），模型即可照样子完成新任务；**会话结束即失效**。
- **易错**：❌ 认为 ICL 改了参数；❌ 与 RAG 混（RAG 检索**外部知识**）；❌ 与微调混（微调**改参数**）。

### M1-K19 · 模型分类（模态 / 开源 / 用途） 🟡`[B]`

- 分类是**维度**问题，可叠加：按模态（语言 / 视觉 / 语音 / 多模态）、按开放性（开源权重可得 / 闭源 API）、按用途（通用基座 / 垂直领域 / 专用能力如向量模型、重排序模型）。
- **易错**：❌ "开源 = 一定可商用免费"（商用看许可协议）；❌ 认为分类互斥。
- ⚠️ 官方六大模块中**无多模态**模块，多模态仅作为"按模态分类"中的一个类别名称出现。

### M1-K20 · 大模型四大特点 🔴`[C]`

> ⚠️ 「四大特点」的**具体四项表述未获官方确认**，以下为行业常见归纳，**只作方向性理解，不必逐字背诵**。

1. **强大的语言理解与生成能力**｜2. **通用性与泛化能力**（一个模型多类任务）｜3. **上下文学习能力**（见 M1-K18）｜4. **涌现能力**（见 M1-K17）。

**必须排除的"假特点"**：❌ 不会产生幻觉、永远正确；❌ 能实时联网获取最新信息（原生不具备，要靠知识库/工具）；❌ 具备自主意识与主观判断。

## 八、易错辨析表（本模块内）

| 易混对 | 关键区别 | 一句话判据 |
|---|---|---|
| **幻觉 vs 时间范围** | 编造不存在的 / 不知道新发生的 | "杜撰的/查无此项"→幻觉；"最新的/本月发布的"→时间范围 |
| **时间范围 vs 上下文限制** | 知识有没有 / 装不装得下 | "模型不知道"→时间范围；"材料塞不进去/前面被忘"→上下文限制 |
| **幻觉 vs 上下文限制** | 内容不可信 / 内容没被看到 | "答案错但流畅"→幻觉；"压根没读到后面"→上下文限制 |
| **能做什么 vs 不能替人决定** | **产出候选**（写、改、缩、判） / **最终拍板**（签、投、发、诊） | AI 出草稿，人签字 |
| **知识库 vs 工具** | 查企业文档资料（RAG）/ 实时数据、确定性计算、业务动作 | 「**查知识用 RAG，做动作靠工具**」 |
| **工具 vs 微调** | 外部动作与实时数据 / 稳定行为、格式、风格、分类 | 经常变的外部世界→工具；长期不变的表达习惯→微调 |
| **知识库 vs 微调** | 补知识（可持续更新） / 稳行为（样本沉淀） | 知识会过期→知识库；行为要一致→微调 |
| **ICL vs RAG vs 微调** | 给**示例**（不改参数）/ 检索**外部知识** / **改参数** | 看是否改参数、是否有外部检索 |
| **模型 vs 产品** | 模型（千问/万相是模型）/ 平台（百炼是平台） | 说话→千问；画图→万相；搭应用→百炼 |
| **注意力 vs MoE 路由** | 看输入里**哪些 Token** / 用模型里**哪些专家** | 一个在输入侧，一个在结构侧 |
| **MoE vs 量化** | 只激活部分专家 / 降低数值精度 | "只激活一部分参数"→MoE |
| **"大" vs "不会错 / 不受限"** | "大"是参数/数据/算力规模 | 规模再大也有幻觉、有时间范围、有上下文上限 |

## 十一、一句话总览（考前 30 秒过一遍）

> **大模型=在海量数据上训出巨大参数的语言模型，能写、能改、能缩、能归纳、能给候选建议；它基于上下文逐 Token 地生成内容（→ M1-K04），因此会「编」（幻觉）、会「缺最新」（时间范围）、会「塞不下」（上下文限制）→ 所以凡涉及事实准确性就接知识库，凡涉及最新或实时信息就接知识库 / 调工具，凡涉及动作就用工具，凡涉及高风险就保留人工确认——它永远给参考，不能替人拍板（→ M1-K03）。一句判断口诀：查知识用 RAG，做动作靠工具，稳行为才考虑微调，AI 辅助起草但不能替代最终责任人。**
