## 三、⭐ 官方核心①：「不能直接替人决定什么」专章

> **官方原文**：理解大模型是什么，能做什么，**不能直接替人决定什么**。
> **官方配套原文（M6）**：遇到医疗、金融、合同、对外发布等高风险场景，**AI 可以辅助整理和起草，但不能替代最终责任人**。
> **官方配套原文（M4）**：**高风险动作必须人工确认。**

### 3.1 先划清楚两个词：「决定」和「辅助」

**「决定」= 要承担后果与责任的行为。** 判定标准（四选一命中即为"决定"）：

| 判定特征 | 说明 | 例子 |
|---|---|---|
| **要担责** | 出错后有人要负责、要被追责 | 授信额度、录用与否、诊断结论 |
| **要判断取舍** | 在多个方案中拍板采用哪一个 | 选哪版文案定稿、选哪家供应商 |
| **要对外承诺** | 一旦说出即对外部产生效力 | 报价承诺、赔付承诺、发布公告 |
| **要给出终局结论** | 结论直接生效、不再有人复核 | 报销"通过/驳回"并自动生效、工单自动关闭 |

**「辅助」= 不产生终局效力的中间产物。** 典型动作：**整理、归纳、起草、列候选、标风险、给依据、提选项**。

> **一句话边界**：**AI 出草稿，人签字。** 模型可以参与全过程，但**不能在终点上替人落笔**。

### 3.2 为什么不能拍板（三条死因）

| 死因 | 说明 | 对应官方局限 |
|---|---|---|
| **幻觉风险** | 输出看似合理但可能与事实不符，且语气自信、格式工整，难以肉眼识别 | M1-K05 |
| **训练数据时间范围** | 不了解训练截止之后发生的政策、价格、规则变化 | M1-K06 |
| **输出带概率性** | 同一问题多次问可能得到不同答案；模型**天然不是责任主体**，无法承担后果 | M1-K04 的必然后果 |

### 3.3 正反例清单（8 组 · 背熟这一张表就够用）

| # | 场景 | ✅ 模型可以这样辅助 | ❌ 不能直接替人决定 |
|:---:|---|---|---|
| 1 | 报销审核 | 读取单据、提取金额与事由、标出与规则不符的疑点、给出建议"建议驳回（事由缺发票）" | 直接给出"通过/驳回"的**终审结论并自动生效**，无人复核 |
| 2 | 合同 | 起草条款、比对版本差异、标出风险点与缺失条款 | 决定**签不签**、接受哪份条款、承担何种违约责任 |
| 3 | 金融授信 | 整理客户材料、归纳财务状况、列出风险因素 | 决定**授信额度**、放不放款 |
| 4 | 医疗健康 | 整理病历要点、普及常识、提示就医方向 | 给出**诊断结论**、决定用不用药 |
| 5 | 对外发布 | 起草新闻稿/公告正文、给出多版文案候选 | 决定**发不发**、以哪版对外发布 |
| 6 | 招聘 | 归纳简历要点、按岗位要求做初步匹配整理 | 决定**录不录用** |
| 7 | 客服赔付 | 归纳用户诉求、匹配政策条款、拟出答复草稿 | 决定**赔不赔、赔多少**的终局答复 |
| 8 | 生产变更 | 生成变更说明、列出回滚步骤草稿 | 决定**是否直接上线生产环境**并自动执行 |

### 3.4 四条记忆锚点

1. **AI 可以辅助整理和起草，但不能替代最终责任人。**（官方 M6 原文）
2. 高风险场景（**医疗、金融、合同、对外发布**）**必须人工确认**。
3. 输出带概率性：**同一问题多次答案可能不同**，因此不能作为唯一依据。
4. 幻觉与时间范围限制意味着：**未经核实的模型输出不能当事实直接使用**。

### 3.5 考法提示

题干的经典长相：**「设计方案是由大模型直接给出 XX 结论并自动生效，无需任何人查看，是否可行？」**
标准答案：**不可行** —— 模型可辅助整理、归纳、给参考意见，但终局决定须由责任人作出。
干扰项通常设在两个极端：**A/C 说"规则写清楚/微调之后就可以取消人工环节"**（错：再好的提示词与微调也消除不了幻觉与概率性）；**D 说"模型连辅助都做不到"**（错：走向另一个极端，模型恰恰擅长辅助）。

## 四、⭐ 官方核心②：三大局限专章

> **官方原文**：理解大模型**基于上下文生成内容**的基本方式，以及由此带来的**幻觉、训练数据时间范围和上下文限制**。

**一句话总纲**：三个局限**同宗同源**，都出在同一件事上 —— 模型**只会依据当下上下文做概率预测**，它既不查证事实、也不自动更新知识、还不能无限装内容。

### 4.0 三大局限横向对照表（⭐ 必背主表）

| 维度 | **幻觉** M1-K05 | **训练数据时间范围** M1-K06 | **上下文限制** M1-K07 |
|---|---|---|---|
| **一句话** | **编**：编造不存在的内容 | **缺**：不知道训练截止后的事 | **塞不下**：一次装不了那么多 |
| **表现（长什么样）** | 生成**看似合理但与事实不符**的内容：杜撰不存在的法条条款、文献、数据、案例、接口、链接；语气自信、格式工整 | 知识停留在**训练数据截止时点**：对之后发生的事件、新发布的政策法规、最新价格/库存/版本答不上来，或给出**过时答案** | 一次能处理的 Token 总量有**上限**（输入 + 输出合计）；超出后被**截断**或不被同等重视；超长文档开头/中后部被忽略；长对话前面说过的内容被淡化 |
| **成因（为什么会这样）** | 模型的目标是在给定上下文下预测"**最可能的下一个 Token**"，而不是"经验证为真的答案"；训练语料本身的错误与缺失也会带来偏差 | 知识来自训练时见过的数据；训练完成后模型**不会自动更新**，也不具有天然的"今天"概念 | 上下文窗口有限；注意力计算与显存开销随长度增长，做不到无限扩展 |
| **后果（会导致什么事故）** | 错误决策依据；对外发布事故；法律与合规风险（尤其医疗、金融、合同） | 信息过期导致决策错误；与最新政策/流程冲突；给客户报错价 | 遗漏关键信息、前后答复不一致、长文档问答质量骤降 |
| **缓解手段** | ① 接**知识库（RAG）**让答案有据可依 ② 要求给**来源引用**并抽检 ③ 关键结论**保留人工确认** ④ **优化输入**（限定范围、允许答"不知道"、要求不确定时说明） | ① 查企业资料/最新文档 → **接入知识库（RAG）** ② 要**实时数据**（天气、股价、库存、物流）→ **调用工具** ③ 带时效的信息**标注日期并人工核实** | ① **拆分处理**：分段摘要 → 再汇总 ② 用**检索/知识库**只把相关片段放进上下文 ③ **精简对话**，必要时开新会话并重给关键信息 ④ 关键事实放在**当前问题附近** |
| **对应模块** | M3 知识库 + M6 人工复核 | M3 知识库 / 工具 | M3 检索 + M2 优化输入 |
| **题干关键词** | "**不存在的**""**杜撰的**""**查无此项**""编造的条款/文献/数据" | "**最新的**""**最近刚**""**本周/本月发布的**""**实时**价格/库存" | "**超长**文档""**几十万字**一次喂进去""**前面说过的内容**被忽略了" |

> **判据口诀**：**「编的是幻觉，缺的是时间，塞不下的是上下文」**

### 4.1 局限一：幻觉（Hallucination）🟢`[A]`

- **典型长相**：问"某型号是否通过 XX 认证" → 答"该型号已于 20XX 年通过国家 XX 认证，证书编号……"（技术部门核查：该认证从未存在）。
- **为什么难防**：它不是"乱码"，而是**语法通顺、格式工整、语气自信**的一段话；越是在模型知识空白区，越容易补全式编造。
- **易错**
  - ❌ "换个更大的模型就能彻底消除幻觉" —— 只能**缓解**，不能根除。
  - ❌ "要求模型再检查一遍就一定正确" —— 模型对自己的错误同样会自信地肯定。
  - ❌ "模型给了引用就一定是真的" —— 引用本身也可能是生成出来的，必须**抽检溯源**。

### 4.2 局限二：训练数据时间范围 🟢`[A]`

- **典型长相**：问"本月初刚发布的退换货新政有哪些变化" → 答出一份格式工整但与公司最新文件不符的内容。
- **与幻觉的边界**：它**不知道**新政策（缺），于是很可能**顺手编一份**（编）。所以时间范围问题常常**以幻觉的形式表现出来** —— 但**归因要归在"知识过期"上，对策要落在"接知识库/调工具"上**。
- **易错**
  - ❌ "微调可以解决时效性问题" —— 微调成本高，且喂进去的知识**同样会过期**；要持续拿最新资料，首选 **RAG**。
  - ❌ 把"答不上来/答得过时"全当成幻觉 —— **时间范围是"缺"，幻觉是"编"**，见 4.0 对照表。

### 4.3 局限三：上下文限制 🟢`[A]`

- **典型长相**：把约 50 万字标书一次性粘贴提问 → 对**开头**条款能答，对**中后部**条款几乎无法回答。
- **易错**
  - ❌ "上下文长度按字数算" —— 以 **Token** 计（见 M1-K13）。
  - ❌ "只要模型支持长上下文，就可以把整本手册全塞进去并期待全部记住" —— **能装下 ≠ 能同等重视每一段**。
  - ❌ "这是幻觉" —— 题干特征是"**读不到/答不出**"，而不是"编造内容"。

### 4.4 三大局限判据表（做题时按关键词秒判）

| 题干关键词 | 属于哪项局限 | 首选对策 |
|---|---|---|
| "**不存在的**""**杜撰的**""**查无此项**""编造的条款/文献/数据" | **幻觉** | 接知识库 + 要引用 + 人工核实 |
| "**最新的**""**最近刚**""**本周/本月发布的**""**实时**价格/库存" | **训练数据时间范围** | 接知识库（查资料）/ 调工具（取实时数据） |
| "**超长**文档""**几十万字**一次喂进去""**前面说过的内容**被忽略" | **上下文限制** | 拆分分段 / 检索取相关片段 / 精简上下文 |

### M1-K01　大模型定义与"大"的体现　🟢`[A]`

**① 一句话定义**：大模型是在**海量数据**上训练出来的、**参数规模巨大**的深度学习模型，"大"= 参数量大 + 训练数据量大 + 算力投入大。

**② 是什么**：大模型（Large Model，大语言模型 LLM）指参数规模巨大、在海量数据上训练而成的深度学习模型，能理解并生成自然语言，完成问答、写作、摘要、推理等多种任务。它与传统"一个任务一个模型"的做法不同：**一个模型可以承担多类任务**。"大"体现在三个维度：一是**参数量大**，即模型内部可学习权重的数量巨大，是承载知识与语言模式的"容量"；二是**训练数据量大**，覆盖海量文本，模型才具备通用的语言理解与世界知识；三是**算力投入大**，训练与推理都需要大量计算资源，这是"大"的成本面。三者共同支撑的是**能力边界被拓宽**，而不是"相同能力跑得更快"。

**③ 为什么**：规模是能力跃迁的前提。参数量决定"能装多少模式"，数据量决定"见过多少世界"，算力决定"能不能真的训完"。当规模跨过阈值，模型会表现出小模型不具备的能力（见 M1-K17 涌现）。但要注意，**规模带来的是能力拓宽，不是缺陷消失**——官方原文紧接着就点出了三大局限，正说明"大"不等于"全知全能"。

**④ 怎么做 / 怎么用**：
- 场景：向非技术同事解释"为什么这个模型能干这么多活"。
- 输入（你的解释）：「它'大'在三件事：参数多（容量大）、训练数据多（见过的语言与世界知识多）、算力投入大（成本也高）。所以它一个模型能写、能改、能缩、能归纳。」
- 输出示意（同事的理解）：「明白了——它不是'更快的旧工具'，而是'能力范围更宽的新工具'；但它再大也有不知道的事。」

**⑤ 易错点**
- ❌ 常见误解："大"意味着能处理任意长度的输入，且回答必然正确、不受训练数据时间范围影响。
- ✅ 正确说法："大"只体现在**参数、数据、算力**三方面规模；它**依然有上下文限制、依然会产生幻觉、知识依然停在训练数据截止时点**。
- ❌ 常见误解：只要模型更大，就不用接知识库了。
- ✅ 正确说法：规模只能**缓解**幻觉，解决"企业私有知识/最新信息"要靠**接入知识库（RAG）**。

**⑥ 考法提示**：常以**多选题**出现，三个正确项（参数 / 数据 / 算力）+ 一个"过度外推"的错误项。陷阱词固定在：**"任意长度""必然正确""不受……影响""可以取消人工环节"**——见到这类绝对化表述，直接判错。

**⑦ 记忆锚点**：**「参、数、算」** = 参数多、数据多、算力多；**规模大 ≠ 没边界**。

### M1-K02　大模型能做什么：生成 / 总结 / 分析　🟢`[A]`

**① 一句话定义**：官方原文点明三类"放心交给模型"的任务——**生成、总结、分析**，产出草稿、要点与洞察。

**② 是什么**：**生成**是从目标出发产出原本不存在的内容（写文案、写周报、写邮件、拟提纲）；**总结**是把已有材料压缩、提炼、抽出关键字段（长文要点、会议纪要、通话小结、从合同提取金额与期限）；**分析**是基于**给定材料**做归纳、对比、推断（对调研材料做对比表、提炼风险点、归纳用户反馈主题）。三者的共同前提是：**必须把材料与要求放进上下文**，因为模型只能"基于上下文生成"（M1-K04）。官方表述的完整逻辑是：先判断适不适合做这三类，不适合时再上知识库、工具或人工确认。

**③ 为什么**：官方把"生成、总结、分析"单独点名，是因为这三类任务**不需要外部事实、不需要执行动作、也不直接产生终局责任**，正好落在模型的能力区间内；而一旦任务要"查企业资料""取实时数据""执行动作"或"对外负责"，就超出了这个区间，需要别的手段来补。这正是"能力边界判断"的起点。

**④ 怎么做 / 怎么用**：
- 场景：把一次 60 分钟的客户访谈录音转写稿（约 8000 字）变成可汇报的要点。
- 输入：「以下是访谈转写稿（全文附后）。请：① 压缩成 500 字要点；② 归纳客户最关心的 3 个问题；③ 标注原文中不确定的地方，不要补全。」
- 输出示意：「**要点**：客户当前痛点集中在……（约 500 字）｜**三个主要问题**：交付周期 / 售后响应 / 价格透明度｜**待确认**：第 3 段提到的'明年预算'未说明具体金额。」
- 判断链：材料**已在上下文**中 → 不依赖外部事实 → 属于**总结 + 分析** → **直接交给模型**；若要点要对外发布，再**加一道人工确认**。

**⑤ 易错点**
- ❌ 常见误解："分析 = 模型自己知道答案"。
- ✅ 正确说法：模型分析的是**喂进去的材料**；材料不含的信息它只能用先验猜测，极易产生幻觉（M1-K05）。
- ❌ 常见误解："只要一句『帮我分析』就够了"。
- ✅ 正确说法：不给材料、不给评价标准，输出不可控——这属于**优化输入**（M2）的范畴。

**⑥ 考法提示**：常与 M1-K08 合体出**多选题**或**场景单选**：四个选项里三个分别含"实时数据""业务动作""高风险决策"，正确项必然是**"材料已提供 + 纯文字压缩/归纳"**。陷阱设在**"材料已经在不在上下文里"**这个前置条件上。

**⑦ 记忆锚点**：**「造、缩、判」** —— 生成 = 造，总结 = 缩，分析 = 判（**判要人复核**）。

### M1-K03　不能直接替人决定什么　🟢`[A]`

**① 一句话定义**：大模型可以**产出候选与参考**，但**不承担最终决定权、签字权、发布权与责任**——决定权永远在人。

**② 是什么**：这是官方原文点名的第三个问句：「理解大模型是什么，能做什么，**不能直接替人决定什么**」。所谓"决定"，指**要承担后果与责任的行为**：要担责（授信额度、录用与否）、要判断取舍（采用哪一版）、要对外承诺（报价、赔付、发布公告）、要给出终局结论（报销通过/驳回并自动生效）。所谓"辅助"，指不产生终局效力的中间产物：整理、归纳、起草、列候选、标风险、给依据、提选项。**模型可以参与全过程，但不能在终点上替人落笔。**

**③ 为什么**：三条死因决定了它不能拍板。**其一，幻觉风险**——输出看似合理但可能与事实不符，且语气自信、格式工整，肉眼难辨（M1-K05）；**其二，训练数据时间范围**——不了解训练截止之后发生的政策、价格、规则变化（M1-K06）；**其三，输出带概率性**——同一问题多次问可能得到不同答案，且模型**天然不是责任主体**，无法承担后果。官方在 M6 明确配套：**「AI 可以辅助整理和起草，但不能替代最终责任人」**；在 M4 明确：**「高风险动作必须人工确认」**。

**④ 怎么做 / 怎么用**：
- 场景：报销初审流程接入大模型。
- ✅ 正确设计（辅助）：模型读取单据 → 提取金额、事由、票据信息 → 标出与规则不符的疑点 → 输出「**建议**：驳回（事由缺发票附件）」，**由审核人确认后生效**。
- ❌ 错误设计（替人决定）：模型直接输出"通过/驳回"并**自动生效、无人复核**。
- 输出示意：前者是"**建议 + 依据 + 责任人确认**"，后者是"**终局结论 + 自动执行**"——差别就在那道人工确认。

**⑤ 易错点**
- ❌ 常见误解："提示词写得足够好 / 用了微调，就可以免除人工确认"。
- ✅ 正确说法：再好的提示词、再充分的微调，也**无法消除幻觉与概率性**；高风险动作**必须人工确认**。
- ❌ 常见误解："模型给出理由充分 = 结论可靠"。
- ✅ 正确说法：**有理由不等于有事实**——理由本身也可能是生成出来的。
- ❌ 常见误解："不能直接决定 = 不能参与"。
- ✅ 正确说法：恰恰相反，**辅助整理、起草、分析正是它最合适的角色**。

**⑥ 考法提示**：题干经典长相是「由模型直接给出 XX 结论并自动生效、无需任何人查看，是否可行？」→ 答案**不可行**。干扰项固定在两个极端：一侧说"规则写清楚/微调后就能取消全部人工环节"（错），另一侧说"模型连辅助整理都做不到"（错）。**完整正反例见第三章 3.3（8 组）。**

**⑦ 记忆锚点**：**「决定权在人，参考稿在 AI」／「AI 出草稿，人签字」**。

### M1-K04　基于上下文生成内容（工作方式）　🟢`[A]`

**① 一句话定义**：模型每一次输出，都是**依据当前上下文**预测"下一个最可能的 Token"，并把生成结果拼回上下文继续预测，直到结束。

**② 是什么**：所谓"上下文"，包含系统说明 + 历史对话 + 你本次提供的材料 + 已生成的部分。模型在其中做**概率预测**，而不是"检索数据库再念出来"。由此推出四条重要结论：**其一，给它什么它才有什么**——模型不会主动去查缺失的材料；**其二，上下文质量决定输出质量**——材料杂乱、要求含糊，输出必然不稳（这正是 M2 提示词工程存在的理由）；**其三，上下文装不下就用不上**——长度以 Token 计且有上限（M1-K07）；**其四，输出天然带概率性**——每次刷新可能不同，前面的错误还可能被一路带偏。

**③ 为什么**：官方原文把这条当作后面三大局限的**总因**：「理解大模型**基于上下文生成内容**的基本方式，**以及由此带来的**幻觉、训练数据时间范围和上下文限制」。因为是"预测最可能的下一个"而非"查证最真实的事实"→ 会**编**（幻觉）；因为知识只来自训练时见过的数据、且不会自动更新 → 会**缺**（时间范围）；因为一次能装进上下文的量有限 → 会**塞不下**（上下文限制）。

**④ 怎么做 / 怎么用**：
- 场景：让模型写项目周报。
- ❌ 弱输入：「写一份项目周报。」→ 模型只能凭先验泛泛而谈，易编造进度。
- ✅ 强输入：「以下是本周的三条进展记录与两个风险项（附后）。请按『进展 / 风险 / 下周计划』三段输出，不超过 400 字；**只使用我提供的信息，未提及的部分写"本周无更新"**。」
- 输出示意：三段式周报，未提及事项标注"本周无更新"——**因为材料进了上下文，幻觉风险大幅下降**。

**⑤ 易错点**
- ❌ 常见误解：模型是"从数据库检索后再念出来"。
- ✅ 正确说法：原生大模型**不检索**，是**基于上下文的概率生成**；要检索得靠**知识库（RAG）**。
- ❌ 常见误解："只要问得足够具体，就不需要知识库"。
- ✅ 正确说法：再具体的问法，也**变不出模型没见过的事实**。

**⑥ 考法提示**：陷阱常设在"**模型会自己去找资料核实**""**模型记得上次对话之外的全部历史**""**模型知道今天几号**"这类表述上——见到"自动/主动获取"一律判错。另一个高频陷阱：把"**不知道**"（时间范围）与"**没读到**"（上下文限制）混为一谈。

**⑦ 记忆锚点**：**「上下文是模型的全部世界」**——它不查、不记、不主动，只会看着眼前这一段往下接。

### M1-K05　局限一：幻觉　🟢`[A]`

**① 一句话定义**：幻觉 = 模型生成**看似合理但与事实不符**的内容，即"**编**"。

**② 是什么**：典型表现是杜撰不存在的法条条款、文献、数据、案例、接口、链接，而且语气自信、格式工整，很难靠肉眼识别。它不是一个"偶发 bug"，而是工作方式的副产物：模型的目标是预测"最可能的下一个 Token"，不是输出"经验证为真的答案"。训练语料本身的错误与缺失也会带来偏差。**后果**是错误决策依据、对外发布事故、法律与合规风险（尤其医疗、金融、合同场景）。

**③ 为什么**：见 M1-K04——基于上下文的概率生成本身就不包含"事实校验"环节。模型在知识空白区不会说"不知道"，而是倾向于**补全式编造**，且越具体、越像模像样。所以官方把幻觉列为三大局限之首，并在 M3/M6 分别给出对策（知识库 / 人工复核）。

**④ 怎么做 / 怎么用**：
- 场景：产品手册问答。
- ❌ 现象：问"该型号是否通过国家 XX 认证" → 答"已于 20XX 年通过，证书编号……"（核查：**该认证从未存在**）。
- ✅ 缓解组合拳：① **接入知识库**，让答案有据可依；② 在输入中要求"**给出来源引用**"并抽检溯源；③ 允许模型答"**未检索到**"；④ 关键结论**保留人工确认**。
- 输出示意：接了知识库后，同样的问题会答「手册中未检索到该认证信息（来源：产品手册 v3，第 5 章）」。

**⑤ 易错点**
- ❌ 常见误解："换个更大的模型就能彻底消除幻觉"。
- ✅ 正确说法：规模只能**缓解**，不能根除；幻觉是工作方式的固有产物。
- ❌ 常见误解："让模型再检查一遍就一定正确"。
- ✅ 正确说法：模型对自己的错误**同样会自信地肯定**；引用本身也可能是编的，必须**抽检溯源**。

**⑥ 考法提示**：判据词是"**不存在的 / 杜撰的 / 查无此项 / 从未发生过**"。陷阱是把它与"时间范围"混：题干说"本月刚更新的政策答成了旧版"→ 归**时间范围**（缺）而非幻觉；题干说"编了一个从未存在的认证"→ 归**幻觉**（编）。

**⑦ 记忆锚点**：**「编的是幻觉」**——流畅不等于正确，自信不等于事实。

### M1-K06　局限二：训练数据时间范围　🟢`[A]`

**① 一句话定义**：模型的知识停留在**训练数据的截止时点**，即"**缺**"——不知道训练之后发生的事。

**② 是什么**：表现为对之后发生的事件、新发布的政策法规、最新价格/库存/版本答不上来，或给出**过时答案**。成因是：知识来自训练时见过的数据，训练完成后模型**不会自动更新**，也不具备天然的"今天"概念。**后果**是信息过期导致决策错误、与最新政策/流程冲突、给客户报错价。

**③ 为什么**：这不是"模型记性不好"，而是它的知识**是训练时固化下来的静态快照**。因此官方在 M3 给出的对策是"外接"而不是"重训"：**查企业资料/最新文档 → 接入知识库（RAG）；取实时数据（天气、股价、库存、物流）→ 调用工具**。

**④ 怎么做 / 怎么用**：
- 场景：客服问"**本月初刚发布**的产品退换货新政有哪些变化"。
- ❌ 现象：模型给出格式工整但与公司最新文件不符的答复。
- ✅ 处理：把最新政策文件放进**知识库**，让模型基于检索到的资料回答；必要时在答案中**标注文件版本与日期**并**人工核实**。
- 输出示意：「根据《退换货管理办法（2026-09 版）》第 3 条……（来源：知识库文档，更新日期 2026-09-01）」。

**⑤ 易错点**
- ❌ 常见误解："微调可以解决时效性问题"。
- ✅ 正确说法：微调成本高，且喂进去的知识**同样会过期**；持续拿最新资料首选 **RAG**。
- ❌ 常见误解："答得过时 = 幻觉"。
- ✅ 正确说法：**时间范围是"缺"，幻觉是"编"**；时间范围问题常常**以幻觉的形式表现出来**，但归因与对策不同（一个补资料，一个要核事实 + 引用）。

**⑥ 考法提示**：判据词是"**最新 / 最近刚 / 本月（本周）刚发布 / 实时 / 当前价格 / 此刻库存**"。陷阱是把这类题误选"调工具"——**要看要的是"文档资料"还是"实时数据"**：查企业文档 → 知识库；查此刻的库存股价 → 工具。

**⑦ 记忆锚点**：**「缺的是时间」**——模型没有"今天"，只有"训练截止那天"。

### M1-K07　局限三：上下文限制　🟢`[A]`

**① 一句话定义**：模型一次能接收并处理的 **Token 总量有上限**（输入 + 输出合计），即"**塞不下**"。

**② 是什么**：表现为超出上限后内容被**截断**或被挤出有效范围；超长文档一次投喂时，模型可能"看不见"中间或开头的信息；长对话中前面说过的内容也可能不被重视。成因是上下文窗口有限，注意力计算与显存开销随长度增长，做不到无限扩展。**后果**是遗漏关键信息、前后答复不一致、长文档问答质量骤降。

**③ 为什么**：官方把这条与幻觉、时间范围并列，是因为它是"基于上下文生成"的**物理约束**——材料进不了上下文，就等于模型没见过。对策也对应着 M3 的检索思路：**只把相关的放进去，而不是全都塞进去**。

**④ 怎么做 / 怎么用**：
- 场景：约 50 万字项目标书一次性粘贴提问。
- ❌ 现象：对**开头**条款能答，对**中后部**条款几乎无法回答。
- ✅ 缓解四招：① **拆分处理**（分段摘要 → 再汇总）；② 用**检索/知识库**只把相关片段放进上下文；③ **精简对话**，必要时开新会话并重新给出关键信息；④ 把最关键的事实放在**当前问题附近**，而不是几千字之前。
- 输出示意：改为"先按章节生成摘要 → 再基于摘要回答"的两段式流程后，中后部条款可被正常回答。

**⑤ 易错点**
- ❌ 常见误解："上下文长度按字数算"。
- ✅ 正确说法：以 **Token** 计（见 M1-K13），且**不要背换算比例**。
- ❌ 常见误解："只要模型支持长上下文，就可以把整本手册全塞进去并期待全部记住"。
- ✅ 正确说法：**能装下 ≠ 能同等重视每一段**。
- ❌ 常见误解："这是幻觉"。
- ✅ 正确说法：题干特征是"**读不到 / 答不出**"，属于容量问题，不是编造问题。

**⑥ 考法提示**：判据词是"**超长 / 几十万字一次喂进去 / 前面说过的内容被忽略了 / 只答得出来开头**"。陷阱是把"开头能答、后面答不出"误判为"模型没见过这份材料"（那是时间范围）——**材料已经喂给它了，问题在装不下**。

**⑦ 记忆锚点**：**「塞不下的是上下文」**——装得进 ≠ 记得住。

### M1-K08　能力边界判断（本模块第一考点）　🟢`[A]`

**① 一句话定义**：官方点名的核心考法——判断**什么时候适合生成、总结、分析，什么时候需要知识库、工具或人工确认**。

**② 是什么**：它是一套**选型**能力，不是知识点记忆。官方给出的标准答案池共六项：**优化输入 → 接入知识库 → 调用工具 → 使用微调 → 协作 Agent ⋯ 或保留人工确认**。判断路径是"三问"（第五章 5.2）：**肚子里有没有这个事实** → **要不要做动作/算准** → **错了谁负责**。三问都否，就是纯文字活，直接生成/总结/分析。

**③ 为什么**：官方在全局声明里写得很直白——「考试重点是**理解大模型能力边界**，并能在业务场景中选择合适的方法」。因为真实业务里绝大多数事故不是"模型不会写"，而是"**该接知识库的用了生成、该调工具的让模型算、该人工确认的让它自动生效**"。所以本考点是 **M1 通向 M2–M6 的地基**。

**④ 怎么做 / 怎么用**：
- 场景：电商"客户问价机器人"，需求含 ① 获取**当前实时**价格 ② 按固定**阶梯折扣规则算出精确金额** ③ 经确认后**写入报价单**。
- ❌ 错误做法 A：只优化提示词，把折扣规则写进提示词让模型自己算 → 提示词拿不到实时价、也保证不了算术精度。
- ❌ 错误做法 B：用微调把折扣规则训进模型 → 微调是**稳行为/格式/风格/分类**，不是"补实时数据/做精确计算/执行动作"。
- ✅ 正确做法：由**工具**获取当前价格、完成确定性计算与写单动作；模型负责理解意图、组织答复、解释口径。
- 输出示意：「该商品当前单价 ¥X，按 3 档阶梯折扣折后 ¥Y（**由业务系统计算**），报价单已生成待确认。」

**⑤ 易错点**
- ❌ 常见误解：一见效果不好就想到微调。
- ✅ 正确说法：微调是**稳行为 / 格式 / 风格 / 分类能力 / 轻量部署**；补知识首选 **RAG**。
- ❌ 常见误解：把工具当成"补知识"的手段。
- ✅ 正确说法：**查企业文档资料 = 知识库；取实时数据 / 确定性计算 / 业务动作 = 工具**。
- ❌ 常见误解：手段只能选一个。
- ✅ 正确说法：手段**可组合**（如"知识库 + 人工确认"）。

**⑥ 考法提示**：本模块**至少 2 题**，且大概率是场景题。秒杀顺序：**先找题干里的触发词**（企业私有/内部资料 → 知识库；实时/此刻/算准/写库/下单 → 工具；医疗金融合同发布 → 人工确认；格式风格稳定 → 微调；多步骤交付 → Agent；材料已给 + 纯文字 → 直接生成/总结/分析）。干扰项常把"知识库"和"工具"对调，或让"微调"承担补知识的角色。

**⑦ 记忆锚点**：**「查知识用 RAG，做动作靠工具，稳行为才考虑微调，高风险留人工确认。」**

### M1-K09　典型应用场景（4 类）　🟢`[A]`

**① 一句话定义**：大模型典型应用分四类——**生成创作 / 润色转换 / 摘要与信息提取 / 信息推理与表格解读**。

**② 是什么**：
| 场景类别 | 在做什么 | 例子 |
|---|---|---|
| **文本生成与创作** | 从无到有产出内容 | 写营销文案、写周报、写故事、写邮件草稿 |
| **文本润色与转换** | 对已有文本做改写 / 转换 | 润色语病、风格改写、翻译、口语转书面语、格式转换 |
| **文本摘要与信息提取** | 压缩 + 抽关键信息 | 长文要点总结、会议纪要、从合同里提取甲乙方/金额/期限 |
| **信息推理与表格解读** | 基于给定数据做推断 / 计算式理解 | 读销售报表给结论、对比多方案、按表格内容回答追问 |

**归类方法：看"输入 → 输出"发生的变化**——原来没有、现在生成了 = **生成创作**；原来有、只是换了说法/语种/风格 = **润色转换**；原来很长、现在变短或抽出字段 = **摘要与信息提取**；原来是一堆数据、现在给出结论/判断 = **信息推理与表格解读**。

**③ 为什么**：官方把"典型应用场景"写进「建议掌握的知识」，是因为场景归类直接决定**选型**：同样是"处理一份合同"，抽字段属于信息提取（可直接做），而判断"该不该签"属于高风险决策（必须人工确认）。场景 × 边界的组合，就是本模块场景题的出题模型。

**④ 怎么做 / 怎么用**：
- 输入 A：一份 20 页调研报告 → 要求"压缩成 300 字要点"。判断：**长度被压缩** → **摘要与信息提取** → 材料已提供，可直接交给模型。
- 输入 B：中文版产品说明 → 要求"翻译成英文"。判断：**已有内容换语种** → **润色与转换**（不是创作）。
- 输入 C：合同全文 → 要求"提取甲乙方、金额、付款期限"。判断：**抽已有字段** → **摘要与信息提取**（不是推理——推理要产生新结论）。
- 输入 D：一份月度销售表 → 要求"哪个区域下滑最明显、可能原因是什么"。判断：**基于数据下结论** → **信息推理与表格解读**，且结论对外要**人工确认**。

**⑤ 易错点**
- ❌ 常见误解："长文压成 300 字要点 = 润色转换"。
- ✅ 正确说法：**长度被压缩 = 摘要**；润色只改说法、不压缩内容。
- ❌ 常见误解："从合同中提取金额和期限 = 信息推理"。
- ✅ 正确说法：**抽字段 = 信息提取**；只有**基于数据下结论**才算推理。
- ❌ 常见误解："中文翻译成英文 = 生成创作"。
- ✅ 正确说法：**已有内容换形式 = 转换**。

**⑥ 考法提示**：常以**多选题**出现，四个选项分别对应四类场景，其中一个混入"能力边界越界"的做法（如"依据本月刚更新的价格表直接生成精确报价"）作为错误项。**判据：看输入输出之间发生了什么变化，而不是看用了什么词。**

**⑦ 记忆锚点**：**「造、改、抽、断」** = 造（生成）、改（润色转换）、抽（摘要提取）、断（推理判断，断要人复核）。

### M1-K12　训练三阶段：预训练 → SFT → RLHF　🟡`[B]`

**① 一句话定义**：**先有料（预训练）→ 再听话（SFT）→ 后讨喜（RLHF）**。

**② 是什么**：**预训练**是在海量无标注文本上预测下一个 Token，产出**基座模型**（有知识、会续写，但不听指令）；**SFT（监督微调）**用"指令-回答"示例训练，让模型**遵循指令、按格式回答**；**RLHF（人类反馈强化学习）**用人类偏好反馈调整输出倾向，让回答**更符合人类价值观与偏好**。

**③ 为什么**：这三个阶段解释了一个常见困惑——**为什么"有知识"不等于"好用"**。预训练给了知识，但模型只会"续写"；要让它变成"会答题、懂意图"的助手，还需要指令遵循与偏好对齐。这也是**"模型训练"与 M5 的"业务微调"必须区分开**的原因。

**④ 怎么做 / 怎么用**：
- 场景：同事问"为什么基座模型补全句子很流畅，但让它'总结这段话'就跑偏？"
- 你的解释：「它只做了**预训练**（会续写），还没充分做**指令遵循与偏好对齐**。我们用的对话模型已经走完了这三步；而**业务侧的微调**（M5）是另一件事，是为了稳行为、格式、风格。」
- 输出示意：同事不再把"训练"和"业务微调"混为一谈。

**⑤ 易错点**
- ❌ 常见误解：阶段顺序可颠倒。
- ✅ 正确说法：必须 **预训练 → SFT → RLHF**。
- ❌ 常见误解：RLHF 用来注入新知识。
- ✅ 正确说法：RLHF 只**调输出倾向**，不注入知识。
- ❌ 常见误解：这里的 SFT = M5 的业务微调。
- ✅ 正确说法：两者**不是一回事**；M5 微调是**面向业务目标**的再训练，用于稳行为/格式/风格/分类。

**⑥ 考法提示**：官方明确「**不考模型训练**…细节」，因此只可能考**方向性表述**（"预训练学知识 / SFT 学听指令 / RLHF 学对齐"✅），不会考流程参数。

**⑦ 记忆锚点**：**「先有料、再听话、后讨喜」**。

### M1-K13　分词 Tokenization　🟡`[B]` ⚠️ **了解即可，非官方明列考点**

**① 一句话定义**：Token 是模型处理文本的**基本单位**，上下文长度与调用量都按 Token 计。

**② 是什么**：模型不直接处理字符或整词，而是先把文本切成 Token 再处理。中英文**都会被切分**，一个英文单词**可能被拆成多个 Token**；训练与推理都要分词，且必须用**同一套分词器/词表**。它在考试中的**唯一作用**，是支撑"**上下文限制**"（M1-K07）这条真实考点——因为上限是按 Token 计的，不是按字数计的。

**③ 为什么**：按 Token 而非字符处理，能在词表规模与表达力之间取得平衡，也让模型能处理未见过的词。对备考而言，理解"**上下文有上限且以 Token 计**"就够了，具体切分规则属于实现细节。

**④ 怎么做 / 怎么用**：
- 场景：同事抱怨"我把 50 万字标书粘进去，模型好像没读完"。
- 你的解释：「一次能处理的 **Token 总量有上限**（输入 + 输出合计），所以要么**拆分分段**，要么用**检索**只把相关片段放进来。」
- 输出示意：同事明白问题出在**容量**而不是"模型偷懒"。

**⑤ 易错点**
- ❌ 常见误解：Token = 字数 / 字符数，或"一个汉字 = 一个 Token"。
- ✅ 正确说法：不同分词器**粒度不同**，**不要背换算比例**；只知道"按 Token 计、有上限"即可。
- ❌ 常见误解：分词只在训练时做。
- ✅ 正确说法：**训练与推理都要做**。

**⑥ 考法提示**：⚠️ **官方 M1 考试内容未提及分词**，题库**不出题**。若出现在选项里，通常是作为**无关干扰项**（如把"答不出新政策"归因于分词错误 ❌）。

**⑦ 记忆锚点**：**「上下文按 Token 算，不按字数算」**——只记这一句就够。

### M1-K14　注意力机制　🟡`[B]` ⚠️ **了解即可，非官方明列考点**

**① 一句话定义**：处理某个 Token 时，动态计算它与上下文中其他 Token 的**相关权重**并按权重汇总信息。

**② 是什么**：它让模型能够建立长距离依赖（例如判断"它"指代的是前文提到的"蓝牙耳机"）。要点是：**注意力决定"看输入里的哪些 Token"**，属于**输入侧**机制；而 MoE 的路由决定"用模型里的哪些专家"，属于**结构侧**——两者不要混。

**③ 为什么**：它是 Transformer 的核心组件，也是"能并行处理整段序列、从而把模型做大"的关键。对备考而言，它的价值仅在"能与技术人员基本沟通"（官方原文表述）。

**④ 怎么做 / 怎么用**：
- 场景：技术同学说"这段提示词太长，注意力被分散了"。
- 你的理解：信息太多时，模型对**关键内容**的关注可能被稀释 → 对应 M1-K07 的缓解手段：**精简上下文、把关键事实放在当前问题附近**。
- 输出示意：你把 8000 字材料改为"先摘要、再提问"的两段式，回答质量回升。

**⑤ 易错点**
- ❌ 常见误解：把注意力当成"记忆 / 数据库"。
- ✅ 正确说法：它是**相关性加权计算**，不是检索，也不保证正确性。
- ❌ 常见误解："注意力权重高 = 事实正确"。
- ✅ 正确说法：只说明**关注了哪里**，不说明**说的是真的**。
- ❌ 常见误解：注意力 = MoE 路由。
- ✅ 正确说法：**注意力看输入 Token（输入侧），MoE 路由选结构专家（结构侧）**。

**⑥ 考法提示**：⚠️ **官方 M1 考试内容未提及注意力机制**，题库**不出题**。不要为它花备考时间。

**⑦ 记忆锚点**：**「注意力决定看哪些词，MoE 路由决定用哪些专家」**。

### M1-K15　Transformer 架构　🟡`[B]`

**① 一句话定义**：以**自注意力**为核心的神经网络架构，可**并行**处理整段序列，是当代大模型的架构底座。

**② 是什么**：不同于 RNN 逐词串行处理，Transformer 可以并行处理整段序列，训练效率大幅提升，因而**才可能把模型规模做大**。它是 2017 年提出的架构，也是 M1-K10 技术发展脉络中的关键节点。

**③ 为什么**：它在脉络中的意义是"**让做大成为可能**"，而不是"它本身就是大模型"。架构是可复用的骨架，规模与训练才决定"大"。

**④ 怎么做 / 怎么用**：
- 场景：同事问"Transformer 和大模型是一回事吗？"
- 你的解释：「不是。**架构是骨架，规模 + 训练才是'大'**。就像同一套建筑结构，可以盖平房也可以盖高楼。」
- 输出示意：同事区分开了"架构"与"规模"两个概念。

**⑤ 易错点**
- ❌ 常见误解："Transformer = 大模型"。
- ✅ 正确说法：**架构 ≠ 规模**；**规模（参数/数据/算力）+ 训练**才是"大"。
- ❌ 常见误解：需要掌握架构实现细节。
- ✅ 正确说法：⛔ **不考实现、不考公式、不考代码**。

**⑥ 考法提示**：若考，只考**脉络中的方向性作用**（"为模型规模化训练奠定基础"✅），不考结构细节。

**⑦ 记忆锚点**：**「骨架是 Transformer，大小靠规模和训练」**。

### M1-K16　MoE 架构　🟡`[B]` ⚠️ **了解即可，非官方明列考点**

**① 一句话定义**：**Mixture of Experts** = 多专家 + 路由 + **稀疏激活**——参数总量大，但单次推理只激活少量专家。

**② 是什么**：模型内部有多个"专家"网络，由一个**路由**机制为每次输入挑选少量专家参与计算。效果是"**大容量 + 低推理开销**"。它是**效率与容量层面**的设计，与幻觉、时效这类**正确性层面**的问题无关。

**③ 为什么**：它回答的是"**怎么用得起**"的问题——在保持模型容量的同时控制单次推理开销，属于 M1-K10 脉络里"降本路线"的一环。

**④ 怎么做 / 怎么用**：
- 场景：同事问"用了 MoE 是不是就不会答错了？"
- 你的解释：「不会。MoE 解决的是**容量与推理开销**的取舍，不解决**事实正确性**；要减少答错，靠**知识库 + 引用 + 人工确认**。」
- 输出示意：同事不再把架构优化当成质量手段。

**⑤ 易错点**
- ❌ 常见误解：每次推理用全部参数。
- ✅ 正确说法：恰恰相反——**稀疏激活，只激活少量专家**。
- ❌ 常见误解：MoE = 量化。
- ✅ 正确说法：**量化降数值精度，MoE 选专家**。
- ❌ 常见误解：MoE 能解决幻觉 / 时效问题。
- ✅ 正确说法：它是**效率与容量**层面的设计，**不是事实校验手段**。

**⑥ 考法提示**：⚠️ **官方 M1 考试内容未提及 MoE**，题库**不出题**。若出现在选项里，多为干扰项。

**⑦ 记忆锚点**：**「MoE = 人多但每次只派几个」**。

### M1-K17　涌现能力　🟡`[B]`

**① 一句话定义**：规模跨过阈值后**突然出现**小模型不具备的能力，且**非显式训练所得**。

**② 是什么**：典型如多步推理、复杂指令遵循等，在规模较小时几乎不存在，跨过某个规模后明显出现。它强调的是**跃迁**而非线性提升。

**③ 为什么**：它是"为什么要做大模型"的经验性解释——不是"同样能力跑得更快"，而是"**出现了原本没有的能力**"。这也呼应 M1-K01 中"规模带来能力边界拓宽"的说法。

**④ 怎么做 / 怎么用**：
- 场景：同事问"小模型也能写文案，为什么要用大的？"
- 你的解释：「小模型能做简单的写和改，但**多步推理、复杂指令遵循**这类能力是在规模跨过阈值后**涌现**出来的；**但涌现不消除幻觉与时效**，该接知识库还得接。」
- 输出示意：同事形成了"能力跃迁 + 边界仍在"的正确预期。

**⑤ 易错点**
- ❌ 常见误解：涌现 = 平滑线性提升。
- ✅ 正确说法：强调**跃迁**（跨阈值后突然出现）。
- ❌ 常见误解：涌现 = 无所不能。
- ✅ 正确说法：**不消除幻觉、不突破时间范围与上下文限制**。

**⑥ 考法提示**：⚠️ 了解即可。若出现，陷阱是把"涌现"说成"模型变得不会出错"。

**⑦ 记忆锚点**：**「大到一定程度，突然会了；但会 ≠ 全对」**。

### M1-K18　上下文学习 ICL　🟡`[B]`

**① 一句话定义**：**不更新参数**，只在输入中给若干示例（few-shot），模型即可照样子完成新任务；**会话结束即失效**。

**② 是什么**：它利用的是模型"基于上下文生成"（M1-K04）的特性：把示例放进上下文，模型就会模仿示例的模式继续输出。**不改参数、也不获取外部数据**。

**③ 为什么**：它解释了"为什么提示词工程这么重要"——在不动模型的前提下，仅靠**输入里的示例与约束**就能显著改变输出。这也是 M2 提示词工程存在的基础。

**④ 怎么做 / 怎么用**：
- 场景：让模型按固定格式抽取字段。
- 输入：「示例 1：原文… → 输出『甲方：A 公司；金额：10 万；期限：30 天』。示例 2：… → …。请按同样格式处理以下原文：……」
- 输出示意：模型按示例格式输出 → 这是 **ICL / 优化输入**；**它不会让模型知道示例之外的外部事实**（那要靠 RAG）。

**⑤ 易错点**
- ❌ 常见误解：ICL 修改了模型参数。
- ✅ 正确说法：**不改参数**，只影响本次上下文。
- ❌ 常见误解：ICL = RAG。
- ✅ 正确说法：**RAG 检索外部知识；ICL 只给示例**。
- ❌ 常见误解：多给示例就能保证实时数据准确。
- ✅ 正确说法：示例再多也**不获取外部数据**，实时性要靠**工具**。

**⑥ 考法提示**：⚠️ 了解即可，但**极易与 RAG / 微调混**，是本模块易错辨析的高频项。判据：**看是否改参数、是否有外部检索**。

**⑦ 记忆锚点**：**「ICL 给示例（不改参数），RAG 给资料（外部检索），微调改参数」**。

### M1-K19　模型分类（模态 / 开源 / 用途）　🟡`[B]`

**① 一句话定义**：分类是**维度**问题，可叠加——按模态、按开放性、按用途，互不互斥。

**② 是什么**：按**模态**可分为语言模型、视觉模型、语音模型、多模态模型；按**开放性**可分为开源权重可得与闭源 API；按**用途**可分为通用基座、垂直领域模型、专用能力模型（如向量模型、重排序模型）。一个模型可以同时落在多个维度上。

**③ 为什么**：理解"维度可叠加"能避免非此即彼的分类误判。例如"开源的语言基座模型"同时命中三个维度。

**④ 怎么做 / 怎么用**：
- 场景：同事问"这个模型是多模态的，那它是不是闭源的？"
- 你的解释：「这是**两个维度**：模态说的是能处理什么输入，开放性说的是权重/接口是否可得，可以任意组合。」
- 输出示意：同事不再把分类当作单选。

**⑤ 易错点**
- ❌ 常见误解：开源 = 一定可商用免费。
- ✅ 正确说法：商用要看**许可协议**。
- ❌ 常见误解：分类互斥。
- ✅ 正确说法：**维度可叠加**。
- ❌ 常见误解：多模态是独立考区。
- ✅ 正确说法：官方六大模块中**无多模态**，它仅作为"按模态分类"中的一个类别名称出现。

**⑥ 考法提示**：⚠️ 了解即可。若考，只考"**维度可叠加**"这一条。

**⑦ 记忆锚点**：**「分类是维度，不是格子」**。

### M1-K20　大模型四大特点　🔴`[C]` ⚠️ **待核实**

**① 一句话定义**：行业常见归纳的四项特点——**语言理解与生成能力、通用性与泛化能力、上下文学习能力、涌现能力**；⚠️ **具体四项表述未获官方确认**。

**② 是什么**：常见归纳为：① 强大的**语言理解与生成能力**；② **通用性与泛化能力**（一个模型承担多类任务）；③ **上下文学习能力**（见 M1-K18）；④ **涌现能力**（见 M1-K17）。这四项彼此有交叉，且更像是"对现象的归纳"而非官方定义。

**③ 为什么**：本条标 🔴`[C]`，是因为**官方大纲并未给出"四大特点"这一说法**，它属于课程侧或行业侧的归纳。因此**只作方向性理解，不必逐字背诵**，也不要把它当成标准答案的选项依据。

**④ 怎么做 / 怎么用**：
- 场景：看到某份资料说"大模型四大特点是 A/B/C/D"。
- 你的处理：记住**方向**（能理解生成、能通用泛化、能靠示例适配、规模大了会涌现），**不背具体措辞**；遇到选项时**以官方原文的三大局限 + 能力边界为准**。
- 输出示意：你把复习时间从"背四项"转移到"背官方三局限与六选一"。

**⑤ 易错点**
- ❌ 常见误解：把行业归纳当成官方考点逐字背诵。
- ✅ 正确说法：⚠️ **待核实**，只作方向参考；**官方依据是"能做什么 / 不能直接替人决定什么 / 三大局限 / 能力边界判断"**。
- ❌ 常见误解："四大特点"包含"不会产生幻觉""能实时联网"。
- ✅ 正确说法：这两条是**必须排除的假特点**——幻觉是官方明列的局限，原生模型**不具备实时联网**能力，要靠**知识库 / 工具**。

**⑥ 考法提示**：⚠️ **待核实**。题库**不出题**。若真出现此类选项，**优先按官方原文判断**：凡出现"不会出错""自动获取最新信息""具备自主意识"等表述，一律判错。

**⑦ 记忆锚点**：**「真特点记官方那几句，假特点一律排除」**。

## 九、⭐ 本模块必背清单（考前 10 分钟过一遍）

### 9.1 官方原文四句（一字不差地记）

1. 「理解大模型是什么，**能做什么，不能直接替人决定什么**。」
2. 「理解大模型**基于上下文生成内容**的基本方式，以及由此带来的**幻觉、训练数据时间范围和上下文限制**。」
3. 「掌握**能力边界判断**：什么时候适合**生成、总结、分析**，什么时候需要**知识库、工具或人工确认**。」
4. 「本认证**不要求考生编写代码，也不考模型训练和协议实现细节**。」

### 9.2 三个数字

- 本模块权重 **18%** → **9 题（6 单选 + 3 多选）** → 每题 2 分，满分 **18 分**
- 全局：**50 题、100 分、及格 80 分、60 分钟**
- 目标：本模块 **≥ 8/9 题**，失分控制在 **2 分以内**

### 9.3 三大局限口诀

> **「编的是幻觉，缺的是时间，塞不下的是上下文」**
> - **编**（幻觉）→ 接知识库 + 要引用 + 人工核实
> - **缺**（训练数据时间范围）→ 接知识库（查资料）/ 调工具（取实时数据）
> - **塞不下**（上下文限制）→ 拆分分段 / 检索取片段 / 精简上下文

### 9.4 能力边界六选一（标准答案池）

```
优化输入  →  接入知识库  →  调用工具  →  使用微调  →  协作 Agent
                                          ⋯ 或 →  保留人工确认
```

**三条判据**
- **查知识用 RAG，做动作靠工具，稳行为才考虑微调。**
- 需要**实时数据、确定性计算或业务动作**时 → **用工具**。
- **AI 可以辅助整理和起草，但不能替代最终责任人**；**高风险动作必须人工确认**。

### 9.5 判断三问（场景题解题路径）

1. 这件事要的事实，**模型肚子里有吗**？→ 没有 → **知识库 / 工具**
2. 这件事要**做动作或算准**吗？→ 要 → **工具**（多步骤 → **Agent**）
3. 这件事**错了谁负责**？→ 高风险 → **人工确认**
4. 三问都否 → **直接生成 / 总结 / 分析**（效果不稳先**优化输入**）

### 9.6 场景四类口诀

> **「造、改、抽、断」** = 造（生成创作）、改（润色转换）、抽（摘要与信息提取）、断（信息推理与表格解读，**断要人复核**）

### 9.7 边界红线（见到即判错）

- ❌ "任意长度输入""必然正确""不受时间范围影响"
- ❌ "自动 / 主动联网获取最新信息"
- ❌ "可以承担最终责任""替人决定是否通过""取消全部人工环节"
- ❌ "具备自主意识与主观判断"
- ❌ 涉及具体论文标题、精确发布日期、参数规模、版本号、控制台路径、定价

### 9.8 一句话总览（考前 30 秒）

> **大模型 = 在海量数据上训出巨大参数的语言模型，能写、能改、能缩、能归纳、能给候选建议；它基于上下文逐 Token 地生成内容，因此会「编」（幻觉）、会「缺最新」（时间范围）、会「塞不下」（上下文限制）→ 凡涉及事实准确性就接知识库，凡涉及最新或实时信息就接知识库 / 调工具，凡涉及动作就用工具，凡涉及高风险就保留人工确认——它永远给参考，不能替人拍板。查知识用 RAG，做动作靠工具，稳行为才考虑微调，AI 辅助起草但不能替代最终责任人。**

## 十、易错辨析表（本模块内）

| 易混对 | 关键区别 | 一句话判据 |
|---|---|---|
| **幻觉 vs 时间范围** | 编造不存在的 / 不知道新发生的 | "杜撰的 / 查无此项"→幻觉；"最新的 / 本月发布的"→时间范围 |
| **时间范围 vs 上下文限制** | 知识有没有 / 装不装得下 | "模型不知道"→时间范围；"材料塞不进去 / 前面被忘"→上下文限制 |
| **幻觉 vs 上下文限制** | 内容不可信 / 内容没被看到 | "答案错但流畅"→幻觉；"压根没读到后面"→上下文限制 |
| **能做什么 vs 不能替人决定** | **产出候选**（写、改、缩、判）/ **最终拍板**（签、投、发、诊） | **AI 出草稿，人签字** |
| **知识库 vs 工具** | 查企业文档资料（RAG）/ 实时数据、确定性计算、业务动作 | 「**查知识用 RAG，做动作靠工具**」 |
| **工具 vs 微调** | 外部动作与实时数据 / 稳定行为、格式、风格、分类 | 经常变的外部世界→工具；长期不变的表达习惯→微调 |
| **知识库 vs 微调** | 补知识（可持续更新）/ 稳行为（样本沉淀） | 知识会过期→知识库；行为要一致→微调 |
| **ICL vs RAG vs 微调** | 给**示例**（不改参数）/ 检索**外部知识** / **改参数** | 看是否改参数、是否有外部检索 |
| **优化输入 vs 微调** | 改的是"这次怎么说" / 改的是"模型本身" | 一次性的表达问题→优化输入；长期稳定的行为→微调 |
| **模型 vs 产品平台** | 模型（千问 / 万相是模型）/ 平台（百炼是平台） | 说话→千问；画图→万相；搭应用→百炼 |
| **"大" vs "不会错 / 不受限"** | "大"是参数 / 数据 / 算力规模 | 规模再大也有幻觉、有时间范围、有上下文上限 |
| **注意力 vs MoE 路由** | 看输入里**哪些 Token** / 用模型里**哪些专家** | 一个在输入侧，一个在结构侧 |
| **MoE vs 量化** | 只激活部分专家 / 降低数值精度 | "只激活一部分参数"→MoE |
| **ICL vs 上下文** | ICL 是**一种用法** / 上下文是**模型的输入环境** | 示例放进上下文 = ICL |
