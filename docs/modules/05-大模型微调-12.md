### M5-K01　微调的定义与本质　🟢`[A]`

**① 一句话定义**：微调是在**已预训练好的基座模型**上，用**特定任务的样本数据**继续训练，从而**改变模型自身的行为习惯**——它更新的是**模型权重**。

**② 是什么**：预训练模型已经具备通用语言能力与世界知识，但不知道你的业务要它"怎么说话"。微调就是用一批「输入 → 期望输出」的成对样本，在这个基座上继续训练，把这些期望**写进模型参数**。它与 RAG、提示词的根本区别在于作用点：**提示词和 RAG 改的是"喂给模型什么"（输入侧），微调改的是"模型本身"（参数侧）**。微调不是从零训练一个模型，而是站在预训练成果之上做定向调整；正因为基座已经"读过万卷书"，微调只需要教它"在什么场合用什么腔调说话"。因此微调的成本与门槛，都远低于从零训练。

**③ 为什么**：官方把微调列为手段之一，是为了解决提示词与 RAG 解决不了的问题——**行为不稳定**。提示词是"每次提醒"，长尾问法下会偶发失效；RAG 是"给资料"，只解决"答什么"不解决"怎么答"。这两者都不改变模型本身，所以行为层面的漂移（格式时好时坏、语气时冷时热、同一句话被分到不同类）反复出现。微调通过更新权重，把行为变成模型的"习惯"而非"临时要求"。官方原文「微调不是万能按钮」则同时划定了它的边界：它改变的是**行为**，不能替模型补充会变化的知识，也不能给它执行动作的能力。

**④ 怎么做 / 怎么用**：
- 场景：某保险公司的理赔初审助手，每次输出的字段名不统一（`claim_type` / `type` / `理赔类型` 混着来），下游系统解析经常失败。
- 之前（提示词约束）：在提示词里写死 JSON schema 并附 3 个示例 → 常规问法下 OK，遇到长句、多轮追问、用户夹杂方言时，约有 8% 的请求仍跑偏。
- 之后（微调）：整理 2000 条「用户诉求 → 标准 JSON」的样本（字段固定、枚举值固定、话术统一），在基座上按官方五步流程微调 → 跑偏率降到 1% 以下，且提示词里**不必再塞那一大段 schema 说明**，输入更短、响应更快。
- 判断链：字段不统一是"行为"问题（怎么说），不是"知识"问题（不知道）→ 提示词已试过仍不稳 → 命中官方「稳行为才考虑微调」。

**⑤ 易错点**：
- ❌ 常见误解：微调就是"把企业资料喂给模型，让它记住"。
- ✅ 正确：那是 **RAG** 的活儿。资料会变、要溯源，微调进去**会过时且不可追溯**。微调改的是**行为**，不是**知识库**。
- ❌ 常见误解：微调是从零开始训练一个新模型。
- ✅ 正确：微调必须**站在预训练基座之上**（官方五步第 ③ 步就叫「选择基模」）；基座是天花板，微调只能在天花板之下做改善。

**⑥ 考法提示**：最常作为**干扰项的判别依据**出现，而非单独成题。凡是选项里出现"把资料 / 手册 / 制度 / 政策微调进模型"，判错；凡是选项里出现"用样本更新模型参数 / 权重"，判对。硬判据只有一句：**「有没有改模型权重」**——改了就是微调，没改就是提示词 / RAG / 工具。

**⑦ 记忆锚点**：**「RAG 换资料，微调换习惯」**；提示词是"每次提醒"，微调是"养成习惯"。

### M5-K02　适用场景①：稳定行为　🟢`[A]`

**① 一句话定义**：让模型在某个任务上的**整体反应长期稳定下来**——同类输入给出同质的处理，不随问法、不随上下文漂移。

**② 是什么**：这是官方五项适用场景中的**总纲**。它描述的不是某一个具体维度，而是"整体行为一致性"：同样一类用户诉求，不管用户怎么措辞、不问几轮、不管前面聊了什么，模型都按既定方式应答；该拒答的边界稳定不摇摆；该走某个处理动作就稳定地走那个动作。官方把「稳定行为、格式、风格、分类能力」并列列出，说明**格式 / 风格 / 分类是"稳定行为"的三种具体表现**——考场上既可以考总纲（行为漂移），也可以考分支（格式 / 风格 / 分类）。微调之所以能做到，是因为它把行为**写进权重**：提示词是每次输入的外部要求，长尾问法下会偶发失效；权重里的习惯则不会随单次输入波动。

**③ 为什么**：大模型本质是"基于上下文生成"，对同一个意思的不同说法，输出天然存在波动。业务上这种波动是致命的：下游系统要解析、质检要打分、用户要有一致体验。官方把"稳定行为"放在五项之首，正是因为**"不稳"是提示词最难根治、RAG 完全无解的问题**——RAG 换的是资料，资料再准，说话方式照样漂。**「稳行为才考虑微调」**这句口诀里的"稳行为"，第一落点就是这一项。

**④ 怎么做 / 怎么用**：
- 场景：政务热线助手，对"我要投诉"类诉求，有时直接给投诉指引、有时先安抚、有时反问一堆问题，导致质检评分忽高忽低。
- 之前（提示词）：写了一份 800 字的处理流程说明 → 常见问法遵守，换个说法（"你们这也太过分了"）就触发另一种反应。
- 之后（微调）：整理"诉求 → 标准三步响应（共情 → 确认要点 → 给指引）"的样本 → 同类诉求的响应路径稳定，质检通过率显著上升。
- 判断信号词：**「换个说法就变」「时好时坏」「不稳定」「忽高忽低」「每次反应不一样」**。

**⑤ 易错点**：
- ❌ 常见误解：行为不稳定，说明模型不知道该怎么做，多给点资料就好了（RAG）。
- ✅ 正确：模型**知道**该怎么做，只是**做不稳**；这是行为问题，资料再多也不解决稳定性，应走**微调**（且先试提示词）。
- ❌ 常见误解：只要提示词写得更长更细，稳定性就能和微调一样。
- ✅ 正确：提示词能改善但**难以根治**长尾漂移；微调是把行为内化，稳定性质变。

**⑥ 考法提示**：多选题里常作为**正确项**以概括性表述出现（"希望模型在某类任务上的整体反应长期稳定，不因用户换个说法就给出不同处理结果"）。干扰项往往长得像"稳定"但其实是**知识或动作**类（如"希望模型能回答最新报价"）。**看选项问的是"稳不稳"还是"知不知道"。**

**⑦ 记忆锚点**：**稳定行为 = 总纲；格式 / 风格 / 分类 = 三条分支。** 口诀：行为稳不稳，问微调；知识新不新，问 RAG。

### M5-K03　适用场景②：格式　🟢`[A]`

**① 一句话定义**：要求模型**每次都按同一个结构输出**，并且这个要求长期不变——把格式从"输入里的要求"变成"模型里的习惯"。

**② 是什么**：典型形态包括：必须输出符合约定 schema 的 JSON、病历必须按「主诉 - 现病史 - 诊断 - 处置」四段输出、工单必须含「问题类型 / 紧急度 / 责任部门」三个字段、表格列顺序固定。它与"内容对不对"无关，**只管"长什么样"**。提示词当然能约束格式，而且在多数场景下是**首选**；但当格式要求长期固定、下游系统要**自动解析**、且提示词反复优化后仍会偶发跑偏时，微调的价值就出现了——它把格式约束**内化进权重**，使稳定性从"大概率遵守"变成"几乎必然"。

**③ 为什么**：格式之所以值得单列为官方五项之一，是因为它是**"程序要读"**的场景。人读答案不怕格式微差，程序读答案差一个字段就崩。而大模型对格式的遵守是概率性的：输入变长、多轮上下文、用户插入无关信息，都会让格式遵守率下滑。微调把"输出结构"变成模型的行为习惯，等于把校验成本从下游移到模型侧。这也是官方把它归入"稳行为"而非"补知识"的原因。

**④ 怎么做 / 怎么用**：
- 场景：客服工单系统要自动抽取「问题类型 / 紧急程度 / 处理建议 / 是否转人工」四个字段写入数据库。
- 之前（提示词 + 示例）：90% 合规；长对话与追问场景下掉到 82%，偶尔输出成数组、偶尔多出解释性文字，解析失败。
- 之后（微调）：用 3000 条标准四字段样本微调 → 合规率稳定在 99%+，且提示词里**不再需要那一大段 schema 示例**，输入更短、响应更快、成本更低。
- 判断信号词：**「字段固定」「必须能被程序解析」「下游系统要自动读取」「结构化输出」**。

**⑤ 易错点**：
- ❌ 常见误解：格式跑偏是因为模型不知道字段含义，应该把字段说明文档接进知识库。
- ✅ 正确：模型**懂**字段含义，只是**输出不稳**；接知识库（RAG）不解决结构稳定性 → 应微调。
- ❌ 常见误解：只要刚提出格式要求还没试过，就该直接微调。
- ✅ 正确：**先优化提示词**。官方手段序列里「优化输入」排在「使用微调」之前；题干说"已在提示词中反复约束后仍跑偏"才轮到微调。

**⑥ 考法提示**：**最高频的"该不该微调"题面**。题干模板固定为「要求固定结构输出 + **已在提示词中反复约束后仍跑偏**」→ 选微调。若题干改成「刚提出格式要求 / 只有几条样例」→ 选**先优化提示词（少样本示例）**。干扰项必定有一个 **RAG**（把格式问题包装成知识问题）和一个 **换更大模型**（把稳定性问题包装成能力问题）。

**⑦ 记忆锚点**：**「要程序读 → 要稳定 → 微调」**；提示词是"每次提醒带模板"，微调是"刻进肌肉记忆"。

### M5-K04　适用场景③：风格　🟢`[A]`

**① 一句话定义**：让输出的**语气、话术、文风**长期统一——品牌调性、专业口吻、人设一致性。

**② 是什么**：风格是"怎么说"最典型的形态，与"知道什么"完全无关。典型形态：客服永远用温和话术且不评价竞品、法务文书的严谨措辞、医疗问答的审慎表达、公文风与新媒体风二选一、品牌禁用词与必用语的长期遵守。风格问题有两个特征：一是**类别难以穷举**（"温和"有无数种说法，没法全写进规则）；二是**需要长期一致**（今天温和明天冷淡，用户能感知到）。这两点恰好是提示词的弱项、微调的强项——规则写不完，但样本可以示范；样本喂进去，语气就内化成了模型习惯。

**③ 为什么**：官方单独点名"风格"，是因为它是**最常见也最容易被误判的微调场景**：很多人第一反应是"语气不对就改提示词"，但提示词只能给出**原则性描述**（"请语气友好"），而"友好"的具体形态要靠大量示范才能稳定。微调通过成百上千条同风格样本，把抽象的"调性"变成具体的输出习惯。同时它也是最安全的微调场景之一：不涉及事实知识，不存在"知识过时"风险。

**④ 怎么做 / 怎么用**：
- 场景：某高端品牌的在线顾问，要求"专业、克制、不承诺、不评价竞品"，但模型时常用"绝对""最好""秒杀同行"这类禁用表达。
- 之前（提示词）：写了 20 条禁用词与语气要求 → 常规问法遵守；用户情绪激烈时模型开始"共情过头"，出现"别家确实不行"这类违规表达。
- 之后（微调）：用该品牌历史优质对话（统一润色过）作为样本微调 → 禁用表达基本消失，且**不再需要在提示词里塞那 20 条规则**，输入显著变短。
- 判断信号词：**「品牌调性」「话术规范」「语气」「人设」「统一口吻」「文风」**。

**⑤ 易错点**：
- ❌ 常见误解：风格不统一是内容质量问题，应该给模型更多产品资料（RAG）。
- ✅ 正确：风格是**行为**问题，资料再多语气照样漂 → **稳行为才考虑微调**。
- ❌ 常见误解：微调了风格，答案的事实准确性也会同步提升。
- ✅ 正确：不会。微调调的是**表达方式**，事实准确要靠 **RAG 补知识**；两者常常**组合使用**（RAG 补知识 + 微调定风格）。

**⑥ 考法提示**：常与 K03（格式）**捆绑出多选或单选**，题干同时提"固定 JSON + 统一话术"，两个诉求落在同一答案（微调）上。干扰项会塞一个"接知识库"进来，让人误以为"话术规范"是一份文档、所以要检索。**记住：话术是行为，不是资料。**

**⑦ 记忆锚点**：**风格 = 说话的"味道"**；资料给"料"，微调给"味"。

### M5-K05　适用场景④：分类能力　🟢`[A]` 🆕

**① 一句话定义**：让模型**稳定地把输入归入预先定义好的类别集合**——意图分类、工单分类、情感分类、标签打标。

**② 是什么**：分类任务的三个特征：**类别既定**（咨询 / 投诉 / 售后 / 建议……数量有限、边界明确）、**不需要外部知识**（规则就在任务里，不必查资料）、**输出空间极小**（就那几个标签）。这三点让分类成为**微调性价比最高的场景之一**。相比提示词方案（要在输入里塞一长串类别定义 + 每类若干示例），微调后模型能**直接输出类别标签**，带来三个优势：**更稳定**（边界样本不再摇摆，换个说法不会被分到别的类）、**更快**（输入变短，推理更快）、**更省 Token**（不必每次携带大段说明与示例，调用成本更低）。官方把「分类能力」与格式、风格并列，说明它属于"稳行为"家族：模型**知道**有哪些类别，问题在于**判得稳不稳**。

**③ 为什么**：分类失败的表现很典型——"同一个意思换个说法就被分到不同的类"。这不是知识缺失，而是**决策边界不稳定**。提示词能改善，但当类别较多、边界模糊、表述多样时，提示词里的示例永远覆盖不全；微调则能从大量标注样本中学到稳定的边界。同时，分类往往部署在高并发链路上（每条来单都要过一遍），**省 Token + 低延迟**的收益会被放大，这正是它与第 ⑤ 项"支持轻量模型部署"天然搭配的原因。

**④ 怎么做 / 怎么用**：
- 场景：客服系统把用户来单自动分派到 5 个既定处理类别（咨询 / 投诉 / 售后 / 建议 / 其他），类别体系长期不变。
- 之前（提示词 + 少量示例）：整体准确率 85%；"你们这物流也太慢了吧，我要退款"这类**兼有多种意图**的边界样本摇摆不定，同一句话换个说法就换类别；且每次请求都要带上 5 个类别的定义与示例，延迟偏高。
- 之后（微调）：用按目标类别标注好的真实来单样本微调 → 边界样本判定稳定，准确率提升；模型直接输出标签，**输入变短、响应更快、成本更低**。
- 前置条件：**必须先试提示词**（类别定义 + 少量示例），若准确率仍不稳定才考虑微调。
- ⚠️ 例外：**类别体系频繁增减**（每月都要加新类别）→ **先别微调**，退回提示词，把类别列表放进输入即可随时调整。

**⑤ 易错点**：
- ❌ 常见误解：分类不准是因为模型不知道分类规则，应该把规则文档接进知识库检索出来再判（RAG）。
- ✅ 正确：类别**既定**、规则在模型可理解范围内，**不缺知识** → 不触发「查知识用 RAG」。检索规则文档只会让输入变长，**解决不了判定边界不稳定**这个行为问题。
- ❌ 常见误解：分类只需要"分对"，用工具做关键词硬匹配更稳，比微调好。
- ✅ 正确：关键词硬匹配**抽掉了语义理解**，处理不了同义表达与隐含意图，恰恰在边界样本上失效。**工具 / 工具调用**的用武之地是实时数据与执行业务动作，不是替模型做语义判断。

**⑥ 考法提示**：**官方本轮明确点名的新增场景，极易出原题。** 题干模板：「自动归类 / 打标签 / 路由到不同部门 / 判定属于哪一类 + 类别既定长期不变 + 提示词试过仍不稳（+ 希望降低延迟）」→ 选**微调（分类能力）**。
⚠️ **反向陷阱**：若题干强调「类别**每月都在变**」「要依据**最新的分类规则文档**」→ 那变成**知识 / 规则更新**问题，答案转向 **RAG**。

**⑦ 记忆锚点**：**分类三特征：类别既定、无需外知、输出极小** → 微调最划算。**「分类要稳，微调来定。」**

### M5-K06　适用场景⑤：支持轻量模型部署　🟢`[A]` 🆕

**① 一句话定义**：把某个**专项能力**从大模型迁移到**参数量更小的模型**上，用"小而专"替代"大而全"，从而**降低推理成本与响应延迟**。

**② 是什么**：很多线上场景其实只做一件事——意图分类、格式抽取、固定话术回复。用通用大模型来做，属于"杀鸡用牛刀"：每次推理都要为大模型的全部参数买单，成本高、延迟大，高并发下账单和响应时间都扛不住。做法是：先用大模型在该专项任务上产出高质量输出作为样本，再用这些样本去微调一个小模型，让小模型在这个**单一专项**上接近大模型的表现，然后部署这个小模型。收益是**推理成本更低、响应更快、便于部署在资源受限的环境**（边缘设备、高并发链路、成本敏感业务）。

**③ 为什么**：官方把这一项列入"微调适合什么"，揭示了微调一个容易被忽视的价值——**它不只是提升效果，也可以是降本提速的手段**。这一点与"补知识"完全无关，再次印证微调的定位是"改行为"：小模型不需要变得"懂得更多"，只需要在这个专项上**做得更稳**。这也解释了为什么它常与第 ④ 项"分类能力"组合出现：分类任务简单、高频、对通用能力要求低，是最适合下放到小模型的场景。

**④ 怎么做 / 怎么用**：
- 场景：某 App 的日活用户量很大，每条用户消息都要先做意图分类再路由，用通用大模型日均推理成本过高、P95 延迟也不达标。
- 之前：全量用大模型做分类 → 成本高、延迟高。
- 之后：用大模型标注 / 产出的一批高质量分类样本，微调一个**小模型**专门做分类 → 该专项上表现接近大模型，**推理成本与延迟显著下降**，高并发扛得住。
- 边界：这个小模型**只在分类这个专项上好用**，让它去回答开放式问题就明显不如大模型。若它同时还需要回答最新资料，**仍要给它接知识库（RAG）**。
- 判断信号词：**「推理成本太高」「响应太慢」「想用更小的模型」「高并发成本扛不住」「部署到资源受限环境」**。

**⑤ 易错点**：
- ❌ 常见误解：用小模型替代大模型，可以完成开放式问答、全领域知识问答，反正微调一下就行。
- ✅ 正确：轻量模型**通用能力有限**，只在被微调的那个**专项**上表现好；全领域问答它会明显退化。微调降的是**成本与延迟**，不是"把小模型变成大模型"。
- ❌ 常见误解：轻量部署后，模型需要的最新知识也能一并解决，不用接 RAG。
- ✅ 正确：**轻量部署解决"跑得动、跑得起"，不解决"知道最新的事"**；需要最新资料仍要 **RAG** 补知识。

**⑥ 考法提示**：多选题的**必考正确项**之一（"希望用一个更小、更轻的模型承担这项固定任务，以降低推理开销与响应延迟"）。干扰项陷阱是把轻量部署**泛化**为"用小模型全面替代大模型"——见到"全面 / 全领域 / 开放式"就判错。

**⑦ 记忆锚点**：**「大模型教，小模型干。」** 降本提速靠轻量部署，补最新知识还得靠 RAG。

### M5-K07　微调五步流程（官方）　🟢`[A]` 🔧

**① 一句话定义**：官方给出的微调基本流程是**五步**——**定义目标 → 准备样本 → 选择基模 → 控制数据质量 → 评估效果**。

**② 是什么**：这是官方原文逐字点名的流程，也是本模块**唯一会考的流程版本**。五步依次为：① **定义目标**（明确要把什么行为稳定下来，以及什么叫做好了）；② **准备样本**（整理「输入 → 期望输出」成对样本）；③ **选择基模**（挑一个预训练好的模型作为起点，微调不是从零训练）；④ **控制数据质量**（清洗、统一标注口径、划分独立的评测集）；⑤ **评估效果**（在未参与训练的评测集上对照目标验收，并与基座对比）。注意官方五步中**没有**单独的"配置训练参数""执行训练""上线部署"环节——因为官方明示不考模型训练细节。

**③ 为什么**：官方把「控制数据质量」从「准备样本」中**单独拆出来**列为一个独立步骤，这是一个强烈的信号：**数据质量是微调成败的关键变量，不是可省略的附属环节**。同样，把「定义目标」放在第一步，是因为微调最大的浪费来自"目标没想清楚就动手"——目标错了，样本再多也是白做。把「评估效果」放在最后并独立成步，是因为"有没有效果"必须靠独立评测来回答，而不是靠训练过程的感觉。

**④ 怎么做 / 怎么用**：
- 场景：客服机器人"语气时冷时热"，负责人当场拍板"马上导出历史对话开始微调"。
- 正确路径：
  1. **定义目标**：把"统一语气"具体化为可验收标准——"任意抽样 100 条，语气合规率 ≥ 95%，且禁用表达出现次数为 0"。
  2. **准备样本**：导出历史对话后**不是直接用**，而是筛选 + 改写为符合目标语气的「输入 → 期望输出」对。
  3. **选择基模**：确认现有基座的通用能力是否达标（基座是天花板）；若同时要降本，考虑更小的模型。
  4. **控制数据质量**：统一标注口径（"温和"的标准全队一致）、剔除语气混杂的样本、划出一份**不参与训练**的评测集。
  5. **评估效果**：在独立评测集上算合规率，与基座对比，同时检查通用能力有没有退化。
- 若效果不达标 → **回到 ① 或 ② 迭代**，而不是盲目加大数据量。

**⑤ 易错点**：
- ❌ 常见误解：本库旧版的"六步流程"（数据准备→选基座→配超参→训练→评测→部署）是对的。
- ✅ 正确：**旧版六步已作废**，一律以**官方五步**为准（官方五步无"配超参 / 训练 / 部署"）。
- ❌ 常见误解：数据越多越好，把所有历史数据都用上，用同一批数据评估就行。
- ✅ 正确：**质量 > 数量**；评测必须用**未参与训练**的独立数据，否则分数虚高（等于让学生考做过的卷子）。

**⑥ 考法提示**：**流程题只考"名称与顺序"**。四种固定挖坑方式：
① 把"评估效果"放到"准备样本"之前 → 错（评估是第 ⑤ 步、最后一步）；
② "用全部数据训练，再用同一批数据评估" → 错（必须用未参与训练的数据）；
③ "先考虑微调，提示词以后再说" → 错（官方手段序列里优化输入排在微调之前）；
④ 把"选择基模"说成"从零训练一个模型" → 错（微调的前提是已有预训练模型）。

**⑦ 记忆锚点**：**「目、样、基、质、评」** 五字口诀 —— 目标、样本、基模、质量、评估。

### M5-K08　官方选型口诀　🟢`[A]` ⭐⭐

**① 一句话定义**：官方给出的选型口诀——**「查知识用 RAG，做动作靠工具，稳行为才考虑微调。」**

**② 是什么**：这是本模块**最高频、最值钱**的一句原文，也是全部场景判断题的**唯一答案池**。三个分支：
- **查知识** → **RAG**：模型不知道答案需要的信息（企业资料、产品手册、内部制度、政策条款、最新事件）。
- **做动作** → **工具 / 工具调用**：需要实时数据（今天天气、汇率、库存）、确定性计算（算金额、算日期）、执行业务动作（下单、退款、建工单、发邮件）。
- **稳行为** → **微调**（且是"才考虑"）：官方五项——稳定行为、格式、风格、分类能力、支持轻量模型部署。
一个"**才**"字分量极重：它说明微调是**后置选项**，排在优化输入、接入知识库、调用工具之后。

**③ 为什么**：这句口诀把"微调不是万能按钮"落成了可操作的判断规则。三条分支的分水岭是**问题类型**：**"不知道"**（缺知识）走 RAG，**"做不到"**（缺动作能力）走工具，**"说不好"**（行为不稳）走微调。之所以如此划分：知识会变且要溯源 → 微调进去会过时且不可追溯；动作需要外部系统与确定性 → 模型改权重也拿不到实时数据；只有行为，才是模型"自己身上"的事，才适合用改权重的方式解决。

**④ 怎么做 / 怎么用**：做题时默念**判定三连问**——
1. 是"查知识"吗？（模型不知道 / 要最新 / 要可追溯）→ **RAG**
2. 是"做动作"吗？（实时数据 / 确定性计算 / 业务动作）→ **工具 / 工具调用**（多步编排 → **Agent**）
3. 是"稳行为"吗？（格式 / 风格 / 分类 / 轻量部署 / 整体稳定）→ **还没试过提示词 → 先优化提示词**；**提示词反复优化后仍不达标 → 微调**
- **做题信号词速查**：看到「资料 / 手册 / 制度 / 政策 / 文档 / 上周刚更新 / 必须标出处」→ RAG；看到「实时 / 今天 / 查询余额 / 自动生成工单 / 调用外部系统」→ 工具；看到「格式 / 风格 / 语气 / 分类 / 想用小模型」**且提示词已试过仍不行** → 微调。

**⑤ 易错点**：
- ❌ 常见误解：回答不够好就微调；效果不好立刻启动微调。
- ✅ 正确：缺了前提。**先优化提示词**，再判断是不是"稳行为"问题，最后才考虑微调。"一上来就微调"这个**顺序本身**就是错的。
- ❌ 常见误解：用了 RAG 就不需要微调 / 微调了就不需要 RAG。
- ✅ 正确：**两者不互斥**——**RAG 负责"答什么"，微调负责"怎么答"**，典型组合是"RAG 补知识 + 微调定风格"。

**⑥ 考法提示**：**本模块 6 题里至少 3 题由它直接决定答案。** 三个分支各有固定干扰项：查知识分支的干扰项是"微调"（把补知识当成微调用途，本模块第一大坑）；做动作分支的干扰项是"微调 / RAG"；稳行为分支的干扰项是"接知识库"和"换更大的模型"。

**⑦ 记忆锚点**：**「查知识 → RAG；做动作 → 工具；稳行为 → 才考虑微调。」** 三个词对三个词，一字不差背下来。

### M5-K09　与 RAG 的边界及组合　🟢`[A]` ⭐⭐

**① 一句话定义**：**RAG 补知识（改"喂什么"），微调定行为（改"怎么说"）**——两者不互斥，可叠加。

**② 是什么**：两者的硬判据是**「有没有改模型权重」**：RAG 在推理时把检索到的资料放进上下文，**一个参数都不改**；微调更新模型参数，**知识/行为被写进权重**。由此衍生出四项关键差异：
- **可更新**：RAG 改文档即刻生效；微调必须重新训练。
- **可追溯**：RAG 能附上"这条出自哪份文档"；微调融进参数后**无法指出来源**。
- **时效性**：RAG 能回答最新信息；微调训练完即冻结。
- **作用对象**：RAG 解决"答什么"，微调解决"怎么答"。
因为作用对象不同，**两者完全可以组合**：用 RAG 拿到最新、可追溯的资料，再让微调过的模型用固定话术和固定 schema 输出。

**③ 为什么**：这是官方「建议掌握的知识」中点名的"**与提示词、RAG 的选型边界**"，也是本模块**最大的失分点**所在——最常见的错误就是把"补知识"当成微调的用途。理解边界的关键在于认清：**微调改变的是行为，而知识是"会变且要溯源"的东西**，恰恰是权重最不擅长的载体。医疗、金融、法务这类**强溯源**场景必须 RAG，正是因为微调做不到"指出出处"。

**④ 怎么做 / 怎么用**：
- 场景 A（纯知识）：公司上周更新了报价单，希望模型准确回答报价 → **RAG**（会变、要核对 → 微调进去很快过期且说不出出处）。
- 场景 B（纯行为）：模型知道怎么答，但 JSON 时而是对象时而是数组 → **微调**。
- 场景 C（组合）：客服既要回答**最新产品条款**，又要**统一话术与固定格式** → **RAG + 微调**：RAG 检索最新条款（答什么），微调过的模型用统一话术 + 固定 JSON 输出（怎么答）。
- 判断链：先问"缺的是知识还是稳定"，缺知识 → RAG；缺稳定 → 微调；两者都缺 → **都要**。

**⑤ 易错点**：
- ❌ 常见误解：把公司资料 / 制度 / 手册微调进模型，模型就记住了，还省去检索、回答更快。
- ✅ 正确：**知识会过时 + 不可追溯**两大硬伤 → **查知识用 RAG**。"更快"不是选型的首要依据。
- ❌ 常见误解：微调后只要替换知识库文档，模型就能同步掌握最新知识。
- ✅ 正确：那是 RAG 的特性。微调后的模型要同步新知识，**必须重新训练**。

**⑥ 考法提示**：几乎**必考**。典型题干：给出"每年更新 + 必须标注出处"的场景，问"把规范微调进模型"这个提议对不对 → **不赞同，应优先 RAG**。干扰项会设一个"改用 Agent 编排工具"（答非所问）和一个"增加训练数据量即可解决更新问题"（方向错了，加大剂量也无效）。

**⑦ 记忆锚点**：**「RAG 提供『料』，微调提供『味』。」** —— 换料找 RAG，换味找微调。

### M5-K10　与提示词的先后边界　🟢`[A]`

**① 一句话定义**：**先优化提示词，后考虑微调**——在官方的手段序列里，「优化输入」排在「使用微调」之前，**微调不是第一选择**。

**② 是什么**：官方列出的可选手段顺序是：**优化输入（提示词） → 接入知识库（RAG） → 调用工具 → 使用微调 → 协作 Agent（或保留人工确认）**。这个顺序不是随意排列的，它体现的是**成本与改动代价递增**：改几句话最便宜、改几篇文档次之、接接口再次、改模型权重最重、搭 Agent 最复杂。因此判断"该不该微调"时，**前置条件是低成本手段已经试过且仍不达标**。提示词能做的事（写清目标 / 背景 / 角色 / 约束 / 示例 / 输出格式 / 评价标准，加少样本示例）应**先做**；只有提示词反复优化后仍不稳定，才轮到微调。

**③ 为什么**：微调的代价是**重且难改**——每次调整都要重走"准备样本 → 控制质量 → 评估"的完整循环。如果提示词加几个示例就能解决，走微调就是明显的过度投入。官方在 M5 开头就写"**微调不是万能按钮**"，在口诀里又用一个"**才**"字（"稳行为**才**考虑微调"），两处都在强调这个先后关系。

**④ 怎么做 / 怎么用**：
- 场景：要求模型输出固定 JSON。
- 第一步（**必须**）：在提示词里写清 schema、给 2-3 个示例、明确"只输出 JSON、不要解释" → 观察一段时间，统计合规率。
- 若合规率达标 → **到此为止，不要微调**。
- 若反复优化后仍跑偏（尤其长尾输入）→ 才进入微调，走官方五步。
- 另一个典型：只有 **5 条**样本就想让模型学会新格式 → **提示词加少样本示例**，样本量太少微调不成立。

**⑤ 易错点**：
- ❌ 常见误解：微调比提示词高级，效果好就直接上微调。
- ✅ 正确：**先提示词，后微调**。题干若说"刚提出要求、还没试过"→ 答案是**优化提示词**；只有"反复优化后仍不达标"才选微调。
- ❌ 常见误解：用了微调就不需要提示词了。
- ✅ 正确：微调后仍需要把任务要求讲清楚（目标、背景、约束），两者是**互补**而非替代。

**⑥ 考法提示**：作为**隐藏前置条件**渗透在场景题中。题干里"**已在提示词中反复约束后仍跑偏**"这句话，就是官方在告诉你"前置条件已满足，可以选微调了"。反之，题干若**没有**这句话（或明说"刚提出""还没试过"），答案就是**先优化提示词**。

**⑦ 记忆锚点**：**「先看有没有试过提示词。」** 手段顺序：输 → 库 → 具 → 调 → 体（优化输入 / 知识库 / 工具 / 微调 / Agent）。

### M5-K11　微调的局限　🟡`[B]`

**① 一句话定义**：**微调不是万能按钮**——它不改变模型"知道什么"，也拿不到实时数据、执行不了动作，且有会过时、不可追溯、迭代不灵活、可能灾难性遗忘四大局限。

**② 是什么**：官方"微调不是万能按钮"的直接含义，展开为六条：
① **知识会过时**：训练结束那一刻知识就被冻结，新政策、新价格、新事件一概不知，要跟上只能重新训练；
② **不可追溯**：知识融进海量参数，无法指出答案来自哪份文档哪一条；
③ **迭代不灵活**：每次调整都要重走完整流程，不像改文档那样即刻生效；
④ **灾难性遗忘**：过度训练可能损害原有通用能力，典型表现是"专科变强了，常识变差了"；
⑤ **高度依赖样本质量**：口径不一致或充满噪声的样本会把行为教歪；
⑥ **不解决时效与实时**：模型没有外部数据源也没有执行能力，实时数据与业务动作要靠**工具调用**。

**③ 为什么**：这些局限不是"微调做得不够好"，而是**由"改权重"这一机制决定的结构性代价**。知识写进参数 = 不可单独更新、不可单独查看；行为写进参数 = 改起来要重训。正因如此，官方才把它排在手段序列的**后位**，并用"才考虑"三个字限定。理解局限，才能真正理解"什么时候**不该**微调"——而这恰恰是本模块出题最密集的地方。

**④ 怎么做 / 怎么用**：
- 场景：把公司制度微调进模型 → 半年后制度改了，模型还在用旧制度回答，且说不出依据 → **应改用 RAG**。
- 场景：微调后的模型在客服话术上很稳，但让它顺便写个周报就明显变差 → **灾难性遗忘**的典型表现 → 应控制训练强度、保留通用能力样本、并在评测中加入通用能力检查项。
- 场景：医疗问答要求每条结论标出处 → 微调**做不到** → 必须 RAG。

**⑤ 易错点**：
- ❌ 常见误解：微调可以完全解决幻觉。
- ✅ 正确：微调只能**降低**特定场景下的幻觉（行为更可控），**不能消除**；幻觉的根治靠 RAG 提供可靠依据。
- ❌ 常见误解：微调的局限主要在于"训练成本高"，降低成本就没问题了。
- ✅ 正确：官方**不考成本**；真正的结构性局限是**会过时、不可追溯、迭代不灵活、可能遗忘**。

**⑥ 考法提示**：**多选题的高频题面**（"关于微调的局限性，下列说法正确的有"）。四个正确项通常就是：会过时、不可追溯、迭代不灵活、灾难性遗忘。**必设干扰项**："微调完成后只需替换知识库文档即可同步最新知识"——这是把 **RAG 的特性安到了微调头上**（概念串台），是本模块最高频的失分点之一。

**⑦ 记忆锚点**：**微调三宗罪：会过时、查不到、改不动。** 相对地：**RAG 三优势：可更新、可追溯、改完即生效。**

### M5-K12　数据要求：质量 > 数量　🟡`[B]`

**① 一句话定义**：微调样本**质量 > 数量**——一致性、正确性优先于堆量；标注口径必须统一，且必须留出**独立的评测集**。

**② 是什么**：对应官方五步中的第 ④ 步「**控制数据质量**」，它包含三件事：**清洗**（去重、剔除错误与互相矛盾的样本、统一格式）、**规范标注口径**（同一类问题的期望输出必须写法一致）、**划分训练集与独立评测集**（评测集先划出来，且不参与训练）。官方把这一步从"准备样本"中单独拆出来列为独立步骤，说明**数据质量是决定微调成败的关键变量**，不是附属环节。

**③ 为什么**：微调的目的是让模型学到**稳定**的行为。如果样本本身口径不一致（同一类问题两种写法）、混着旧格式、夹杂噪声，模型学到的恰恰是"**不稳定**"——等于把要治的病又教了一遍。这就是为什么"垃圾进，垃圾出"在微调上比在别的环节更致命：**教材印错了，习惯就养歪了**。反之，规模不大但高度一致、准确的样本，往往比大批含噪数据效果好得多。

**④ 怎么做 / 怎么用**：
- 场景：整理客服样本时，A 同事写的期望输出是"您好，非常抱歉给您带来不便……"，B 同事写的是"抱歉，我们尽快处理"——两种都算"温和"，但模型学完就会在两种风格间摇摆。
- 正确做法：**先定标注规范**（确定唯一的话术模板与字段写法）→ 全队按同一标准整理 → 交叉抽检一致性 → 划出 20% 作为评测集**锁起来不参与训练** → 训练后只在评测集上评估。
- 常见坑对照：❌ 直接把原始聊天记录 / 日志丢进去不做整理；❌ 只挑容易的样本，遇到真实长尾就崩；❌ 用训练集自评（分数虚高）。

**⑤ 易错点**：
- ❌ 常见误解：微调数据里有少量噪声没关系，多堆一些数据就行。
- ✅ 正确：**质量 > 数量**，噪声会把行为教歪，堆量救不回来。
- ❌ 常见误解：数据全部用来训练效果最好，评测可以拿训练数据看。
- ✅ 正确：评测必须用**未参与训练**的独立数据，否则等于让学生考做过的卷子，分数虚高。

**⑥ 考法提示**：主要渗透在流程题（M5-K07）的解析与干扰项中，也常作为多选题的**正确项**出现（"样本质量比数量更重要，标注口径必须一致"）。干扰项固定为"多堆一些数据就行"。

**⑦ 记忆锚点**：**「教材印错了，习惯就养歪了。」** 质量 > 数量；口径一致 > 数量堆砌。

### M5-K13　微调评测方法　🟡`[B]`

**① 一句话定义**：在**未参与训练**的评测集上，对照第 ① 步定义的目标验收，**并与基座模型对比**，同时检查通用能力是否退化。

**② 是什么**：对应官方五步中的第 ⑤ 步「**评估效果**」，包含四个动作：
① 用**独立评测集**（未参与训练）评估；
② 评测指标与第 ① 步的目标口径一致（格式合规率 / 分类准确率 / 风格一致性……）；
③ **与基座模型对比**——确认"真的更好了"，而不是"感觉更好了"；
④ **检查通用能力是否退化**（灾难性遗忘）。
必要时补充**人工评审**（风格、话术这类难以自动量化的维度）。上线后还需**持续监控**，因为效果会随业务分布变化而衰减。

**③ 为什么**：没有评测，微调就无法回答"到底有没有用"。而"有没有用"只能由**目标**定义——所以第 ① 步"定义目标"里必须包含可衡量的验收标准，否则第 ⑤ 步无从判成败。与基座对比是必需的：很多时候"微调后的绝对分数"看着不错，但基座本来就做得不差，微调带来的增益其实很小，这时就不值得为此承担微调的重资产与迭代成本。

**④ 怎么做 / 怎么用**：
- 场景：目标是"统一客服语气"，验收标准定为"抽样 100 条，语气合规率 ≥ 95%，禁用表达 0 次"。
- 评测：在**锁定的独立评测集**上跑 → 微调模型 96%，基座模型 71% → 有显著增益，**通过**。
- 再检查通用能力：让它做 20 条通用问答与 20 条其他任务的抽取 → 若明显变差，说明训练过度，需回到第 ② 步调整样本配比。
- 上线后：每周抽样复评，发现衰减及时迭代（回到 ① 或 ②）。
- 常见坑：❌ 只看训练过程的指标下降；❌ 用训练过的数据自评；❌ 上线后不监控。

**⑤ 易错点**：
- ❌ 常见误解：训练过程的损失降下来、拟合得很好，就说明微调成功了。
- ✅ 正确：训练指标不等于**业务效果**；必须在独立评测集上对照目标验收。
- ❌ 常见误解：评测只需要看目标任务的表现。
- ✅ 正确：还要**与基座对比**（确认增益真实）并**检查通用能力是否退化**（灾难性遗忘）。

**⑥ 考法提示**：渗透在流程题（Q004）与局限题（Q006）的解析中。可能的**正确项**表述："评测应当使用未参与训练的独立数据，并与基座模型对比"。干扰项："用全部数据训练后再用同一批数据评估""只要训练指标下降就算成功"。

**⑦ 记忆锚点**：**「独立数据 + 对目标 + 比基座 + 查退化」** 四件事，缺一不可。

## 四、【专章 ⭐⭐】微调适合什么（官方五项）

> **官方原文（背下来）：**
> **「掌握微调适合什么：稳定行为、格式、风格、分类能力，或支持轻量模型部署。」**
>
> 这五项是本模块**唯一**被官方点名的适用场景。考场上凡是超出这五项的"微调能干什么"，基本都是干扰项。

```
            微调适合什么？（官方五项，逐个背）
    ┌─────────┬─────────┬─────────┬─────────────┬──────────────┐
    │ ①稳定行为 │ ②格式   │ ③风格    │ ④分类能力     │ ⑤轻量模型部署  │
    │ 行为不漂移 │ 结构不变 │ 语气一致  │ 归到既定类别   │ 专项能力下放    │
    └─────────┴─────────┴─────────┴─────────────┴──────────────┘
         └────────────── 共同本质：改的是「怎么说」，不是「知道什么」─────────────┘
```

### 4.1 ① 稳定行为 ⭐

**是什么**：让模型在某个任务上的**整体行为长期稳定下来**——同样的输入类型，输出反应一致，不随问法、不随上下文漂移。

| 维度 | 说明 |
|---|---|
| 典型表现 | 一律按既定步骤应答；该拒答的边界稳定不摇摆；对同一类询问给出同质的处理动作 |
| 与其他四项的关系 | **「稳定行为」是总纲，格式 / 风格 / 分类是它的三种具体表现**——官方并列列出，说明既可以考总纲也可以考分支 |
| 为什么提示词做不到 | 提示词是**每次输入的外部要求**，长尾问法下会偶发失效；微调是把行为**写进权重**，成为模型本身的习惯 |
| **适用场景举隅** | 政务热线对同类诉求的响应路径统一；风控助手对高危提问的拒答边界稳定；多轮对话中不因上下文变化而摇摆 |
| **不适用场景** | "答得不对"（缺知识 → RAG）;"要查实时数据 / 要执行动作"（→ 工具）;"只是指令没说清楚"（→ 提示词） |
| **与其他手段对比** | 提示词：能改善但难根治长尾漂移；RAG：完全无解（换资料不换说话方式）；工具：解决的是"做动作"，与稳定性无关 |

> **一句话：提示词是"每次提醒"，微调是"养成习惯"。**
> 判断信号词：**「换个说法就变」「时好时坏」「不稳定」「忽高忽低」**。

### 4.2 ② 格式

**是什么**：要求模型**每次都按同一个结构输出**，并且这个要求长期不变。

| 维度 | 说明 |
|---|---|
| 典型表现 | 永远输出符合约定结构的 JSON；病历按「主诉 - 现病史 - 诊断 - 处置」四段输出；工单必须含「问题类型 / 紧急度 / 责任部门」三个字段 |
| 为什么选微调 | 提示词能约束格式，但在**长尾输入**下会偶发跑偏；微调把格式内化，稳定性质变 |
| **适用场景举隅** | 下游系统要**自动解析**的结构化输出；报表字段固定；抽取结果的枚举值固定 |
| **不适用场景** | 格式要求每月都变（→ 把格式模板放进提示词 / 输入即可，别微调）；刚提出格式要求还没试过（→ 先优化提示词） |
| **与其他手段对比** | 提示词：首选、成本最低，但长尾会跑偏；RAG：解决"字段值从哪来"，不解决"结构稳不稳"；工具：可做后处理校验，但那是补救不是根治 |

| 判断信号词 | 「字段固定」「必须能被程序解析」「下游系统要自动读取」「结构化输出」 |
|---|---|

> ⚠️ **前置条件**：题干若说「已在提示词中写明格式并附示例，反复优化后**仍**跑偏」→ 标准答案是**微调**。
> 题干若说「刚提出格式要求，还没试过」→ 正确答案是**先优化提示词**。

### 4.3 ③ 风格

**是什么**：让输出的**语气、话术、文风**长期统一。

| 维度 | 说明 |
|---|---|
| 典型表现 | 客服永远用温和话术且不评价竞品；法务文书的严谨措辞；公文风 / 新媒体风二选一；品牌禁用词长期遵守 |
| 为什么选微调 | 风格是"怎么说"的典型形态，属于行为范畴，与知识无关；且"调性"难以用规则穷举，只能靠大量示范内化 |
| **适用场景举隅** | 品牌统一话术；专业角色口吻（医生 / 律师 / 教师）；对外发布内容的文风一致 |
| **不适用场景** | 一次性的文风要求（→ 提示词里描述即可）；要引用最新资料（→ RAG）；文风规范本身每月变（→ 放进提示词） |
| **与其他手段对比** | 提示词：能给出原则（"请语气友好"），但抽象调性难稳定；RAG：补资料不补语气；工具：无关 |

| 判断信号词 | 「品牌调性」「话术规范」「语气」「人设」「统一口吻」「文风」 |
|---|---|

### 4.4 ④ 分类能力 ⭐（本轮补齐，重点看）

**是什么**：让模型**稳定地把输入归入既定的类别集合**——类别是预先定义好、数量有限、边界明确的。

| 维度 | 说明 |
|---|---|
| 典型场景 | **意图分类**（咨询 / 投诉 / 售后 / 闲聊）、**工单分类**（归属部门与紧急程度）、**情感分类**（正面 / 中性 / 负面）、**标签打标**（内容属于哪几个既定标签） |
| 三个特征 | ① 类别**既定**，不需要外部知识；② 输出空间**很小**，行为极易被稳定和规范化；③ 一旦训好，模型能**直接输出类别标签**，不必在提示词里塞一长串类别说明和示例 |
| **相对提示词的三个优势** | **更稳定**（边界 case 不再摇摆）、**更快**（提示词不必每次携带大量示例）、**更省 Token**（少传说明，调用成本更低，响应也更快） |
| **适用场景举隅** | 来单自动分派 / 路由到不同部门；评论情感判定；内容打标签；风险等级判定 |
| **不适用场景** | **类别体系频繁增减**（→ 退回提示词，把类别列表放进输入）；要依据**最新分类规则文档**（→ RAG）；只有几条样例（→ 提示词少样本示例） |
| **与其他手段对比** | 提示词：首选，但类别多、边界模糊时覆盖不全；RAG：**类别既定不缺知识**，接了也不解决边界摇摆；工具：关键词硬匹配**抽掉语义理解**，恰在边界样本上失效 |
| 前置条件 | **必须先试提示词**：写清类别定义 + 少量示例，若准确率仍不稳定，再考虑微调 |

> 🔑 **考场信号词**：「自动归类」「打标签」「路由到不同部门」「判定属于哪一类」「分类准确率不稳定」→ 选**微调（分类能力）**。
> ⚠️ 但如果题干强调「类别每个月都在变」「要依据最新的分类规则文档」→ 那是**知识 / 规则更新**问题，转向 **RAG**。

### 4.5 ⑤ 支持轻量模型部署 ⭐（本轮补齐，重点看）

**是什么**：把一个专项能力从大模型**迁移到参数量更小的模型**上，让**小模型**在这个专项任务上也能有接近的表现，从而**降低推理成本与延迟**。

```
   大模型（通用能力强、推理成本高）
            │  用它在专项任务上的高质量输出作为样本
            ▼
   小模型（轻量、成本低、延迟小）  ←── 微调，把专项能力迁移过来
            │
            ▼
   部署到资源受限 / 高并发 / 成本敏感的场景
```

| 维度 | 说明 |
|---|---|
| **为什么值得做** | 大模型"杀鸡用牛刀"：一个只做意图分类的场景，用通用大模型既贵又慢；小模型在该专项上微调后，性价比显著更好 |
| **降的是什么** | **推理成本**与**响应延迟**（小模型每次推理更省更快），也便于部署在资源受限的环境 |
| **适用场景举隅** | 高并发的意图分类链路；边缘 / 端侧部署；成本敏感的高频固定任务；对延迟有硬指标的接口 |
| **不适用场景** | 开放式问答、全领域知识问答（小模型通用能力有限）；任务尚未稳定、还在频繁变化（先别下放） |
| **代价 / 边界** | 小模型**只在被微调的那个专项上表现好**，专项之外的能力弱于大模型 |
| **与 RAG 的配合** | 若轻量模型同时还**需要准确回答最新资料**，它自己的知识不够，仍要给它**接知识库（RAG）**。**轻量部署解决的是"跑得动、跑得起"，不解决"知道最新的事"** |
| **与其他手段对比** | RAG：解决"知道什么"，不解决"跑得快慢"；提示词：不减小模型体积；工具：无关 |

| 判断信号词 | 「推理成本太高」「响应太慢」「想用小模型」「高并发下成本扛不住」「部署到资源受限环境」 |
|---|---|

> 🔑 **考场信号词**：「希望用一个**更小的模型**完成这个固定任务，降低推理成本与延迟」→ 选**微调（支持轻量模型部署）**。
> ⚠️ 陷阱：若选项写成「用小模型替代大模型去做**开放式问答 / 全领域知识问答**」→ 错，轻量模型扛不住通用任务。

### 4.6 ❌ 微调不适合什么（"不是万能按钮"的四种典型）

| 不该用微调的场景 | 原因（对应官方口诀） | 正确解法 |
|---|---|---|
| **缺私域知识**（公司制度、产品手册、政策） | 知识会改，一改就要重训；且融进权重后**无法溯源** | **RAG**（查知识用 RAG） |
| **要最新 / 时效信息**（新法规、今日价格） | 训练完即冻结，追不上变化 | **RAG** |
| **要实时数据或要执行业务动作**（查汇率库存、下单退款） | 模型本身没有实时数据源、也没有执行能力 | **工具 / 工具调用**（做动作靠工具） |
| **只是指令没说清楚、回答泛泛** | 零成本手段还没试过 | **优化提示词**（先做第一步） |

> **口诀：查知识用 RAG，做动作靠工具，稳行为才考虑微调。**（详见第六章）

### 4.7 一个对照记忆法

```
   ┌──────────────────────────────────────────┐
   │  同一份「答案内容」，两种改法：              │
   │                                          │
   │  改「答什么」  →  RAG（换喂进去的资料）      │
   │  改「怎么答」  →  微调（换模型的行为习惯）    │
   └──────────────────────────────────────────┘
```

> **一句话主线：微调改的是「怎么说」，不是「知道什么」。**
> **RAG 换资料，微调换习惯。**

## 五、【专章 ⭐⭐】微调五步流程（官方原文版）

> **官方原文（务必逐字背）：**
> **「理解微调的基本流程：定义目标、准备样本、选择基模、控制数据质量、评估效果。」**

```
   ① 定义目标 ──► ② 准备样本 ──► ③ 选择基模 ──► ④ 控制数据质量 ──► ⑤ 评估效果
        │                                                                │
        └────────────────── 效果不达标则回到 ① 或 ② 迭代 ───────────────┘
```

> 🔴 **重要修正（🔧）**：本库旧版写的是**六步**（数据准备→选基座→配超参→训练→评测→部署），**与官方不一致，已作废**。
> 请以**官方五步**为准。注意官方五步里**没有**单独的「配置超参数」「训练执行」「上线部署」——因为官方明示**不考模型训练细节**。
> ⛔ 顺序记忆口诀：**目、样、基、质、评。**

### ① 定义目标

| 项目 | 内容 |
|---|---|
| **做什么** | 明确「要把模型的**什么行为**稳定下来」，以及**什么叫做好了**（验收标准 / 评测口径） |
| **关键决策** | 目标是**行为问题**还是**知识问题**？目标是否**单一、明确、可定义**（固定格式 / 统一风格 / 分对类别）？提示词这条路是否已经试过？ |
| **常见坑** | ❌ 目标写成「让模型更聪明 / 懂我们的业务」——那是**知识问题**，该走 RAG；<br>❌ 只有模糊期望、没有可衡量的验收标准，导致第 ⑤ 步无法判成败；<br>❌ 还没试过提示词就直接立项微调（跳过官方手段序列的前几步） |
| **做不好会怎样** | 目标错了，后面四步做得再规范也是白做——最常见的浪费就是"目标没想清楚就动手导数据" |

### ② 准备样本

| 项目 | 内容 |
|---|---|
| **做什么** | 收集 / 整理成「**输入 → 期望输出**」的成对样本，让样本**代表目标行为**，并覆盖真实场景中的各类情况 |
| **关键决策** | 期望输出长什么样，样本就必须长什么样（要 JSON 就全给 JSON，要温和语气就全是温和语气）；覆盖面与获取成本怎么权衡 |
| **常见坑** | ❌ 样本里混着旧格式 / 不同语气的样例 → 模型学不到**稳定**行为；<br>❌ 直接把原始聊天记录 / 日志丢进去，不做整理；<br>❌ 只挑容易的样本，遇到真实长尾就崩 |
| **做不好会怎样** | 模型学到一个"平均"但摇摆的行为，甚至把历史数据里的坏习惯原样保留下来 |

### ③ 选择基模

| 项目 | 内容 |
|---|---|
| **做什么** | 挑一个**预训练好的模型**作为起点（微调**不是**从零训练） |
| **关键决策** | 基座的**通用能力是否已达标**（基座是天花板，微调只能在天花板下做改善）；是否贴合领域；**若为轻量部署，是否需要选择更小的模型** |
| **常见坑** | ❌ 基座本身不具备该能力，指望微调「从不会变会」——那是补知识，不是微调；<br>❌ 误以为「选择基模＝从头训练一个模型」；<br>❌ 规模选择与实际部署诉求不匹配（嘴上说要降本低延迟，却选了更大的模型） |
| **做不好会怎样** | 天花板压死上限：基座不具备的能力，微调也造不出来；或规模选错，降本目标落空 |

### ④ 控制数据质量

| 项目 | 内容 |
|---|---|
| **做什么** | **清洗**（去重、剔除错误与矛盾样本、统一格式）、**规范标注口径**、划分训练集与**独立的评测集** |
| **关键决策** | **质量 > 数量**：一致性与正确性优先于堆量；评测集必须**先划出来**，且不参与训练 |
| **常见坑** | ❌ 标注标准不一致（同一类问题两种写法）→ 正好毁掉微调的意义——学不到稳定行为；<br>❌ 噪声数据直接把行为「教歪」（垃圾进，垃圾出）；<br>❌ 用训练集自评 → 分数虚高 |
| **做不好会怎样** | 直接学歪：教材印错了，习惯就养歪了。这是微调失败最常见的技术原因 |

> ⭐ **注意官方把「控制数据质量」单独列为一步**，而不是并进「准备样本」。这说明**数据质量是一个独立且关键的环节**，很可能在选项中作为独立正确项出现。

### ⑤ 评估效果

| 项目 | 内容 |
|---|---|
| **做什么** | 在**未参与训练**的评测集上，对照第 ① 步的目标验收；与**基座模型对比**看是否真的更好；检查通用能力是否退化 |
| **关键决策** | 评测指标要与第 ① 步的目标口径一致（格式合规率、分类准确率、风格一致性……）；是否需要人工评审 |
| **常见坑** | ❌ 只看训练过程的指标下降，不看真实业务表现；<br>❌ 用训练过的数据自评（等于让学生考做过的卷子）；<br>❌ 上线后不持续监控，效果衰减发现不了 |
| **做不好会怎样** | 无法回答"到底有没有用"；增益很小却背上了微调的重资产与迭代成本 |

### 流程题的常见挖坑方式（记住这四条即可）

| 坑 | 正解 |
|---|---|
| 把「评估效果」放到「准备样本」之前 | 错，评估是第 ⑤ 步、最后一步 |
| 说「用全部数据训练，再用同一批数据评估」 | 错，评估必须用**未参与训练**的数据 |
| 说「先考虑微调，提示词以后再说」 | 错，官方手段序列里**优化输入排在微调之前** |
| 把「选择基模」说成「从零训练一个模型」 | 错，微调的前提是**已经有**预训练模型 |

## 六、【专章 ⭐⭐】官方选型口诀（本模块最高频考法）

> **官方原文（逐字背，一字不差）：**
> # 「查知识用 RAG，做动作靠工具，稳行为才考虑微调。」

```
                        业务需求来了
                             │
        ┌────────────────────┼────────────────────┐
        ▼                    ▼                    ▼
   模型「不知道」        要「做动作」          只是「说不好」
   缺知识 / 要最新      执行业务动作          行为不够稳定
        │                    │                    │
        ▼                    ▼                    ▼
      RAG                工具 / 工具调用     先优化提示词
  （可更新、可追溯）   （实时数据、确定性计算、 （仍不达标）
                          业务动作）              │
                                                 ▼
                                              微调 ✅
```

### 6.1 逐句拆解

#### 第一句：**「查知识用 RAG」**

| 要点 | 说明 |
|---|---|
| 适用场景 | 模型**不知道**答案需要的信息：企业资料、产品手册、内部制度、政策条款、最新事件 |
| 为什么不是微调 | 知识一旦微调进权重，**会过时**（变了要重训）+ **不可追溯**（说不出来自哪份文档） |
| RAG 的两个制胜点 | **可更新**：改文档即刻生效；**可追溯**：答案能附出处 |
| 高频陷阱 | 题干出现「资料」「手册」「制度」「文档」「政策」「报价单」「上周刚更新」→ **一律优先 RAG** |

#### 第二句：**「做动作靠工具」**

| 要点 | 说明 |
|---|---|
| 适用场景 | 需要**实时数据**（今天天气 / 汇率 / 库存）、**确定性计算**（算金额、算日期）、**执行业务动作**（下单、退款、建工单、发邮件） |
| 为什么不是微调 | 微调改的是模型的说话方式，**既拿不到实时数据，也没能力执行动作**；知识也不可能实时更新 |
| 复杂多步时 | 多个工具需要**编排与规划** → 交给 **Agent**（官方手段序列的下一站） |
| 高频陷阱 | 题干出现「实时」「今天」「查询余额」「自动生成工单」「调用外部系统」→ **工具 / 工具调用**（多步则 Agent） |

#### 第三句：**「稳行为才考虑微调」**

| 要点 | 说明 |
|---|---|
| 适用场景 | 官方五项：**稳定行为、格式、风格、分类能力、支持轻量模型部署** |
| 前置条件（易漏） | **先做低成本尝试**——优化提示词；少样本示例能解决的就别微调 |
| 「才」字的分量 | 一个"才"字说明微调是**后置选项**：排在优化输入、接入知识库、调用工具之后 |
| 高频陷阱 | 题干出现「效果不好，**立刻**启动微调」「回答不好就微调」→ 基本都是**错项** |

### 6.2 【必练】口诀驱动的 12 道场景判断题

> 用法：先自己给出答案，再看「✅ 正解」列。**本模块 6 题里至少 3 题是这个题型。**

| # | 场景 | ✅ 正解 | ❌ 常见误选 | 一句理由（依据官方口诀） |
|:---:|---|---|---|---|
| 1 | 客服问「咱们**上周刚改**的退货政策是什么」 | **RAG** | 微调 | 知识会变 + 要可核对 → **查知识用 RAG** |
| 2 | 要查**今天的外汇汇率**并写入报价单 | **工具调用** | 微调 / RAG | 实时外部数据 → **做动作靠工具** |
| 3 | 客服回答内容对，但**语气时冷时热**不符合品牌调性 | **微调**（风格） | RAG | 风格 = 行为问题 → **稳行为才考虑微调** |
| 4 | 要求**每次输出同一结构的 JSON**，提示词反复优化后仍跑偏 | **微调**（格式） | RAG / 换模型 | 格式稳定性 → 把格式内化进权重 |
| 5 | 想把用户来单**自动归到 8 个既定工单类别** | **微调**（分类能力） | RAG | 类别既定，无需外部知识 |
| 6 | 公司制度文档**每月更新**，答案要随文档同步 | **RAG** | 微调 | 高频更新 → 每月重训不现实 |
| 7 | 医疗问答要求**每条结论必须标注出处文档** | **RAG** | 微调 | 强溯源需求，微调不可追溯 |
| 8 | 要把**意图分类**能力迁到**小模型**，降低高并发下的成本与延迟 | **微调**（分类能力 + 轻量部署） | RAG | 专项能力下放，官方场景第 ④⑤ 项 |
| 9 | **售后退款**需要真的调用业务系统完成退款 | **工具调用**（多步则 Agent） | 微调 / RAG | 业务动作 → **做动作靠工具** |
| 10 | 回答**泛泛而谈、抓不住重点** | **先优化提示词** | 微调 / RAG | 成本最低，永远第一步 |
| 11 | 既要**最新产品条款**（已接 RAG），又要**统一客服话术** | **RAG + 微调组合** | 二选一 | 补知识 + 定行为，两者不互斥 |
| 12 | 只有 **5 条**样本想让模型学会新格式 | **提示词加少样本示例** | 微调 | 样本量太少，微调不成立 |

> 📌 **做题口诀**：先看题干有没有「最新 / 变了 / 出处」（→ RAG），再看有没有「实时 / 查询系统 / 执行动作」（→ 工具），剩下的「格式 / 风格 / 语气 / 分类 / 想用小模型」，**且提示词已试过仍不行**（→ 微调）。

## 七、【决策章】完整选型对照表（提示词 → RAG → 工具 → 微调 → Agent）

### 7.1 手段总成本递增顺序（官方手段序列）

```
  优化输入（提示词）  →  接入知识库（RAG）  →  调用工具  →  使用微调  →  协作 Agent
       最轻                  较轻                中            较重          最重
                                                        ⋯ 或 → 保留人工确认
```
> 官方手段序列本身就是**成本与改动代价递增**的顺序。判断"该不该微调"，本质是在问：**更便宜的手段是不是已经试过了？**

### 7.2 五手段完整对照表（必背）

| 维度 | **优化提示词** | **RAG** | **工具 / 工具调用** | **微调** | **Agent** |
|---|---|---|---|---|---|
| **一句话** | 把话说清楚 | **补知识**（改"喂什么"） | **做事**（拿数据 / 执行动作） | **改行为**（改"怎么说"） | **串流程**（把事办完） |
| **解决什么** | 指令不清、缺示例 | 缺私域知识、缺最新信息、幻觉 | 实时数据、确定性计算、业务动作 | 稳定行为、格式、风格、分类能力、轻量部署 | 多步编排、跨工具协作、复杂任务闭环 |
| **是否改模型权重** | ❌ 不改 | ❌ 不改，只改输入上下文 | ❌ 不改 | ✅ **改**，更新模型参数 | ❌ 不改 |
| **更新方式** | 改提示词即刻生效 | **改文档即刻生效** | 接口侧更新 | 必须**重新训练** | 改编排 / 提示 / 工具 |
| **可追溯性** | — | ✅ 可附出处、可引用原文 | ✅ 结果来自系统 | ❌ 融进权重，**无法指出来源** | 取决于所用手段 |
| **前置条件** | 无（**永远第一步**） | 有资料文档即可 | 有可用接口 | 高质量样本 + 明确目标 | 有工具与目标拆解 |
| **典型失败表现** | 回答泛泛、抓不住重点 | 召不回 / 答错 | 接口失败 / 参数错 | 行为没学会 / 过拟合 / 遗忘 | 跑偏、死循环、越权 |
| **与微调的关系** | **先于**微调 | **可与**微调组合 | 与微调正交 | — | 可调用微调后的模型 |

### 7.3 判定三连问（做题时默念，直接对应官方口诀）

```
第1问：是「查知识」吗？（模型不知道 / 要最新 / 要可追溯）
        └── 是 ─────────────────────────► RAG ✅
        └── 否 ↓

第2问：是「做动作」吗？（实时数据 / 确定性计算 / 业务动作）
        └── 是 ─────────────────────────► 工具 / 工具调用 ✅
             （多步编排 → Agent）
        └── 否 ↓

第3问：是「稳行为」吗？（格式 / 风格 / 分类 / 轻量部署 / 整体稳定）
        └── 还没试过优化提示词 ─────────► 先优化提示词 ✅
        └── 提示词反复优化后仍不达标 ───► 微调 ✅
```

> **「查知识」「做动作」「稳行为」三个词就是官方口诀的三个关键词，也是本模块全部场景题的答案池。**

### 7.4 场景判断速查（10 题，逐题练手感）

| # | 场景 | ✅ 正解 | ❌ 经典错选 | 一句理由 |
|:---:|---|---|---|---|
| 1 | 要求模型问诊回复必须像**资深医生写病历**（术语、句式、结构） | **微调**（风格 / 领域表达） | RAG | 表达方式 = 行为问题 |
| 2 | 用户问「公司**内部报销流程**是什么」 | **RAG** | 微调 | 私域知识缺失 → 查知识用 RAG |
| 3 | 要回答 **2026 年新发布**的行业法规 | **RAG** | 微调 | 时效知识，训练完即冻结 |
| 4 | 要读 Excel → 汇总 → 发邮件 → 建待办 | **Agent** | 微调 | 多步 + 多工具编排 |
| 5 | 回答**泛泛而谈、抓不住重点** | **先优化提示词** | 微调 / RAG | 成本最低，永远第一步 |
| 6 | 只有 **5 条**样本想让模型学会新格式 | **提示词加少样本示例** | 微调 | 样本量太少，微调不成立 |

| 8 | 医疗问答要求**每条结论必须标注出处文档** | **RAG** | 微调 | 强溯源需求，微调做不到 |
| 9 | 想把**意图分类**能力迁到一个**小模型**上，降低高并发下的推理成本与延迟 | **微调**（分类能力 + 轻量模型部署） | RAG | 专项能力下放，官方场景第 ④⑤ 项 |
| 10 | **售后退款**需要真的调用业务系统完成退款操作 | **工具调用**（多步则 Agent） | 微调 / RAG | 业务动作 → 做动作靠工具 |

### 7.5 最高频的三个陷阱句式

> **陷阱一：「把公司资料 / 制度微调进模型」**
> → 看到「资料」「制度」「手册」「政策」「文档」这类**名词性知识**，一律优先 **RAG**。理由：可更新、可追溯、改完即生效。

> **陷阱二：「回答不够好，那就微调一下」**
> → 缺了前提。正确表述：**先优化提示词**，再判断是不是「稳行为」问题，最后才考虑微调。「一上来就微调」这个顺序本身就是错的。

> **陷阱三：「用了 RAG 就不需要微调 / 微调了就不需要 RAG」**
> → 两者**不互斥**：**RAG 负责「答什么」，微调负责「怎么答」**，典型组合是「RAG 补知识 + 微调定风格」。

### 7.6 组合使用的正确姿势

```
        ┌──────────── RAG：负责「答什么」────────────┐
        │  知识库检索 → 得到最新、可追溯的资料片段      │
        └───────────────────┬──────────────────────┘
                            ▼
        ┌──────────── 微调：负责「怎么答」────────────┐
        │  用固定话术 + 固定 JSON schema 输出答案       │
        └───────────────────┬──────────────────────┘
                            ▼
                    （可选）Agent 负责「串起来」
                    工具负责「动手」（查实时 / 执行动作）
```

> **记忆句：RAG 提供「料」，微调提供「味」，工具负责「动手」，Agent 提供「流程」。**

## 八、微调的局限（"不是万能按钮"的具体表现）

| 局限 | 说明 | 导致的后果 |
|---|---|---|
| **知识会过时** | 训练结束那一刻，知识就被「冻结」在权重里 | 新政策、新价格、新事件一律不知道；要跟上只能**重新训练** |
| **不可追溯** | 知识融进参数，无法指出答案来自哪份文档哪一条 | 医疗、金融、法务等**强溯源**场景难以合规 → 只能用 RAG |
| **迭代不灵活** | 每次调整都要重新经历「准备样本 → 控制质量 → 评估」的完整循环 | 不像 RAG 那样「改完文档即生效」，跟不上高频变化 |
| **灾难性遗忘** | 过度训练可能损害模型原有的通用能力 | 「专科变强了，常识变差了」 |
| **高度依赖样本质量** | 口径不一致、充满噪声的样本会把行为教歪 | **质量 > 数量**；教材印错了，习惯就养歪了 |
| **不解决时效与实时** | 模型本身没有外部数据源，也没有执行能力 | 实时数据 / 业务动作 → **工具调用** |
| **不降低成本敏感度** | 相对「改几句话」「改几篇文档」的其他手段，微调投入明显更重 | 所以排在官方手段序列的**后位**，不该作为首选 |
| **不能消除幻觉** | 只能降低特定场景下的幻觉，无法根治 | 根治靠 RAG 提供可靠依据 + 人工复核 |

> **口诀：微调三宗罪 —— 会过时、查不到、改不动。**
> 与之相对：**RAG 三优势 —— 可更新、可追溯、改完即生效。**

### 9.1 全参数微调 vs 高效参数微调（⚠️ 了解即可 · 官方不考）

| | **全参数微调** | **高效参数微调（PEFT）** |
|---|---|---|
| 做法 | 更新模型**全部**参数 | **冻结**基座大部分参数，只训练**少量**参数 |
| 开销 | 高 | 低得多 |
| 存储 | 每个任务一份完整模型副本 | 只存一份很小的增量权重，基座可复用 |
| 效果 | 理论上拟合上限更高 | 多数业务场景**接近**全参数微调，性价比高 |
| 备考 | ⚠️ 了解即可 | ⚠️ 了解即可 |

> **一句话：全参数微调是「重写整本教材」，高效参数微调是「只贴几页修订页」。**

### 9.2 低秩适配类方法（LoRA / QLoRA）（⚠️ 了解即可 · 官方不考）

- **LoRA**：**冻结**基座模型原始权重**不动**，在旁路引入一对低秩小矩阵学习「增量」，训练时只更新这些少量参数。
  - ⚠️ 仅供与技术人员沟通、不考：「LoRA 会修改基座原权重」是**错的**，恰恰相反它被冻结。
- **QLoRA**：LoRA **+ 量化（Quantization）**，把被冻结的基座用更低精度表示，进一步降低资源占用。

> ⛔ **以下一律不考**：秩的取值、学习率、训练轮数、批大小、显存占用数值、训练时长、训练费用、训练框架与代码。

> 按考场上"踩坑概率"排序。**考前 5 分钟看这一张表就够了。**

| 排名 | 陷阱 | 典型错误说法 | ✅ 正确认知 |

| **2** | **一上来就微调** | 「回答不够好，那就微调一下」「效果不好立刻启动微调」 | **先优化提示词**（官方手段序列第一位）；提示词反复优化后仍不达标，才考虑微调 |
| **3** | **把 RAG 的更新方式安到微调头上** | 「微调后只需替换知识库文档，即可同步最新知识」 | 那是 **RAG**。微调要同步新知识，**必须重新训练** |

| **6** | **流程记成六步 / 顺序记错** | 「先准备样本再定义目标」「先微调，提示词以后再说」 | 官方**五步**：**定义目标 → 准备样本 → 选择基模 → 控制数据质量 → 评估效果**；旧版六步**已作废** |
| **7** | **用训练数据自评** | 「用全部数据训练，再用同一批数据评估，效果很好」 | 评测必须用**未参与训练**的独立数据，并**与基座对比** |
| **8** | **"多堆数据就行"** | 「数据里有少量噪声没关系，多堆一些就好了」 | **质量 > 数量**，口径不一致 / 噪声会把行为教歪 |

## 十一、⭐ 本模块必背清单（考前 10 分钟过一遍）

### 11.1 必背 · 官方原文三句（一字不差）

1. **「微调不是万能按钮。」**
2. **「微调适合什么：稳定行为、格式、风格、分类能力，或支持轻量模型部署。」**
3. **「查知识用 RAG，做动作靠工具，稳行为才考虑微调。」**

### 11.2 必背 · 官方五步流程

> **定义目标 → 准备样本 → 选择基模 → 控制数据质量 → 评估效果**
> 口诀：**目、样、基、质、评**。（⚠️ 旧版六步已作废）

### 11.3 必背 · 官方手段顺序（成本递增）

> **优化输入（提示词） → 接入知识库（RAG） → 调用工具 → 使用微调 → 协作 Agent（或保留人工确认）**
> → **微调不是第一选择**，一个"才"字是考点。

### 11.4 必背 · 官方五项适用场景（一句话版）

| 项 | 一句话 |
|---|---|
| ① 稳定行为 | 同类输入给同质反应，不随问法漂移（**总纲**） |
| ② 格式 | 每次都按同一结构输出（**要程序读**） |
| ③ 风格 | 语气、话术、品牌调性长期一致（**说话的味道**） |
| ④ 分类能力 | 稳定归入既定类别；比提示词**更稳、更快、更省 Token** |
| ⑤ 支持轻量模型部署 | 专项能力下放到小模型，**降推理成本与延迟** |

### 11.5 必背 · 微调三宗罪 vs RAG 三优势

> **微调三宗罪：会过时、查不到（不可追溯）、改不动。**
> **RAG 三优势：可更新、可追溯、改完即生效。**

### 11.6 必背 · 三句类比

| 类比 | 含义 |
|---|---|
| **「RAG 换资料，微调换习惯」** | 改"答什么"找 RAG，改"怎么答"找微调 |
| **「提示词是每次提醒，微调是养成习惯」** | 提示词是外部要求，微调是内化行为 |
| **「RAG 提供料，微调提供味，工具负责动手，Agent 提供流程」** | 四手段分工一句话 |

### 11.7 必背 · 数据质量与评测

> **质量 > 数量**；标注口径必须一致；**独立评测集**（未参与训练）；**与基座对比**；**检查通用能力是否退化**。

### 11.8 必背 · 不考清单（看到就跳过）

> **高效参数微调方法（PEFT）、低秩适配（LoRA / QLoRA）、超参数数值（学习率 / 轮数 / 批大小 / 秩）、训练成本与显存、训练与部署代码、平台控制台操作与定价** —— ⚠️ **官方明示不考**。

## 十二、易错辨析表

### 12.1 手段辨析：到底该用哪个

| 场景 | 常见错误答案 | ✅ 正解 | 理由 |
|---|---|---|---|
| 输出 JSON 时而是对象时而是数组 | RAG / 换模型 | **提示词强约束 → 微调** | 格式稳定性（官方场景②） |
| 要模型一直用统一客服话术 | RAG | **微调** | 固定行文风格（官方场景③） |
| 工单要自动归到既定类别且长期不变 | RAG | **微调** | 分类能力（官方场景④） |
| 想把专项能力迁到小模型降本提速 | RAG | **微调** | 支持轻量模型部署（官方场景⑤） |
| 公司新出的产品报价单问答 | 微调 | **RAG** | 查知识用 RAG |
| 模型不知道内部报销流程 | 微调 | **RAG** | 私域知识缺失 |
| 要查实时天气 / 汇率 / 库存 | 微调 | **工具调用** | 做动作靠工具 |
| 要真的完成退款 / 下单 | 微调 / RAG | **工具调用**（多步则 Agent） | 模型不能执行动作 |
| 读表格 → 计算 → 发邮件 | 微调 | **Agent** | 多步编排 |
| 回答泛泛、抓不住重点 | 微调 | **优化提示词**（先试） | 永远第一步 |
| 要求答案必须标出处 | 微调 | **RAG** | 微调不可追溯 |
| 只有几条样例想统一格式 | 微调 | **提示词少样本示例** | 样本量不足以微调 |
| 既要最新条款又要统一话术 | 只选一个 | **RAG + 微调** | 两者可组合 |
| 类别体系每月都在变 | 微调 | **提示词 / RAG**（看是否涉及规则文档） | 高频变化不适合微调 |
| 用小模型全面替代大模型做全领域问答 | 微调 | **不成立** | 轻量模型通用能力有限，只在专项上好用 |

### 12.2 概念辨析

| 对比项 | A | B | 判据 |
|---|---|---|---|
| **RAG vs 微调** | 改**输入**（喂资料），不改权重 | 改**权重**（改行为） | 「有没有改模型参数」是唯一硬判据 |
| **工具调用 vs 微调** | 拿到实时数据 / 执行动作，不改模型 | 改模型行为，拿不到实时数据 | 「要做事」还是「要稳行为」 |
| **提示词 vs 微调** | 改输入，成本低、立即生效、灵活性高 | 改模型，行为更稳定、但重且难改 | **先提示词，后微调** |
| **质量 vs 数量**（样本） | 一致性、正确性优先 | 堆量而噪声大反而更差 | 质量 > 数量 |
| **训练集 vs 评测集** | 用来学习 | **必须独立**，用来验证 | 用训练集自评 = 分数虚高 |
| **「查知识」vs「稳行为」** | 不知道 → RAG | 说不好 → 微调 | 官方口诀给出的第一分水岭 |
| **「不知道」vs「不会做」** | 缺知识 → RAG | 缺动作能力 → 工具 / Agent | 官方口诀第二分水岭 |
| **微调 vs Agent** | 改模型自身行为 | 编排多步任务与工具 | 「改模型」还是「串流程」 |
