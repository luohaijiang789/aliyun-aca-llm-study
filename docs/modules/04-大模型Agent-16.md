### M4-K01　Agent 的价值：把「回答问题」推进到「完成任务」　🟢`[A]`

**① 一句话定义**：Agent 的价值不在于「答得更准」，而在于**它能把一件事真的做完**——官方原话是「把『回答问题』推进到『完成任务』」。

**② 是什么**：普通大模型交互是**问答式**的：你问一句、它答一句，产出物是一段文字，句号一画就结束，外部世界没有任何变化。Agent 是**任务式**的：你交代一个目标，它自己拆步骤、查资料、调工具、看中间结果、修正、再往下走，最终交付一个**实际成果**（一份文件、一条工单、一次批量改名、一封待发邮件）。区别在于**有没有对外部世界产生作用**。官方「通过认证可证明的能力」里写的是「能够使用大模型和个人 AI Agent 辅助完成**信息提取、内容生成、资料分析、知识问答、办公自动化**等任务」——注意动词是「**完成**任务」，不是「回答问题」。

**③ 为什么**：大模型本身只会**生成 token**，它不会读你的硬盘、不会发邮件、不会改数据库。要在「生成文字」之外产生实际作用，就必须在模型外面加一层**能感知、能行动、能循环**的东西——这就是 Agent。所以官方把 Agent 写成五选一手段中的一格：「优化输入、接入知识库、调用工具、使用微调、**协作 Agent**，或保留人工确认」。前四格都是在「把答案弄好」，只有 Agent 这一格是在「把事情办完」，这正是它权重从 10% 涨到 16% 的原因。

**④ 怎么做 / 怎么用**：**Before（问答式）**——你问「上个月华东区销售额是多少？」，模型回答「我不知道你们公司的数据」；即使接了知识库，它也只能**说出**数字。**After（任务式）**——你说「把上月华东区销售分析做成周报并发给张总」，Agent 自己去取数、算同比环比、套模板生成周报、对照自检清单核对数字、最后生成待发邮件交你确认。同一个需求，前者的交付物是**一段话**，后者是**一件做完了的事**。

**⑤ 易错点**：
- ❌ 常见误解：Agent 就是「更强的大模型」，换它就能答得更准 → ✅ 正确：Agent 是**基于大模型的应用架构**，模型能力仍是底座；它解决的是「做不做得到」，不是「模型聪不聪明」。
- ❌ 常见误解：只要接了工具就是 Agent → ✅ 正确：单次工具调用只是「补能力」（见 M3）；Agent 的关键特征是**围绕一个目标自主推进多步循环**，并对最终结果负责。

**⑥ 考法提示**：最常见的是**概念定位单选**，题干问「官方认为 Agent 的价值是什么」，正确项必然含「**完成任务**」字样；干扰项通常写成「提高模型的推理能力」「降低模型幻觉」「减少调用成本」——这些都不是官方口径的 Agent 价值。另一种考法是**场景判断**：给一个需求，问该用「单次问答 / RAG / 工具 / Agent」，判据是**要不要多步推进 + 要不要对外部产生作用**。

**⑦ 记忆锚点**：**「问答是说话，Agent 是干活」**——类比助理与顾问：顾问给你**建议**（答完就走），助理把事**办完**（取数、排版、发件、留痕）。

### M4-K02　Agent 的定义与三大核心能力（感知 / 思考 / 行动）　🟢`[A]`

**① 一句话定义**：Agent = **大模型（大脑）+ 工具与知识库（手脚与资料）+ 循环机制（反复推进）**，对外表现为**感知 → 思考 → 行动**的闭环。

**② 是什么**：三大能力各管一段：**感知**是从外部拿到信息（读文件、检索知识库、查接口、看命令行返回值、理解用户指令）；**思考**是基于大模型做推理——拆任务、定计划、判断下一步、解读刚拿到的结果；**行动**是把决定变成实际动作（调用工具、写文件、创建工单、发消息）。三者不是走一遍就结束，而是**循环**：行动产生新结果 → 新结果进入下一轮感知 → 再思考 → 再行动，直到达成目标或触发停止条件。这正好对应官方课时里「让 Agent 接入知识库和工具」——知识库增强**感知**（有依据可查），工具增强**行动**（有能力可做）。

**③ 为什么**：只有思考没有感知和行动，就是普通聊天机器人（不知道你的数据、也做不了事）；只有行动没有思考，就是脚本（不会看情况调整）。三者闭环才产生「自主推进」的能力，也才带来 Agent 特有的风险：**错误会被真的执行出去**（见 M4-K14）。官方把「AI Agent 的**基本能力**」列入建议掌握的知识，考的就是这三者及其闭环关系。

**④ 怎么做 / 怎么用**：做一个「合同关键信息提取」Agent——**感知**：读取 `/合同/` 目录下的 PDF，解析出文本；**思考**：判断哪些段落是金额、有效期、违约责任，计划先抽金额再抽日期；**行动**：调用结构化输出工具生成字段表，写入结果文件。中途发现某份合同是扫描件（感知失败），**思考**后决定改用 OCR 工具重试——这个「看结果→改计划」的过程就是闭环。

**⑤ 易错点**：
- ❌ 常见误解：三大能力是「感知、思考、行动、**记忆**」 → ✅ 正确：官方语境下讲三大核心能力就是**感知 / 思考 / 行动**三者闭环；「记忆」不作为官方表述的第四项，题目里出现「记忆」多半是凑数干扰项。
- ❌ 常见误解：把三大能力与「Agent 四要素」混为一谈 → ✅ 正确：三大能力讲「**Agent 自身有什么本事**」，四要素讲「**你要把任务交代到什么程度**」，二者维度完全不同（详见 M4-K03）。

**⑥ 考法提示**：典型干扰项设计——用「感知、思考、行动、记忆」冒充官方四要素，或用「目标、背景、角色、约束」（M2 提示词要素）冒充。题干若出现「Agent 的**基本能力**」字样，选**感知/思考/行动**；若出现「给 Agent **明确**……」字样，选**四要素**。

**⑦ 记忆锚点**：**「眼（感知）—脑（思考）—手（行动），三样转成一个圈」**——少了任何一样，要么瞎干、要么空想、要么只会打字。

### M4-K03　⭐⭐ 四要素之一：目标　🟢`[A]`

**① 一句话定义**：**目标** = 交付物 + 范围 + 成功标准，回答「到底要交付什么、做成什么样算完成」。

**② 是什么**：官方要求「给 Agent 明确**目标**」。一个明确的目标必须三件套齐全：**交付物形态**（一份报告 / 一个表格 / 一封邮件 / 一条工单 / 一次批量操作）、**范围边界**（包含什么、**不包含什么**、时间范围、对象范围）、**成功标准**（什么叫做完、什么算合格）。缺任何一件，Agent 就会按它自己的理解自由发挥。它与 M2 提示词里的「目标」是同一个词但层级不同：M2 管**单次输入怎么说清楚**，本考点管**多步任务的委托书**。

**③ 为什么**：Agent 有自主推进能力，目标越含糊，它的「自由发挥空间」越大，跑偏的概率越高，而且**跑偏后它会继续基于错误方向执行好几步**，等你发现时已经做完了另一件事。这是 Agent 与问答最本质的风险差异：问答答偏只是一句话错了，Agent 目标偏了是**一整件事白干**。

**④ 怎么做 / 怎么用**：
- ❌ 模糊：「帮我分析一下上月的销售数据。」
- ✅ 明确：「输出上月（**2026-08**）**华东大区**的销售分析（**范围**：不含华南、不含退货），形态为一份 **Markdown 报告**，含**同比、环比两张表**与一段 **≤200 字**结论（**成功标准**：所有数字必须能在『销售明细-08.xlsx』中找到同名行）。」
- **前后对比**：模糊版交付的是「一篇看起来挺专业的分析」，但你没法验收、没法核对、也没法复用；明确版交付的东西**别人照着也能做出来**，且能直接转成本章 4.6 的自检清单条目。

**⑤ 易错点**：
- ❌ 常见误解：「目标」就是一句话说清要干什么，越简短越好 → ✅ 正确：**明确 ≠ 简短**。必须含交付物形态、范围边界、成功标准，「写得专业一点」这类形容词不算成功标准。
- ❌ 常见误解：把「成功标准」交给 Agent 自己定，它更懂 → ✅ 正确：成功标准必须由**人**给出（见 M4-K15 人机分工），否则验收权就交出去了，也无法写自检清单。

**⑥ 考法提示**：场景题里判断「哪种任务下达方式最符合四要素」，正确项一定**同时**出现交付物形态 + 范围 + 可判定的标准；只写「尽量准确、尽量专业」的选项一律是**不达标**。多选题里常问「明确目标包括哪些内容」，正确项含**交付物 / 范围 / 成功标准**，干扰项会混入「模型温度参数」「工具版本号」等实现细节。

**⑦ 记忆锚点**：**「交什么、管多宽、算做完」**——三问全答出来，目标才算明确。

### M4-K04　⭐⭐ 四要素之二：资料来源　🟢`[A]`

**① 一句话定义**：**资料来源** = 允许 Agent 依据哪些信息来作答，以及**查不到时该怎么说**。

**② 是什么**：官方要求「给 Agent 明确**资料来源**」。它包含四件事：① **指定来源**（哪个知识库 / 哪个文件 / 哪个接口 / 哪个看板，尽量精确到版本或路径）；② **限定排他性**（**只用**这些来源，其余一律不许参考）；③ **规定缺省行为**（查不到时必须回答「未找到 / 未收录」，禁止自行推测补全）；④ **要求留出处**（每条关键结论标注来自哪个文档的哪一段）。

**③ 为什么**：这是 Agent 最容易出事的一处。不指定来源，Agent 会**默认用模型自身记忆**作答——知识可能过期、可能不是你们公司的口径；会把不同来源的信息混在一起，产出**看似合理实则拼凑**的结论；一旦出错**无法追溯、无法定责**。官方在考试内容 3 里强调「模型不是什么都要靠记忆回答」，本考点是这句话在 Agent 场景下的落地。

**④ 怎么做 / 怎么用**：
- ❌ 模糊：「根据公司资料回答客户关于退款政策的问题。」
- ✅ 明确：「**只依据**知识库『售后政策-v3.2』中的内容回答；该库未收录的一律回答『该问题超出当前资料范围，需转人工确认』；每条结论后注明依据的**章节名**。」
- **前后对比**：模糊版遇到库里没有的问题，模型会**编一条**听起来很像那么回事的政策（这就是幻觉被「执行力」放大）；明确版会老实说「未找到」并转人工——**宁可说不知道，也不能编**，这是资料来源这条要素的核心价值。

> ⚠️ **与 M3 的衔接**：指定「资料来源」后，Agent 取资料的机制就是 **知识库 / RAG**（详见 M3）。本模块只需知道：**资料来源是四要素之一，由人来指定；接了知识库不等于模型永久学会了。**

**⑤ 易错点**：
- ❌ 常见误解：只要接了知识库，就等于明确了资料来源 → ✅ 正确：接库是**能力建设**，指定「**只用哪个库、查不到怎么办**」才是**要素明确**；接了三个库却不指定用哪个，依然是不明确。
- ❌ 常见误解：查不到时让模型「根据行业通行做法补充一下」更贴心 → ✅ 正确：这等同于**授权它编造**；官方口径是查不到必须说未找到，或转人工。

**⑥ 考法提示**：这是场景综合题（如 Q002）里**最常被漏掉的一项**——干扰项往往工具边界和检查点都写得很漂亮，唯独没限定数据来源。看到选项里出现「**不得使用其他来源**」「**查不到标注未找到**」「**注明出处章节**」这类表述，就是资料来源要素到位的信号。

**⑦ 记忆锚点**：**「依据什么？查不到怎么办？——答：说未找到，不许编。」**

### M4-K05　⭐⭐ 四要素之三：工具边界　🟢`[A]`

**① 一句话定义**：**工具边界** = Agent 被允许调用哪些工具，以及每个工具**能做什么、不能做什么、做到什么程度要停下**。

**② 是什么**：官方要求「给 Agent 明确**工具边界**」。落地四件套：**工具白名单**（明确列出可用工具，未列出的默认不可用）、**范围限制**（同一工具限定作用范围，如限定目录、限定库表）、**读写/禁用声明**（明确禁止删除、覆盖、外发等）、**高风险动作标注**（哪些动作必须停下来等人，见 M4-K08）。

**③ 为什么**：Agent 有行动能力却不设边界，等于**把钥匙交出去还不告诉它哪些门不能开**。典型事故：误删文件、误发邮件、误改生产数据、误下单。官方把「工具边界」和「高风险动作必须人工确认」写在**同一句话**里，是有意为之：**边界负责事前限制，人工确认负责事后兜底**，二者缺一不可。

**④ 怎么做 / 怎么用**：
- ❌ 模糊：「你可以用你能用的工具来帮我处理文件。」
- ✅ 明确：「可调用『读取文件』与『生成图表』工具，作用目录限定为 `/shared/report/`，**禁止写入与删除**；涉及向外部邮箱发信时，必须生成草稿交我确认后由我发送。」
- **前后对比**：模糊版等于把全盘权限交出去，Agent 可能为了「更好地完成任务」顺手删掉它认为的临时文件；明确版即使 Agent 判断失误，损失也被限制在**只读**范围内。

**⑤ 易错点**：
- ❌ 常见误解：给了工具清单就是明确了边界 → ✅ 正确：只列工具名是**授权**，不算**边界**；边界必须包含**禁做什么**（写/删/外发）和**作用范围**（哪个目录/哪张表）。
- ❌ 常见误解：工具边界只是安全考虑，与任务质量无关 → ✅ 正确：它还决定**任务可达范围**——不给它取数工具，它再聪明也只能靠猜。

**⑥ 考法提示**：常与「高风险动作」打包考（Q002、Q007）。干扰项典型写法：「赋予 Agent 全部工具权限以便它灵活完成任务」→ 必错；正确项必含**白名单 / 限定目录 / 禁止删除写入 / 高风险动作先确认**中的若干条。

**⑦ 记忆锚点**：**「能动哪些？禁止哪些？哪些要人确认？」**——三问不答全，钥匙就不能交。

### M4-K06　⭐⭐ 四要素之四：阶段检查点　🟢`[A]`

**① 一句话定义**：**阶段检查点** = 在多步任务中**预先约定好的暂停核对点**，到达即停下自检或请人确认，**通过才进入下一阶段**。

**② 是什么**：它解决的核心问题是**错误沿链路传播**：多步任务有依赖传递性，第 2 步错，第 3~N 步会基于错误结果继续跑，到最后才发现，**返工成本指数级上升**；如果中途还执行了真实动作（发邮件、改数据），损失已经**无法撤回**。写法是三步式：「在第【几步之后】停下来 → 核对【什么内容】 → 【通过】才继续，【不通过】怎么办（停下 / 回滚 / 转人工）」。

**③ 为什么**：官方把它列为四要素之一，是因为 Agent 与问答的根本差异在于**它会连续执行多步**。一次问答错了，损失是一句话；多步任务错了且没设检查点，损失是**整条链路**。检查点的价值在于**在错误还能低成本修正的时候把错误拦住**。

**④ 怎么做 / 怎么用**：
- ❌ 模糊：「你看着办，有把握就行。」（这句等于**没有检查点**，也是场景题里最典型的错误项）
- ✅ 明确：「① 数据抓取完成后，**先输出字段口径清单交我确认**，通过后才进入分析；② 分析结论生成后，**再对照自检清单核对一遍**；③ 最终报告发送前，**生成待发版本给我终审**。」
- **三类检查点**：**口径确认点**（取数/检索之后、分析之前，拦"取错数据、取错口径"）、**中间结果自检点**（每步产出后，拦"字段缺失、格式不符、不可解析"）、**终审发布点**（对外交付/不可逆动作之前，拦"错误结论被真实执行出去"）。

**⑤ 易错点**：
- ❌ 常见误解：阶段检查点就是「让它慢一点 / 分几步做」 → ✅ 正确：它的价值在**拦错**，不在**减速**；只有「停下来 → 核对 → 通过才继续」三步齐全才算检查点。
- ❌ 常见误解：有自检清单就够了，不必设检查点 → ✅ 正确：**检查点解决「何时拦」，清单解决「拦下来查什么」**，两者必须成对出现（见 M4-K07）。

**⑥ 考法提示**：场景题中最典型的丢分点是选项里写了「调用上一步生成的 Pass 结果继续下一步」——**这不是检查点，因为它没有停下核对的动作**。另外「你自己看着办就行」是**没有阶段检查点**的标志性表述，见到必判错。

**⑦ 记忆锚点**：**「何时停下？核对什么？不通过怎么处置？」**——类比流水线上的**质检工位**：不是让流水线慢下来，而是在每个关键工位把不良品挑出来。

### M4-K07　⭐⭐ 自检清单三要求：具体、可核对、有证据　🟢`[A]`

**① 一句话定义**：官方原话——「**自检清单要具体、可核对、有证据**」。

**② 是什么**：自检清单是 Agent 交付前的**验收闸门**。三个要求各管一件事：**具体**=把"好不好"翻译成"哪个字段、满足什么条件"（含对象、环节、判定阈值）；**可核对**=每条都能被机械地逐项打勾判定通过/不通过，不依赖主观感觉；**有证据**=每条都要求留下**可展示的凭证**（原文出处、工具返回值、计算结果、失败报错），供第三方复核。

**③ 为什么**：写得好，清单是**过滤器**；写得含糊，它只是一句自我安慰。「检查一下内容是否准确」这类条目，模型只能自己给自己发合格证——它没有判定对象、没有门槛、也没有凭证，不同人（或不同次的模型）会得出完全不同的结论。官方把「**自检闭环**」列入「建议掌握的知识」，作为「帮助 Agent 沉淀方法和提升输出质量的实践方式」，说明它被视为**质量保障机制**而非形式流程。

**④ 怎么做 / 怎么用**：
- ❌ 反例：「检查内容是否准确 / 确保质量达标 / 数据应该是正确的 / 注意不要有错误 / 已检查完毕」。
- ✅ 正例：「周报中**每个数字**都必须能在『经营数据/2026-08.xlsx』的『华东』页签中找到**同名行**，并在清单中记录其**所在行列位置**；查不到的一律判为不合格并**逐条列出**。」
- **可复用模板**见第五章 5.3。**识别口诀**：凡出现「**准确 / 合理 / 完善 / 适当 / 差不多 / 质量好**」这类形容词而**没有判定门槛和凭证**的，一律不合格。

**⑤ 易错点**：
- ❌ 常见误解：自检清单只要写得「全面」就够了 → ✅ 正确：官方要求的是**具体、可核对、有证据**，不是「条数多」。
- ❌ 常见误解：按清单自检 = 让模型多生成几个版本挑最好的（best-of-N） → ✅ 正确：best-of-N 只有"挑"没有"改"，也不产生证据；自检是「**逐项核对 → 发现具体不符 → 带着问题修正 → 再审**」，有明确的修正靶向与留痕。

**⑥ 考法提示**：单选常问「下列检查项最符合要求的是」，正确项一定**同时**具备：明确检查对象 + 判定门槛 + 要求留下凭证；干扰项固定三类——**形容词无门槛**、**只说重做不说哪里不合格**、**best-of-N 采样择优**。多选可能问「合格清单应满足哪些要求」，三要求全选。

**⑦ 记忆锚点**：**「具体=查什么，可核对=能不能打勾，有证据=凭什么说它过了。」**

### M4-K08　⭐⭐ 高风险动作必须人工确认　🟢`[A]`

**① 一句话定义**：官方原话——「**高风险动作必须人工确认**」。这是**陈述句规则**，不是建议，没有例外。

**② 是什么**：高风险动作的判据是满足以下任一条：**不可逆**（撤销成本极高）、**对外产生实际影响**、**涉及资金 / 数据资产 / 他人权益**。典型清单：删除或覆盖文件、对外发送邮件与消息、支付与交易（下单、付款、退款、改价）、修改生产环境数据与配置、对外发布（公告、营销内容、政策口径）、合同与承诺类（签署合同、给出法律/医疗/金融结论）。落地三件套：**事前划定清单**（哪些动作属高风险）→ **事中卡住执行**（只生成待执行草稿，人点了才执行）→ **事后留痕可查**（谁确认的、确认了什么、依据是什么）。

**③ 为什么**：① **Agent 的错误是有执行力的**——普通问答错了只是答错，Agent 错了是**做错了**，损失已经发生；② **自检清单拦不住清单之外的错**——清单是人写的，覆盖不到的盲区恰恰最危险；③ **责任不能被转移**——官方金句：「**AI 可以辅助整理和起草，但不能替代最终责任人**」；④ **合规要求**——医疗、金融、合同、对外发布等场景本身就要求人工复核留痕（详见 M6）。

**④ 怎么做 / 怎么用**：
- ❌ 错误：「接到告警后，你可以自行判断是否需要重启服务并直接执行。」
- ✅ 正确：「接到告警后先完成查询与原因分析并输出处置建议；涉及**重启服务、回滚版本、修改生产配置**的动作，一律生成操作预案提交我确认，**未经确认不得执行**；执行过程与确认人全程留痕。」
- **事前确认 vs 事后留痕**：**事前确认**是在动作发生**之前**拦住它（能阻止损失），**事后留痕**是记录已发生的动作（只能追责与复盘，不能阻止损失）。二者**不可互换**——「事后补一条执行记录代替事前确认」是典型错误项。

**⑤ 易错点**：
- ❌ 常见误解：自检闭环做得足够好，高风险动作就可以由 Agent 自主执行 → ✅ 正确：官方说「**必须**」，不存在"足够完善即可免除"的例外。
- ❌ 常见误解：人工确认只针对对外发布类动作 → ✅ 正确：删除、支付、改生产数据、改本地文件同样属于高风险。
- ❌ 常见误解：人工确认只要口头同意即可 → ✅ 正确：需记录**确认人、确认内容、依据**，满足可追溯（M6 审计追踪）。

**⑥ 考法提示**：**本模块最高频的多选考点**。正确项通常三条（删除覆盖前确认 / 外发前先出草稿给人审 / 支付与改生产数据保留人工环节），干扰项固定三条：「自检完善即可自主执行」「事后补记录可代替事前确认」「口头同意不必留痕」。题干中只要出现 Agent 具备**读写文件、发邮件、操作系统**的能力，就要立刻想到这一考点。

**⑦ 记忆锚点**：**「能不能撤回？会不会影响外人？涉及钱和责任吗？」——三问任一为是，就交给人拍板。**

### M4-K09　⭐ Skill：固化重复工作方法 + Skill 编排　🟢`[A]`

**① 一句话定义**：官方原话——「**Skill 用来固化重复工作方法**」。

**② 是什么**：Skill = **流程步骤**（先做什么、后做什么）+ **所需工具**（每步要调哪些工具 / 查哪个知识库）+ **约束与验收标准**（格式要求、禁用行为、什么算做合格）。它把「这次怎么说」变成「**这套活儿以后都这么干**」，沉淀为可复用资产——换人、换会话直接套用。**Skill 编排**则是把多个 Skill / 工具按依赖关系组织成一个工作流（A 的产出是 B 的输入，或按条件分支选择不同 Skill）。

**③ 为什么**：不用 Skill 的痛点是：同一件事每次都靠临时写一段长提示词 → 说法不一致、工具调用顺序全靠当时的心情、质量与格式不稳定、别人无法复用。官方把「**Skill、自检闭环**」并列为「帮助 Agent **沉淀方法**和提升**输出质量**的实践方式」——注意「沉淀方法」这四个字就是 Skill 的官方定位。

**④ 怎么做 / 怎么用**：团队每周做数据周报，把方法固化为 Skill：规定「先取数 → 再与上周对比 → 按模板排版 → 最后检查数据口径」的先后顺序，规定每步调用哪几个工具以及字段格式要求，之后同事换个会话也能直接套用。**Before**：每人每周重写一遍长提示词，格式各不相同、口径常对不上；**After**：一个 Skill 固定下来，产出稳定、可交接、可复用。若再加一个「周报分发 Skill」（读取上一步产物 → 生成待发邮件 → 交人工确认），两个 Skill 串起来就是**Skill 编排**。

**⑤ 易错点**：
- ❌ 常见误解：Skill 等于一句写得很长的提示词 → ✅ 正确：关键增值在于**工具集合 + 约束/验收标准 + 可复用**，提示词只管"这次怎么说"。
- ❌ 常见误解：Skill 会给模型增加新能力 → ✅ 正确：它封装的是**已有的模型能力 + 工具**，不产生新能力。
- ❌ 常见误解：用了 Skill 就一定能做对 → ✅ 正确：流程设计本身有问题照样错，仍需自检清单与阶段检查点。

**⑥ 考法提示**：典型题干是「把每周做法固定下来，同事换会话也能套用，这属于什么」，正确项必含「**固化重复工作方法**」；干扰项固定三个：**长提示词**、**只是调用了一个工具**、**Multi-Agent**。注意 Skill 的适用前提是**重复性**工作——「一次性、只做一遍的任务」不适合做 Skill。

**⑦ 记忆锚点**：**「工具回答『能做什么』，Skill 回答『这件事该怎么干』，Skill 编排回答『这些事按什么顺序干』。」**

### M4-K10　工具调用（Function Calling）　🟢`[A]`

**① 一句话定义**：**模型不执行工具，模型只是"说出"它想调用什么**——真正的执行在模型之外的运行时。

**② 是什么**：完整链路四步：① 事先告诉模型有哪些工具（名称 / 功能描述 / 入参格式）；② 模型判断需要用工具时，输出**结构化的调用请求**（工具名 + 参数）；③ 由模型之外的运行时（Agent）**执行**该工具，拿到返回值；④ 把返回值作为新的上下文**回灌**给模型，模型继续推理或直接作答。分工是：**模型负责**决定"要不要调、调哪个、参数填什么"；**运行时负责**真正执行、处理异常、把结果回灌。

**③ 为什么**：必须用**结构化**请求，因为自然语言不可靠——"帮我查一下上周的销售额"这种说法程序无法稳定解析执行，而 `{"tool":"query_sales","region":"华东","period":"2026-08"}` 可以被程序确定性地执行。官方把「**工具调用**」列入「建议掌握的知识」，且明确用它解决「需要实时数据、确定性计算或业务动作」的问题（见 M3）。

**④ 怎么做 / 怎么用**：用户问「今天杭州天气怎么样」→ 模型判断自己不知道实时天气 → 输出结构化调用请求（工具名 `get_weather`，参数 `city=杭州`）→ 运行时调用天气接口拿到 `28℃ 晴` → 结果回灌模型 → 模型生成自然语言回答。**注意**：模型从头到尾**没有碰过接口**，它只产出了"我要调谁、传什么参"这段文字。

**⑤ 易错点**：
- ❌ 常见误解：「模型在执行过程中直接执行被调用的程序」→ ✅ 正确：**执行在模型之外**，这是本考点最高频陷阱。
- ❌ 常见误解：工具调用会给模型补充知识 → ✅ 正确：提供的是**能力**，不是知识；补知识靠**知识库/微调**。工具也可能失败、参数也可能填错，所以**不保证结果正确**。

**⑥ 考法提示**：常与 MCP、Skill 打包成**层级辨析题**（Q005）。看到选项说「模型直接执行工具」「有了 MCP 就不需要 Function Calling」，一律判错。

**⑦ 记忆锚点**：**「模型只动嘴，运行时才动手。」**

### M4-K11　MCP 的作用与定位（不考协议细节，主考点在 M3）　🟢`[A]`

**① 一句话定义**：**MCP 是一套让 Agent / 应用更方便地连接外部工具与数据源的通用方式**——按同一方式适配一次，就可以被多处使用，不必为每个工具单独做一套对接。

**② 是什么**：它位于**连接侧**，解决「工具与数据源**怎么接进来**」的问题，而不是「接进来之后**能提供什么能力**」（那是工具的事）。官方在考试内容 3 中明列「了解 **MCP 的作用，不要求掌握协议细节**」；在「建议掌握的知识」中把「**工具调用、MCP** 和个人 AI Agent 接入知识库与工具的方法」并列——所以本模块只需掌握**用法层**：Agent 可以通过它接入工具与知识库。

**③ 为什么**：没有统一方式时，每接一个工具/数据源都要单独做一套对接（N 个应用 × M 个工具 = N×M 套集成）；有了通用连接方式，适配一次即可多处复用。这是它被称为「通用方式」的原因，也是官方只考「作用」够用的原因。

**④ 怎么做 / 怎么用**：某团队要给 Agent 接上「内部工单系统」和「产品手册知识库」。**Before**：为工单系统写一套对接，为知识库再写另一套，换一个 Agent 又得重来；**After**：两侧都按同一通用方式适配一次，多个 Agent / 应用都能直接连上使用。**考试只考到这里**，不问它内部怎么通信。

**⑤ 易错点**：
- ❌ 常见误解：MCP 是一个具体好用的工具 → ✅ 正确：MCP 是**连接方式/标准**，真正执行动作的是被连进来的**工具**。
- ❌ 常见误解：MCP 等同于 Function Calling → ✅ 正确：Function Calling 在**模型侧**（怎么表达调用意图），MCP 在**连接侧**（工具与数据源怎么接进来）。**层次不同、不是互相替代**。

**⑥ 考法提示**：⛔ **官方明示不考握手、报文格式、传输方式、JSON-RPC 等协议实现细节**，题目里出现这类词的选项**一律不选**。本模块只考一句「它是 Agent 接入工具与知识库的一种通用方式，本身不是工具」。

**⑦ 记忆锚点**：**「MCP ≈ 接口标准（Type-C），工具 ≈ 外接设备（U 盘、打印机），Function Calling ≈ 发出的驱动调用，Agent ≈ 用电脑干活的人。」**（类比只用于理解定位，不考实现）

### M4-K12　桌面 Agent（本地运行形态）　🟢`[A]`

> ⚠️ **产品名称待核实**：具体产品名称、安装包获取方式、菜单路径**不在本资料考证范围内**，也不考安装步骤与配置项。**只考概念与定位。**

**① 一句话定义**：**桌面 Agent = 运行在用户本地设备上的 Agent 形态**，因此能触及本地文件系统与本地执行能力。

**② 是什么**：它与云端 Agent 的差异只在**部署形态与可达资源**：桌面 Agent 跑在**用户自己的电脑 / 本地环境**，可达**本地文件、本地命令行/终端、本地已安装软件**，典型任务是整理本地文件夹、批量重命名、读改本地文档、跑本地脚本；云端 Agent 跑在**服务端**，可达云端 API、SaaS 服务、云数据库，适合在线助手、定时任务、事件触发流程。二者**走的是同一套 Agent 范式**（感知—思考—行动）。

**③ 为什么**：很多个人工作流的数据本来就在本机（本地文档、本地表格、本地项目目录），把它们搬到云端既不必要也有合规顾虑；本地运行让数据可以**留在本机**处理，同时天然贴近个人日常操作。代价是它拿到了**本地文件与终端权限**，误删、误覆盖、误执行命令的风险随之而来。

**④ 怎么做 / 怎么用**：**Before**：每周要把散落在下载目录里的几十份报表按规则重命名归档，人工做一遍要半小时；**After**：交给桌面 Agent，它读取本地目录、按命名规则批量改名并归档，最后输出一份改动清单交你确认。**因为是同一套范式**，四要素、Skill、自检清单、人工确认对它**同样适用**。

**⑤ 易错点**：
- ❌ 常见误解：桌面 Agent 是另一种技术路线，不遵循 Agent 范式 → ✅ 正确：**同一套范式，只是部署形态不同**。
- ❌ 常见误解：桌面 Agent 因为跑在本地，推理能力更强 → ✅ 正确：推理能力由**底层模型**决定，与部署位置无关；桌面形态改变的是**可达资源**。
- ❌ 常见误解：本地运行的数据必须上传云端，隐私性更差 → ✅ 正确：恰恰相反，数据可留在本机是它的特点之一。

**⑥ 考法提示**：单选常问「关于桌面 Agent 与云端 Agent 的差异，正确的是」，正确项必含「**本地运行、可操作本地文件与终端**」+「**权限最小化 / 高风险动作人工确认**」；干扰项会写成「另一种技术路线」「推理能力更强」「必须上传云端」。

**⑦ 记忆锚点**：**「换了地方干活，没换脑子；手伸得更长，所以要管得更紧。」**

### M4-K13　个人 AI Agent 接入知识库　🟢`[A]`

**① 一句话定义**：**Agent + 知识库 = 既有依据地回答、又能动手把事做掉的「执行体」**——让 Agent **按库里的规矩做事**。

**② 是什么**：官方原文把「个人 AI Agent 接入知识库与工具的方法」并列写出，说明这是两条独立的增强路径：**知识库补知识**（依据），**工具补能力**（行动）。典型链路：用户提需求 → Agent 先**检索知识库**拿到依据/标准/模板（这正是四要素中的「**资料来源**」）→ 依据检索结果**调用工具执行** → 输出交付物并附出处。

**③ 为什么**：只有知识库（RAG）能查到答案并讲清楚，但**做不了事**；只有工具调用能做事，但**不知道你的规矩**（会凭常识乱来）；两者结合才能**按库里的规矩做事**——这是 Agent 在真实业务里可用的前提。

**④ 怎么做 / 怎么用**：客服 Agent 接了《售后政策》知识库 + 工单创建工具：用户说「我要退货」→ Agent 先检索出「7 天无理由、需保留吊牌」的政策原文 → 判断符合条件 → 调用工单工具创建退货单 → 回复用户并附上政策出处。**变了**：能用私域/最新知识、结论可追溯出处、减少"不知道就编"、文档更新后**立即生效**无需重训。**没变**：**不提升模型本身的推理能力**、**不等于把知识永久写进参数**（那是微调）、**不等于获得执行外部动作的能力**（那是工具）。

**⑤ 易错点**：
- ❌ 常见误解：接入知识库后模型就"永久学会了"这些文档 → ✅ 正确：检索是**外挂**，文档更新即刻生效；「写进参数、永久学会」描述的是**微调**。
- ❌ 常见误解：接了知识库就自动获得写文件、发请求的能力 → ✅ 正确：那是**工具**的职责，与知识库无关。**知识 ≠ 能力**。

**⑥ 考法提示**：**本模块最容易漏选正确项的多选题**（Q008）。正确项围绕「有依据、可溯源、即时更新、不提升智商、能力来自工具、高风险仍需人工」；最典型陷阱是「知识永久写进参数、真正学会了」。

**⑦ 记忆锚点**：**「接知识库 → 有依据、可溯源、即时更新，但不提升智商、不等于微调；接工具 → 有执行力，但高风险动作必须留人工确认。」**

### M4-K14　Agent 的适用场景与局限性　🟢`[A]`

**① 一句话定义**：**该上 Agent 的信号**是"多步 + 需外部能力 + 需动态调整 + 验收标准可描述"；**不该上**的信号是"单轮可闭环"或"写不出验收标准"。

**② 是什么**：官方要求掌握「AI Agent 的基本能力、**适用场景、局限性**和协作使用方式」。适用场景即官方列举的五大任务：**信息提取、内容生成、资料分析、知识问答、办公自动化**（详见 M4-K17）。局限性则包括：错误会被执行出去、循环失控导致时延与成本、权限与越界风险、幻觉被放大并沿链路传播。

**③ 为什么**：Agent 的能力来自「自主多步 + 可调工具」，这两点同时也是它的成本来源——多步意味着**时延与调用成本**，可调工具意味着**权限风险**。所以「该不该上 Agent」本质是一个**投入产出判断**：任务越复杂、越多步、越需要外部能力，Agent 的净收益越大；任务越简单，上 Agent 只是**过度设计**。

**④ 怎么做 / 怎么用**：
- **该上**：从 50 份合同里提取金额与有效期并汇总成表（多步 + 需读文件 + 需结构化输出 + 可验收）。
- **不该上**：一句话问答、闲聊、常识解释（单轮即可，上 Agent 只增加时延、成本与出错面）；只缺私域知识（→ **知识库/RAG**）；只要求格式文风统一（→ **微调**）；单次固定动作如查一次天气（→ **单次工具调用**）；**验收标准写不出来的任务**（→ 先人工跑通流程再谈自动化）。

**⑤ 易错点**：
- ❌ 常见误解：任务越难越该上 Agent → ✅ 正确：**不为"难"而上**。难的**知识问题**走 RAG，难的**格式问题**走微调，只有"**多步且需要边看边调、还要调用外部能力**"才上 Agent。
- ❌ 常见误解：Agent 出错只是答错，不会造成实际损失 → ✅ 正确：**Agent 有执行力**，错了就是真做错了，这是它的主要局限。

**⑥ 考法提示**：常以「下列场景**不适合**使用 Agent 的是」出现，正确（不适合）项多半是**简单单轮问答**或**只需查一次资料**；也会以多选题形式问「Agent 的局限性包括哪些」，正确项含**错误会被执行出去 / 循环失控与成本 / 权限越界风险 / 幻觉沿链路传播**。

**⑦ 记忆锚点**：**"写不出验收标准的任务，不要交给 Agent 全自动跑。"** —— 这正是官方要求「自检清单要具体、可核对、有证据」的原因。

### M4-K15　Agent 的协作使用方式（人机分工）　🟢`[A]`

**① 一句话定义**：官方用的是「**协作**使用方式」——**Agent 是协作者，不是替代者**。

**② 是什么**：分工表（见第九章 9.3 完整版）：**人**负责定目标、定资料来源、定工具边界、阶段确认、高风险动作拍板、承担最终责任；**Agent** 负责检索、起草、计算、批量执行低风险动作，以及按清单自检。官方金句：「**AI 可以辅助整理和起草，但不能替代最终责任人**」。

**③ 为什么**：Agent 有执行力但无责任能力——它能把事做出来，却不能为后果负责；人有判断力与责任能力，但在"多、快、重复"上不如机器。官方把「**协作**」二字写进考点，就是要否定「Agent 全自动替代人」这一思路。

**④ 怎么做 / 怎么用**：对外发布公告的场景——Agent 负责：检索历史公告模板、起草初稿、对照自检清单核对口径与格式；**人**负责：确认内容、点击发布、为对外承诺担责。**Before**（全自动）：Agent 直接发布，错了一个数字就是对外承诺事故；**After**（协作）：Agent 出草稿，人终审后发布，效率保留了，责任也守住了。

**⑤ 易错点**：
- ❌ 常见误解：协作就是"人先看一遍 Agent 的输出"，其余不用管 → ✅ 正确：协作包含**事前设边界**（四要素）和**事中设检查点**，不只是末端看一眼。
- ❌ 常见误解：接入知识库与工具后，所有环节都可交给 Agent 全自动完成 → ✅ 正确：高风险动作**仍须人工确认**，且写不出验收标准的任务本就不该自动化。

**⑥ 考法提示**：多选题常把「所有环节可全自动、人不必介入」作为**核心错误项**，与之对应的正确项是「即便接入了知识库和工具，删除/外发/支付等动作仍须人工确认」（Q008 E 项，最易漏选）。

**⑦ 记忆锚点**：**「Agent 负责『多、快、稳地干』，人负责『定方向、设边界、拍高风险、担最终责任』。」**

### M4-K16　⭐ 概念层级辨析（工具 / MCP / Function Calling / Skill）　🟢`[A]`

**① 一句话定义**：**调用机制 ≠ 连接标准 ≠ 被执行对象 ≠ 作业方法**——四者层级不同，不能互换。

**② 是什么**：**Function Calling（L1）**是模型侧的**调用机制**，让模型把「我要调谁、传什么参」表达成结构化请求；**工具（L2）**是具体可执行某个动作的**能力单元**（查天气、建工单、写文件）；**MCP（L2）**是**连接侧**的通用方式，解决工具与数据源**怎么接进来**；**Skill（L4）**是把流程 + 所需工具 + 约束与验收标准封装成的**作业方法**。**Agent（L3）**是执行体，用大脑（L0 大模型）调度以上全部并对目标负责。

**③ 为什么**：这四个词在日常讨论中经常被混用（尤其在"接了一个工具"这类表述里），但它们的**层级、职责、归属**完全不同。官方在「建议掌握的知识」里把「**工具调用、MCP**」和「**Skill、自检闭环**」分别列出，本身就说明它们是**不同层次的东西**。这是本模块**最高频的混淆点**。

**④ 怎么做 / 怎么用**：用一个场景串起来——「帮我查库存并给缺货商品建补货工单」：Agent 收到目标 → 加载 **Skill**（规定先查库存、再比对安全库存、最后建单）→ 需要查库存时，模型通过 **Function Calling** 输出结构化调用请求 → 该工具是按 **MCP** 这种通用方式接进来的库存查询**工具** → 工具返回值回灌模型 → 继续下一步。四者各在其位，缺一不可。

**⑤ 易错点**：
- ❌ 常见误解：MCP 是一个功能强大的工具，可以直接替 Agent 完成查询库存等动作 → ✅ 正确：**MCP 是连接方式，能力来自被接入的具体工具**。
- ❌ 常见误解：有了 MCP 就不需要 Function Calling → ✅ 正确：**不同层次、通常共存**（模型侧 vs 连接侧）。
- ❌ 常见误解：Skill 与提示词没有本质区别 → ✅ 正确：Skill 含**工具集合 + 约束/验收标准 + 可复用**，官方定位是「固化重复工作方法」。
- ❌ 常见误解：模型直接执行工具 → ✅ 正确：模型**只输出调用请求**，执行在模型之外。

**⑥ 考法提示**：**必考一题（Q005）**。出题形式是四个选项各陈述一个概念，只有一个全对；干扰项固定四种错误：**MCP=工具**、**MCP 替代 Function Calling**、**Skill=长提示词**、**模型直接执行工具**。⛔ 绝不出现协议细节选项。

**⑦ 记忆锚点**：**「MCP ≈ 接口标准，工具 ≈ 外接设备，Function Calling ≈ 驱动调用，Skill ≈ 作业指导书，Agent ≈ 干活的人。」**

### M4-K17　五大典型应用：信息提取 / 内容生成 / 资料分析 / 知识问答 / 办公自动化　🟢`[A]`

**① 一句话定义**：官方「建议掌握的知识」原文列举的**五大落地任务**，也是「能够使用大模型和个人 AI Agent 辅助完成」的具体所指。

**② 是什么**：**信息提取**——从大量文档/网页中抽取结构化字段（合同金额、发票号、简历要素）；**内容生成**——写报告、文案、摘要、邮件；**资料分析**——读表取数、比对、归因、生成图表；**知识问答**——基于企业资料的问答（接知识库限定来源）；**办公自动化**——批量改文档、整理文件、生成工单、发通知。

**③ 为什么**：这五类任务有三个共同点，恰好匹配 Agent 的能力结构：① **步骤多**（不是一句话能答完的）；② **需要外部资料或外部动作**（要读文件、查系统、写结果）；③ **产出可验收**（能写成自检清单）。正因如此，官方才会把这五项写成 Agent 的落地任务清单。

**④ 怎么做 / 怎么用**：以**办公自动化**为例——每月初要把上月各区域的报销单据汇总、校验发票号是否重复、生成汇总表并发给财务。Agent 的用武之地：批量读取文件（感知）→ 抽取字段并查重（思考+工具）→ 生成汇总表（行动）→ 对照自检清单核对漏项（自检）→ 生成待发邮件交人确认（高风险留人工）。**Before**：人工半天；**After**：Agent 十几分钟完成，人只需终审。

**⑤ 易错点**：
- ❌ 常见误解：这五类任务都**必须**用 Agent 做 → ✅ 正确：它们只是**适合**用 Agent 辅助；简单的单轮内容生成（如写一封短邮件）直接调模型即可，上 Agent 是过度设计。
- ❌ 常见误解：「知识问答」只要接了模型就能做 → ✅ 正确：基于**企业资料**的问答必须接**知识库**并限定资料来源，否则模型会凭常识编造。

**⑥ 考法提示**：多选可能问「官方列举的可用大模型和个人 AI Agent 辅助完成的任务包括哪些」，五项全选；干扰项会混入「模型训练」「算法研发」「数据标注」等**非应用侧**内容。

**⑦ 记忆锚点**：**「抽取、生成、分析、问答、办公」**——五个词都是**做事**，不是**答题**。

### M4-K18　ReAct 范式与 Multi-Agent 分工（背景了解）　🟡`[B]`

**① 一句话定义**：**ReAct** = 「想一步（Reason）→ 做一步（Act）→ 看结果 → 再想」的循环范式；**Multi-Agent** = 多个 Agent 按角色分工、任务分发、结果汇总协作完成复杂任务。

**② 是什么**：ReAct 是 Agent 循环的一种经典表述，把「思考」与「行动」交替进行，并把**每步的观察结果**回灌进下一轮推理——这正是 M4-K02 三大能力闭环的具体运行方式。**Multi-Agent** 则是把复杂任务拆给不同角色的 Agent（如检索 Agent、写作 Agent、检查 Agent），各自完成后由汇总者合并结果。

**③ 为什么**：单轮「想完全部再动手」在开放环境里不现实——中间结果不可预知，必须边做边看。ReAct 的价值就在于**让计划可以被中间结果修正**。Multi-Agent 的价值在于**角色隔离**：每个 Agent 的目标更小、工具更少、更不容易跑偏，也更容易单独验收。

**④ 怎么做 / 怎么用**：写行业研究报告——检索 Agent 负责找资料，写作 Agent 负责成文，检查 Agent 负责对照自检清单挑错，最后汇总成稿。**注意**：Multi-Agent 与 **Skill 编排**不同——前者是**多个执行体分工**，后者是**一套流程按序调用多个 Skill/工具**。

**⑤ 易错点**：
- ❌ 常见误解：ReAct 和 Multi-Agent 是官方点名的必考考点 → ✅ 正确：官方「建议掌握的知识」**未单点列出**这两个词，本模块把它们降为**背景了解**，题库不出题；真正要背的是四要素、自检三要求、人工确认、Skill。
- ❌ 常见误解：Multi-Agent 就等于 Skill 编排 → ✅ 正确：前者是**多个执行体分工协作**，后者是**一个执行体按流程串接多个 Skill**。

**⑥ 考法提示**：若真的考到，只会以「下列说法正确的是」形式出现，且正确项一定是**常识性表述**（如"Agent 通常按思考—行动—观察的循环推进"）。**不会**考循环的具体轮次、角色数量、通信方式等实现细节。

**⑦ 记忆锚点**：**「想一步、做一步、看一眼、再想一步。」**

## 四、⭐⭐ Agent 四要素专章（官方最核心考点）

> **官方原文**：「掌握如何给 Agent 明确**目标、资料来源、工具边界和阶段检查点**。」

**一句话理解**：把 Agent 当成一个**新来的同事**——你交代得越含糊，它越会自由发挥；四要素就是一份让它不容易跑偏的"任务委托书"。

**四要素全景：**

| 要素 | 回答的问题 | 一句话定义 | 不明确时的典型后果 | 写明确的标志 |
|---|---|---|---|---|
| **目标** | 到底要交付什么？ | 交付物 + 范围 + 成功标准 | 做完了，但不是你要的 | 含交付物形态 + 范围 + 可判定的成功标准 |
| **资料来源** | 依据什么来答？ | 允许/禁用哪些信息源 | 混入模型记忆或臆测，编数据、不可追溯 | 指定来源 + 只用这些 + 查不到说未找到 + 要出处 |
| **工具边界** | 能动哪些东西？动到什么程度？ | 工具白名单 + 每个工具的可做/不可做 | 越权调用，误删、误发、误改 | 白名单 + 限定范围 + 禁用声明 + 高风险标注 |
| **阶段检查点** | 什么时候停下来给你看？ | 预设的暂停核对点，通过才继续 | 一步错步步错，错误被"执行"出去后返工成本极高 | 何时停 + 核对什么 + 不通过怎么处置 |

> 📌 **四要素之间的配套关系（易考辨析）**
> 「**阶段检查点**」讲的是**在什么时间点拦下来**；「**自检清单**」（第五章）讲的是**拦下来之后拿什么去核对**。两者必须成对出现——只设检查点没有清单，人/模型不知道看什么；只有清单没有检查点，错误会一路跑到最后才被发现。

---

### 4.1 要素① 目标 ⭐⭐

**是什么**：任务最终要交付的东西，以及"做成什么样算完成"。

**不明确会怎样**：Agent 会按它自己的理解自由发挥。最常见的结果是——**它确实干完了活，但干的是另一件事**。

**怎么写才算明确**（三个必填项）：

| 必填 | 说明 | 例子 |
|---|---|---|
| **交付物形态** | 具体是什么：一份报告 / 一个表格 / 一封邮件 / 一次工单创建 | 「输出一份 Markdown 周报文件」 |
| **范围边界** | 包含什么、**不包含什么**、时间范围、对象范围 | 「只覆盖 8 月华东大区，不含华南」 |
| **成功标准** | 什么叫做完、什么叫合格 | 「含 3 张图表，字数 ≤ 800 字，所有数字均可回溯到源表」 |

**Good vs Bad：**

| ❌ 模糊写法 | ✅ 明确写法 |
|---|---|
| 「帮我分析一下上月的销售数据」 | 「输出上月（2026-08）华东大区的销售分析，含同比/环比两张表与一段 200 字结论，所有数字必须能在『销售明细-08.xlsx』中找到同名行」 |
| 「写个周报，专业一点」 | 「按『周报模板v3』结构写周报，三个小节，每节 ≤ 3 条要点，不写主观评价」 |

---

### 4.2 要素② 资料来源 ⭐⭐

**是什么**：允许 Agent 依据哪些信息来回答问题/完成任务。

**不明确会怎样**（这是 Agent 最容易出事的一处）：
- Agent 会**默认使用模型自身的记忆**作答 → 知识可能过期、可能不是你们公司的口径
- 会把不同来源的信息混在一起，产出**看似合理实则拼凑**的结论
- 一旦出错**无法追溯、无法定责**——你不知道它这句话是从哪来的

**怎么写才算明确**（四项动作）：

1. **指定来源**：哪个知识库 / 哪个文件 / 哪个接口 / 哪个看板，尽量精确到版本或路径。
2. **限定排他性**：明确「**只用**这些来源」，其余一律不许参考。
3. **规定缺省行为**（最关键的一条）：来源里查不到时，**必须回答"未找到 / 未收录"**，禁止自行推测或补全。
4. **要求留出处**：每条关键结论标注来自哪个文档的哪一段，便于人工核查。

**示例：**

> ❌ 「根据公司资料回答客户关于退款政策的问题。」
> ✅ 「只依据知识库『售后政策-v3.2』中的内容回答；该库未收录的一律回答『该问题超出当前资料范围，需转人工确认』；每条回答结论后注明依据的章节名。」

---

### 4.3 要素③ 工具边界 ⭐⭐

**是什么**：Agent 被允许调用哪些工具，以及每个工具**能做什么、不能做什么、做到什么程度要停下**。

**不明确会怎样**：Agent 有行动能力却不设边界，等于把钥匙交给它还不告诉它哪些门不能开。典型事故：**误删文件、误发邮件、误改生产数据、误下单**。

**怎么写才算明确**（四件套）：

| 动作 | 说明 | 例子 |
|---|---|---|
| **工具白名单** | 明确列出可使用的工具，未列出的默认不可用 | 「只允许使用『读文件』『生成图表』两个工具」 |
| **范围限制** | 对同一工具限定作用范围 | 「读文件仅限 `/shared/report/` 目录」 |
| **读写/禁用声明** | 明确哪些操作被禁止 | 「禁止删除、禁止覆盖已有文件、禁止写入任何目录」 |
| **高风险动作标注** | 划出必须人工确认的动作（详见第六章） | 「发送外部邮件前必须经我确认」 |

**示例：**

> ❌ 「你可以用你能用的工具来帮我处理文件。」
> ✅ 「可调用『读取文件』与『生成图表』工具，作用目录限定为 `/shared/report/`，**禁止写入与删除**；涉及向外部邮箱发信时，必须生成草稿交我确认后由我发送。」

> 📌 **记忆锚点**：官方把「工具边界」和「**高风险动作必须人工确认**」放在同一句话里——**边界负责事前限制，人工确认负责事后兜底**，二者缺一不可。

---

### 4.4 要素④ 阶段检查点 ⭐⭐

**是什么**：在多步任务推进过程中，**预先约定好的暂停核对点**。到达该点时 Agent 停下来做自检或请人确认，**通过才进入下一阶段**。

**它解决的核心问题**：多步任务有依赖传递性——第 2 步错，第 3~N 步会基于错误结果继续跑，到最后才发现，**返工成本指数级上升**；如果中途还执行了真实动作（发邮件、改数据），损失已经无法撤回。

**怎么写才算明确**（三步式）：

```
在第【几步之后】停下来 → 核对【什么内容】 → 【通过】才继续，【不通过】怎么办（停下/回滚/转人工）
```

**示例：**

> ❌ 「你看着办，有把握就行。」
> ✅ 「① 数据抓取完成后，**先输出字段口径清单交我确认**，通过后才进入分析；② 分析结论生成后，**再对照自检清单核对一遍**；③ 最终报告发送前，**生成待发版本给我终审**。」

**常见的三类检查点：**

| 类型 | 放在哪里 | 拦什么 |
|---|---|---|
| **口径确认点** | 取数/检索之后、分析之前 | 拦住"取错数据、取错口径" |
| **中间结果自检点** | 每一步产出之后 | 拦住"字段缺失、格式不符、不可解析" |
| **终审发布点** | 对外交付/不可逆动作之前 | 拦住"错误结论被真实执行出去"（→ 第六章人工确认） |

> ⚠️ **高频辨析**：阶段检查点 ≠ 只是"让它慢一点"。它的价值在于**在错误还能低成本修正的时候把错误拦住**。

### 4.5 四要素速查卡（考前 1 分钟）

```
目标      → 交什么？管多宽？算做完？
资料来源  → 依据什么？查不到怎么办？（答：说未找到，不许编）
工具边界  → 能动哪些？禁止哪些？哪些要人确认？
阶段检查点→ 何时停下？核对什么？不通过怎么处置？
```

### 4.6 🆕 完整任务委托书示例（四要素合体）

> 把四要素写进同一段话，就是一份合格的「任务委托书」。下面的示例可直接照抄改造。

```
【任务】生成本月（2026-09）华东大区经营分析周报

① 目标
   交付物：一份 Markdown 周报文件，含同比、环比两张表与一段 ≤200 字的结论
   范围  ：仅华东大区，不含华南；时间范围为 2026-09-01 ~ 2026-09-30；不含退货数据
   成功标准：所有数字可回溯到源表；结论不含主观评价

② 资料来源
   只允许使用『经营数据/2026-09.xlsx』与知识库『经营分析口径-v2.1』
   不得使用上述来源之外的任何资料，也不得依据模型自身记忆补充
   查不到的字段一律标注「未找到」，禁止自行推测或按行业惯例补全
   每条结论后注明来源文件名 + 页签/章节

③ 工具边界
   只允许调用「读取文件」与「生成图表」两个工具
   读取范围限定为 /shared/report/ 目录
   禁止写入、覆盖与删除任何文件；禁止调用发消息、发邮件类工具

④ 阶段检查点
   检查点1（取数后）：先输出字段口径清单交我确认，通过后才进入分析
   检查点2（分析后）：对照自检清单逐项核对，未通过项列明并修正
   检查点3（交付前）：生成待发版本交我终审；如需对外发送，由我本人发送
```

> 📌 **做题时的检验法**：拿到一个场景选项，用四要素逐条打勾——**四条全中的才是最佳答案**，缺一条就不是（Q002 的 C 项就是缺了资料来源与阶段检查点）。

## 五、⭐⭐ 自检清单三要求专章（官方原话：具体、可核对、有证据）

> **官方原文**：「**自检清单要具体、可核对、有证据。**」

**定位一句话**：自检清单是 Agent 交付前的**验收闸门**——写得好，它是过滤器；写得含糊，它只是一句自我安慰。

| 要求 | 回答的问题 | 含义 | 怎么检验这条够不够格 |
|---|---|---|---|
| **具体** | 检查**什么**、按**什么门槛**判定？ | 把"好不好"翻译成"哪个字段、满足什么条件"；含对象、环节、判定阈值 | 换个不熟业务的人来对照，**能不能得到同一个结论**？ |
| **可核对** | 能不能**逐项打勾**判定通过/不通过？ | 每条都能被机械地执行并给出是/否，不依赖主观感觉 | 这条能不能做成一张**逐项打勾的表**？还是只能"看着差不多"？ |
| **有证据** | 凭什么说它过了？ | 每条都要求留下**可展示的凭证**（原文出处、工具返回值、计算结果、失败报错），供第三方复核 | 别人复核时，能不能**看到那条凭证**，而不是只看到一个"✅"？ |

> 📌 **三者关系**：**具体**解决"检查项不存在歧义"，**可核对**解决"结论可以稳定复现"，**有证据**解决"结论可以被追责和复盘"。缺任一条，清单都会退化成形式。

---

### 5.1 反例：模糊的清单长什么样（考试常拿来当错误选项）

| ❌ 模糊写法 | 它违反了哪一条 | 为什么没用 |
|---|---|---|
| 「检查一下内容是否准确」 | 不**具体** | 什么叫准确？没有判定对象与门槛，模型只能自己给自己发合格证 |
| 「确保整体质量达标」 | 不具体 + 不可核对 | 全靠主观感觉，不同人不同 Agent 结论完全不同 |
| 「数据应该是正确的」 | 不可核对 | 没有数据源可比对，无法逐项判定 |
| 「注意不要有错误」 | 不可核对 | 这是**祈使句**，不是检查项；没有"查出来了怎么办"的动作 |
| 「已检查完毕」 | 无**证据** | 只有一个结论，没有留下任何可供复核的凭证 |
| 「不合格就重新生成一遍」 | 无靶向 + 无证据 | 不说**哪里**不合格，大概率重犯同样错误，也不留凭证 |

> ⚠️ **识别口诀**：凡是出现「**准确 / 合理 / 完善 / 适当 / 差不多 / 质量好**」这类形容词而**没有判定门槛和凭证**的，一律是不合格清单。

---

### 5.2 正例：合格的清单长什么样

| 检查项 | 具体（对象+门槛） | 可核对（怎么打勾） | 有证据（留下什么） |
|---|---|---|---|
| 数据一致性 | 报告中每个数字必须能在源表 `销售明细-08.xlsx` 的「华东」页签找到同名行 | 逐个数字回溯比对，命中为✅、查无为❌ | 记录每个数字的**源表行列位置** |
| 依据可溯源 | 每条政策结论必须注明知识库文档名 + 章节号 | 缺出处的条目直接判❌ | 保留检索到的**原文片段** |
| 格式可交付 | 输出必须能被标准 JSON 解析器解析，且含 5 个指定字段 | 跑一次解析，通过为✅ | 保留**解析结果 / 报错信息** |
| 范围合规 | 不得出现来源清单之外的任何数据来源 | 列出全部引用来源与白名单比对 | 保留**引用来源清单** |
| 工具安全 | 本轮未调用任何白名单外的工具，未发生删除/外发操作 | 比对工具调用日志 | 保留**调用记录**（详见 M6 审计追踪） |

### 5.3 🆕 可复用模板（直接套用）

```
自检清单（每条后面必须能贴上证据）
□ 交付物形态符合要求：________（附：文件/输出预览）
□ 必填字段齐全，无空缺：________（附：字段清单）
□ 每个数字可回溯到指定源：________（附：源表行列位置）
□ 每条结论有出处（文档名+章节）：________（附：原文片段）
□ 未引用白名单外的来源：________（附：引用清单）
□ 未发生禁止类工具调用：________（附：调用记录）
□ 未通过项已列出并已修正/已转人工：________
```

> 📌 **四条不合格判定**：凡检查项里出现 **① 形容词没有门槛**、**② 结论没有凭证**、**③ 只有要求没有动作**、**④ 不合格了没有处置** 中的任何一条，就不算合格的清单。

### 5.4 🆕 三个「不等于」（高频混淆点，必考）

| # | 说法 | 判断 | 正解 |
|:---:|---|---|---|
| ① | 自检清单齐全 = 可以不要人工审核 | ❌ | 自检是 **Agent 按清单自动核对**，解决的是"常见错误可以批量拦住"；**高风险动作的拍板权在人**（第六章）。官方把两者并列写出，说明**自检替代不了人工确认** |
| ② | 按清单自检 = 让模型多生成几个版本挑最好的（best-of-N 采样） | ❌ | best-of-N 只是**多次采样择优**——只有"挑"，没有"针对发现的具体问题去修正"，也不产生证据；自检是「**逐项核对 → 发现具体不符 → 带着问题修正 → 再审**」，有明确的修正靶向与留痕 |
| ③ | 有自检闭环 = 结果百分百正确 | ❌ | 清单本身可能有漏洞、模型自评也可能不准。自检提升的是**稳定性与可拦截率**，**不是消除错误**；且必须设**重试/停止上限**，超限**转人工** |

> 📌 **一句话收口**：**自检能拦住"清单里写到的错"，拦不住"清单之外的错"；能降低错误率，不能保证零错误；能减少人工工作量，不能免除人工拍板。**

## 六、⭐ 高风险动作必须人工确认专章（官方硬性规则）

> **官方原文**：「**高风险动作必须人工确认。**」
> ⚠️ 注意这是官方给出的**陈述句规则**，不是建议。凡看到选项说「自检足够完善时可免除人工确认」「由 Agent 自主判断是否跳过确认」，一律判错。

### 6.1 哪些算高风险动作

判据很简单——满足以下任一条即视为高风险：**不可逆（undone 成本极高）**、**对外产生实际影响**、**涉及资金/数据资产/他人权益**。

| 类别 | 典型动作 | 为什么高风险 |
|---|---|---|
| **删除 / 覆盖** | 删除文件、清空目录、覆盖已有文档、删库 | **不可逆**，误操作难以恢复 |
| **对外发送** | 发邮件/群消息给客户或外部联系人、提交表单、发布至公网 | 一旦发出**无法撤回**，且直接影响公司形象 |
| **支付 / 交易** | 下单、付款、退款、修改价格、动用额度 | 直接涉及**资金**，损失真实且难以追回 |
| **改生产数据** | 修改线上数据库、变更配置、执行生产环境命令 | 影响真实业务运行，可能引发**系统性故障** |
| **对外发布** | 发布公告、发布营销内容、对外答复政策口径 | 属于**对外承诺**，错发的代价远高于内部草稿 |
| **合同 / 承诺类** | 生成并签署合同、给出法律/医疗/金融结论 | 官方 M6 明确的高风险领域，**AI 不能替代最终责任人** |

### 6.2 为什么要人工确认

1. **Agent 会犯错，且错误是有执行力的**——普通问答错了只是答错，Agent 错了是**做错了**，损失已经发生。
2. **自检清单拦不住"清单之外的错"**——清单是人写的，覆盖不到的盲区恰恰是最危险的地方。
3. **责任不能被转移**——官方金句：「**AI 可以辅助整理和起草，但不能替代最终责任人。**」
4. **合规要求**——医疗、金融、合同、对外发布等场景本身就要求人工复核留痕（详见 M6）。

### 6.3 怎么落地（三件套）

| 落地手段 | 做法 | 对应四要素 |
|---|---|---|
| **① 事前划定清单** | 明确列出哪些动作属于高风险、必须停下来等人 | **工具边界**（4.3） |
| **② 事中卡住执行** | 到达高风险动作时**只生成待执行草稿/预案**，由人点击才真正执行 | **阶段检查点**（4.4） |
| **③ 事后留痕可查** | 记录谁确认的、确认了什么、依据是什么 | M6 **审计追踪 / 来源留存** |

**示例：**

> ❌ 「接到告警后，你可以自行判断是否需要重启服务并直接执行。」
> ✅ 「接到告警后先完成查询与原因分析并输出处置建议；涉及**重启服务、回滚版本、修改生产配置**的动作，一律生成操作预案提交我确认，**未经确认不得执行**；执行过程与确认人全程留痕。」

### 6.4 🆕 事前确认 vs 事后留痕（必须分清）

| 维度 | **事前确认** | **事后留痕** |
|---|---|---|
| 发生时机 | 动作执行**之前** | 动作执行**之后** |
| 作用 | **拦住**尚未发生的不可逆动作 → **阻止损失** | 记录已发生的事实 → **追责、复盘、审计** |
| 能否止损 | ✅ 能 | ❌ 不能 |
| 典型错误项 | 「自检完善即可自主执行」 | 「事后补一条执行记录可代替事前确认」 |
| 二者关系 | **必须并存**：先确认，再执行，全过程留痕。**事后留痕不能替代事前确认。** | |

### 6.5 🆕 与 M6「人工复核」的关系

| 维度 | M4 本考点（**人工确认**） | M6 考点（**人工复核**） |
|---|---|---|
| 官方出处 | 考试内容 5：「高风险动作**必须人工确认**」 | 考试内容 6：「AI 可以辅助整理和起草，但**不能替代最终责任人**」 |
| 着眼点 | **动作层面**：这一步要不要由人点了才执行 | **责任与合规层面**：最终责任由谁负、是否留痕可审计 |
| 触发条件 | 落到**具体高风险动作**（删除/外发/支付/改生产数据/对外发布） | 落到**高风险场景**（医疗、金融、合同、对外发布） |
| 关系 | **同一件事的两个视角**：M4 管"**做之前拦住**"，M6 管"**做了之后谁负责、怎么审计**"。考试中两者常同时出现，**都要选** | |

### 6.6 易错辨析

| 说法 | 判断 | 说明 |
|---|---|---|
| 自检闭环做得足够好，高风险动作就可以由 Agent 自主执行 | ❌ | 官方明确「**必须**人工确认」，且自检无法覆盖清单之外的错误 |
| 人工确认只针对对外发布类动作 | ❌ | 删除、支付、改生产数据同样属于高风险 |
| 高风险动作让 Agent 生成草稿、由人审阅后执行，符合要求 | ✅ | 这正是官方「协作方式」的典型落地 |
| 人工确认只需要有一个人点确认，不需要留痕 | ❌ | 合规要求留痕可追溯（详见 M6） |
| 事后补记一条执行记录可以代替事前确认 | ❌ | 留痕不能止损，也无法替代确认（见 6.4） |
| 桌面 Agent 只是本地工具，删除本地文件不算高风险 | ❌ | 删除/覆盖本地文件同样**不可逆**，属高风险动作 |

## 七、Skill、工具调用、MCP、知识库、桌面 Agent

### 7.1 ⭐ Skill：固化重复工作方法（官方措辞）

> **官方原文**：「理解 **Skill 用来固化重复工作方法**。」

**定义（用官方措辞背）**：**Skill 是把一套重复性的工作方法固化下来、可反复调用的可复用单元。**

```
Skill = 流程步骤（先做什么、后做什么）
      + 所需工具（每一步要调用哪些工具 / 查哪个知识库）
      + 约束与验收标准（格式要求、禁用行为、什么算做合格）
```

**为什么需要 Skill（它解决的痛点）**：同一件事每次都靠临时写一段长提示词 → 说法不一致、工具调用顺序全靠当时的心情、质量和格式不稳定、别人无法复用。**Skill 把"这次怎么说"变成"这套活儿以后都这么干"。**

#### 7.1.1 Skill 与提示词的区别（考辨析必背）

| 对比维度 | Skill | 提示词 |
|---|---|---|
| 官方定位 | **固化重复工作方法** | 优化单次输入（见 M2） |
| 粒度 | 一套**完整的多步工作方法** | 一次交互的说法/指令 |
| 是否含工具编排 | ✅ 明确规定了何时调哪个工具 | ❌ 一般不含 |
| 是否含验收标准 | ✅ 通常自带，直接支撑自检清单 | 视写法而定 |
| 复用性 | 沉淀为**可复用资产**，换人换会话直接套用 | 每次重写、难沉淀 |
| 适用前提 | **重复性**工作（会做很多遍） | 一次性或探索性任务 |

#### 7.1.2 Skill 编排

把多个 Skill / 工具按依赖关系组织成一个工作流（A 的产出是 B 的输入，或按条件分支选择不同 Skill）。

> 📌 **辨析**：**Skill 编排 ≠ Multi-Agent**。前者是**一个执行体按流程串接多个 Skill**，后者是**多个执行体分工协作**（见 9.4）。

#### 7.1.3 Skill 在概念层级中的位置（速览）

```
L4  Skill（作业方法：流程 + 工具 + 约束/验收）   ← 规定"这件事该怎么干"
L3  Agent（执行体：感知—思考—行动循环）          ← 按 Skill 干活
L2  工具（能力单元）｜MCP（接入方式）            ← 提供"能做什么 / 怎么接进来"
L1  Function Calling（结构化表达调用意图）        ← 模型侧的调用机制
L0  大模型（理解 + 推理 + 生成）                 ← 底座
```

> 📌 **一句话**：工具回答"**能做什么**"，Skill 回答"**这件事该怎么干**"，**Skill 编排**回答"**这些事按什么顺序干**"。

#### 7.1.4 三个「不是」

| 说法 | 判断 | 正解 |
|---|---|---|
| Skill 等于一句写得很长的提示词 | ❌ | 关键增值在于**工具集合 + 约束/验收标准 + 可复用** |
| Skill 会给模型增加新能力 | ❌ | 它封装的是**已有的模型能力 + 工具**，不产生新能力 |
| 用了 Skill 就一定能做对 | ❌ | 流程设计本身有问题照样错，仍需自检清单与阶段检查点 |

---

### 7.2 工具调用（Function Calling）

**一句话：模型不执行工具，模型只是"说出"它想调用什么。**

```
① 事先告诉模型有哪些工具（名称 / 功能描述 / 入参格式）
② 模型判断需要用工具时，输出【结构化的调用请求】（工具名 + 参数）
③ 由模型之外的运行时（Agent）执行该工具，拿到返回值
④ 把返回值作为新的上下文回灌给模型，模型继续推理或直接作答
```

| 要点 | 说明 |
|---|---|
| 模型负责 | 决定"**要不要调、调哪个、参数填什么**" |
| 运行时负责 | 真正执行、处理异常、把结果回灌 |
| 为什么必须结构化 | 自然语言不可靠，结构化请求才能被程序稳定解析执行 |
| **不解决什么** | 工具调用**不给模型增加知识**（那是知识库/微调），也**不保证结果正确**（工具可能失败、参数可能填错） |

> ⚠️ 最高频陷阱：「模型在执行过程中**直接执行**被调用的程序」 → ❌，**执行在模型之外**。

---

### 7.3 MCP（只考作用与定位，主考点在 M3）

> ⛔ **官方明示不考协议实现细节**（握手、报文格式、传输方式、JSON-RPC 等一律不考）。
> 📌 **主考点归属 M3**（官方把 MCP 放在「考试内容 3 · 增强大模型应用的能力」）。本模块只掌握下面这一句用法层表述。

**本模块要掌握的全部内容（一句）：**

> **MCP 是一套让 Agent / 应用更方便地连接外部工具与数据源的通用方式**——按同一方式适配一次，就可以被多处使用，不必为每个工具单独做一套对接。

**必须记住的两条边界：**

| 说法 | 判断 | 原因 |
|---|---|---|
| MCP 是一个具体好用的工具 | ❌ | MCP 是**连接方式/标准**，真正执行动作的是被连进来的**工具** |
| MCP 等同于 Function Calling | ❌ | Function Calling 是**模型侧**的调用机制（怎么表达调用意图）；MCP 是**连接侧**的方式（工具与数据源怎么接进来）。**层次不同、不是互相替代** |

> 📌 **类比速记**：MCP ≈ **接口标准**（Type-C），工具 ≈ **外接设备**（U 盘、打印机），Function Calling ≈ **发出的驱动调用**，Agent ≈ **用电脑干活的人**。
> ⚠️ 类比只用于理解定位，**考试不会考接口如何实现**。

---

### 7.4 个人 AI Agent 接入知识库

**Agent + 知识库 = 既有依据地回答、又能动手把事做掉的「执行体」。**

| 只有知识库（RAG） | 只有工具调用 | 知识库 + 工具调用（Agent） |
|---|---|---|
| 能查到答案并讲清楚 | 能做事但**不知道你的规矩** | **按库里的规矩做事** |

典型链路：用户提需求 → Agent 先**检索知识库**拿到依据/标准/模板（这就是四要素中的「**资料来源**」）→ 依据检索结果**调用工具执行** → 输出交付物并附出处。

**接了知识库，哪些变了、哪些没变（高频辨析）：**

| ✅ 变了 | ❌ 没变 |
|---|---|
| 能使用**私域/最新**知识，结论可追溯出处 | **不提升模型本身**的推理能力 |
| 减少"不知道就编"的幻觉 | **不等于把知识永久写进模型参数**（那是**微调**） |
| 文档更新后**立即生效**，无需重新训练 | **不等于获得执行外部动作的能力**（那是**工具**） |

### 7.5 桌面 Agent

> ⚠️ **产品名称待核实**：具体产品名称、安装包获取方式、菜单路径**不在本资料考证范围内**，也不考安装步骤与配置项。**只考概念与定位。**

**桌面 Agent = 运行在用户本地设备上的 Agent 形态。**

| 维度 | 桌面 Agent（本地） | 云端 Agent（服务端） |
|---|---|---|
| 运行位置 | **用户自己的电脑 / 本地环境** | 云端服务器 |
| 可达资源 | **本地文件系统、本地命令行/终端、本地已安装软件** | 云端 API、SaaS 服务、云数据库 |
| 典型任务 | 整理本地文件夹、批量重命名、读改本地文档、跑本地脚本 | 在线助手、定时任务、事件触发流程 |
| 关键特点 | 数据可留在本机、贴近个人工作流 | 可长期在线、多端访问、易横向扩展 |

**三条核心考点：**
1. **形态定位**：本地运行 → 能触碰**本地文件与终端**，这是它区别于云端 Agent 的关键。
2. **因为是同一套范式**，桌面 Agent 依然遵循「感知—思考—行动」，四要素、Skill、自检清单、人工确认**同样适用**。
3. **风险同源放大**：拥有本地文件/终端权限 → **权限最小化** + **高风险动作人工确认**（删除、覆盖本地文件属高风险）缺一不可。

## 八、⭐ 概念层级辨析（用官方用词）

### 8.1 四层结构图（本模块最高频混淆点）

```
┌──────────────────────────────────────────────────────┐
│ L4  作业方法：Skill（流程SOP + 所需工具 + 约束/验收标准）    │
│      └─ Skill 编排：多个 Skill 按依赖组成工作流            │
├──────────────────────────────────────────────────────┤
│ L3  执行体：Agent（感知-思考-行动循环，对目标负责；含桌面形态）│
├──────────────────────────────────────────────────────┤
│ L2  连接与执行：MCP（怎么接进来）｜工具（连进来后能做什么）    │
├──────────────────────────────────────────────────────┤
│ L1  调用机制：Function Calling（结构化地表达调用意图）       │
├──────────────────────────────────────────────────────┤
│ L0  基础：大模型（理解 + 推理 + 生成）                     │
└──────────────────────────────────────────────────────┘
```

> 说明：Skill（作业方法）位于最上层，它**规定** Agent 该按什么流程调用哪些工具；Agent 位于 Skill 之下，是被调度去干活的执行体。**层级是"谁规定谁"，不是"谁包含谁"，考试只要求能区分四者定位。**

### 8.2 一句话区分（横向对照表）

| 概念 | 一句话 | 类比 | 常被误认为 |
|---|---|---|---|
| **Function Calling** | 模型**表达"我要调用谁、传什么参"**的机制 | 发出的驱动调用 | 被当成工具本身 |
| **工具 / 工具调用** | 具体可执行某个动作的能力单元 | 外接设备（U 盘、打印机） | 被当成连接方式 |
| **MCP** | 让 Agent **把工具与数据源接进来**的通用方式 | Type-C 接口标准 | 被当成工具本身 |
| **Skill** | 把一堆工具 + 流程 + 规矩封装成的**工作方法** | 作业指导书 / SOP | 被当成一句长提示词 |
| **Agent** | 用大脑（L0）调度以上全部、**为目标负责**的执行体 | 干活的人 | 被当成"更强的模型" |

### 8.3 四组常考对比结论

1. **MCP ≠ 工具**：MCP 是"**怎么接进来**"，工具是"**接进来之后能提供什么能力**"。
2. **MCP ≠ Function Calling**：Function Calling 在**模型侧**（如何把意图说成结构化请求）；MCP 在**连接侧**（工具与数据源如何接进来）。二者不在同一层，**不是互相替代**关系。
3. **Skill ≠ 提示词**：提示词偏"**这次怎么说**"；Skill 是"**这套活儿以后都这么干**"，且含工具集合与验收标准，是可复用资产。
4. **Agent ≠ 更强的模型**：Agent 是**基于大模型的应用架构**，模型能力仍是底座；也没有"有了 Agent 就不需要好提示词"这回事。

## 九、⭐ 适用场景、局限性与协作使用方式

> **官方原文**：「AI Agent 的基本能力、**适用场景、局限性**和**协作使用方式**。」

### 9.1 适用场景（该上 Agent 的信号）

**官方「建议掌握的知识」列举的五大任务：**

| 任务类型 | 说明 | Agent 的用武之地 |
|---|---|---|
| **信息提取** | 从大量文档/网页中抽取结构化字段 | 检索 + 抽取 + 按字段清单自检 |
| **内容生成** | 写报告、文案、摘要 | 查资料 → 按模板生成 → 对照清单自检 |
| **资料分析** | 读表取数、比对、归因 | 多次取数 + 反复验证 + 阶段检查点 |
| **知识问答** | 基于企业资料的问答 | 接知识库限定**资料来源**，答不上就说未找到 |
| **办公自动化** | 批量改文档、整理文件、生成工单、发通知 | 多步执行 + 工具调用 + 高风险动作留人工确认 |

**该上 Agent 的五个信号（满足越多越该上）：**
1. 任务**无法一步完成**，需要拆成多步
2. 步骤间**有依赖**，下一步取决于上一步结果
3. 需要调用**外部能力**（检索、接口、文件、终端）
4. 需要根据中间结果**动态调整**计划
5. 验收标准**可描述**（能写成自检清单）

---

### 9.2 局限性（何时不该上 Agent）

| 场景 | 不该上 Agent 的原因 | 应改用什么 |
|---|---|---|
| 一句话问答、闲聊、常识解释 | 单轮即可，**上 Agent 只会增加时延、成本与出错面** | 直接调用模型 + 优化提示词 |
| 只缺私域/最新知识，不需要执行动作 | 本质是"不知道"，不是"不会做" | **知识库 / RAG** |
| 只要求统一的格式、语气、风格 | 本质是"行为不稳定" | **微调** |
| 单次固定动作（查一次天气、翻译一句） | 单步即可闭环 | 单次**工具调用**即可 |
| 验收标准写不出来 | **无法写自检清单 → 无法验收 → 不该自动化** | 先人工跑通流程，再考虑固化 |

> 📌 **最重要的一条局限性**：**写不出验收标准的任务不要交给 Agent 全自动跑。** 这正是官方要求「自检清单要具体、可核对、有证据」的原因。

**其他固有局限：**

| 局限 | 表现 | 应对方向 |
|---|---|---|
| **错误会被执行出去** | 普通问答错了只是答错；Agent 错了会真的造成损失 | 阶段检查点 + **高风险动作人工确认** |
| **循环失控 / 成本与时延** | 多轮调用重复打转，token 与时延远超单轮问答 | 明确适用范围、**设重试与步数上限**、超时停止 |
| **权限与越界风险** | 拥有文件/终端/接口权限后误删、误改、误发 | **权限最小化**、工具边界白名单、留审计记录 |
| **幻觉被放大、错误沿链路传播** | 一步错导致后续全错 | 指定资料来源、要求标注出处、阶段检查点分段拦 |

---

### 9.3 协作使用方式（人与 Agent 怎么分工）

> 官方把它写成「**协作**使用方式」，隐含的判断是：**Agent 是协作者，不是替代者。**

| 环节 | 谁主导 | 具体动作 |
|---|---|---|
| **定目标** | **人** | 明确交付物、范围、成功标准（M4-K03） |
| **定资料来源** | **人** | 指定可用/禁用来源与查不到怎么办（M4-K04） |
| **定工具边界** | **人** | 白名单、读写限制、高风险动作清单（M4-K05） |
| **检索 / 起草 / 计算 / 批量执行低风险动作** | **Agent** | 多轮取数、草稿生成、格式化输出 |
| **自检** | **Agent** | 按「具体·可核对·有证据」的清单逐项核对并修正 |
| **阶段确认** | **共担** | Agent 到检查点停下提交，人确认是否继续 |
| **高风险动作拍板** | **人** | 删除、外发、支付、改生产数据、对外发布（M4-K08） |
| **最终责任** | **人** | 官方金句：**AI 可以辅助整理和起草，但不能替代最终责任人** |

> 📌 **一句话**：**Agent 负责"多、快、稳地干"，人负责"定方向、设边界、拍高风险、担最终责任"。**

### 9.4 🆕 Multi-Agent（角色分工、任务分发、结果汇总）

> 🟡`[B]` **背景了解**：官方「建议掌握的知识」**未单点列出 Multi-Agent**，本模块不出题，只需能与 Skill 编排区分。

| 维度 | **Multi-Agent** | **Skill 编排** |
|---|---|---|
| 主体 | **多个**独立 Agent，各有角色与目标 | **一个**执行体按流程串接多个 Skill |
| 核心机制 | **角色分工 + 任务分发 + 结果汇总** | **依赖关系 + 顺序/分支** |
| 典型角色 | 检索 Agent、写作 Agent、检查 Agent、汇总 Agent | 取数 Skill → 分析 Skill → 分发 Skill |
| 适用 | 任务面宽、可并行、需要不同"视角" | 流程固定、步骤串行、强调一致性 |

> ⚠️ **考试提示**：题干若描述"把一套方法固化下来、同事换个会话也能套用"→ 这是 **Skill**，不是 Multi-Agent（Q004 的 D 项即为此陷阱）。

## 十、⭐ 本模块高频陷阱 TOP 10

> 按丢分频率排序。**这 10 条覆盖了本模块绝大多数失分点，考前必看。**

| # | 陷阱 | ❌ 典型错误想法 | ✅ 正解（官方口径） |
|:---:|---|---|---|
| 1 | **自检完善即可免除人工确认** | 「清单写得够全，高风险动作就能交给 Agent 自主执行」 | 官方：**高风险动作必须人工确认**，无例外；自检拦不住清单之外的错 |
| 2 | **把四要素与三大能力/提示词要素混淆** | 「四要素是感知、思考、行动、记忆」 | 四要素 = **目标 / 资料来源 / 工具边界 / 阶段检查点**；感知-思考-行动是**基本能力** |
| 3 | **MCP = 工具** | 「接上 MCP，Agent 就能查库存、建工单」 | MCP 是**连接方式/标准**，能力来自**被接入的具体工具** |
| 4 | **MCP 协议细节是考点** | 「要看握手 / 报文 / 传输层才能判断」 | 官方：**不要求掌握协议细节**；出现这类词的选项**一律不选** |
| 5 | **模型直接执行工具** | 「模型在推理过程中把程序跑了一遍」 | 模型**只输出结构化调用请求**，**执行在模型之外** |
| 6 | **Skill = 一句长提示词** | 「Skill 就是把提示词写长一点」 | Skill = **流程 + 所需工具 + 约束/验收标准 + 可复用**，官方定位「**固化重复工作方法**」 |
| 7 | **知识库 = 永久学会** | 「接入知识库后文档内容就写进模型参数了」 | 检索是**外挂**，文档更新即刻生效；「写进参数」是**微调**的事 |
| 8 | **模糊清单当合格清单** | 「检查内容是否准确、确保质量达标」 | 必须 **具体（对象+门槛）/ 可核对（能打勾）/ 有证据（留凭证）** |
| 9 | **自检 = best-of-N 采样择优** | 「多生成几版挑一个最好的就是自检」 | best-of-N 只"挑"不"改"、无证据；自检是**逐项核对→带着问题修正→再审** |
| 10 | **Agent 出错只是答错** | 「它说错了改一下就行，没什么损失」 | **Agent 有执行力**，错误会被**真实执行出去**（这是它最大的局限） |

> 🔻 **三个次级陷阱（出现频率略低但同样致命）**：
> - **「事后补一条记录代替事前确认」** —— 留痕只能追责，不能止损；**事前确认不可省略**。
> - **「桌面 Agent 是另一种技术路线 / 推理能力更强」** —— 同一套范式，**只是部署形态与可达资源不同**，推理能力由底层模型决定。
> - **「所有环节都能交给 Agent 全自动」** —— 官方用词是「**协作**使用方式」，且**写不出验收标准的任务不该自动化**。

## 十一、⭐ 本模块必背清单（考前 10 分钟过一遍）

### 11.1 官方原话（一字不改地背）

> 1. 「Agent 的价值是把「回答问题」推进到「**完成任务**」。掌握如何给 Agent 明确**目标、资料来源、工具边界和阶段检查点**。理解 **Skill 用来固化重复工作方法**，**自检清单要具体、可核对、有证据**。**高风险动作必须人工确认。**」
> 2. 「AI Agent 的基本能力、**适用场景、局限性**和**协作使用方式**。」
> 3. 「**Skill、自检闭环**等帮助 Agent 沉淀方法和提升输出质量的实践方式。」
> 4. 「**AI 可以辅助整理和起草，但不能替代最终责任人。**」

### 11.2 必背八条

| # | 必背结论 | 一句话展开 |
|:---:|---|---|
| 1 | **Agent 的价值 = 完成任务** | 不是答得更准，而是**真的把事做完**；问答式产出文字，Agent 产出实际成果 |
| 2 | **四要素** | **目标 / 资料来源 / 工具边界 / 阶段检查点**（考"给 Agent 明确什么"必选这四项） |
| 3 | **查不到就说未找到** | 资料来源的**缺省行为**，禁止自行推测补全 |
| 4 | **检查点管"何时拦"，清单管"拦下来查什么"** | 二者成对出现，缺一不可 |
| 5 | **自检三要求** | **具体（查什么+门槛）/ 可核对（能打勾）/ 有证据（留凭证）** |
| 6 | **三个不等于** | 自检 **≠** 人工确认，**≠** best-of-N，**≠** 百分百正确（且要设重试上限） |
| 7 | **高风险清单** | **删除 / 外发 / 支付 / 改生产数据 / 对外发布 / 合同承诺** → 人工确认；事前确认 ≠ 事后留痕 |
| 8 | **概念层级** | MCP（怎么接）≠ 工具（做什么）≠ Function Calling（怎么表达）≠ Skill（怎么干） |

### 11.3 金句速查（考场默念）

- **官方**：**「Agent 的价值是把『回答问题』推进到『完成任务』。」**
- **四要素**：**「交什么、依据什么、能动哪些、何时停下。」**
- **资料来源**：**「宁可说未找到，也不能编。」**
- **自检**：**「具体=查什么，可核对=能不能打勾，有证据=凭什么说它过了。」**
- **人工确认**：**「能不能撤回？会不会影响外人？涉及钱和责任吗？」**
- **Skill**：**「工具回答能做什么，Skill 回答这件事该怎么干。」**
- **MCP**：**「标准不是设备；插上接口不等于有人帮你打了文件。」**
- **协作**：**「Agent 负责多快稳地干，人负责定方向、设边界、拍高风险、担责任。」**
- **术语**：官方统一说法是「**工具 / 工具调用**」。

## 十二、易错辨析表

### 12.1 手段辨析：该用哪个（官方五选一 + 人工确认）

| 需求 | 正确方案 | 典型错误选法 |
|---|---|---|
| 回答质量不稳定、理解有偏差 | **优化输入（提示词）** | 上 Agent |
| 缺公司制度、最新产品信息等私域/时效知识 | **接入知识库（RAG）** | 微调 |
| 需要实时数据、确定性计算或业务动作 | **调用工具** | 微调 |
| 输出格式、文风不统一 | **微调** | 知识库 |
| 多步任务 + 需边看结果边调整 + 调外部工具 | **协作 Agent** | 单次工具调用 |
| **删除 / 外发 / 支付 / 改生产数据 / 对外发布** | **保留人工确认** | 交给 Agent 自主执行 |
| 把一套多步骤工作方法沉淀复用 | **Skill** | 每次重写长提示词 |
| 想让产出稳定达标 | **具体·可核对·有证据的自检清单 + 自检闭环** | 多生成几份挑一个（best-of-N） |
| 简单单轮问答 | **直接调模型** | 上 Agent（过度设计） |

### 12.2 四要素辨析

| 做法 | 属于哪个要素 |
|---|---|
| 「输出一份 ≤800 字、含 3 张图表的周报」 | **目标** |
| 「只依据知识库『售后政策-v3.2』，库中没有就答未找到」 | **资料来源** |
| 「只允许读取 `/shared/report/`，禁止写入和删除」 | **工具边界** |
| 「数据抓取完成后先输出口径给我确认，通过再分析」 | **阶段检查点** |
| 「调用上一步生成的 Pass 结果继续下一步」 | ❌ 不是检查点，缺少停下核对动作 |
| 「检查一下内容是否准确」 | ❌ 不合格的自检项（不具体、不可核对、无证据） |
| 「你看着办，有把握就行」 | ❌ 没有阶段检查点（标志性错误表述） |
| 「你可以用你能用的工具来处理」 | ❌ 没有工具边界（只有授权，没有禁做项） |

### 12.3 概念辨析

| 说法 | 判断 | 说明 |
|---|---|---|
| Agent 是比大模型更强的模型 | ❌ | 是**基于大模型的应用架构**，模型能力仍是底座 |
| Agent 的价值是把「回答问题」推进到「完成任务」 | ✅ | 官方原文金句 |
| Agent 只需给个目标，其余它可以自己搞定 | ❌ | 官方要求明确**四要素** |
| 有了 Agent 就不需要好的提示词 | ❌ | 目标描述、工具说明、约束仍是质量关键 |
| 工具执行是在模型内部完成的 | ❌ | 模型**只输出调用请求**，执行在模型之外的运行时 |
| 工具调用会给模型补充知识 | ❌ | 提供的是**能力**，不是知识（知识靠知识库/微调） |
| MCP 是一个强大的工具 | ❌ | MCP 是**连接方式/标准**，真正执行动作的是工具 |
| 有了 MCP 就不需要 Function Calling | ❌ | 不同层次，通常共存 |
| Skill 就是写得很长的一条提示词 | ❌ | 含工具集合与验收标准，可复用、可编排 |
| Skill 的作用是固化重复工作方法 | ✅ | 官方原文措辞 |
| Skill 编排等同于 Multi-Agent | ❌ | 前者一个执行体串流程，后者多个执行体分工 |
| 自检清单只要写得"全面"就够了 | ❌ | 官方要求**具体、可核对、有证据** |
| 自检清单完善后高风险动作可由 Agent 自主执行 | ❌ | 官方：**高风险动作必须人工确认** |
| 按清单自检等同于 best-of-N 多次采样择优 | ❌ | 后者只"挑"不"改"，且无针对性修正与留痕 |
| 自检闭环可以不设上限，让它改到对为止 | ❌ | 必须设重试上限，超限转人工 |
| 自检闭环能保证结果百分百正确 | ❌ | 只能提升稳定性，标准本身也可能有漏洞 |
| 事后补记一条执行记录可代替事前确认 | ❌ | 留痕不能止损，确认的价值在于**事前拦住** |
| 桌面 Agent 与云端 Agent 是两种技术路线 | ❌ | 同一套范式，**部署形态与可达资源**不同 |
| Agent 接入知识库后，模型就永久学会了知识 | ❌ | 检索是**外挂**，文档更新即刻生效；写进参数是微调 |
| 接了知识库就自动获得写文件、发请求的能力 | ❌ | 那是**工具**的职责，与知识库无关 |
| Agent 出错只是答错，不会造成实际损失 | ❌ | **Agent 有执行力**，错误会被执行出去（这是它的主要局限） |

### 12.4 判断题速记

| 表述 | 对/错 |
|---|---|
| Agent 四要素 = 目标、资料来源、工具边界、阶段检查点 | ✅ |
| 自检清单三要求 = 具体、可核对、有证据 | ✅ |
| 高风险动作必须人工确认 | ✅ |
| 阶段检查点解决"何时拦"，自检清单解决"拦下来查什么" | ✅ |
| 「查不到就说未找到」是对资料来源缺省行为的正确要求 | ✅ |
| 感知、思考、行动构成 Agent 的闭环 | ✅ |
| 简单单轮问答不应引入 Agent | ✅ |
| 桌面 Agent 拥有本地文件与终端权限，需权限最小化 | ✅ |
| Agent 生成草稿、人审阅确认后再执行，符合官方协作方式 | ✅ |
| Skill 适合用来固化一次性的、只做一遍的任务 | ❌（固化**重复**工作方法） |
| 检查项里出现"准确/合理/完善"等形容词没有门槛，算合格 | ❌ |
| Agent 可以替代最终责任人签署对外文件 | ❌ |
| 有了 MCP 之后 Function Calling 就不需要了 | ❌ |
| 自检闭环足够完善时，可免除高风险动作的人工确认 | ❌ |
