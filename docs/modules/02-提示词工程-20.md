#### M2-K01 好答案来自好输入（提示词基础）　🟢`[A]`

**① 一句话定义**：输出的质量首先取决于输入的质量——把需求说清楚，是所有优化里成本最低、也最先该做的那一步。

**② 是什么**：这是官方对本模块写的第一句话：「**好答案来自好输入**」。提示词（输入）是你和模型之间唯一的接口：模型看不到你的表情、不知道你的公司、不了解你的潜台词，它只能依据你写下的文字，按"最可能的续写"来生成。因此"改模型"之前永远要先问"我把话说明白了吗"。这一条同时决定了本模块在整张卷子里的位置——它是官方六选一手段清单（优化输入 / 接入知识库 / 调用工具 / 使用微调 / 协作 Agent / 保留人工确认）的**第一顺位**。

**③ 为什么**：官方把「优化输入」排在最前，理由是成本结构——提示词优化不改架构、不要数据、不花训练费用、当天就能验证；而知识库、工具、微调、Agent 都要额外建设。更重要的是**前置关系**：需求都没讲清就去做 RAG 或微调，等于把模糊的问题搬到了更贵的环节上，症状不会消失。官方另一条原文「不要求考生编写代码，也不考模型训练和协议实现细节」进一步说明：本认证考的是**理解能力边界并选对方法**，不是考实现。

**④ 怎么做 / 怎么用**：
```
❌ 坏：帮我写个方案。
   → 模型不知道什么方案、给谁、多长、什么格式，只能写一份"万能模板"。

✅ 好：你是十年经验的 B 端市场分析师（角色）。
   背景：我们要向中小企业主推广新的库存管理模块，用于 Q3 渠道推广（背景+目的）。
   目标：写一份可直接发给客户的推广文案（目标+交付物）。
   约束：仅依据我提供的产品文档，不得编造性能数字；文档没提的写"未提及"（约束+兜底）。
   输出：500 字以内、分三段、附三条核心卖点（输出格式）。
   评价标准：每条卖点必须指向老板的具体痛点而非功能罗列；出现无出处数字即不合格（评价标准）。
```

**⑤ 易错点**
- ❌ 常见误解：「回答不好就是模型不够聪明，换个更大的模型 / 调下参数就行。」
  ✅ 正确：官方路径的**第一步永远是优化输入**；换模型、调参数不是官方给的手段，也不在本模块考纲内。
- ❌ 常见误解：「提示词写得越长越好。」
  ✅ 正确：长度 ≠ 质量。**七要素齐全 + 约束强相关且必要**才有效；堆无关约束会让模型顾此失彼。

**⑥ 考法提示**：题干最常见形态是「业务方说效果不好，第一步最应该做什么」。正确项一定是"把目标、背景、约束等讲清楚 / 优化提示词"。干扰项常在这几个词上设陷阱：把"**微调**""**知识库**""**Agent**"写成看似专业的首选（跳步），或塞入"**调采样参数**""**换更大模型**"（越界到 M3 / 不在考纲）。

**⑦ 记忆锚点**：**「先怪自己没说清，再怪模型不知道。」** 类比：提示词像给新同事的派活说明——你没说清 deadline 和交付形态，换十个同事也一样交不出你要的东西。

#### M2-K02 七要素①目标　🟢`[A]`

**① 一句话定义**：用一句动词开头的话，说清"要做什么 + 交付什么"，让模型知道终点在哪。

**② 是什么**：目标不是"主题"，而是**任务 + 交付物**。它包含三层：动作（分类 / 提取 / 改写 / 总结 / 生成）、对象（对哪些材料做）、产物（交出来是一张三列表格、一段 300 字摘要，还是一个判定结论）。官方把「目标」列为七要素第一项，也把它列为"建议掌握的知识"里四件套（目标、背景、约束、验收标准）的第一项——**它是后面所有要素的锚点**。

**③ 为什么**：模型没有意图推断能力，它只会选"最常见的那种理解"。你不写目标，它就用训练语料里最高频的用法来答，于是出现"我让它分析一下，它给我写了一篇科普"。目标缺失导致的失败模式是**答非所问与长度失控**，这是所有失败模式里最容易归因、也最容易修的一个。

**④ 怎么做 / 怎么用**：
```
❌ 帮我分析一下这些反馈。
✅ 目标：把下面【反馈】逐条判定问题类型，输出一张「编号 / 问题类型 / 紧急度」的表格；
   这件事做到出表为止，后续由运营团队接手派单。
```
一句话模板：**「把 <对象> <动词> 成 <交付物>，用于 <下游环节>。」**

**⑤ 易错点**
- ❌ 常见误解：「目标写个主题就够了，细节让模型自己发挥。」
  ✅ 正确：发挥就是猜。目标必须包含**交付物定义与边界**（做到哪一步为止）。
- ❌ 常见误解：「目标 = 背景。」
  ✅ 正确：目标回答"做什么"，背景回答"为什么做、依据什么口径"（见 M2-K03）。

**⑥ 考法提示**：题干给一段提示词问"缺什么"，若里面只有"帮我看看 / 分析一下 / 写点东西"这类模糊动词而**没有交付物定义**，答案就是目标。干扰项会把"背景""角色"写得像正确答案——先确认题干里那些要素是否已经给了。

**⑦ 记忆锚点**：**目标 = 动词 + 对象 + 交付物。** 判断标准：写完这句话，一个陌生人不问你也能照着做。

#### M2-K03 七要素②背景　🟢`[A]`

**① 一句话定义**：交代来龙去脉、资料来源、业务口径与下游用途，让模型不要按"默认世界"理解你的任务。

**② 是什么**：背景是模型做判断时缺失的那部分世界知识。四块内容最常写：**资料来源与时间范围**（来自 2026 年 Q2 的客服工单）、**业务口径**（这里的"投诉"仅指已升级到主管的工单）、**使用场景**（给管理层汇报 / 给客户看）、**下游环节**（结果用于向仓储团队提改进项）。

**③ 为什么**：模型脑子里只有通用语料里的"平均世界"。你公司把"服务态度"和"物流时效"分开统计，它不知道；你说"客户"指的是经销商而非终端用户，它不知道。不写背景的直接后果是**专业味不对、口径踩偏、建议不符合场景**——而且这类错误很隐蔽，因为输出看起来很通顺。

**④ 怎么做 / 怎么用**：
```
❌ 这些是用户反馈，帮我分类。
✅ 背景：这批文本来自我们平台 618 大促期间的售后工单；
   按公司《投诉分级标准》，"服务态度"与"物流时效"必须分开统计，不得合并；
   结果将用于向仓储团队提出改进项。
```
一句话模板：**「材料来自 <来源/时间>，口径是 <定义>，结果用于 <下游用途>。」**

**⑤ 易错点**
- ❌ 常见误解：「背景就是客套话，写不写无所谓。」
  ✅ 正确：背景是**口径的来源**，尤其是分类、提取、总结任务的准确率关键。
- ❌ 常见误解：「把材料直接贴进去就等于给了背景。」
  ✅ 正确：材料只给了"是什么"，没给"怎么算、给谁用、什么口径"。

**⑥ 考法提示**：场景题里若出现"模型把 A 和 B 混为一谈""按行业通用理解分类，和我们的口径不符""建议不符合我们场景"，缺的就是背景（或背景里的业务口径）。干扰项常写"缺示例"——示例解决**格式与类别边界**，背景解决**口径与来源**，先看清症状。

**⑦ 记忆锚点**：**背景 = 让模型"知道自己在哪家公司上班"。**

#### M2-K04 七要素③角色　🟢`[A]`

**① 一句话定义**：给模型一个身份，用来对齐语气、视角与专业深度。

**② 是什么**：有效的角色设定是**四件套**：身份（资深电商售后质检员）+ 领域经验（10 年）+ 服务对象（判定结果给运营主管看）+ 行为准则（只依据原文与规则判定，无法判定时输出"证据不足"）。官方把「角色」明确列入七要素，说明它是**提示词层面的标准手段**，不是玄学。

**③ 为什么**：模型输出是条件概率的续写，角色描述会显著改变它调用的"语域"——同样一件事，写给法务和写给客户的措辞完全不同。角色 + 行为准则还有一个副作用很有用：它把"不确定就别硬答"这类兜底要求提前写入了模型的行为倾向。

**④ 怎么做 / 怎么用**：
```
❌ 你是一个专家，请帮忙看看。
✅ 你是一名有 10 年经验的电商售后质检员，你的判定结果将交给运营主管执行。
   准则：只依据用户原话与下面的《售后投诉分级标准》判定；
        不得臆造未出现的情节；无法判定时输出"证据不足"。
```

**⑤ 易错点**
- ❌ 常见误解：「角色设定只是心理暗示，实际不起作用。」
  ✅ 正确：角色是官方七要素之一，直接影响语气与视角，是本模块的正经考点。
- ❌ 常见误解：「角色写得越牛越好，多加几个专家身份。」
  ✅ 正确：叠加互不相关的身份（律师+医生+程序员+营销总监）会让角色互相打架，输出更飘。**一个角色，贴着任务。**

**⑥ 考法提示**：出现"输出像通用助手""语气不对""没有行业味道""正式/口语尺度不受控"→ 补角色。陷阱是把"角色"当万能答案——若症状是**分类口径不一致**，正确答案是示例；若是**不知道本公司资料**，那是知识问题（M3）。

**⑦ 记忆锚点**：**角色 = 身份 + 经验 + 服务对象 + 行为准则**（缺一不可的四件套）。

#### M2-K05 七要素④约束　🟢`[A]`

**① 一句话定义**：告诉模型什么能做、什么不能做，以及**不知道时该怎么办**。

**② 是什么**：约束有三类条款，缺一不可：
1. **范围约束**：素材来源限定（"仅依据以下【资料】作答，不得引用外部知识"）；
2. **禁止项**：不许做什么（"不得编造数据；不得省略原文中的型号与金额"）；
3. **兜底行为**：**不知道时必须怎么办**（"资料中没有的内容直接输出'未提及'"）。← 最常被漏掉的一条

**③ 为什么**：只写"不许编造"是不够的——你禁止了一个行为，却没告诉模型这时该做什么，它大概率仍会硬答一个（因为它总得输出点什么）。**兜底条款把"沉默"变成一个合法选项**，这才是抑制幻觉的关键动作。约束还承担了安全的第一道防线（高风险场景的边界），这也是它与 M6 的接口。

**④ 怎么做 / 怎么用**：
```
❌ 请认真回答，不要编造。
✅ 约束：
   1. 仅依据【资料】作答，不得引用资料之外的知识；
   2. 不得编造或推测金额、日期、责任人；
   3. 【资料】中未提及的内容，一律输出"未提及"，不得留空也不得猜测。
```

**⑤ 易错点**
- ❌ 常见误解：「只要说'不许编造'就够了。」
  ✅ 正确：必须同时给**兜底行为**，否则模型照样硬答。
- ❌ 常见误解：「约束越多越保险。」
  ✅ 正确：原则是**强相关且必要**；无关约束会分散注意力，让主要要求反而被忽略。
- ❌ 常见误解：「用形容词写约束，比如'写得专业一点'。」
  ✅ 正确：形容词不可验收，等于没约束（见 M2-K19）。

**⑥ 考法提示**：法务、医疗、金融、合同、对外发布类场景题里，若选项出现"**合同中没有的字段一律标记'未提及'**"，它几乎一定是正确项。干扰项会写"不许编造"但**不给兜底**——看着对，实际不完整。

**⑦ 记忆锚点**：**约束三件套 = 只能用什么 + 不许做什么 + 不知道怎么办。**

#### M2-K06 七要素⑤示例　🟢`[A]`

**① 一句话定义**：给几条"输入 → 正确输出"的样例，把口径、格式、话术锚定下来。

**② 是什么**：按示例数量分为 **Zero-shot（0 个）/ One-shot（1 个）/ Few-shot（2~N，通常 3~5）**。它不是在教模型新知识，而是在告诉模型"**这类问题在我们这儿长这样**"。详情见 M2-K16。

**③ 为什么**：模型的默认口径来自训练语料，而你的业务口径是公司自定义的。示例是成本最低的对齐方式——几条样例就能把边界说清，比用文字描述边界可靠得多（尤其是易混类别）。

**④ 怎么做 / 怎么用**：
```
请将下列反馈按【物流/服务/商品质量/其他】分类。
示例：
输入：快递丢件了没人管      → 物流
输入：客服回复很及时        → 服务
输入：包装破损但东西没问题  → 物流      ← 易混类，必须覆盖
现在请分类：收到时外箱变形 →
```
一句话模板：**「输入：… → 输出：…（覆盖易混边界，口径全文一致）」**

**⑤ 易错点**
- ❌ 常见误解：「示例越多越好，堆二三十条最稳。」
  ✅ 正确：**质量 > 数量**；示例自带错误或口径不一致，错误会被忠实复制。
- ❌ 常见误解：「分类不准就换个更专业的角色。」
  ✅ 正确：角色不知道你们公司第 4 类的边界在哪，缺的是**示例与类别定义**。

**⑥ 考法提示**：症状是"某两类互相误判""同类样本前后结果不一致""输出格式照模型习惯来"→ 补示例。陷阱是把答案写成"把要求重复写三遍"——提高音量不等于提高精度。

**⑦ 记忆锚点**：**口径对不齐 → 补示例。示例错了，模型会错得很自信。**

#### M2-K07 七要素⑥输出格式　🟢`[A]`

**① 一句话定义**：事前规定交付物的形态——结构化 / 版式 / 字数条数 / 措辞语气，外加模板、禁止项与空结果行为。

**② 是什么**：四类约束 + 两个补充动作：
- **结构化**：JSON / 表格 / 字段清单；
- **版式**：章节、编号、段落数；
- **量化**：字数、条数、每条多少字；
- **措辞语气**：正式书面语 / 口语 / 禁用夸张修辞；
- **补充**：给**模板**（`[{"item":"","amount":0}]`）+ 加**负面约束**（"除此之外不要输出任何内容"）+ 规定**空结果行为**（"无结果输出 []"）。

**③ 为什么**：模型默认会在答案前后加"好的，以下是您要的内容……"这类客套话——人读起来没问题，但下游 JSON 解析会直接崩。输出格式不是审美问题，是**工程可用性**问题。

**④ 怎么做 / 怎么用**：
```
❌ 请把合同里的金额提取出来。
✅ 请从文本中提取所有金额，仅输出如下 JSON 数组，不要输出任何其他内容：
   [{"item": "项目名称", "amount": 123.45, "currency": "CNY"}]
   若没有金额信息，输出 []。
```

**⑤ 易错点**
- ❌ 常见误解：「输出格式只能靠微调固化。」
  ✅ 正确：**先在提示词里强约束**；反复约束仍不稳定才考虑微调（M5）。这是本模块高频陷阱。
- ❌ 常见误解：「说了 JSON 就够了。」
  ✅ 正确：还要给**字段模板**、**负面约束**和**空结果行为**，否则稳定性不够。

**⑥ 考法提示**：题干出现"写入数据库""下游解析失败""有时返回 JSON 有时返回散文"→ 选"明确输出格式 + 给模板 + 加负面约束"。干扰项必放"**做微调**"（跳步）和"**调采样参数**"（越界 M3）。

**⑦ 记忆锚点**：**格式四件套 = 类型 + 模板 + 别输出别的 + 没结果怎么办。**

#### M2-K08 七要素⑦评价标准　🟢`[A]` 🔴 本轮重点

**① 一句话定义**：把"好"翻译成**可被检验的条款**，让好答案能被挑出来、被复制、被判断有没有进步。

**② 是什么**：官方七要素的第七项，回答三个问题：
1. **看哪些维度？**（准确性 / 完整性 / 可执行性 / 语气 / 长度）
2. **每个维度的尺度是什么？**（"每条不超过 30 字""必须含时间和责任人""不得出现无出处的数字"）
3. **谁来判断、怎么判断？**（"由业务负责人对照原文抽检""模型输出后先自查一遍再给结论"）

**③ 为什么**（这是官方把它与前六项并列的原因）：
- 没有评价标准，**你分不出三版输出哪一版更好**，只能凭感觉挑；
- 没有评价标准，**迭代无法判断"改好了没有"**，测试结果无法对照；
- 没有评价标准，**验收标准也就无从谈起**（见 M2-K11）；
- 写进提示词后，模型会向这个标准对齐输出，还可要求它**交付前自查一遍**。

**④ 怎么做 / 怎么用**：
```
✅ 评价标准：
   1. 每条建议必须是可执行动作（含动词、责任人、时限），泛泛而谈视为不合格；
   2. 结论中的每个数字都必须能在【资料】中找到出处，找不到的视为不合格；
   3. 交付前请按以上两条自查一遍，剔除不合格条目后再输出最终结果。

❌ 评价标准：写得专业一点，尽量好一些。   ← 形容词，不可验收，等于没写
```

**⑤ 易错点**
- ❌ 常见误解：「评价标准 = 写得专业、详细、优质。」
  ✅ 正确：形容词不可验收，模型无从对齐，人也无从判断。
- ❌ 常见误解：「写了尺子就够了。」
  ✅ 正确：建议再加一句"**交付前先自查一遍**"，把标准变成动作。

**⑥ 考法提示**：题干出现「**连出三版，团队争论不休、无法判断哪一版更好**」「不知道该选哪版」「改了几轮也不知道有没有进步」→ 直接找**评价标准**。这是本轮官方补齐的缺口，也是本模块最可能出现的新题。

**⑦ 记忆锚点**：**前六项管"让模型做对"，第七项管"让你能判断它对没对"。** 类比：前六项是让厨师做菜，第七项是那张打分表。

#### M2-K09 复杂任务：先列计划和关键信息，确认后再生成　🟢`[A]` 🔴 本轮重点

**① 一句话定义**：面对复杂任务，第一步不是生成，而是让模型**先列出计划与它还缺的关键信息**，人确认之后再开工。

**② 是什么**：官方原文逐字：「**面对复杂任务，先列计划和关键信息，确认后再生成**」。包含两个动作 ——「计划」（分几步、每步输入输出、需要哪些资料）和「关键信息」（受众、口径、不许改什么、截止时间、数据范围），以及一个前提条件：**确认后再生成**。

**③ 为什么**：复杂任务的特征是"**模型必须自行假设缺失信息**"。它一旦在第一步假设错了（比如默认报告是给技术团队看的），后面每一步都建立在错误假设上，整篇报废，且你**不知道错在哪一步**。先在生成前把假设摆到桌面上让人确认，是把"返工整篇"降级为"改一句话"。此外，这一步本身也常常暴露出"其实需求还没定义清楚"，从而与 M2-K14 采访模式衔接。

**④ 怎么做 / 怎么用**：
```
❌ 一次性让模型出终稿：
   "请写一份公司近三年产品战略复盘报告，给管理层看。"（模型自行假设一切，一步跑偏全篇废）

✅ 先列计划与关键信息：
   第一步（先不要生成报告正文）：
   背景：我要向公司管理层汇报近三年产品战略复盘。
   请你先输出两样东西：
   1. 完成这份报告的计划：分几步、每步做什么、需要我提供什么资料；
   2. 你还不清楚的关键信息清单：请逐条列出并向我提问。
   在我确认之后再进入下一步。
```

**⑤ 易错点**
- ❌ 常见误解：「复杂任务就该把要求写得更长，让它一次做完。」
  ✅ 正确：写长 ≠ 降耦合；官方给的路径是**先列计划 + 确认关键信息**。
- ❌ 常见误解：「复杂任务一步到位才显得专业。」
  ✅ 正确：返工成本远高于先确认的成本。
- ❌ 常见误解：「多步任务就该上 Agent。」
  ✅ 正确：官方路径是**先在输入层面解决**；只有需要模型自主规划并**调用工具**实际执行时才进入 Agent（M4）。

**⑥ 考法提示**：题干出现「任务复杂 / 资料多 / 判断链条长 / 返工成本高 / 不知道该怎么下手」→ 找「**先列出计划与关键信息，确认后再生成**」。干扰项常放"直接生成后逐段挑错""拆给多个模型分头生成""先做微调记住资料"。

**⑦ 记忆锚点**：**「先对齐'怎么干、依据什么'，再让它干。」**

#### M2-K10 翻译 / 改写 / 总结 / 分类：补受众、目的、术语、不可改写信息　🟢`[A]` 🔴 本轮重点

**① 一句话定义**：这四类任务的输入已经给定，所以七要素之外还要额外补**受众、目的、术语、不可改写信息**这四项。

**② 是什么**：官方原文逐字：「**面对翻译、改写、总结、分类等任务，补充受众、目的、术语和不可改写信息**」。四项的含义：
- **受众**：给谁看 → 决定措辞深浅与详略；
- **目的**：拿来做什么决策或动作 → 决定取舍重点；
- **术语**：专业名词怎么统一 → 决定译法/类别名一致性；
- **不可改写信息**：哪些内容一个字都不能动 → 决定合规底线。

**③ 为什么**：这四类任务的输出是"对既有内容的再表达"，模型天然倾向"优化"它——包括把型号本地化、把金额四舍五入、把免责声明概括掉。而**模型不会天然保护数字和条款**，它只按概率续写。所以必须由你显式圈出"不许动的部分"。

**④ 怎么做 / 怎么用**：
```
❌ 把这份说明书翻译成英文。
✅ 目标：把这份中文产品说明书改写为英文，供海外经销商阅读（受众）。
   背景：用于 Q3 海外渠道推广物料，由市场部统一印制（目的/用途）。
   术语：按附件术语表统一译法，"履约时效"统一译为 fulfillment SLA。
   不可改写信息：以下保持原样，不得翻译、改写、删减或概括：
                 产品型号 XY-200、全部规格参数与金额数字、第 5 条免责声明全文、公司名称与注册商标。
   约束：除上述内容外其余可自由润色；不得新增原文没有的性能承诺。
   输出格式：保留原文章节结构与编号，逐节输出。
   评价标准：型号/数字/免责声明与原文逐字一致，术语译法全文统一，任一条不符即不合格。
```

**⑤ 易错点**
- ❌ 常见误解：「翻译只要说'翻译成英文'就行。」
  ✅ 正确：官方明确要求**额外**补这四项。
- ❌ 常见误解：「模型跟人一样会保护数字和法务条款。」
  ✅ 正确：不会。不写"不可改写信息"，型号/金额/免责声明就有被改写的风险。
- ❌ 常见误解：「受众和目的是一回事。」
  ✅ 正确：受众是**给谁看**，目的是**拿来干什么**，两者分别影响措辞与取舍，都要写。

**⑥ 考法提示**：题干出现「翻译 / 改写 / 总结 / 分类」→ 优先找含「**受众、目的、术语、不可改写信息**」的选项；若问"最容易漏的是哪一项" → 答「**不可改写信息**」。干扰项常混入"字号字体要求""采样参数""训练配置"。

**⑦ 记忆锚点**：**「翻译改写总结分类 → 受众、目的、术语、不可改写信息」**；翻车最多的是最后一项。

#### M2-K11 验收标准　🟢`[A]` 🔴 本轮重点

**① 一句话定义**：站在任务交付方一侧，写清"达到什么尺度才算完成、由谁用什么方式核对"，决定这次交付能不能放行。

**② 是什么**：官方「建议掌握的知识」原文列出四件套：**任务目标、背景、约束和验收标准**。验收标准是其中的"闸门"，三条硬性要求：**可量化**（有阈值、有样本、有数量）、**可核对**（不同人拿同一份输出能得出同一结论）、**有证据**（达标与否可追溯到具体样本或出处）。

**③ 为什么**：没有验收标准，"做好了没有"就变成拍脑袋；而且它与提示词里的**评价标准必须同源**——模型按 A 标准输出、你按 B 标准验收，永远对不齐。它与 M4「自检清单要具体、可核对、有证据」是同一套思路，跨模块通用。

**④ 怎么做 / 怎么用**：
```
❌ 验收标准：提取效果达到可用水平即可上线。       ← 不可核对
✅ 验收标准：在 20 份测试合同上，关键字段准确率 ≥ 95%、漏提 ≤ 1 处才允许上线；
   由法务抽检 5 份，每份记录命中的条款编号作为证据。
```

**⑤ 易错点**
- ❌ 常见误解：「验收标准 = 评价标准，是一回事。」
  ✅ 正确：评价标准**写在提示词里、给模型看**，用来对齐输出；验收标准**写在任务需求里、给人和项目看**，用来决定放行。两把尺子必须同源、口径一致。
- ❌ 常见误解：「为了达到验收标准，应该先做微调。」
  ✅ 正确：顺序错误。先把目标/背景/约束/验收标准讲清楚并迭代验证，反复不稳才考虑微调。

**⑥ 考法提示**：题干出现「要把……讲清楚」「这一版能不能上线」「要求可被检验」→ 找包含「**目标、背景、约束、验收标准**」这一组的选项。注意官方四件套里**没有**"角色/示例/输出格式"——这是多选题最爱做的手脚。

**⑦ 记忆锚点**：**评价标准 = 给模型的尺子；验收标准 = 给任务的闸门。**

#### M2-K12 优化输入在决策树中的位置　🟢`[A]`

**① 一句话定义**：在官方给出的手段清单里，「**优化输入**」永远排第一——成本最低、见效最快、且是其他手段的前置。

**② 是什么**：官方原文列出的手段池（六选一，顺序即优先级）：
```
优化输入 → 接入知识库 → 调用工具 → 使用微调 → 协作 Agent，或 → 保留人工确认
```
对应症状分别是：**说不清**（表达/理解问题）→ 优化输入；**不知道**（缺私域/最新知识）→ 知识库；**做不了**（实时数据 / 确定性计算 / 业务动作）→ 工具；**改不了**（长期固定的行为、格式、风格）→ 微调；**要自主规划多步执行** → Agent；**高风险** → 保留人工确认。

**③ 为什么**：这是成本序也是依赖序。RAG 要建索引、工具要接接口、微调要备数据训模型、Agent 要做编排，唯独优化输入零基础设施。而且**所有手段都建立在"需求已说清"的前提上**——把模糊问题搬去微调，只是把模糊固化下来。

**④ 怎么做 / 怎么用**：拿到"效果不好"的反馈先做归因三问：
```
第 1 问：它是听得懂但答得糙（说不清）？→ 优化输入（本模块）
第 2 问：还是它根本不知道（缺知识 / 缺实时能力 / 做不了动作）？→ 知识库 / 工具
第 3 问：还是要求长期固定（行为/格式/风格）？→ 微调；要自主执行 → Agent；高风险 → 人工确认
```

**⑤ 易错点**
- ❌ 常见误解：「效果不好就上知识库 / 上微调，一步到位。」
  ✅ 正确：那是跳步；题干只说"不够好"而未给出缺知识等症状时，第一步是**优化输入**。
- ❌ 常见误解：「Agent 更高级，所以优先。」
  ✅ 正确：高级 ≠ 优先；普通问答质量不佳用 Agent 是杀鸡用牛刀。

**⑥ 考法提示**：题干只说"回答不够好"→ 选优化输入。陷阱是选项里混进"看起来很对症"的微调/RAG——只有当题干明确出现"**不知道我司资料**""**要查实时数据/精确计算/发邮件**""**每次语气都要像同一个人**""**要自主规划执行**"这些症状时，才选对应手段。

**⑦ 记忆锚点**：官方金句 + 归因口诀：
**「查知识用 RAG，做动作靠工具，稳行为才考虑微调。」**
**「说不清优化输入，不知道接知识库，做不了调工具，改不了用微调，要落地协作 Agent，风险高保留人工确认。」**

#### M2-K13 本模块不考什么　🟢`[A]`

**① 一句话定义**：官方明确划出的边界——不考代码、不考模型训练与协议实现细节、不考参数默认值 / 控制台菜单 / 产品定价。

**② 是什么**：官方声明原文：「**本认证不要求考生编写代码，也不考模型训练和协议实现细节**」。由此推出的排除清单：代码编写、temperature / top_p / max_tokens 等 API 调用参数、参数默认值、控制台菜单路径、产品定价、模型训练流程细节、MCP 协议细节（MCP 只考作用与定位，属 M3）。

**③ 为什么**：本认证面向**企业 AI 通识教育**，考核目标是"理解能力边界并选对方法"，不是工程实现。出题人会在选项里放这些**越界项当干扰**——认出它们，就能直接排除。

**④ 怎么做 / 怎么用**：答题时的"三秒排除法"：
```
看到「写一段代码实现…」          → 排除（不考代码）
看到 temperature / top_p / max_tokens → 排除（属 M3，且本模块不考参数）
看到 LoRA / PEFT / 训练批次 / 学习率  → 排除（不考训练细节）
看到「控制台 → 某某菜单」「单价 / 计费」 → 排除（不考菜单与定价）
```

**⑤ 易错点**
- ❌ 常见误解：「调低采样参数就能解决输出不稳定。」
  ✅ 正确：那是 M3 的调用层话题，本模块不考；输出不稳定先在提示词层面做**输出格式约束 + 示例**。
- ❌ 常见误解：「MCP 协议细节是 M2 的重点。」
  ✅ 正确：MCP 属 M3，且官方明说**不考协议细节**，只考作用与定位。

**⑥ 考法提示**：几乎每道题都会安排 1 个越界干扰项。看到就秒排，能省时间也能防止被"专业名词"唬住。

**⑦ 记忆锚点**：**「代码不写、参数不调、模型不训、菜单不点、价格不背。」**

#### M2-K14 采访模式　🔴`[C]` ⚠️ 待核实

**① 一句话定义**：不是你说完要求，而是**让模型反过来向你提问**，用问答把缺失的信息补出来。

**② 是什么**：常规用法是人单方面把需求写完；采访模式把提问方向反转——由模型提出"完成这件事我还需要知道什么"（受众、口径、范围、交付形态、截止时间），人来回答，一轮或多轮之后需求才成型。

**③ 为什么**：当**你自己还没想清楚**时，你写不出七要素；但你知道模型需要什么。让模型来问，比让人凭空补全七要素效率高得多，也不会把"我以为的要求"当成"真实的要求"塞给模型。

**④ 怎么做 / 怎么用**（概念层示例，不涉及任何产品操作）：
```
我不知道还缺什么信息。请你先向我提问，一次问 3 个最关键的问题，
在我回答之后，再按我们最终确认的需求生成。
```
- **适用**：需求不清、范围不明、关键信息缺失（"我要一份市场分析报告"——给谁看？什么周期？要几个结论？）
- **不适用**：需求已经很清楚的简单任务（直接给七要素即可，先采访是浪费）。

**⑤ 易错点**
- ❌ 常见误解：「采访模式是让模型少说话、用户一次性说完。」
  ✅ 正确：恰好相反，是**让模型向你提问**。
- ❌ 常见误解：「任何任务都该先采访一轮。」
  ✅ 正确：需求清楚时直接写七要素更有效率。

**⑥ 考法提示**：只可能考"什么时候用 / 解决什么问题"。题干出现「需求还没想清楚」「不知道该提什么要求」「范围不明」→ 选"让模型反过来向你提问"。干扰项一定把方向写反（"用户一次说完，模型不再追问"）。

**⑦ 记忆锚点**：**「我不知道自己想要什么 → 采访模式（让它问你）。」** 与七要素的关系：它问的正是你缺失的目标、背景、约束、评价标准。

#### M2-K15 深度思考模式　🔴`[C]` ⚠️ 待核实

**① 一句话定义**：让模型**展开更长的推理过程再作答**，而不是立刻给结论。

**② 是什么**：一步到位的答案在多条件判断、多步推算上容易跳步出错；深度思考模式把中间推理展开，再给出结论。它与手法层的「先想后答 / 思维链 CoT」（M2-K17）是**同一思路**，可视为其产品化形态。

**③ 为什么**：复杂推理的错误大多来自"跳步"——模型直接猜结论而不是逐步验证。展开推理既降低跳步概率，也让**人能顺着步骤检查**在哪一步出错。

**④ 怎么做 / 怎么用**（概念层示例，不涉及任何产品操作）：
```
请先把推理过程完整展开：逐条比对政策条件并说明是否满足，再给出最终结论，
最后说明依据的条款编号。
```
- **适用**：复杂推理 / 多步任务（多条款比对、多步计算、需交叉验证的判断）。
- **不适用**：简单事实问答、格式转换——展开推理只会增加耗时。

**⑤ 易错点**
- ❌ 常见误解：「深度思考是跳过推理直接给结论，省时间。」
  ✅ 正确：恰好相反，是**展开更长的推理**。
- ❌ 常见误解：「任何任务开启后效果一定更好。」
  ✅ 正确：只适合复杂推理/多步任务；简单任务没必要。任何手段都不存在"一定更好"。

**⑥ 考法提示**：题干出现「多条款比对」「多步推算」「一步到位容易出错」→ 选"展开更长推理再作答"。陷阱是"适合所有任务，任何场景都更好"这种绝对化表述。

**⑦ 记忆锚点**：**「事情很难想 → 深度思考模式（让它慢慢想）。」**

> **两者怎么选**：需求说不清 → 采访模式（让它问你）；事情很难想 → 深度思考模式（让它慢慢想）；需求清楚又简单 → 都不用，直接按七要素写。

#### M2-K16 Zero-shot / One-shot / Few-shot　🟡`[B]`

**① 一句话定义**：按提示词里**给的示例数量**划分的三种用法：0 / 1 / 2~N 条。

**② 是什么**：
| 类型 | 数量 | 适用 | 代价 |
|---|:---:|---|---|
| Zero-shot | 0 | 通用成熟任务（翻译、摘要） | 口径/格式不可控 |
| One-shot | 1 | 锚定输出风格或格式 | 占用少量上下文 |
| Few-shot | 2~N（通常 3~5） | **自定义分类口径、格式模板、行业话术**要严格对齐 | 占用上下文；示例必须高质量且口径一致 |

**③ 为什么**：示例的作用是"锚定"而非"教学"——它不改变模型能力，只改变模型选择的输出分布。因此**示例质量直接决定输出质量**，示例里的错误会被忠实复制。

**④ 怎么做 / 怎么用**：出现**格式不对、分类口径不一致、话术不像本公司**时，**第一选择是补 Few-shot 示例**，而不是换手段。示例要覆盖**易混边界**（如第 4 类及其相邻类别）。

**⑤ 易错点**
- ❌ 常见误解：「Zero-shot 一定比 Few-shot 弱。」
  ✅ 正确：通用任务 Zero-shot 足够，堆示例是浪费上下文。
- ❌ 常见误解：「示例越多越好。」
  ✅ 正确：**质量 > 数量**，且**口径一致**最关键。
- ❌ 常见误解：「按输出字数或推理步数来区分 Zero/One/Few-shot。」
  ✅ 正确：划分维度是**示例数量**。

**⑥ 考法提示**：症状"自定义类别误判""格式照模型习惯"→ 补示例。陷阱是"把要求重复写三遍"。

**⑦ 记忆锚点**：**「口径对不齐，示例来对齐；示例错了，错得自信。」**

#### M2-K17 先想后答（CoT 思维链）　🟡`[B]`

**① 一句话定义**：让模型**把推理过程写出来再给结论**，而不是直接抛答案。

**② 是什么**：常见触发写法是"先逐条比对条件并说明是否满足，再给出结论，最后说明依据"。它可与 Few-shot 叠加（示例里给出带推理过程的样例）。

**③ 为什么**：多步推理的失败主要来自跳步。把推理显式写出来，既降低跳步概率，也让**人能定位错在哪一步**。概念上与 M2-K15 深度思考模式是同一思路。

**④ 怎么做 / 怎么用**：
```
❌ 这份合同是否符合第 3 条赔付条件？
✅ 请逐步分析：① 列出第 3 条的全部构成要件；② 逐条比对合同原文说明是否满足；
   ③ 给出最终结论；④ 说明依据的条款编号与原文引用。
```

**⑤ 易错点**
- ❌ 常见误解：「CoT 能给模型补充推理所需的新知识。」
  ✅ 正确：**CoT 不注入新知识**，只把已有推理能力展开；材料不全，写了 CoT 也算不出来（那要转 M3 知识库）。
- ❌ 常见误解：「CoT 和 Few-shot 是一回事。」
  ✅ 正确：CoT 给**推理过程**，Few-shot 给**输入→输出样例**；二者可叠加。

**⑥ 考法提示**：题干出现"多条件判断""多步计算""一步到位出错"→ 先想后答。若同时出现"材料本身不全"，正确答案应转向**接入知识库**（M3），而不是继续优化推理。

**⑦ 记忆锚点**：**「先想后答 = 把草稿纸摊开给你看。」**

---

#### M2-K18 任务拆解　🟡`[B]`

**① 一句话定义**：把一个大任务拆成若干**有依赖关系的子步骤**，每步一个提示词，前一步的输出作为后一步的输入。

**② 是什么**：
```
读全文 → 抽摘要 → 提炼要点 → 出大纲 → 翻译成目标语言   ⇒ 5 步 5 个提示词
```
每步都可单独抽检，出错只需重做那一小步。

**③ 为什么**：单步提示词塞太多要求会出现"样样稀松"——模型注意力被摊薄，且出错后无法定位。拆解是**降耦合**，也是"复杂任务先列计划"（M2-K09）最常见的落地形态。

**④ 怎么做 / 怎么用**：判断标准是"**单步能否被稳定执行**"。能 → 不必拆；不能 → 拆，并在每步之间保留人工抽检点。

**⑤ 易错点**
- ❌ 常见误解：「任务拆解 = 把要求写得更详细。」
  ✅ 正确：写详细仍是**单步堆叠**，拆解是**降耦合为多步**。
- ❌ 常见误解：「所有任务都该拆。」
  ✅ 正确：简单任务拆解反而增加往返和上下文损耗。

**⑥ 考法提示**：题干"一个提示词塞了五件事，样样稀松"→ 拆解。干扰项"把要求写得更长更细"。

**⑦ 记忆锚点**：**拆解是切流水线，不是写长作文。**

#### M2-K19 明确性、具体性与边界约束　🟡`[B]`

**① 一句话定义**：把模糊的形容词换成**量化、可核对的条款**，并只保留强相关且必要的约束。

**② 是什么**：四个动作——
- **明确性**：不用形容词做验收标准 → "使用正式书面语，每段不超过 3 句，不使用夸张修辞"；
- **具体性**：给量化、给对象、给场景 → "面向中小企业主，300 字，突出 3 个卖点"；
- **范围约束**：限定素材来源 → "仅依据以下资料回答，不得使用资料外的信息"；
- **禁止项 + 兜底**：不只说"不许编造"，还要说"资料没有就输出'未提及'"。

**③ 为什么**：形容词无法被模型对齐，也无法被人验收。量化条款同时解决了"模型不知道做到什么程度算够"和"人不知道有没有做到"两个问题。

**④ 怎么做 / 怎么用**：
```
❌ 写得专业一点、详细一点、尽量好一些。
✅ 面向中小企业主（对象）；300 字以内（量化）；突出 3 个卖点，每个卖点不超过 30 字（量化）；
   使用正式书面语，不使用夸张修辞（明确）；术语须与产品文档一致（可核对）。
```

**⑤ 易错点**
- ❌ 常见误解：「约束越多越保险。」
  ✅ 正确：**强相关且必要**；无关约束分散注意力。
- ❌ 常见误解：「'不知道怎么办'属于可选加分项。」
  ✅ 正确：**兜底条款是最常被遗漏、也是失分最多的一条**。

**⑥ 考法提示**：题干要求"把'写得专业点'改成可验收的写法"→ 选含具体阈值、对象、条数的选项。

**⑦ 记忆锚点**：**「能量化就量化，量化不了就给样例，给不了样例就给反例。」**

#### M2-K20 常见失败模式与归因　🟡`[B]`

**① 一句话定义**：看到坏输出先**归因**（说不清 / 不知道 / 做不了 / 改不了），再决定是在提示词里修还是换手段。

**② 是什么**：归因表（**属本模块**的可在提示词层面解决；不属的必须换手段）：

| 失败模式 | 典型症状 | 提示词层面的改进 | 属本模块？ |
|---|---|---|:---:|
| **指令模糊** | "写得好看点""分析一下" → 泛泛而谈 | 量化要求、明确对象、明写输出格式与评价标准 | ✅ |
| **缺上下文 / 背景** | 答非所问，误解业务口径 | 补背景、补角色、补业务定义 | ✅ |
| **缺输出格式约束** | 一会儿 JSON 一会儿散文 | 明写格式 + 给模板 + 加禁止项 | ✅ |
| **缺评价标准** | 出了几版分不出好坏 | 补"好"的可核对定义 + 要求交付前自查 | ✅ |
| **复杂任务未先对齐** | 一步跑偏全篇报废 | 先列计划与关键信息，确认后再生成 | ✅ |
| **四类任务漏补信息** | 术语不一致、不可改写内容被改 | 补受众 / 目的 / 术语 / 不可改写信息 | ✅ |
| **任务过载** | 一个提示词塞 5 件事，样样稀松 | 任务拆解，分步执行 | ✅ |
| **口径不一致** | 同类样本分类结果前后矛盾 | Few-shot 示例锚定口径 | ✅ |
| **缺知识**（私域 / 最新） | 不知道你家产品、最新政策 | ❌ 提示词解决不了 → **接入知识库 / RAG（M3）** | ❌ |
| **超出能力边界**（实时 / 精确计算 / 业务动作） | 要查今天天气、要算精确账、要发邮件 | ❌ 提示词解决不了 → **调用工具（M3）** | ❌ |
| **要长期固定风格且反复约束不稳** | 每次语气都要像同一个人 | 先试提示词 → 不行再**微调（M5）** | ⚠️ 先本模块 |

**③ 为什么**：归因错了，手段就选错了——最常见的错误是"把知识问题当表达问题"（狂改提示词）和"把表达问题当知识问题"（直接上 RAG）。官方六选一的顺序本质就是一张**归因表**。

**④ 怎么做 / 怎么用**：三步归因：① 模型本身能不能做？② 缺的是信息还是能力？③ 要求的是一次性的还是长期固定的？——再决定留在 M2 还是转 M3/M4/M5。

**⑤ 易错点**
- ❌ 常见误解：「效果不好就重试几次，抽一个好的。」
  ✅ 正确：抽样不是优化，结果不可复制；要建测试集、做归因、一次只改一处。
- ❌ 常见误解：「没跑完迭代循环就换手段。」
  ✅ 正确：这是考试最爱设的陷阱——微调/RAG 出现在选项里显得专业，但顺序上它排在后面。

**⑥ 考法提示**：题干给一段失败输出问"根因是什么"→ 先分清表里前三列；若症状明确是"**不知道**""**做不了**"，答案必不在本模块。

**⑦ 记忆锚点**：**「说不清优化输入，不知道接知识库，做不了调工具，改不了用微调，要落地协作 Agent，风险高保留人工确认。」**

#### M2-K21 提示词迭代循环（写 → 测 → 分析 → 改）　🟡`[B]`

**① 一句话定义**：把提示词当成可版本化的产物，按「写 → 测 → 分析 → 改」循环，用固定测试集验证，一次只改一处。

**② 是什么**：
```
① 写（Write）  → 按七要素搭初版，明写评价标准
② 测（Test）   → 用固定的一组测试用例（3~10 条，含边界样本）全跑一遍
③ 分析（Analyze）→ 归因：格式？口径？缺背景？跑题？缺知识？超边界？
④ 改（Revise） → 针对归因做**一处**改动
⟲ 回到 ②
```
关键配套：**固定测试集**（迭代的前提）、**一次只改一处**（归因能力的前提）、**版本号**（便于回滚）。

**③ 为什么**：一次改三处，效果好了你也不知道是哪处的功劳，下次就复制不了。固定测试集则让"改好了没有"有客观答案——这正是**评价标准/验收标准**存在的意义。

**④ 怎么做 / 怎么用**：
```
v1：初版 → 测 10 条，8 条合格 → 归因：2 条漏提金额
v2：只改"金额字段必填 + 无则输出 []" → 复测，9 条合格
v3：只改"补 3 条易混类示例" → 复测，10 条合格 → 固化并写入验收标准
```

**⑤ 易错点**
- ❌ 常见误解：「多试几次抽个好的就是优化。」
  ✅ 正确：那叫抽卡——不稳定、不可复制、也无法沉淀。
- ❌ 常见误解：「一次改多处效率更高。」
  ✅ 正确：无法归因，等于放弃复用的可能。

**⑥ 考法提示**：题干出现"改了几轮也没进步""不知道哪次改动起了作用"→ 选"建立固定测试集 + 一次只改一处"。

**⑦ 记忆锚点**：**「写测分改，一次一处，测试集固定。」**

#### M2-K22 典型业务场景应用　🟡`[B]`

**① 一句话定义**：把技巧组合起来用在具体业务上——不同场景有不同的"默认配方"。

**② 是什么**：

| 业务场景 | 提示词设计要点 | 常用组合 |
|---|---|---|
| **批量文本分析**（评论/工单打标） | 统一口径、分隔符隔开逐条输入、明写评价标准 | Few-shot + 输出格式约束 + 类别定义（术语） |
| **信息提取**（姓名/金额/日期/条款） | 字段清单写死、给 JSON 模板、规定"没有就输出 []" | 输出格式约束 + 禁止项 + 兜底 |
| **内容生成**（文案/报告/回复拟稿） | 给受众、目的、字数、语气、卖点数量 | 角色设定 + 量化要求 + 评价标准 |
| **翻译 / 改写** | 给术语表、**标明不可改写信息**、说明受众与目的 | 七要素 + 四类任务四件套 |
| **总结** | 给受众与用途、限定字数、点明不可遗漏的关键点 | 目的 + 受众 + 输出格式 + 评价标准 |
| **分类** | 给类别定义（术语）与每类的示例 | Few-shot + 术语定义 + 评价标准 |

**③ 为什么**：场景决定"最可能缺哪一项"。翻译最可能漏**不可改写信息**，提取最可能漏**输出格式与兜底**，生成最可能漏**受众/目的/评价标准**，分类最可能漏**术语定义与示例**。记住这张表，场景题就能秒定位。

**④ 怎么做 / 怎么用**：通用判断顺序 —— 先问"**模型本身能不能做**"（能 → 在提示词层面想办法），再问"**要不要外部知识或工具**"（要 → 转到别的模块）。

**⑤ 易错点**
- ❌ 常见误解：「所有场景都用同一套模板。」
  ✅ 正确：翻译类不加"不可改写信息"就是埋雷；提取类不加"空结果行为"就是给下游埋雷。
- ❌ 常见误解：「场景题要选最高级的方案。」
  ✅ 正确：优先选**成本最低且对症**的方案。

**⑥ 考法提示**：场景题占本模块大头。读题时先圈出**任务类型**（翻译/改写/总结/分类/提取/生成）和**症状**，再回这张表找配方。

**⑦ 记忆锚点**：**「先认任务类型，再查缺项配方。」**

## 四、提示词七要素专章 ⭐（官方明确列举，必背）

> 官方原文：**"掌握如何说明目标、背景、角色、约束、示例、输出格式和评价标准。"**
> 这七个词是官方给的标准清单，**顺序、措辞都按官方背**；场景题里"这份提示词缺什么"就在这七项里找答案。

### 4.1 七要素总览（逐要素：写什么 / 不写会怎样 / 一句话模板）

| # | 要素 | 回答模型的哪个疑问 | 写什么 | 不写会怎样 | 一句话模板 |
|:---:|---|---|---|---|---|
| 1 | **目标** | 你要我做什么？ | 动词任务 + 交付物定义 + 边界 | 自由发挥，答非所问、长度失控 | 「把 <对象> <动词> 成 <交付物>」 |
| 2 | **背景** | 我为什么要做、场景是什么？ | 来源/时间、业务口径、下游用途 | 按默认世界理解，口径踩偏 | 「材料来自 <来源>，口径是 <定义>，用于 <用途>」 |
| 3 | **角色** | 我以什么身份说？ | 身份 + 经验 + 服务对象 + 行为准则 | 语气/视角/专业度不对 | 「你是 <身份>，服务 <对象>，准则：…」 |
| 4 | **约束** | 什么能做、什么不能做？ | 范围限定 + 禁止项 + **兜底** | 编造、越界引用外部信息 | 「只能用…；不许…；没有就输出'未提及'」 |
| 5 | **示例** | 好答案长什么样？ | 2~5 条"输入 → 正确输出"，覆盖易混边界 | 口径不一致、格式照模型习惯 | 「输入：… → 输出：…（口径一致）」 |
| 6 | **输出格式** | 交付成什么形态？ | 类型 + 模板 + 负面约束 + 空结果行为 | 一会儿 JSON 一会儿散文，下游解析失败 | 「仅输出 JSON，字段为…，除此之外不要输出任何内容；无结果输出 []」 |
| 7 | **评价标准** | 什么样算好？ | 判定维度 + 尺度 + 交付前自查 | 好坏全凭感觉，无法取舍和复制 | 「每条 ≤ 30 字且含动词与责任人，不符合即不合格；交付前自查一遍」 |

> 🧠 **记忆锚点**：**目的（目标）+ 来龙去脉（背景）+ 谁在说（角色）→ 规矩（约束）+ 样板（示例）+ 长相（输出格式）→ 打分尺子（评价标准）。**
> 前六个管"让模型做对"，第七个管"让你能判断它对没对"。

### 4.2 坏提示词 → 好提示词 完整对照（同一任务两版）

**任务背景**：运营团队要把一批售后工单整理成一份给仓储团队的改进建议。

```
❌ 坏提示词
────────────────────────────────────────────
帮我分析一下这些售后工单，写一份改进建议。
────────────────────────────────────────────
缺什么：目标（交付物没定义）、背景（来源/口径/用途全无）、角色（没有）、
        约束（没有兜底）、示例（没有）、输出格式（没有）、评价标准（没有）。
典型后果：一篇放之四海皆准的"加强沟通、优化流程"式空话。
```

```
✅ 好提示词
────────────────────────────────────────────
【角色】你是一名有 10 年经验的电商售后质检员，你的结论将交给仓储主管执行。
【背景】以下工单来自本平台 618 大促期间的售后记录；按公司《投诉分级标准》，
       "服务态度"与"物流时效"必须分开统计，不得合并。
【目标】从工单中提炼可执行的改进建议，交付物是一份不超过 5 条的改进清单。
【输入】<工单文本>
【约束】1. 仅依据上述工单作答，不得引用外部知识；
       2. 不得编造单号、金额、日期；
       3. 工单中未提及的原因一律写"未提及"，不得推测。
【示例】输入："快递显示签收但没收到，联系客服三天没回音" → 输出：物流-派送异常（高）
【输出格式】仅输出如下 JSON 数组，除此之外不要输出任何内容；无结果输出 []：
       [{"问题":"","紧急度":"高/中/低","建议动作":"","责任方":""}]
【评价标准】1. 每条建议必须含动词、责任方、时限，泛泛而谈视为不合格；
         2. 结论中的每个数字都必须能在工单中找到出处；
         3. 交付前按上述两条自查一遍，剔除不合格条目后再输出。
────────────────────────────────────────────
```

### 4.3 七要素速填模板（考前默背）

```
### 目标      一句话动词任务 + 交付物定义 + 做到哪为止
### 背景      资料来源 / 时间范围 / 业务口径 / 下游用途
### 角色      身份 + 领域经验 + 服务对象 + 行为准则
### 输入      <用分隔符包起来的待处理材料>
### 约束      范围限定 + 禁止项 + 不知道时怎么办（兜底）
### 示例      输入 1 → 输出 1；输入 2 → 输出 2（口径必须一致，覆盖易混边界）
### 输出格式  JSON / 表格 / 字数 / 字段清单 + 模板 + 「除此之外不要输出任何内容」+ 空结果行为
### 评价标准  判定维度 + 尺度 + 交付前自查
### （复杂任务）先列计划与关键信息，确认后再生成
### （翻译/改写/总结/分类）受众、目的、术语、不可改写信息
```

### 4.4 答题时的"逐项扫题法"

> ✅ 题干给一段提示词问"缺什么"时，**按七要素逐项扫一遍**，缺的那一栏就是答案；
> 若发现缺的不止一项，选**官方清单里被点名的那一项**（尤其是"评价标准""约束里的兜底""输出格式"）。

| 扫描顺序 | 快速判断 |
|:---:|---|
| 1 | 有没有**动词 + 交付物**？没有 → 缺目标 |
| 2 | 有没有**来源 / 口径 / 用途**？没有 → 缺背景 |
| 3 | 有没有**身份**？没有 → 缺角色 |
| 4 | 有没有**"不知道怎么办"的兜底**？没有 → 缺约束 |
| 5 | 有没有**样例**？（自定义口径任务必须有）没有 → 缺示例 |
| 6 | 有没有**格式 + 模板 + 负面约束**？没有 → 缺输出格式 |
| 7 | 有没有**"什么样算好"的可核对条款**？没有 → 缺评价标准 ← 最新、最常考 |

## 五、复杂任务：先列计划和关键信息，确认后再生成 ⭐（M2-K09）

> 官方原文：**"面对复杂任务，先列计划和关键信息，确认后再生成。"**

### 5.1 什么是"复杂任务"

满足以下任一特征，都属于官方所说的复杂任务，**不要一口气让模型出终稿**：

| 特征 | 例子 |
|---|---|
| 需要**多步**才能完成 | 先读 100 页报告 → 摘要 → 提炼数据 → 出大纲 → 翻译 |
| 依赖**未说清的关键信息** | "整理一份管理层报告"，但没说给谁看、看多久、要几个建议 |
| 涉及**多个数据源或口径** | 财报 + 行业报告 + 内部口径同时要用 |
| 结果**会被下游直接使用** | 要入库、要对外发布、要作为决策依据 |
| 错了**返工成本高** | 批量处理 1 万条、跨部门分发 |

### 5.2 标准操作流程（三步走）

```
① 让模型先列「计划」── 这件事准备分几步做？每步的输入输出是什么？需要哪些资料？
        ↓
② 让它列出「关键信息」── 完成这件事它还不清楚的：受众是谁？口径是什么？
                        哪些内容不许改？截止时间？数据范围？**由人来回答 / 确认**
        ↓
③ 确认计划与关键信息后，再让它按已确认的计划逐步生成 ── 每步产出都可抽检
```

一句话版本：**先对齐"怎么干、依据什么"，再让它干。**

### 5.3 为什么必须分两步（答题时的标准理由）

| 直接生成 | 先列计划再生成 |
|---|---|
| 模型自行假设缺失信息，一步跑偏 → 全篇报废 | 缺口在动手前暴露，关键信息由人补齐 |
| 出错后不知道错在哪一步 | 每步可抽检，定位成本低 |
| 返工要重来一遍 | 只需重做出错的那一小步 |
| 结果可能与业务口径整体跑偏 | 计划阶段就能对齐口径 |

### 5.4 提示词写法示例

```
第一步（先不要生成报告正文）：
背景：我要向公司管理层汇报近三年产品战略复盘。
请你先输出两样东西：
1. 完成这份报告的计划：分几步、每步做什么、需要我提供什么资料；
2. 你还不清楚的关键信息清单：请逐条列出并向我提问。
在我确认之后再进入下一步。
```

### 5.5 反例：一次性让模型输出长文

```
❌ "请把公司近三年产品战略、竞品格局和来年机会点整理成一份完整报告，直接给我终稿。"
   问题：受众、篇幅、口径、数据范围全部由模型假设；
        任一假设错了，整篇都要重写，而且你无法定位是哪一步错的。
```

### 5.6 易错辨析

| ❌ 错误做法 | ✅ 正解 |
|---|---|
| "复杂任务就该多写几句让模型一次做完" | 写长不等于降耦合；**先列计划 + 确认关键信息**才是官方给的路径 |
| "复杂任务一步到位才显得专业" | 返工成本远高于先确认的成本 |
| "复杂任务必须上 Agent" | 官方路径是**先在输入层面解决**；只有需要模型自主规划并**调用工具**实际执行时，才进入 Agent（M4） |
| "让模型列问题很啰嗦，浪费时间" | 这正是官方点名的做法：把信息缺口在生成前补上 |

> 🧠 **答题口诀**：题干出现「任务复杂 / 需求多步 / 返工成本高 / 不知道该怎么下手」→ 找「**先列出计划与关键信息，确认后再生成**」这个选项。

## 六、翻译 · 改写 · 总结 · 分类：四类任务的补充信息 ⭐（M2-K10）

> 官方原文：**"面对翻译、改写、总结、分类等任务，补充受众、目的、术语和不可改写信息。"**

这四类任务的共同特点是：**输入已经给定了**（待译文本 / 待改写文本 / 待总结文档 / 待分类条目），所以七要素之外，官方额外要求补这四项——它们决定"译得像不像、改得对不对、总结到不到位、分得准不准"。

### 6.1 四项补充信息逐条拆解

| 补充项 | 回答什么 | 不写会怎样 | 写法示例 |
|---|---|---|---|
| **受众** | 这份输出给谁看？ | 术语深浅、详略、语气全错：给工程师看的译文塞给客户、给老板看的总结写成流水账 | "面向海外经销商（非技术背景）" / "给公司管理层汇报用" |
| **目的** | 拿来做什么决策或动作？ | 抓错重点：用于"快速扫读"的总结写成了"完整保留细节"的长文 | "用于管理层 5 分钟口头汇报" / "用于售后团队据此派单" |
| **术语** | 专业名词怎么统一？ | 同一个术语前后译法不一致、行话被翻成通用词 | "附术语表：'履约时效'统一译为 fulfillment SLA；'客诉'统一译为 customer complaint" |
| **不可改写信息** 🔴 | **哪些内容一个字都不能动？** | **型号、规格、金额、法务条款、免责声明、专有名词被"优化"掉或改写，后果最严重** | "以下信息保持原文不变，不得翻译、改写、删减或概括：产品型号 XY-200、金额数字、第 5 条免责声明、客户名称" |

### 6.2 四类任务 × 四要素 对照矩阵 ⭐

| 任务 | 受众 | 目的 | 术语 | 不可改写信息 | 最该补的（若只能补一项） | 典型翻车 |
|---|:---:|:---:|:---:|:---:|---|---|
| **翻译** | ○ | ○ | **●●** | **●●** | **不可改写信息** | 术语前后不一致；型号/数字被本地化改写 |
| **改写** | **●●** | ○ | ○ | **●●** | **不可改写信息** | 把不许改的条款也一并润色了；改写后语气与客户不匹配 |
| **总结** | **●●** | **●●** | ○ | ○ | **目的 + 受众** | 平均用力没有重点；漏掉决策所需的关键数据 |
| **分类** | ○ | **●●** | **●●** | ○ | **术语（类别定义）** | 按模型的默认理解分类，与业务口径不符 |

> ●● = 最关键；○ = 建议补但优先级次之。**四类任务都必须补满四项，上表只用于"最该补哪项"的取舍判断。**

### 6.3 每类的最小可用写法

```
【翻译】受众：海外经销商（非技术背景）；目的：Q3 渠道推广物料；
       术语：按术语表，"履约时效" → fulfillment SLA；
       不可改写：型号 XY-200、规格参数、金额、第 5 条免责声明、公司名与商标。

【改写】受众：已签约客户（非技术）；目的：当日由客户经理对外发送；
       不可改写：价格、有效期、退款条款、联系邮箱；其余可自由润色。

【总结】受众：公司管理层；目的：5 分钟口头汇报，只需结论与三项关键数据；
       输出：一页，不超过 5 条，每条 ≤ 30 字；不得遗漏营收与同比数据。

【分类】术语：类别定义如下（A=…；B=…；C=…）；目的：结果用于售后派单；
       示例：输入 X → A；输入 Y → B（覆盖易混边界）；无匹配归为"其他"。
```

### 6.4 完整示例（翻译任务）

```
目标：把这份中文产品说明书改写为英文，供海外经销商阅读（受众）。
背景：用于 Q3 海外渠道推广物料，将由市场部统一印制（目的与用途）。
术语：请统一使用附件术语表；"履约时效"统一译为 fulfillment SLA。
不可改写信息：以下信息保持原样，不得翻译、改写、删减：产品型号 XY-200、全部规格参数与金额数字、
              第 5 条免责声明全文、公司名称与注册商标。
约束：除上述"不可改写信息"外，其余内容可自由润色；不得新增原文没有的性能承诺。
输出格式：保留原文的章节结构与编号，逐节输出。
评价标准：型号/数字/免责声明与原文逐字一致；术语译法全文统一；任一条不符即为不合格。
```

### 6.5 易错辨析

| ❌ 误解 | ✅ 正解 |
|---|---|
| "翻译只要说'翻译成英文'就行" | 官方明确要求**额外**补受众、目的、术语、不可改写信息 |
| "模型和人类翻译一样会保护数字和条款" | 模型按"最可能的续写"生成，**不保证原文照抄**；不写"不可改写信息"就有被改写的风险 |
| "分类任务不需要术语" | 类别名本身就是要对齐的术语，自定义类别必须给定义与示例 |
| "受众和目的是一回事" | 受众是**给谁看**，目的是**拿来干什么**；两者分别影响措辞与取舍，都要写 |

> 🧠 **答题口诀**：题干出现「翻译 / 改写 / 总结 / 分类」→ 优先找含「**受众、目的、术语、不可改写信息**」的选项；
> 若问"最容易漏的是哪一项" → 答「**不可改写信息**」。

## 七、提示词优化迭代流程（写 → 测 → 分析 → 改）⭐（M2-K21）

### 7.1 四步循环

```
① 写（Write）   → 按七要素搭初版，明写评价标准与验收标准
② 测（Test）    → 用固定的一组测试用例（3~10 条，含边界样本）全跑一遍
③ 分析（Analyze）→ 归因：格式？口径？缺背景？跑题？缺知识？超边界？
④ 改（Revise）  → 针对归因做**一处**改动
⟲ 回到 ②
```

### 7.2 三条纪律

| 纪律 | 为什么 | 违反的后果 |
|---|---|---|
| **固定测试集** | 没有对照组，"改好了没有"无法判断 | 凭印象迭代，越改越偏 |
| **一次只改一处** | 改多处则无法归因，成功经验无法复制 | 好了不知道为什么好，坏了不知道哪里坏 |
| **留版本号** | 便于回滚到效果最好的一版 | 改崩了回不去 |

### 7.3 归因 → 动作对照表

| 归因结论 | 提示词层面的动作 | 是否需要换手段 |
|---|---|:---:|
| 泛泛而谈、长度失控 | 量化目标 + 明写输出格式与评价标准 | 否 |
| 口径踩偏、答非所问 | 补背景 + 补业务定义 | 否 |
| 分类/格式前后不一致 | 补 Few-shot 示例（覆盖易混边界） | 否 |
| 下游解析失败 | 明写输出格式 + 模板 + 负面约束 + 空结果行为 | 否 |
| 分不出哪版更好 | 补评价标准 + 要求交付前自查 | 否 |
| 一步跑偏全篇报废 | 先列计划与关键信息，确认后再生成 | 否 |
| 术语不一致 / 不可改写内容被改 | 补受众、目的、术语、不可改写信息 | 否 |
| 一个提示词塞太多事 | 任务拆解，分步执行 | 否 |
| **不知道我司资料 / 最新政策** | 提示词解决不了 | **是 → 接入知识库 / RAG（M3）** |
| **要实时数据 / 精确计算 / 业务动作** | 提示词解决不了 | **是 → 调用工具（M3）** |
| **长期固定的行为 / 格式 / 风格反复约束仍不稳** | 先试提示词 | **是 → 微调（M5）** |
| **要自主规划、多步执行** | 先试提示词 | **是 → 协作 Agent（M4）** |
| **高风险（医疗 / 金融 / 合同 / 对外发布）** | 约束 + 兜底 | **是 → 保留人工确认（M6）** |

### 7.4 决策树：优化输入永远是成本最低的第一步

```
回答不够好
   │
   ├─ 第 1 问：是「它说不清」还是「它不知道 / 做不了」？
   │
   ├─ 表达 / 理解问题（听得懂，只是答得糙）
   │     → ① 优化输入（提示词）  💰 最低、见效最快  ← 本模块 M2
   │           └─ 还不够好 → 再看缺什么：
   │                 缺私域 / 最新知识 → ② 接入知识库（M3）
   │                 要实时数据 / 确定性计算 / 业务动作 → ③ 调用工具（M3）
   │                 要长期固定行为 / 格式 / 风格 → ④ 使用微调（M5）
   │                 要自主规划、多步执行 → ⑤ 协作 Agent（M4）
   │                 高风险场景 → ⑥ 保留人工确认（M6）
   │
   └─ 知识 / 能力问题 → 直接从 ②~⑥ 里选（但通常仍建议先把话说清楚）
```

> ✅ **答题策略**：题干只说"效果不好 / 不满意"，**第一步永远选"优化输入（提示词）"**，
> 除非题干明确出现了缺知识、缺实时能力、要长期固定风格、要自主多步执行的症状。

### 7.5 一页纸工作流

| # | 武器 | 什么时候先想到它 |
|:---:|---|---|
| 1 | **七要素自检** | 拿到任何任务先扫一遍：目标/背景/角色/约束/示例/输出格式/评价标准缺哪项 |
| 2 | **明确与量化**（含评价标准） | 输出跑偏、太泛、分不出好坏 |
| 3 | **Few-shot 示例** | 格式不对、分类口径不一致、话术不像本公司 |
| 4 | **输出格式约束** | 需要机器解析、需要表格/JSON、字数不可控 |
| 5 | **先列计划 + 任务拆解** | 任务复杂、多步、返工成本高 |
| 6 | **四类任务补四件套** | 翻译 / 改写 / 总结 / 分类 |
| 7 | **迭代循环** | 改了几轮没进步 / 不知道哪次改动起作用 |

```
② 官方四件套     任务目标 · 背景 · 约束 · 验收标准
③ 四类任务四补充 受众 · 目的 · 术语 · 不可改写信息
④ 手段六选一     优化输入 → 接入知识库 → 调用工具 → 使用微调 → 协作 Agent，或保留人工确认
```

### 9.4 必背四条口诀

```
· 前六项管"让模型做对"，第七项（评价标准）管"让你能判断它对没对"。
· 评价标准是给模型的尺子，验收标准是给任务的闸门；两把尺子必须同源。
· 说不清优化输入，不知道接知识库，做不了调工具，改不了用微调，要落地协作 Agent，风险高保留人工确认。
· 翻译改写总结分类 → 受众、目的、术语、不可改写信息；最容易漏的是「不可改写信息」。
```

### 9.5 必背"扫题三步"

```
Step 1  圈出任务类型（翻译 / 改写 / 总结 / 分类 / 提取 / 生成 / 复杂多步）
Step 2  圈出症状（泛泛而谈？口径不一致？格式不稳？分不出好坏？内容被改？不知道？）
Step 3  回对应清单找缺项 —— 官方点名的那一项就是答案
```

### 9.6 见到即排除（⛔ 越界项）

```
代码 / 写一段实现      temperature · top_p · max_tokens
LoRA · PEFT · 训练批次 · 学习率     控制台菜单路径 · 计费单价
采样参数取值          MCP 协议细节
```

## 附：与其他模块的连接

- → **M3 增强大模型应用的能力（22%）**：换手段的第一站——缺知识用**知识库 / RAG**，要实时数据、确定性计算或业务动作时**调用工具**；API 调用参数也并入了该模块。
- → **M5 大模型微调（12%）**：当格式 / 风格 / 分类行为反复约束仍不稳定时才考虑。
- → **M4 大模型 Agent（16%）**：当任务需要模型自主规划并调用工具实际执行时进入；注意本模块只到"先列计划 + 分步提示"，不引入工具调用。
- → **M6 大模型安全合规（12%）**：高风险场景的人工复核属于 M6，**不要在本模块展开**；但本模块的「约束 + 兜底」是它的第一道防线。
