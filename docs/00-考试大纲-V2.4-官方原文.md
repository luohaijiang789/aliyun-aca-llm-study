## 一、考试背景（官方原文）

阿里云大模型工程师 ACA 认证（Alibaba Cloud Certified Associate - LLM）面向**企业 AI 通识教育**，适合**非技术背景人员、无算法背景的技术人员**，以及希望系统了解大模型应用方法的学习者。该认证主要考核考生对大模型基础知识、典型应用方式、AI Agent 使用方法和安全合规要求的理解，以及将大模型能力应用到实际业务场景中的能力。

### 通过认证可证明的能力

- 了解大模型的基本概念、工作原理和常见应用场景，能够与大模型相关技术人员进行基本沟通协作。
- 掌握**提示词工程、RAG、知识库、工具调用、MCP、微调、Agent 和 Skill** 等改进大模型应用效果的方法。
- 能够使用大模型和个人 AI Agent 辅助完成**信息提取、内容生成、资料分析、知识问答、办公自动化**等任务。
- 理解如何围绕**业务目标和评测机制**打造面向他人的高质量 AI 服务。
- 了解大模型应用，尤其是 **Agent 应用**中的安全合规风险来源与治理方法。

### 报名入口

<https://edu.aliyun.com/certification/aca13>

## 二、建议掌握的知识（官方原文 · 等同于官方考点清单）

- 大模型的基础概念、**技术发展脉络**、工作方式和典型应用场景。
- 提示词基础、**输入优化方法**、**采访模式**、**深度思考模式**，以及把**任务目标、背景、约束和验收标准**讲清楚的方法。
- RAG、**知识库服务**和知识问答系统的基本原理与质量改进方法。
- **工具调用、MCP** 和个人 AI Agent 接入知识库与工具的方法。
- 大模型微调的**适用场景、基本流程**，以及与提示词、RAG 的**选型边界**。
- AI Agent 的**基本能力、适用场景、局限性**和协作使用方式。
- **Skill、自检闭环**等帮助 Agent 沉淀方法和提升输出质量的实践方式。
- 大模型应用和 Agent 应用的**安全合规风险与治理建议**。

## 四、考试内容（官方原文 · 逐字摘录，这是出题的直接依据）

> ⚠️ 官方声明：**本认证不要求考生编写代码，也不考模型训练和协议实现细节。**
> 考试重点是**理解大模型能力边界**，并能在业务场景中选择合适的方法：
> **优化输入、接入知识库、调用工具、使用微调、协作 Agent，或保留人工确认。**

### 1. 大模型概念

> 理解大模型是什么，能做什么，**不能直接替人决定什么**。理解大模型**基于上下文生成内容**的基本方式，以及由此带来的**幻觉、训练数据时间范围和上下文限制**。掌握**能力边界判断**：什么时候适合生成、总结、分析，什么时候需要知识库、工具或人工确认。

### 2. 提示词工程

> 好答案来自好输入。掌握如何说明**目标、背景、角色、约束、示例、输出格式和评价标准**。面对**复杂任务**，先列计划和关键信息，确认后再生成；面对**翻译、改写、总结、分类**等任务，补充**受众、目的、术语和不可改写信息**。

### 3. 增强大模型应用的能力

> 模型不是什么都要靠记忆回答。掌握选型：**查企业资料用 RAG，需要实时数据、确定性计算或业务动作时用工具**。理解 RAG 的**解析、切分、检索、重排序和评测**会影响答案质量；了解 **MCP 的作用，不要求掌握协议细节**。

### 4. 大模型微调

> 微调不是万能按钮。掌握微调适合什么：**稳定行为、格式、风格、分类能力，或支持轻量模型部署**。理解微调的基本流程：**定义目标、准备样本、选择基模、控制数据质量、评估效果**。能区分：**查知识用 RAG，做动作靠工具，稳行为才考虑微调**。

### 5. 大模型 Agent

> Agent 的价值是把「回答问题」推进到「完成任务」。掌握如何给 Agent 明确**目标、资料来源、工具边界和阶段检查点**。理解 **Skill 用来固化重复工作方法**，**自检清单要具体、可核对、有证据**。**高风险动作必须人工确认。**

### 6. 大模型安全合规

> 安全合规的核心是**让 AI 在边界内工作**。掌握**内容安全、数据安全、权限控制、生成内容标识、来源留存、审计追踪和人工复核**。遇到**医疗、金融、合同、对外发布**等高风险场景，**AI 可以辅助整理和起草，但不能替代最终责任人**。

## 五、官方用词对照（⚠️ 必须遵守）

官方大纲**全文未出现「插件」一词**，统一使用「**工具 / 工具调用**」。
本库此前使用的「插件」视为旧版遗留说法，已按官方口径统一为「工具」。

| 本库旧说法 | 官方说法 | 说明 |
|---|---|---|
| 插件 | **工具 / 工具调用** | 官方全文 0 次「插件」 |
| （无） | **人工确认 / 人工复核** | 官方列为可选手段之一，也是合规要求 |
| LoRA / PEFT 细节 | **未出现** | 官方明说「不考模型训练细节」 |
| 多模态 | **未出现** | 六大模块中无多模态 |

### 官方列举的场景处理办法（可组合，无固定顺序）

```
优化输入（提示词）／接入知识库（RAG）／调用工具／使用微调／协作 Agent
高风险动作叠加人工确认；按任务需要组合，不按箭头顺序机械实施
```
