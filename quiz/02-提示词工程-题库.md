### Q001 [M2-K01] [B] 单选

某运营同学给大模型写的提示词只有一句话：「帮我总结一下」。模型回复了一大段泛泛而谈、格式混乱的内容。从**提示词的构成要素**角度分析，这段提示词最主要的缺陷是：

- A. 缺少**指令**，没有告诉模型要做什么
- B. 缺少**输入数据**和**输出格式要求**，既没给要总结的材料，也没说要输出成什么样
- C. 缺少**模型版本**信息，应当换成参数规模更大的模型
- D. 缺少**采样参数**设置，应当把随机性参数调低

**答案**：B
**考点**：M2-K01 提示词的构成要素（指令 / 上下文 / 输入数据 / 输出格式）
**解析**：
- A ❌ 「总结」本身就是一条指令（虽然含糊），指令并非完全缺失；真正缺失的是可被处理的**输入材料**和可预期的**交付形态**。
- B ✅ 高质量提示词通常包含**指令、上下文、输入数据、输出格式（要求）**四部分。本例既没有把待总结的原文交给模型，也没有规定「输出成 Markdown 表格 / 300 字以内 / 只要 3 条要点」，导致模型只能自由发挥，输出自然泛泛而谈。
- C ❌ 换更大的模型属于提高成本的路线，而本题的病因明确在提示词本身（属于 M2-K10 所说「成本递增顺序」中不该跳步的地方）。
- D ❌ 采样参数（temperature 等）相关的 API 参数在 V2.4 中已并入 **M3 增强大模型应用的能力**，不属于本模块（课时 3）讨论的优化手段，且它解决的是随机性问题，不是「没给材料、没给格式」的问题。

**我错了吗**：☐

### Q002 [M2-K03] [B] 单选

客服团队要把用户反馈按公司自定义的 5 类问题打标，模型总是把「第 4 类」误判成其他类别。在提示词层面，**最有效**的改进措施是：

- A. 在提示词中给模型设定「你是一名资深客服主管」的角色
- B. 要求模型输出得更短，用更少的字数降低出错概率
- C. 在提示词中加入若干条已标注好的「反馈原文 → 正确类别」示例，再让模型对新的反馈分类
- D. 把分类要求重复写三遍，以强化模型的重视程度

**答案**：C
**考点**：M2-K03 Zero-shot / One-shot / Few-shot
**解析**：
- A ❌ 角色设定主要影响语气、视角和专业程度，**不能替代口径定义**；「客服主管」也会按自己的理解分类，依然会分错第 4 类。
- B ❌ 字数多少与判别准确率无因果关系，这是典型的无关干扰项。
- C ✅ 这就是典型的 **Few-shot（少样本）**。模型分错的根因是**不知道你们公司自定义的类别口径**，给几条覆盖各类别（尤其是易混的第 4 类）的标注示例，等于用示例把口径锚定下来，是成本最低、见效最快的做法。
- D ❌ 重复指令不等于提高理解精度，模型不会因为「说了三遍」就更懂分类标准；真正缺的是示例而非音量。
- 📌 补充：Zero-shot（0 个示例）适合通用的成熟任务；口径/格式要求高的任务应选 One-shot（1 个）或 Few-shot（2~N 个，通常 3~5 条），且示例本身的口径必须一致。

**我错了吗**：☐

### Q003 [M2-K04] [B] 单选

让大模型根据一份含多条条款的活动规则，判断某个用户订单是否符合退款条件，模型总是直接给出结论且判断错误。以下哪项提示词改动**最能**提升判断准确率？

- A. 要求模型「先逐条比对规则条件并说明是否满足，再给出最终结论」
- B. 要求模型「直接给出结论，不要啰嗦」
- C. 把规则文档从头到尾重复粘贴两遍
- D. 要求模型把结论加粗显示

**答案**：A
**考点**：M2-K04 思维链 CoT（Chain-of-Thought）
**解析**：
- A ✅ 这正是**思维链（CoT）**：让模型把多步推理过程显式写出来再下结论。逐条比对相当于给模型一段「可展开的推理空间」，能显著提升多条件判断类任务的准确率。
- B ❌ 「直接给结论」恰恰是压制推理过程，会让模型跳步，更容易出错。
- C ❌ 重复材料不提供推理结构，且浪费上下文，对准确率无实质帮助。
- D ❌ 加粗只是排版要求，属于输出格式层面的装饰，与判断准确率无关。
- 📌 补充提醒：CoT **不注入新知识**，它只是让模型已有的推理能力被完整展开；所以规则文档本身必须给全。

**我错了吗**：☐

### Q004 [M2-K05] [B] 单选

小李写了一条提示词：「请阅读这份 100 页的行业报告，写出摘要、提炼核心数据、生成汇报大纲，并把结果翻译成英文。」结果四项产出质量都一般。从提示词优化的角度，**最恰当**的做法是：

- A. 保持一轮完成，但把四项要求各写得更详细、更冗长一些
- B. 把报告拆成片段分别丢给模型，让每个片段都把四件事全做一遍
- C. 直接对该场景做微调，让模型一次产出四部分内容
- D. 把这条提示词拆成多个子任务，分步提示（先摘要 → 确认后抽取数据 → 确认后生成大纲 → 最后翻译），每步输出单独确认

**答案**：D
**考点**：M2-K05 任务拆解
**解析**：
- A ❌ 「写得更长」只是增加信息密度，并没有降低任务的耦合度，仍然是一次性完成四件事，过载问题没解决。
- B ❌ 片段各自做四件事只会得到一堆碎片化结果，既难以汇总也无法保证口径一致，反而引入了新的合并问题。
- C ❌ 跳过提示词优化直接微调违反了「成本递增、先便宜后贵」的原则（M2-K10）；且本题病因在任务组织方式，不在模型能力。
- D ✅ 这是典型的**任务拆解**：一个提示词里塞入多项不同性质的任务会导致任务过载、注意力分散。拆成有先后依赖的子步骤后，每步上下文更聚焦、输出可抽检、错在哪一步一目了然，后一步还能复用前一步已确认的结果。
- 📌 注意区分：若任务需要模型**自主规划并调用外部工具**实际执行，那属于 M4 Agent；纯提示词层面的分步串联（人工串、不引入工具）才是本考点。

**我错了吗**：☐

### Q005 [M2-K06] [B] 单选

某系统要把大模型从合同文本中抽取出的信息直接写入数据库，但模型有时返回合规的 JSON，有时返回一大段带分析的自然语言，导致下游解析频繁失败。以下措施中，**应当优先采取**的是：

- A. 在提示词中明确规定输出格式并给出字段模板，例如「仅输出 JSON 数组，字段为……，除此之外不要输出任何内容；无结果时输出 []」
- B. 立即准备数据对该任务做微调，以固化输出格式
- C. 搭建 RAG 知识库，把合同资料灌入后再抽取
- D. 提高模型的随机性参数，让输出更有多样性

**答案**：A
**考点**：M2-K06 输出格式约束
**解析**：
- A ✅ 输出格式问题**首先应该在提示词里解决**：明确格式 + 给出字段模板 + 加「除此之外不要输出任何内容」的负面约束 + 规定空结果行为，这是成本最低且通常足够有效的做法。
- B ❌ 微调确实能固化格式，但它是**成本更高**的手段，必须在「提示词反复约束仍不稳定」之后才考虑（M2-K10 的顺序不能跳）。本题考查的正是这个优先级判断。
- C ❌ RAG 解决的是**缺私域/最新知识**的问题，与输出格式是否规范无关；本题不存在知识缺失。
- D ❌ 提高随机性只会让输出更不稳定，且采样参数在 V2.4 中已并入 M3，不属于本模块（课时 3）的优化手段。

**我错了吗**：☐

### Q006 [M2-K09] [B] 单选

小王优化提示词时给初版加上了角色设定、补充了两条示例、同时新增了字数限制，结果整体效果反而比之前更差。按照提示词迭代优化的方法论，他接下来**最应该**做的是：

- A. 回滚这次改动，立即改用微调方案
- B. 用固定的一组测试用例分别验证，对比改动前后的输出差异，定位是哪一处改动导致退化，再有针对性地回改
- C. 保持当前提示词不变，反复重新生成，直到抽到满意的答案为止
- D. 删除所有约束，让模型完全自由发挥以恢复效果

**答案**：B
**考点**：M2-K09 提示词迭代优化方法论（写 → 测 → 分析 → 改）
**解析**：
- A ❌ 效果变差就换手段，跳过了「分析归因」这一步，违反先便宜后贵的顺序；且连问题出在哪一处都还没搞清楚。
- B ✅ 标准做法：**用固定测试集做对照 → 归因到具体改动 → 一次只改一处**。同时改三处会失去归因能力，正确做法是把改动拆开逐项验证，保留有效项、回退有害项。
- C ❌ 「反复重试抽好答案」不是优化，是抽样运气，产出不具备稳定性，下次同样条件下仍可能失败。
- D ❌ 完全去掉约束会回到「输出不可控」的原始状态，等于放弃了已有效果，不符合迭代优化的思路。

**我错了吗**：☐

### Q007 [M2-K10] [A] 单选

业务方反馈：「大模型给出的回答不够好。」作为工程师，**第一步最应该**考虑的措施是：

- A. 先优化提示词：明确角色、任务、上下文、输入输出要求，必要时补充示例
- B. 先准备领域数据，对模型做微调
- C. 先搭建 RAG 知识库，接入企业文档
- D. 先构建一个 Agent，让模型自主规划完成任务

**答案**：A
**考点**：M2-K10 提示词在决策树中的位置（课时 3：通过优化输入来提升回答质量）
**解析**：
- A ✅ 官方课时 3 的核心主张就是「**通过优化输入来提升回答质量**」。在所有提升手段中，优化提示词**成本最低、见效最快**，因此是永远的第一步。
- B ❌ 微调成本高、周期长，且主要解决的是**固定格式/风格/领域表达习惯**问题；未经提示词优化就直接微调属于跳步。
- C ❌ RAG 解决的是**缺私域知识或最新信息**的问题；题干只说「回答不够好」，并未给出知识缺失的症状。
- D ❌ Agent 用于**复杂多步任务、需自主规划与调用工具**的场景，成本高且引入不确定性；简单问答用 Agent 属于杀鸡用牛刀。
- 🧠 口诀：**先问再说（提示词）→ 缺知检索（RAG）→ 定风微调（微调）→ 多步智能（Agent）→ 越界插件（插件）**。

### Q008 [M2-K02] [B] 多选

关于提示词中的**角色设定与系统角色提示词**，下列做法正确的有：（多选）

- A. 在系统提示词中明确模型的身份、资深程度与专业领域，例如「你是一名有 10 年经验的电商售后质检员」
- B. 角色设定可以随意发挥，是否与具体任务相关都不会影响输出质量
- C. 在设定角色的同时，一并说明该角色应遵守的行为准则与兜底行为，例如「只依据给定材料判定，证据不足时输出'无法判定'」
- D. 角色设定要与具体任务场景相匹配，例如起草对外法务函件时就设定为专业法务角色

**答案**：ACD
**考点**：M2-K02 角色设定与系统角色提示词
**解析**：
- A ✅ 角色设定 = **身份 + 领域经验 + 服务对象**，具体到领域和年限比空泛的「你是一个专家」有效得多，能显著改善语气、视角与专业度。
- B ❌ 角色设定不是装饰品，它会直接影响模型输出的视角、措辞与取舍；与任务错配的角色（例如让「创意文案」去写严谨的合规报告）还会造成文风冲突，使输出偏离要求。
- C ✅ 角色提示词里同时给出**行为准则**（依据来源、边界、兜底行为）才能把「人格」约束住，避免出现臆造内容。这与 K07 的边界约束是配合关系。
- D ✅ 角色必须与任务相匹配，是 A 的自然延伸。注意角色也不是越多越好，一次性叠加多个互不相关的专家身份会让角色互相打架，反而降低输出稳定性。
- 📌 另一个常见误解：「角色是模型训练阶段就固定的，提示词里写没用」——这是错的，角色设定恰恰是**提示词层面**的标准手段，效果可在会话中直接观察到。

### Q009 [M2-K07] [B] 多选

为了让大模型输出「不跑偏」，在提示词中可以设置哪些**明确性与边界约束**？（多选）

- A. 约束应当越多越好，把可能相关的规则不论本次是否用得上都全部写进去
- B. 限定回答所依据的素材范围，例如「仅依据以下【资料】内容回答，不得引用资料之外的信息」
- C. 明确列出禁止项并给出兜底行为，例如「不得编造未提及的数据；资料中没有的内容直接回答'未提及'」
- D. 明确任务的目标对象与量化要求，例如「面向非技术用户，控制在 100 字以内，使用正式书面语，避免使用专业术语」

**答案**：BCD
**考点**：M2-K07 明确性、具体性与边界约束（含限定范围、禁止项）
**解析**：
- A ❌ 约束不等于越多越好。无关或过度约束会让模型顾此失彼、注意力被稀释，正确原则是**与任务强相关且必要**。这是本考点最常见的陷阱说法。
- B ✅ **限定范围**是边界约束的核心，能防止模型用外部知识或记忆「自由补全」答案。
- C ✅ **禁止项必须配兜底行为**：只说「不许编造」而不说「不知道时该怎么办」，模型往往仍会硬答一个；给出「未提及」这样的默认输出才能真正落地。
- D ✅ **可量化、可验收**的要求（对象 / 字数 / 语气 / 术语使用）取代了「写得专业一点」这类无法验收的形容词表述，属于明确性与具体性。

### Q010 [M2-K08] [B] 多选

下列哪些情况属于**提示词本身的失败模式**，应当通过优化提示词来改善？（多选）

- A. 指令模糊，例如「写得好看点」「分析一下」
- B. 缺少必要的背景上下文，导致模型误解了业务口径
- C. 模型不知道本公司内部最新发布的业务政策，因而无法回答相关问题
- D. 一条提示词里同时塞入摘要、抽取、生成、翻译等多项任务，导致任务过载

**答案**：ABD
**考点**：M2-K08 常见失败模式与归因
**解析**：
- A ✅ 指令模糊是典型的提示词失败模式，改法是量化要求、明确对象与验收标准（对应 M2-K07）。
- B ✅ 缺上下文会让模型按自己的默认理解作答，改法是补充背景、业务定义与角色（对应 M2-K01/K02）。
- C ❌ 这是**知识缺失**（私域 / 时效信息）问题，提示词写得再好也无法让模型知道它从未见过的内容，应当采用 RAG / 知识库等检索增强手段处理——属于 M3 增强大模型应用的能力模块。本题考查的正是「该不该用提示词」的边界判断。
- D ✅ 多任务混在一条提示词里导致每件事都做不精，改法是**任务拆解**、分步执行（对应 M2-K05）。
- 🧠 归因口诀：**「说不清」归提示词，「不知道」归检索，「做不了」归插件，「改不了的习惯」归微调。**
