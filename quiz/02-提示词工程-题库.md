## 一、单选题（7 题）

### Q001 [M2-K08] [A] 单选

产品部同学给大模型写了这样一段提示词：

> 「你是一名资深 B 端市场分析师。背景：我们要向中小企业主推广新的库存管理模块。请写一份产品推广文案，面向中小企业老板，500 字左右，使用正式书面语，分三段输出，附三条核心卖点。」

目标、背景、角色都已写清，字数、语体与分段等输出要求也一并给了，但模型连出三版，团队始终争论不休、**无法判断哪一版更好**。按照官方对提示词构成要素的要求，这段提示词**最缺失**的是：

- A. **目标**：没有告诉模型究竟要写什么
- B. **背景**：没有说明为什么要写这份文案
- C. **评价标准**：没有说清"什么样算写得好"，缺少判断与取舍的尺度
- D. **角色**：没有给模型设定专业身份

**答案**：C
**考点**：M2-K08 提示词七要素⑦评价标准（含 M2-K02 目标、M2-K03 背景、M2-K04 角色的反向排除）
**官方依据**：官方原文「掌握如何说明**目标、背景、角色、约束、示例、输出格式和评价标准**」——「评价标准」是官方清单明确列举的第七项。
**解析**：
- A ❌ 目标已经写清——「写一份产品推广文案」，且交付物定义明确（500 字、分三段、附三条卖点）。目标并非缺失项，这是典型的"看着像但其实已给"的干扰项。
- B ❌ 背景也已经给出——「向中小企业主推广新的库存管理模块」，交代了来龙去脉与对象。
- C ✅ 这正是官方七要素中的**第七项**。这段提示词写了"写什么、写给谁、写成什么样"，却没写"**什么样算好**"（例如"每条卖点必须指向老板的具体痛点而非功能罗列""不得出现未经产品文档支持的数字""能被销售直接转发给客户算合格"）。没有这把尺子，输出好坏只能凭感觉，团队自然吵不出结论，迭代也无法对照。
- D ❌ 角色已设定——「资深 B 端市场分析师」，且写明了专业领域，符合"身份 + 领域经验"的写法。
- 📌 记忆锚点：目标/背景/角色/约束/示例/输出格式管"让模型做对"，**评价标准管"让你能判断它对没对"**。
**举一反三**：
1. 若题干改成「模型写出了三版，但每版都偏离了'面向中小企业老板'这个定位」→ 应回头检查**受众/背景**是否写清。
2. 若题干改成「三版都很专业，但销售说一版都用不了」→ 缺的仍是**评价标准**（没写明"能被销售直接转发"这条合格线）。
**易错提醒**：最容易误选 **A 或 D**，因为"目标""角色"是最眼熟的两个词。但题干已明确列出"目标、背景、角色与输出格式都已写清"，**先在题干里把已给的要素划掉**，剩下的才是答案。
**我错了吗**：☐

### Q002 [M2-K09] [A] 单选

业务方提出一个复杂需求：「把公司近三年的产品战略、主要竞品格局和来年的机会点，整理成一份给管理层看的复盘报告。」需求涉及的资料多、判断链条长，一旦跑偏返工成本很高。按照官方对**复杂任务**的提示词做法，**第一步最应该**做的是：

- A. 直接让模型一次性生成完整报告，生成后再逐段挑错修改
- B. 先让模型列出**完成任务的分步计划**和**尚不清晰的关键信息**，与业务方确认后，再让它按确认过的计划逐步生成
- C. 先对公司内部文档做微调，让模型记住近三年的产品战略
- D. 把报告拆成若干片段，分别交给不同的模型生成，最后人工拼接

**答案**：B
**考点**：M2-K09 复杂任务：先列计划和关键信息，确认后再生成（含 M2-K18 任务拆解）
**官方依据**：官方原文「面对**复杂任务，先列计划和关键信息，确认后再生成**」。
**解析**：
- A ❌ "一次生成 + 事后挑错"正是官方要避免的做法。复杂任务一步跑偏会导致整篇报废，且出错后难以定位是哪一步出的问题，返工成本最高。
- B ✅ 这正是官方原文的要求。先让模型说明"分几步做、每步需要什么资料"，再列出它还不清楚的关键信息（受众是谁、看多久、要几个结论、用哪套口径），由人补齐确认后才开工——**把信息缺口消灭在生成之前**。这也符合官方"优化输入"优先的思路。
- C ❌ 微调属于成本更高的手段：本例的病因是**需求没对齐**，不是模型缺知识；未经定位根因就启动微调，缺少必要的目标与评测依据。
- D ❌ 换多个模型分段生成同样没有解决"计划与关键信息未对齐"的根因，还会带来各片段口径不一致、难以汇总的新问题；且这与官方给出的路径无关。
- 📌 延伸：确认后的落地方式通常就是**任务拆解**（先摘要 → 确认 → 抽数据 → 确认 → 出大纲）；只有当任务需要模型自主规划并**调用工具**实际执行时，才进入 Agent（M4）。
**举一反三**：
1. 若题干改成「要批量处理 1 万条工单，口径一旦错了全部返工」→ 同样是**先列计划与关键信息、小批量验证确认后再批量运行**。
2. 若题干改成「模型已经列出了计划，接下来做什么」→ 选"**由人确认计划与关键信息，再逐步生成**"，而不是"立刻开始生成"。
**易错提醒**：最容易误选 **C**，因为"让模型记住近三年战略"听起来很对症。但症状是**需求未对齐**而不是**缺知识**；缺知识才走知识库/RAG，长期固定行为才走微调。
**我错了吗**：☐

### Q003 [M2-K10] [A] 单选

某公司要把一份中文产品说明书改写成面向海外经销商的英文版本。之前试过几次，模型把其中的**产品型号、规格参数和免责声明**也一并意译甚至删掉了，法务评审直接打回。按照官方对**翻译、改写、总结、分类**任务的要求，为避免这类问题，提示词中**必须明确**补充的是：

- A. 模型的角色设定，例如"你是一名资深译者"
- B. **不可改写信息**：明确列出必须原样保留、不得翻译或改写的内容（产品型号、规格参数、金额数字、免责声明、公司名称等）
- C. 输出的字号与字体要求
- D. 采样参数的具体取值

**答案**：B
**考点**：M2-K10 翻译/改写/总结/分类任务需补充受众、目的、术语和**不可改写信息**
**官方依据**：官方原文「面对**翻译、改写、总结、分类**等任务，补充**受众、目的、术语和不可改写信息**」。
**解析**：
- A ❌ 角色设定确实有用（影响语气与专业度），但它解决不了"内容被改写"的问题；且有更直接对应的官方条目。
- B ✅ 模型本质是按概率续写，**不会天然保护数字和条款**；不写"不可改写信息"，型号、参数、免责声明就可能被"优化"掉——本案例的症状（法务打回）完全对应这一项，也是四类任务中**最容易漏、后果最严重**的一项。
- C ❌ 排版细节与"内容是否被改写"无关，且官方不考这类枝节。
- D ❌ 采样参数属于调用层面的话题，官方声明不考代码与参数，相关内容已并入 M3；它也无法约束哪些内容不许改写。
- 📌 配套记忆：四项补充信息各自的作用——**受众**决定措辞深浅、**目的**决定取舍重点、**术语**决定译法一致性、**不可改写信息**决定哪些内容一个字都不能动。
**举一反三**：
1. 若题干改成「模型把'履约时效'一会儿译成 A、一会儿译成 B」→ 缺的是**术语（术语表）**。
2. 若题干改成「改写后的客户简报语气太技术，客户看不懂」→ 缺的是**受众**（未说明面向非技术背景的已签约客户）。
**易错提醒**：最容易误选 **A**——"资深译者"是很自然的联想，但角色管的是语气与视角，管不了"不许改什么"。看到"型号/金额/条款被改动"这个症状，**直接锁定不可改写信息**。
**我错了吗**：☐

### Q004 [M2-K14 / M2-K15] [C] 单选 ⚠️待核实

> ⚠️ 本题涉及的「采访模式」「深度思考模式」为**产品功能**，官方大纲只列入了名称，**未给出交互形态**。以下仅按"概念与作用"层命题，**不得据此记忆任何按钮位置、开关名称或操作步骤**。

关于这两种模式，下列说法正确的是：

- A. 采访模式是指用户一次性把全部要求说完，模型不再追问，以提高效率
- B. 采访模式适用于**需求还不清楚**的场景：让模型反过来**向你提问**，通过问答把缺失的信息补出来
- C. 深度思考模式是让模型跳过推理过程、直接给出结论，以节省时间
- D. 深度思考模式适合所有任务，任何场景开启后效果一定更好

**答案**：B
**考点**：M2-K14 采访模式 / M2-K15 深度思考模式（🔴`[C]` 待与官方课程核实，只考概念与作用）
**官方依据**：官方「建议掌握的知识」原文列出「**采访模式**、**深度思考模式**」，但未描述其产品形态与交互细节 → **官方未明列细节，属 [C] 级推断，⚠️ 待核实**。
**解析**：
- A ❌ 恰好相反。采访模式的特征是**让模型来问你**，而不是你说完它不问；需求不清时一次性说完反而会把假设塞给模型。
- B ✅ 采访模式的核心作用就是**反转提问方向**：由模型提出它完成这件事还缺什么信息（受众、口径、范围、交付形态……），人来回答，从而在生成前补全信息缺口。它适用于**需求不明、范围不清、关键信息缺失**的场景。
- C ❌ 深度思考模式是让模型**展开更长的推理过程再作答**，而非跳过推理直接给结论；跳过推理恰恰是复杂任务更容易出错的原因。
- D ❌ 它适用于**复杂推理 / 多步任务**（多条款比对、多步推算、需要交叉验证的判断）；简单的事实问答或格式转换没有必要展开推理，只会增加耗时。任何手段都不存在"一定更好"。
- 📌 一句话区分：**需求说不清 → 采访模式（让它问你）；事情很难想 → 深度思考模式（让它慢慢想）。**
**举一反三**：
1. 若题干改成「用户说'我要一份市场分析报告'，但说不清给谁看、要几个结论」→ 选**采访模式**。
2. 若题干改成「要逐条比对 8 项政策条款判断是否符合赔付条件」→ 选**深度思考模式**（概念上等同"先想后答 / 先展开推理再给结论"）。
**易错提醒**：最容易误选 **D**，因为"开启后效果更好"符合直觉。凡是出现"**所有任务**""**一定更好**"这类绝对化表述，基本都是干扰项。
- ⚠️ 若官方课程给出不同的产品名称或定义，以官方课程为准。
**我错了吗**：☐

### Q005 [M2-K06] [B] 单选

客服团队要把用户反馈按公司自定义的 5 类问题打标，模型总是把其中「第 4 类」误判成其他类别。在提示词层面，**最有效**的改进措施是：

- A. 在提示词中给模型设定「你是一名资深客服主管」的角色
- B. 要求模型输出得更短，用更少的字数降低出错概率
- C. 在提示词中加入若干条已标注好的「反馈原文 → 正确类别」示例，尤其要覆盖易混的第 4 类，再让模型对新的反馈分类
- D. 把分类要求重复写三遍，以强化模型的重视程度

**答案**：C
**考点**：M2-K06 七要素⑤示例（M2-K16 Zero-shot / One-shot / Few-shot）
**官方依据**：官方原文七要素包含「**示例**」；本题具体手法（Few-shot）为 🟡`[B]` 级——官方「输入优化方法」的展开，官方课程必然覆盖。
**解析**：
- A ❌ 角色设定主要影响语气、视角与专业度，**无法代替口径定义**；"资深客服主管"同样不知道你们公司第 4 类的边界在哪。
- B ❌ 输出字数与判别准确率没有因果关系，属于典型的无关干扰项。
- C ✅ 这是典型的 **Few-shot（少样本）**。误判根因是模型不知道**你们自定义的类别口径**，用若干条"原文 → 正确类别"的示例把口径锚定下来（特别是易混的第 4 类及其相邻类别），是成本最低、见效最快的做法，对应官方七要素中的「**示例**」。
- D ❌ 提高"音量"不等于提高理解精度，模型不会因为说了三遍就更懂分类标准；缺的是示例，不是重复。
- 📌 Zero-shot（0 个示例）适合通用的成熟任务；口径/格式要求高的任务选 One-shot（1 个）或 Few-shot（2~N，通常 3~5 条），且**示例口径必须一致**——示例自带的错误会被忠实复制，**质量 > 数量**。
**举一反三**：
1. 若题干改成「模型分得很准，但输出的类别名一会儿中文一会儿英文」→ 这属于**输出格式**（或术语一致性），不是示例数量问题。
2. 若题干改成「补了示例后准确率反而下降」→ 原因通常是**示例自带错误或口径不一致**（质量 > 数量）。
**易错提醒**：最容易误选 **A**——角色设定名气大、看起来"专业"。记住分工：**角色管语气与视角，示例管口径与格式**。
**我错了吗**：☐

### Q007 [M2-K07] [B] 单选

某系统要把大模型从合同文本中抽取出的信息直接写入数据库，但模型有时返回合规的 JSON，有时返回一大段带分析的自然语言，导致下游解析频繁失败。以下措施中，**应当优先采取**的是：

- A. 在提示词中明确规定**输出格式**并给出字段模板，例如「仅输出 JSON 数组，字段为……，除此之外不要输出任何内容；无结果时输出 []」
- B. 立即准备数据对该任务做微调，以固化输出格式
- C. 搭建知识库，把合同资料灌入后再抽取
- D. 调整模型的采样参数，让输出更稳定

**答案**：A
**考点**：M2-K07 七要素⑥输出格式（含 M2-K20 失败归因、M2-K13 边界、M2-K21 迭代顺序）
**官方依据**：官方原文七要素包含「**输出格式**」；"格式先靠提示词约束、反复不稳再考虑微调"属 🟡`[B]` 级——官方手段清单把「使用微调」排在「优化输入」之后。
**解析**：
- A ✅ 输出格式问题**首先应在提示词里解决**：明确格式 + 给出字段模板 + 加"除此之外不要输出任何内容"的负面约束 + 规定空结果行为，对应官方七要素中的「**输出格式**」，成本低且通常足够有效。
- B ❌ 微调确实能固化格式，但它是**成本更高**的手段，必须在"提示词反复约束仍不稳定"之后才考虑；本题考查的正是这个优先级判断。
- C ❌ 接入知识库解决的是**缺私域/最新知识**，与输出是否规范无关；本题不存在知识缺失。
- D ❌ 采样参数属调用层面（本库归入 M3）。⚠️ 注意：官方原文只逐字声明「**不考代码与模型训练细节**」，"参数取值不考"属本库 [B] 级延伸推断、**非官方逐字原文**；且它也无法约束哪些内容不许改写。本模块不会出现这类正确选项。
- 📌 易错对照：若症状是**字段时有时无、口径不一致** → 补示例；若症状是**形态不规范、混了自然语言** → 明写输出格式与负面约束。
**举一反三**：
1. 若题干改成「JSON 格式稳定了，但'金额'字段有时缺、有时把币种也写进去」→ 应补**字段模板与示例**，并加"缺失时输出 null"的兜底。
2. 若题干改成「提示词已把格式约束写得很死，换了三版仍不稳定」→ 此时才**考虑微调**固化格式（M5）。
**易错提醒**：最容易误选 **B**，因为"固化格式"正是微调的典型用途，看着非常对症。但题目问的是"**优先**"——先提示词、后微调，这是本模块最常考的顺序判断。

### Q008 [M2-K01 / M2-K02 / M2-K03 / M2-K04 / M2-K05 / M2-K06 / M2-K07 / M2-K08] [A] 多选

产品团队准备上线一批提示词，负责人要求"按官方标准把提示词写规范"。官方对本模块的要求是：**"掌握如何说明目标、背景、角色、约束、示例、输出格式和评价标准。"**
据此，一份高质量的提示词应当尽量向模型说明下列哪些要素？（多选）

- A. **任务目标**与**背景**：要做什么、交付什么，以及这件事的来龙去脉与业务口径
- B. **评价标准**：怎样算做得好，用哪些可核对的维度来判断
- C. 模型调用的采样参数取值与计费单价
- D. **角色**、**约束**、**示例**与**输出格式**

**答案**：ABD
**考点**：M2-K01 / K02 / K03 / K04 / K05 / K06 / K07 / K08 提示词七要素（官方原文直接列举）+ M2-K13 本模块不考什么
**官方依据**：官方原文「掌握如何说明**目标、背景、角色、约束、示例、输出格式和评价标准**」；官方声明「不要求考生编写代码，也不考模型训练和协议实现细节」。
**解析**：
- A ✅ **目标 + 背景**是七要素的前两项：目标说清"做什么、交付什么"，背景交代资料来源、业务口径与下游用途，防止模型按默认理解作答。
- B ✅ **评价标准**是第七要素：它决定了"能不能挑出好答案、能不能判断迭代有没有进步"，必须写成**可核对的条款**而非形容词。这是对照官方原文补齐的缺口，也是新题高发区。
- C ❌ 官方原文逐字声明的是「**不要求考生编写代码，也不考模型训练和协议实现细节**」；**参数取值 / 控制台菜单 / 产品定价**属本库据此延伸的排除清单（🟡`[B]` 级，**非官方逐字原文**），且这些内容不属于七要素，属于 M3 的调用层面话题。
- D ✅ 四项均为官方清单中的要素：**角色**（身份 + 领域经验 + 服务对象 + 行为准则）、**约束**（范围限定 + 禁止项 + 兜底行为）、**示例**（锚定口径与格式）、**输出格式**（模板 + 负面约束 + 空结果行为）。
- 🧠 记忆锚点：**前六项管"让模型做对"，第七项（评价标准）管"让你能判断它对没对"**。
**举一反三**：
1. 若选项出现「**验收标准**」而题干问的是"提示词七要素"→ 注意区分：验收标准属于官方**四件套**（目标、背景、约束、验收标准），不在提示词七要素清单内，容易做成陷阱。
2. 若题干改成"官方要求把哪些内容讲清楚"→ 答案应为**目标、背景、约束、验收标准**（四件套），而非七要素。这两组清单要能分开背。
**易错提醒**：最容易漏选 **B**（评价标准），因为很多考生只背了前六项；也容易误选 **C**，被"采样参数"这种专业词唬住——记住**见到参数/定价/代码就排除**。

### Q009 [M2-K10] [A] 多选

公司要用大模型完成一批文本任务：**把中文产品手册翻译成英文版**、**把冗长的会议纪要改写成客户能读的简报**、**把季度经营报告总结成一页要点**、**把客服工单按自定义类别打标**。
官方指出，面对**翻译、改写、总结、分类**这类任务，除了通用的提示词要素外，还应当补充信息。下列做法符合官方要求的有：（多选）

- A. 说明**受众**：英文版给海外经销商（非技术背景）看，一页要点给管理层口头汇报用
- B. 说明**目的**：例如这份简报要用于客户经理当天发送给客户，这份改写稿用于对外发送前的合规预审
- C. 给出**术语**：提供术语表并要求统一译法，例如"履约时效"统一译为 fulfillment SLA；自定义类别要给出每类的定义
- D. 标出**不可改写信息**：产品型号、规格参数、金额数字、免责声明与公司名称必须原样保留，不得翻译、改写或删减

**答案**：ABCD
**考点**：M2-K10 翻译/改写/总结/分类任务的四项补充信息（受众、目的、术语、不可改写信息）+ M2-K13 边界
**官方依据**：官方原文「面对**翻译、改写、总结、分类**等任务，补充**受众、目的、术语和不可改写信息**」。
**解析**：
- A ✅ **受众**决定措辞深浅与详略：给工程师看和给客户看完全不同，给老板看的总结不该写成流水账。
- B ✅ **目的**决定取舍重点：用于决策的建议与用于存档的记录，该保留的信息不一样；说明"拿来做什么"才能抓对重点。
- C ✅ **术语**决定一致性：同一术语前后译法不同会引发误解；自定义分类任务的"类别定义"本身就是要对齐的术语。
- D ✅ **不可改写信息**是最容易漏、后果最严重的一项：模型按概率续写，**不会天然保护数字、型号与法务条款**，不写明就可能被改写、被省略或被"优化"掉，导致合规风险。
- 📌 一句口诀：**翻译改写总结分类 → 受众、目的、术语、不可改写信息**；其中翻车最多的是**不可改写信息**。
**举一反三**：
1. 若题干只问"四类任务中**最容易遗漏**的是哪一项"→ 答「**不可改写信息**」。
2. 若题干改成"把客服工单按自定义类别打标，最该补哪项"→ 答「**术语（类别定义）+ 每类示例**」，因为类别名本身就是要对齐的术语。
3. 若增加选项「在提示词中写明模型的训练批次大小与学习率配置」→ 应判**错**：训练配置属于模型训练细节，官方明确"**不考模型训练**"；且与这类文本任务的输出质量无关。
**易错提醒**：最容易漏选 **D**。四项里前三项（受众、目的、术语）都比较直觉，唯独"**不可改写信息**"容易忽略——而它恰恰是后果最严重（法务/合规）的一项。见到"训练配置/学习率"这类**越界干扰项**一律排除。（📌 本题 A~D 正好是官方原文的四项，答案为 **ABCD 全选**，不要因为"四项全对"而不敢选。）

### Q010 [M2-K11] [A] 多选

某团队要上线一个「合同条款提取」的 AI 应用：任务较复杂，且结果要直接交给法务使用、要求可被检验。按照官方「把**任务目标、背景、约束和验收标准**讲清楚」的要求，下列做法正确的有：（多选）

- A. 讲清**任务目标**：从合同中提取哪些字段、交付成什么、给谁使用
- B. 说明**背景**：合同来源、业务口径、使用场景与下游环节
- C. 列出**约束**：仅依据合同原文提取，不得推断或编造；合同中没有的字段一律标记"未提及"
- D. 明确**验收标准**：例如在 20 份测试合同上关键字段准确率 ≥ 95%、漏提 ≤ 1 处才允许上线；并在批量执行前先让模型列出计划与尚需确认的关键信息，确认后再运行

**答案**：ABCD
**考点**：M2-K11 验收标准 + M2-K09 复杂任务先列计划（含 M2-K02 目标、M2-K03 背景、M2-K05 约束、M2-K12 手段顺序）
**官方依据**：官方「建议掌握的知识」原文「把**任务目标、背景、约束和验收标准**讲清楚的方法」；官方原文「面对**复杂任务，先列计划和关键信息，确认后再生成**」。
**解析**：
- A ✅ 本题四项要求的第一项：**任务目标**——说清做什么、交付什么、交付给谁，这是全部后续工作的锚点。
- B ✅ **背景**是第二项：合同来源、业务口径、使用场景与下游环节决定了"这类合同里什么才是关键条款"，不写模型只能按通用理解提取。
- C ✅ **约束**是第三项：范围限定（仅依据原文）+ 禁止项（不得编造）+**兜底行为**（缺失时输出"未提及"）。兜底是最常被遗漏、也是法务场景最必要的一条。
- D ✅ **验收标准**是第四项，必须**可量化、可核对、有证据**（具体阈值 + 测试样本）；同时本任务属于复杂任务，官方要求**先列计划和关键信息、确认后再生成**，把批处理前的口径对齐做在前面。
- 🧠 区分两组概念：**评价标准**写在提示词里、给**模型**看，用来对齐输出；**验收标准**写在任务需求里、给**人和项目**看，用来决定能不能放行。两把尺子必须同源、口径一致。
**举一反三**：
1. 若题干改成"验收标准应该怎么写才算合格"→ 选"**可量化（有阈值/样本）、可核对（不同人结论一致）、有证据（可追溯）**"那一组。
2. 若题干改成"上线前要不要人工复核"→ 合同、医疗、金融、对外发布属**高风险场景**，答案是要**保留人工确认**（M6）。
3. 若增加选项「为了确保达到验收标准，应当先对公司全部合同数据做微调」→ 本例应判**错**：题干缺目标、背景、约束和验收标准，微调不能替代需求澄清。是否微调要看是否有长期稳定行为需求和足够样本。
**易错提醒**：本题 A~D 四项均能帮助澄清任务，答案为 **ABCD 全选**。角色、示例、输出格式也是官方大纲提及的提示词要素；若题干选项包含它们，应按任务需要判断，不能因不在本题选项中便认为它们不是考点。
**我错了吗**：☐

## 必背清单（考前 10 分钟）

**数字**：本模块 **20%** / **10 题 = 7 单选 + 3 多选** / 满分 **20 分**，目标 **≥ 18 分**；全局满分 100、**及格 80**、60 分钟。

**官方原句 3 句**
1. **「好答案来自好输入。」**
2. **「掌握如何说明目标、背景、角色、约束、示例、输出格式和评价标准。」**
3. **「面对复杂任务，先列计划和关键信息，确认后再生成；面对翻译、改写、总结、分类等任务，补充受众、目的、术语和不可改写信息。」**

**四组清单**
```
① 提示词七要素   目标 · 背景 · 角色 · 约束 · 示例 · 输出格式 · 评价标准
② 本题四项要求     任务目标 · 背景 · 约束 · 验收标准
③ 四类任务四补充 受众 · 目的 · 术语 · 不可改写信息
④ 场景选型办法     优化输入／接入知识库／调用工具／使用微调／协作 Agent；高风险时保留人工确认（按需组合）
```

**四条口诀**
```
· 前六项管"让模型做对"，第七项（评价标准）管"让你能判断它对没对"。
· 评价标准是给模型的尺子，验收标准是给任务的闸门；两把尺子必须同源。
· 说不清优化输入，不知道接知识库，做不了调工具，改不了用微调，要落地协作 Agent，风险高保留人工确认。
· 翻译改写总结分类 → 受众、目的、术语、不可改写信息；最容易漏的是「不可改写信息」。
```

**见到即排除**：代码 / temperature·top_p·max_tokens / LoRA·训练批次·学习率 / 控制台菜单 / 计费单价 / MCP 协议细节。
