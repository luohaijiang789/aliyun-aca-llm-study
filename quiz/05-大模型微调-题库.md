# 二、单选题（4 题）

### Q001 [M5-K03] [A] 单选

某电商公司的智能客服需要对外输出售后处理建议，业务方提出两项硬性要求：
① 每次都必须以**固定结构的 JSON** 返回（字段固定为：问题类型、紧急程度、处理建议、是否转人工）；
② 语气必须符合公司统一的**客服话术规范**。

团队已经在提示词中写明了格式说明并附上了示例，反复优化多轮后，线上**仍会出现格式跑偏或语气不一致**的情况。此时**最合适**的方案是？

- A. 收集一批符合目标 JSON 结构与客服话术规范的高质量样本，在预训练基座模型上进行微调
- B. 将最新的售后政策文档接入知识库，采用 RAG 检索增强生成来回答用户问题
- C. 继续在提示词中追加更多的格式说明与示例，把要求写得更详细、更长
- D. 换用参数规模更大的模型，并在提示词中保留现有的格式说明，由更强的模型自行保证稳定

**答案**：A

**考点**：M5-K03 / M5-K04 适用场景②格式 + ③风格（渗透 M5-K08 官方选型口诀、M5-K10 提示词优先）

**官方依据**：官方原文「掌握微调适合什么：**稳定行为、格式、风格**、分类能力，或支持轻量模型部署」＋「**查知识用 RAG，做动作靠工具，稳行为才考虑微调**」。

**解析**：
- A ✅ **官方原句点名的适用场景：「格式」与「风格」。** 题干两个诉求——固定输出格式（稳定 JSON 结构）与统一行文风格（客服话术）——都属于 **"稳行为"** 问题，不是"查知识"也不是"做动作"；且前置条件已满足（提示词优化反复尝试后仍不达标）。用符合目标格式与话术的高质量样本做微调，可把格式与语气**内化进模型权重**，稳定性显著高于提示词约束，同时还能省掉提示词里那一大段 schema 与话术说明，**输入更短、响应更快**。
- B ❌ **本模块第一大陷阱项**——"把补知识当成微调的用途"。官方口诀前半句是「**查知识用 RAG**」；而本题的模型**知道该怎么答**，只是**答得不稳定**。这类问题并非缺资料，接了知识库 JSON 照样会跑偏、语气照样会漂移。**RAG 换资料，微调换习惯。**
- C ❌ 题干已明确「提示词 + 示例的方式**反复优化多轮后仍不达标**」——继续在同一条已被验证失效的路径上加大投入，属于无效加码。官方手段序列里「优化输入」排在「使用微调」之前，意思是**先试提示词**，而不是**一直试下去**。
- D ❌ 换更大的模型提高的是**通用能力上限**，不解决**行为稳定性**问题；格式与语气这类"习惯"仍要靠目标明确、样本规范的微调来建立。这是把"稳不稳"误当成"强不强"。

**举一反三**：
1. 若题干改成「刚提出 JSON 格式要求，团队还没在提示词里试过」→ 答案变为**先优化提示词**（写清 schema + 给示例），因为官方手段序列里优化输入排在第一位。
2. 若题干再加一句「同时要回答**上周刚更新**的退货政策」→ 正确答案变为 **RAG + 微调组合**：RAG 补最新政策（答什么），微调定格式与话术（怎么答）。

**易错提醒**：最容易误选 **B**，因为"接知识库"听起来最像"企业级解决方案"。记住判别链：**先问模型"知不知道该怎么做"**——本题它知道，只是做不稳 → 不是知识问题 → 排除 RAG。**看到"格式 / 语气 / 话术"+"反复优化仍跑偏"，一律选微调。**

### Q002 [M5-K09] [A] 单选

某医疗机构计划上线智能问答系统，要求：**每条结论都必须标注出处文档**（便于医生核验），且**诊疗规范每年都会更新**。团队中有人提议：「不如把全部诊疗规范整理成数据，微调进模型，这样模型就记住了，回答也更快。」对这一提议，**最恰当**的判断是？

- A. 赞同。微调能把规范知识固化进模型权重，回答时无需检索，速度更快且不会遗忘
- B. 不赞同。诊疗规范属于**需要频繁更新且必须可追溯**的知识，应优先采用 RAG 而非微调
- C. 不赞同。这类需求应当改用 Agent 编排多个工具来完成问答
- D. 赞同，但需要先把规范文档整理成问答对，并大幅增加训练数据量，即可解决更新问题

**答案**：B

**考点**：M5-K09 与 RAG 的边界（渗透 M5-K08 官方选型口诀「查知识用 RAG」、M5-K01 是否改动权重）

**官方依据**：官方原文「**查知识用 RAG**，做动作靠工具，稳行为才考虑微调」。

**解析**：
- A ❌ 前半句「固化进权重」描述本身没错（**微调确实会改动模型权重，这是它与 RAG 最本质的区别**），但**结论错误**。知识一旦进权重就面临两个致命问题：**① 会过时**——规范每年更新，意味着每年都要重训；**② 不可追溯**——知识融进参数后无法指出"这条结论出自哪份文档第几条"，直接违背题干中「必须标注出处」的硬要求。
- B ✅ **官方口诀第一句：查知识用 RAG。** 题干的「每年更新」「必须标注出处」两个信号同时指向 RAG：**可更新**（文档改完即刻生效）、**可追溯**（答案可附引用出处供医生核验）。这正是"微调不是万能按钮"的典型体现。
- C ❌ Agent 解决的是**复杂多步任务与工具编排**问题，并不解决"知识从哪来"与"答案能否溯源"。本题的核心矛盾是知识的**更新与溯源**，而非流程编排，属于答非所问。
- D ❌ 增加训练数据量**不解决**任何根本问题：样本再多，知识仍在权重里，**照样会过时、照样不可追溯**。这属于"用错误的工具，加大剂量"，方向错了。

**举一反三**：
1. 若题干再加一句「且要求回答一律采用统一的医学文书口吻」→ 正解是 **RAG + 微调组合**：RAG 补知识（答什么），微调定风格（怎么答），**两者并不互斥**。
2. 若题干改成「规范十年不变，且只要求模型用固定的三段式结构输出、不要求标出处」→ 那才更接近**微调**（格式 / 风格稳定性）。

**易错提醒**：最容易误选 **A** 或 **D**，因为"微调进模型就记住了""多堆点数据"听起来很专业。记住**两个硬伤**：知识进权重 → **会过时 + 不可追溯**。只要题干出现「**每年 / 每月更新**」「**必须标出处**」「**最新政策 / 报价单**」，答案一律是 **RAG**。

**我错了吗**：☐

### Q003 [M5-K05] [A] 单选

某互联网公司的客服系统需要把用户来单**自动分派**到既定的处理类别（咨询 / 投诉 / 售后 / 建议 / 其他），类别体系已经确定且长期不变。团队已在提示词中写清类别定义并附上少量示例，运行一段时间后发现：**边界模糊的来单归类不稳定**，同一句话换个说法就可能分到不同类别；且业务方希望进一步**降低响应延迟**。此时**最合适**的方案是？

- A. 收集一批按目标类别标注好的真实用户来单样本，在预训练基座模型上进行微调，把分类行为稳定下来
- B. 将公司的分类规则文档接入知识库，先检索出规则再让模型判断该归到哪一类别
- C. 在提示词中继续扩充示例，把历史示例每次都随请求完整带上
- D. 改用工具调用，由外部系统按关键词硬匹配的结果来决定类别，不再由模型判断

**答案**：A

**考点**：M5-K05 适用场景④**分类能力**（渗透 M5-K08 官方选型口诀、M5-K10 提示词优先、M5-K06 轻量部署）

**官方依据**：官方原文「掌握微调适合什么：稳定行为、格式、风格、**分类能力**，或支持轻量模型部署」。

**解析**：
- A ✅ **官方原句点名的适用场景之一：「分类能力」。** 让模型稳定地把输入归到**既定类别**正是微调的典型用武之地：类别**预先定义好、不需要外部知识**，属于纯粹的**行为稳定性**问题。相比提示词方案，微调后模型能直接输出既定类别标签，**更稳定**（边界样本不再摇摆）、**更快**、**更省 Token**（不必每次在输入里携带大段类别说明与示例，因而响应也更快）。前置条件也已满足——提示词方案已试过且效果不稳。
- B ❌ 这是最容易被带偏的一项。**类别既定、规则已在模型能理解的范围内，并不缺知识**，因此不触发官方口诀的「查知识用 RAG」。检索出规则文档，只会让输入变长，并不能让模型**稳定地输出既定类别标签**——它解决不了"同一个意思换种说法就被分到别的类"这个行为层面的不一致。
- C ❌ 题干已明确"提示词 + 少量示例"的方式效果不稳，在同一条已失效的路径上继续加码属于无效投入；而且每次随请求携带大量示例会显著拉长输入、拖慢响应，与"降低响应延迟"的诉求背道而驰。
- D ❌ **抽掉语义理解**去换取稳定性是因噎废食：关键词硬匹配无法处理同义表达与隐含意图，正是题干所指的边界样本会失效。**工具 / 工具调用**的用武之地是**实时数据与执行业务动作**（查询库存、发起退款、创建工单），不是替模型做语义判断。

**举一反三**：
1. 若题干改成「**类别体系每月都在调整**，且要依据**最新版本**的分类规则文档判定」→ 答案转为 **RAG**（规则在变 = 知识更新问题），或至少**先别微调**，退回把类别列表放进提示词。
2. 若题干再加一句「希望把这个分类能力放到**更小的模型**上，降低高并发下的推理成本」→ 答案仍是**微调**，但同时命中官方第 ④ 项「分类能力」与第 ⑤ 项「**支持轻量模型部署**」。

**易错提醒**：最容易误选 **B**，因为题干里出现了"分类规则"，让人联想到"规则文档 → 检索"。**关键判别：类别既定 + 长期不变 = 不缺知识 = 不走 RAG**；题目真正在问的是"判得稳不稳"。记住官方口诀：**查知识用 RAG，稳行为才考虑微调。**

**我错了吗**：☐

### Q004 [M5-K07] [A] 单选

某团队发现客服机器人的回复**语气时冷时热、不够统一**，负责人当即决定：「马上着手做微调，先把历史对话数据导出开始干活。」依据**官方给出的大模型微调基本流程**，该团队**首先**应当完成的是哪一步？

- A. 先定义目标：明确到底要把模型的什么行为稳定下来，以及什么样的输出才算合格
- B. 先准备样本：把历史客服对话导出并整理成「输入 → 期望输出」的成对数据
- C. 先把企业的产品资料与政策文档接入知识库，用增强检索的方式改善回复效果
- D. 先换一个参数规模更大的基座模型，让更强的模型自己把语气统一起来

**答案**：A

**考点**：M5-K07 官方微调五步流程：**定义目标 → 准备样本 → 选择基模 → 控制数据质量 → 评估效果**

**官方依据**：官方原文「理解微调的基本流程：**定义目标**、准备样本、选择基模、控制数据质量、评估效果」。

**解析**：
- A ✅ **官方流程的第一步就是「定义目标」。** 先要回答两个问题：**要把什么行为稳定下来**（本题是"统一语气"，属于官方五项适用中的「风格」），以及**什么叫做好了**（可核对的验收标准，例如"任意抽样 100 条，语气合规率 ≥ 95%"）。没有这一步，后续准备什么样的样本、挑什么样的基座、如何评估都无从谈起——这也是负责人方案最大的漏洞：**还没定义清楚目标就急着动手**。
- B ❌ **「准备样本」是官方流程的第 ② 步，必须排在「定义目标」之后。** 目标没定义清楚就导出历史对话，很可能把各种不同语气的回复原样灌进去，模型学到的恰恰是"不稳定"（对应第 ④ 步「控制数据质量」中的典型坑）。
- C ❌ 这属于另一种手段（**查知识用 RAG**），不属于微调流程的任何一步。而且本题是"语气不统一"的**行为问题**，不是"缺资料"的知识问题，接入知识库药不对症。
- D ❌ 「选择基模」确实是官方第 ③ 步，但：**① 顺序上排在定义目标与准备样本之后**；**② 基座再大也不会自动长出统一的语气**，基座只是能力的天花板，语气这类行为习惯仍需通过目标明确、样本规范的微调来建立。

**举一反三**：
1. 若问「微调完成后，应该用什么数据来评估效果」→ 答案是**未参与训练的独立评测集**，并要**与基座模型对比**、检查通用能力是否退化（官方第 ⑤ 步）。
2. 若问「样本标注口径不一致会导致什么」→ 答案是**学不到稳定行为**（官方第 ④ 步「控制数据质量」的典型坑），正确做法是**质量 > 数量**、统一口径，而不是继续堆量。

**易错提醒**：最容易误选 **B**，因为"导出历史对话开始干活"听起来最像"立刻行动、很有执行力"。**流程题只考名称与顺序**，见到「首先」二字先默念五字口诀：**目、样、基、质、评**。
⚠️ 另注意：官方五步中**没有**"配置训练参数 / 执行训练 / 上线部署"——官方明示**不考模型训练细节**。

**我错了吗**：☐

# 三、多选题（2 题）

### Q005 [M5-K02] [A] 多选

依据官方大纲，下列哪些场景属于**微调适合解决**的问题？

- A. 要求模型每次都按同一个 JSON 结构输出结果，已在提示词中反复约束后仍偶发跑偏
- B. 希望模型在某类任务上的整体反应长期稳定，不再因为用户换个说法就给出不同处理结果
- C. 希望把大量用户来单稳定地归入既定的若干处理类别
- D. 希望用一个更小、更轻的模型来承担这项固定任务，以降低推理开销与响应延迟
- E. 公司上周刚更新了产品报价单，希望模型能准确回答最新的报价问题
- F. 希望模型能回答当天各仓库的实时库存数量

**答案**：ABCD

**考点**：M5-K02 ~ M5-K06 官方五项适用场景：**稳定行为 / 格式 / 风格 / 分类能力 / 支持轻量模型部署**（渗透 M5-K08 官方选型口诀）

**官方依据**：官方原文「掌握微调适合什么：**稳定行为、格式、风格、分类能力，或支持轻量模型部署**」＋「**查知识用 RAG，做动作靠工具，稳行为才考虑微调**」。

**解析**：
- A ✅ 对应官方适用项「**格式**」。同一结构反复输出属于行为稳定性问题；提示词是"每次提醒"，微调是把格式**内化进权重**成为习惯。且题干已给出前置条件"反复约束后仍偶发跑偏"。
- B ✅ 对应官方适用项「**稳定行为**」（五项中的总纲）。"换个说法就变结果"正是典型的行为漂移，微调的目的就是消除这种漂移。
- C ✅ 对应官方适用项「**分类能力**」。类别既定、边界明确、输出空间小，微调后能直接稳定输出既定标签，比在提示词里塞说明与示例更稳、更快、更省 Token。
- D ✅ 对应官方适用项「**支持轻量模型部署**」。把某项专项能力迁移到更小的模型上，让轻量模型在该专项上顶上来，从而**降低推理开销与响应延迟**，便于部署在资源受限或高并发的场景。
- E ❌ **典型的"把补知识当成微调用途"陷阱（本模块第一大坑）**。报价单是**上周刚更新**的事实性知识，会持续变化且必须可核对可溯源 → **查知识用 RAG**。微调进去很快又会过时，而且说不出数字出自哪份文档。
- F ❌ 实时库存属于**实时外部数据**，模型训练完即冻结，知识库里存的也只是过去的数据 → **做动作靠工具**（调用库存系统接口取当下结果；若还涉及多步编排则用 Agent）。

**举一反三**：
1. 若把 E 改成「公司**十年前制定且从未变更**的公文格式规范，希望模型每次都按这个格式输出」→ E 也可选（**格式**，属稳行为）。判别关键不是"是不是文档"，而是**"会不会变、要不要溯源"**。
2. 若增加一个选项「既要回答最新版本的产品条款，又要统一客服话术」→ 该项**应选**，因为正确答案是 **RAG + 微调组合**（两者不互斥）。

**易错提醒**：最容易**漏选 B 或 D**，因为这两项表述比较抽象，不像"JSON""归类"那样有具体信号词。记住官方五项就是这五个：**稳定行为（总纲）/ 格式 / 风格 / 分类能力 / 支持轻量模型部署**。
最容易**多选 E 或 F**：只要选项里出现「**刚更新 / 最新 / 实时 / 今天**」，先停一秒，它多半是 RAG 或工具的活儿。

**我错了吗**：☐

### Q006 [M5-K11] [B] 多选

关于**微调的局限性**，下列说法正确的有？

- A. 训练完成后知识被「冻结」在模型权重中，外部知识发生变化后，需要重新经历样本、训练与评估才能跟上
- B. 知识融入参数后难以指出答案的具体出处，答案的可追溯性较差
- C. 相比更新知识库文档即刻生效，微调每次调整都需要重走完整流程，迭代不够灵活
- D. 过度训练可能损害模型原有的通用能力
- E. 微调完成后，只需替换知识库中的文档，即可让模型同步掌握最新知识

**答案**：ABCD

**考点**：M5-K11 微调的局限（会过时 / 不可追溯 / 迭代不灵活 / 灾难性遗忘）—— 对应官方原文「**微调不是万能按钮**」（渗透 M5-K09、M5-K12、M5-K13）

**官方依据**：官方原文「**微调不是万能按钮**」＋「**查知识用 RAG**，做动作靠工具，稳行为才考虑微调」（🟡`[B]` 级：局限为官方"不是万能按钮"与"查知识用 RAG"的直接推论，⚠️ 非官方逐字明列）。

**解析**：
- A ✅ **知识会过时**是微调最核心的局限。训练结束的那一刻知识就被固定，此后发生的新政策、新价格、新事件模型一概不知，要跟上只能**重新训练**。
- B ✅ **不可追溯**同样是硬伤：知识分散在海量参数里，无法指出"这条结论出自哪份文档哪一条"。因此在医疗、金融、法务等**强溯源**场景中，通常优先选择可附出处的 RAG。
- C ✅ **迭代不灵活**决定了微调不该作为首选：修改知识库文档即刻生效，而微调的每次调整都要重走官方五步流程（准备样本 → 控制数据质量 → 评估效果……），跟不上高频变化的知识。
- D ✅ **灾难性遗忘**：过度训练会让模型在目标任务上变强的同时，原有通用能力下降，典型表现是"专科变强了，常识变差了"。
- E ❌ **概念串台（本模块最高频失分点）**：替换知识库文档即刻生效，那是 **RAG** 的特性，不是微调的。微调后的模型要同步新知识，**必须重新训练**——这正是 A 项所说的局限。把两者的更新方式记混，就会在这里丢分。

**举一反三**：
1. 若增加选项「微调可以完全消除模型幻觉，因此可以取消人工复核」→ **不选**。微调只能**降低**幻觉、稳定行为，**不能替代最终责任人**（高风险动作**必须人工确认**）。
2. 若增加选项「样本标注口径不一致会导致模型学不到稳定行为，因此样本质量比数量更重要」→ **应选**（M5-K12，对应官方第 ④ 步「控制数据质量」）。

**易错提醒**：最容易**多选 E**，因为"替换文档即生效"这句话本身是对的——但它说的是 **RAG**。做这道题时把两句话分开背：**RAG 三优势 = 可更新、可追溯、改完即生效；微调三宗罪 = 会过时、查不到、改不动。**
另外别漏选 **D**："灾难性遗忘"名字唬人，但含义很简单——**专科变强，常识变差**。

**我错了吗**：☐

## 四、⭐ 本模块必背清单（考前 10 分钟）

### 4.1 官方原文三句（一字不差）

1. **「微调不是万能按钮。」**
2. **「微调适合什么：稳定行为、格式、风格、分类能力，或支持轻量模型部署。」**
3. **「查知识用 RAG，做动作靠工具，稳行为才考虑微调。」**

### 4.2 官方五步流程

> **定义目标 → 准备样本 → 选择基模 → 控制数据质量 → 评估效果**
> 口诀：**目、样、基、质、评**。（⚠️ 旧版六步已作废）

### 4.3 官方手段顺序（成本递增，微调不是第一选择）

> **优化输入（提示词） → 接入知识库（RAG） → 调用工具 → 使用微调 → 协作 Agent（或保留人工确认）**

### 4.4 官方五项适用场景（一句话版）

| 项 | 一句话 | 信号词 |
|---|---|---|
| ① 稳定行为 | 同类输入给同质反应，不随问法漂移（**总纲**） | 换个说法就变 / 时好时坏 / 忽高忽低 |
| ② 格式 | 每次都按同一结构输出（**要程序读**） | 字段固定 / 必须能被解析 / 结构化输出 |
| ③ 风格 | 语气、话术、品牌调性长期一致（**说话的味道**） | 品牌调性 / 话术规范 / 统一口吻 / 人设 |
| ④ 分类能力 | 稳定归入既定类别；比提示词**更稳、更快、更省 Token** | 自动归类 / 打标签 / 路由 / 判定属于哪一类 |
| ⑤ 支持轻量模型部署 | 专项能力下放到小模型，**降推理成本与延迟** | 推理成本太高 / 响应太慢 / 想用小模型 / 高并发 |

### 4.5 三宗罪 vs 三优势

> **微调三宗罪：会过时、查不到（不可追溯）、改不动。**
> **RAG 三优势：可更新、可追溯、改完即生效。**

### 4.6 三句类比

| 类比 | 含义 |
|---|---|
| **「RAG 换资料，微调换习惯」** | 改"答什么"找 RAG，改"怎么答"找微调 |
| **「提示词是每次提醒，微调是养成习惯」** | 提示词是外部要求，微调是内化行为 |
| **「RAG 提供料，微调提供味，工具负责动手，Agent 提供流程」** | 四手段分工一句话 |

### 4.7 数据与评测

> **质量 > 数量**；标注口径必须一致；**独立评测集**（未参与训练）；**与基座对比**；**检查通用能力是否退化**。

## 五、⭐ 本模块高频陷阱清单（TOP 10）

| 排名 | 陷阱 | 典型错误说法 | ✅ 正确认知 |
|:---:|---|---|---|
| **1** | **把"补知识"当成微调的用途**（第一大坑，Q002/Q005-E） | 「把公司制度 / 手册 / 政策微调进模型就记住了」 | **查知识用 RAG**：会过时 + 不可追溯 |
| **2** | **一上来就微调** | 「回答不够好，那就微调一下」 | **先优化提示词**；提示词反复优化后仍不达标才考虑微调 |

| **4** | **认为微调与 RAG 互斥** | 「用了 RAG 就不需要微调」 | **可组合**：RAG 管"答什么"，微调管"怎么答" |

| **6** | **流程记成六步 / 顺序记错**（Q004） | 「先准备样本再定义目标」 | 官方**五步**：目 → 样 → 基 → 质 → 评；旧版六步作废 |
| **7** | **用训练数据自评** | 「用同一批数据训练并评估，效果很好」 | 必须用**未参与训练**的独立数据，并**与基座对比** |
| **8** | **"多堆数据就行"** | 「数据里有噪声没关系，多堆一些就好」 | **质量 > 数量**，噪声会把行为教歪 |
| **9** | **误以为微调能消除幻觉 / 替代人工** | 「微调后就不会胡说，可以取消人工复核」 | 只能**降低**幻觉；**不能替代最终责任人** |
| **10** | **在训练细节上纠结** | 纠结高效参数微调方法、超参数取值、训练成本与显存 | **官方明示不考**，别浪费时间 |

| 错因 | 典型表现 | 回填位置 |

| **顺序记错** | 一上来就微调，忘了先优化提示词 | 同上 §6.1 第三句、§7.5 陷阱二 |
| **流程记错** | 官方五步的名称与顺序记混（尤其是第二步就要动手导数据） | 同上 §五 微调五步流程 |
| **场景漏背** | 官方五项适用场景记不全（尤其**分类能力**、**支持轻量模型部署**） | 同上 §四 4.4 / 4.5 |

**本模块过关标准**：6 题正确率 **≥ 5/6**，且 Q001、Q002、Q003 三道场景判断题**必须全对**——这三题错任意一题，说明官方选型口诀这条生命线还没打通。

**最后提醒**：本模块**不考**任何编程实现、不考训练 / 协议实现细节、不考任何数值。把精力全部放在官方点名的三件事上：**适用场景 · 五步流程 · 选型边界**。
