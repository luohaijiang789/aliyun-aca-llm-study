# 一、单选题（4 题）

### Q001 [M5-K03] [A] 单选

某电商公司的智能客服需要对外输出售后处理建议，业务方提出两项硬性要求：
① 每次都必须以**固定结构的 JSON** 返回（字段固定为：问题类型、紧急程度、处理建议、是否转人工）；
② 语气必须符合公司统一的**客服话术规范**。

团队已经在提示词中写明了格式说明并附上了示例，反复优化多轮后，线上**仍会出现格式跑偏或语气不一致**的情况。此时**最合适**的方案是？

- A. 收集一批符合目标 JSON 结构与客服话术规范的高质量问答样本，在预训练基座模型上进行微调
- B. 将最新的售后政策文档接入知识库，采用 RAG 检索增强生成来回答用户问题
- C. 调大 `temperature` 参数，让模型输出更丰富、更完整
- D. 换用参数规模更大的模型，并在提示词中继续增加示例数量

**答案**：A
**考点**：M5-K03 决策点——✅ 该用微调的场景（固定输出格式 + 统一行文风格，且提示词优化后仍不达标）
**解析**：
- A ✅ **这是微调最典型的适用场景**。题干的两个诉求 —— **固定输出格式**（稳定 JSON schema）与**统一行文风格**（客服话术）—— 都属于「模型行为」问题，而非「知识缺失」问题；且**前置条件已满足**（提示词优化已反复尝试仍不达标）。用符合目标格式与话术的高质量样本做微调，可把格式与语气**内化进模型权重**，稳定性显著高于提示词约束。
- B ❌ **最经典的陷阱项**。RAG 解决的是「模型**不知道**」的问题（缺私域知识、缺最新信息）；而本题模型**知道该怎么答**，只是**答得不稳定**。RAG 不会改变模型的输出行为与语气，接了知识库 JSON 照样会跑偏。判断口诀：**RAG 换资料，微调换习惯。**
- C ❌ `temperature` 控制采样随机性，调大会让输出**更发散、更不稳定**，只会加剧格式跑偏与语气漂移，与诉求完全相反。
- D ❌ 换更大的模型不保证格式稳定性，且题干已明确「提示词 + 示例的方式反复优化后仍不达标」—— 继续加示例属于在已失效的路径上追加成本。成本与收益都不划算。
**我错了吗**：☐

### Q002 [M5-K09] [A] 单选

某医疗机构计划上线智能问答系统，要求：**每条结论都必须标注出处文档**（便于医生核验），且**诊疗规范每年都会更新**。团队中有人提议：「不如把全部诊疗规范整理成数据，微调进模型，这样模型就记住了，回答也更快。」对这一提议，**最恰当**的判断是？

- A. 赞同。微调能把规范知识固化进模型权重，回答时无需检索，速度更快且不会遗忘
- B. 不赞同。诊疗规范属于**需要频繁更新且必须可追溯**的知识，应优先采用 RAG 而非微调
- C. 不赞同。这类需求应当改用 Agent 编排多个工具来完成问答
- D. 赞同，但需要先把规范文档整理成问答对，并大幅增加训练数据量，即可解决更新问题

**答案**：B
**考点**：M5-K09 与 RAG 的边界（知识类需求 → RAG；微调不可追溯、会过时）
**解析**：
- A ❌ 前半句「固化进权重」描述本身没错，但**结论错误**。知识一旦进权重就面临两个致命问题：**① 会过时** —— 规范每年更新，意味着每年都要重训；**② 不可追溯** —— 知识融进参数后无法指出「这条结论出自哪份文档第几条」，直接违背题干中「必须标注出处」的硬要求。题干中的「每年更新」「必须标注出处」两个信号同时指向 RAG。
- B ✅ **知识类需求一律优先 RAG**：文档更新即刻生效（改完即生效），答案可附引用出处供医生核验（可追溯）。这正是 RAG 相对微调的两大核心优势 —— **可更新、可追溯**。
- C ❌ Agent 解决的是**复杂多步任务与工具编排**问题，并不解决「知识从哪来」与「答案能否溯源」。本题的核心矛盾是知识的更新与溯源，而非流程编排，用 Agent 属于答非所问。
- D ❌ 增加训练数据量**不解决**任何根本问题：数据再多，知识仍在权重里，**照样会过时、照样不可追溯**。这属于「用错误的工具，加大剂量」，方向错了。

> 💡 **补充**：如果同时还要求「回答必须使用统一的医学文书口吻」，那么正解是 **RAG + 微调组合**（RAG 补知识，微调定风格），二者并不互斥。
**我错了吗**：☐

### Q003 [M5-K05] [B] 单选

关于高效微调方法 **LoRA** 与 **QLoRA**，下列说法正确的是？

- A. LoRA 会更新基座模型的全部原始权重，因此效果一定优于全参数微调
- B. LoRA 会冻结基座模型的原始权重，只训练少量低秩增量参数，因此显存占用更友好
- C. QLoRA 是在 LoRA 的基础上增加训练轮数，以提升模型在垂直领域的表现
- D. LoRA 训练完成后必须与基座合并成完整模型才能使用，因此同一基座无法灵活切换多个任务

**答案**：B
**考点**：M5-K05 LoRA / QLoRA 的原理与特点（渗透 M5-K04 全参数微调 vs PEFT）
**解析**：
- A ❌ **方向记反了**。LoRA 的核心恰恰是**冻结**基座模型的原始权重**不动**，只在旁路引入一对低秩小矩阵来学习「增量」，训练时只更新这些少量参数。此外「效果一定优于」这类绝对化表述本身也不成立：全参数微调在数据充足、算力充足时拟合上限可能更高，LoRA 的优势在于**性价比**而非绝对效果。
- B ✅ 这正是 LoRA（**Lo**w-**R**ank **A**daptation，低秩适配）的要义：被训练的参数量相对基座**小得多**，需要保存与更新的梯度和优化器状态大幅减少，因此**显存占用显著下降**，属于**高效参数微调（PEFT）** 的典型代表。
- C ❌ QLoRA 中的 **Q 指的是量化（Quantization）**，不是「增加训练轮数」。QLoRA = **量化 + LoRA**：在 LoRA 冻结基座的基础上，**再对被冻结的基座模型做量化**（用更低精度表示权重），目的是**进一步降低显存占用**。此外，训练轮数过多反而会带来过拟合风险，不是「越多越好」。
- D ❌ 恰恰相反，LoRA 的一大工程优势就是**增量权重体积小**：一份基座可以搭配多个不同任务的 LoRA 增量权重，**按需加载/合并切换**，存储与部署成本极低。合并回基座是**可选**操作（用于消除推理时的额外开销），并非「必须」。

> ⛔ 本题只考**原理与方向**，LoRA 的秩大小、学习率、显存具体数值一律**不考**，不要去背任何数字。
**我错了吗**：☐

### Q004 [M5-K10] [B] 单选

某团队反馈大模型应用效果不佳，具体表现为：**回答泛泛而谈、抓不住重点，输出格式也不统一**。项目负责人当即决定：**立刻收集数据，启动微调项目**。从技术选型的成本顺序来看，**首先**应该做的是？

- A. 立即启动微调项目，因为输出格式不统一只能通过微调解决
- B. 先搭建 RAG 知识库，用检索增强的方式解决回答质量问题
- C. 先优化提示词（明确角色、任务要求、输出格式与约束条件），仍不达标时再按问题类型判断是走 RAG 还是微调
- D. 直接搭建 Agent，让智能体自主规划与反思，从而提升回答质量

**答案**：C
**考点**：M5-K10 在决策树中的位置（成本递增顺序：提示词 → RAG → 微调 → Agent）
**解析**：
- A ❌ **顺序错了**，这是本模块最常见的送命选项。在决策树中，微调排在**提示词优化与 RAG 之后**，是成本相对更高、迭代更不灵活的手段，不是第一选择。且「格式不统一**只能**用微调」的说法过于绝对 —— 规范化的提示词约束本就是第一道防线。
- B ❌ RAG 解决的是**知识缺失与时效**问题，不解决「表达质量」与「输出格式」。回答泛泛而谈不是因为模型缺资料，此时搭知识库属于药不对症。
- C ✅ **成本递增顺序铁律：优化提示词（💰 最低）→ RAG / 插件（💰💰）→ 微调（💰💰💰）→ Agent（💰💰💰）**。「泛泛而谈、抓不住重点」往往是**指令不清、缺少角色与约束**导致的，属于提示词层面就能显著改善的问题，改几句话的成本远低于微调，理应**先试**。若提示词优化后仍存在「格式/风格不稳定」的行为问题，再考虑微调；若本质是「缺知识」，则走 RAG。
- D ❌ Agent 用于**复杂多步任务**的规划与工具编排。单轮回答质量问题用 Agent 属于「杀鸡用牛刀」，既不解决根因，又引入额外的编排成本与不确定性。

> 💡 **记忆句：先问再说，缺知检索，定风微调，多步智能。**
**我错了吗**：☐

# 二、多选题（2 题）

### Q005 [M5-K02] [A] 多选

下列哪些场景属于**微调适合解决**的问题？

- A. 要求模型每次都按同一个 JSON schema 输出结果，提示词约束后仍偶发跑偏
- B. 要求客服机器人长期使用统一的品牌话术与温和语气
- C. 希望模型能写出符合医疗病历规范的专业表达与术语习惯
- D. 公司上周刚更新了产品报价单，希望模型能准确回答最新的报价问题
- E. 希望模型能回答当天的实时库存数量

**答案**：ABC
**考点**：M5-K02 微调解决什么 —— 固定输出格式 / 行文风格 / 领域表达习惯（不是补知识）
**解析**：
- A ✅ **固定输出格式**是微调的第一典型场景。提示词约束属于「外部要求」，长尾问法下可能偶发失效；微调把格式**内化进权重**，一致性显著提升。
- B ✅ **行文风格 / 语气统一**是微调的第二典型场景。品牌调性、客服人设这类长期稳定且必须一致的要求，正是微调的价值所在。
- C ✅ **垂直领域的表达习惯**（术语、句式、结构）对应课时标题中的「改善在**垂直领域**的表现」，是微调的第三典型场景。
- D ❌ **典型干扰项：把「补知识」当成微调的用途。** 产品报价单属于**会频繁更新的事实性知识**：① 上周刚更新，说明变化快，微调进去很快又会过时；② 报价必须**可追溯、可核对**，而微调进权重后无法指出来源。**知识类需求一律优先 RAG**。
- E ❌ 实时库存属于**实时外部数据**，知识库里存的永远是过去的数据，微调更是训练完即冻结。这类需求应当使用**插件 / API 调用**外部系统获取当下结果（若还涉及多步编排则用 Agent）。

> 💡 **一句话收口：微调解决「怎么说」，不解决「知道什么」和「实时拿到什么」。**
**我错了吗**：☐

### Q006 [M5-K08] [B] 多选

关于**微调的局限性**，下列说法正确的有？

- A. 训练完成后知识被「冻结」在模型权重中，外部知识发生变化后需要重新训练才能跟上
- B. 知识融入参数后难以指出答案的具体出处，答案的可追溯性较差
- C. 相比优化提示词与搭建 RAG，微调在数据、算力与迭代上的成本通常更高
- D. 过度训练可能损害模型原有的通用能力（灾难性遗忘）
- E. 微调后只需替换知识库中的文档，即可让模型同步最新知识

**答案**：ABCD
**考点**：M5-K08 微调的局限（会过时 / 不可追溯 / 成本高 / 灾难性遗忘）
**解析**：
- A ✅ **知识会过时**是微调最核心的局限。训练结束的那一刻知识就被固定，此后发生的新政策、新价格、新事件模型一概不知，要跟上只能**重新训练**。
- B ✅ **不可追溯**同样是硬伤：知识分散在海量参数里，无法指出「这条结论出自哪份文档哪一条」。因此在医疗、金融、法务等**强溯源**场景中，通常优先选择可附出处的 RAG。
- C ✅ **成本更高**决定了微调在决策树中的位置 —— 排在提示词与 RAG 之后。它需要高质量标注数据、算力、评测与反复迭代，属于「提示词和 RAG 都搞不定之后」的选项。
- D ✅ **灾难性遗忘**：过度训练会让模型在目标任务上变强的同时，原有通用能力下降，表现通常是「专科变强了，常识变差了」。这也是优先选择冻结基座权重的 PEFT / LoRA 的原因之一。
- E ❌ **概念串台**：替换知识库文档即刻生效，那是 **RAG** 的特性，不是微调的。微调后的模型要同步新知识，**必须重新训练**，这正是 A 项所说的局限。把两者的更新方式记混，是本模块最高频的失分点。

> 💡 **补充（M5-K06 数据要求）**：微调还高度依赖数据质量 —— **质量 > 数量**，数据必须先清洗、标注口径保持一致，否则噪声数据会直接把模型的行为「教歪」；训练轮数过多则会**过拟合**（只会背训练样本），评测必须使用**未参与训练**的独立评测集。
**我错了吗**：☐
