## 二、单选题（6 题）

### Q001 [M1-K03] [A] 单选

某团队计划把大模型接入报销初审流程，设计方案是：由大模型读取单据后**直接给出"通过/驳回"的最终结论并自动生效，无需任何人查看**。关于这一方案，下列说法正确的是：

- A. 可行。只要把报销规则写清楚，模型的判断就可以等同于审核人的决定
- B. 不可行。大模型可以辅助整理、归纳和给出参考意见，但**不能直接替人决定是否通过**，最终决定须由责任人作出
- C. 可行。只要用微调让模型学会公司报销规则，就可以取消全部人工环节
- D. 不可行。因为大模型完全不具备理解单据内容的能力，连辅助整理都做不到

**答案**：B

**考点**：M1-K03 不能直接替人决定什么

**官方依据**：官方原文「理解大模型是什么，能做什么，**不能直接替人决定什么**」；配套原文（M6）「AI 可以辅助整理和起草，但**不能替代最终责任人**」，（M4）「**高风险动作必须人工确认**」。

**解析**：
- A ❌ 把"能输出答案"当成"能拍板"。官方原文明确要求理解大模型「**不能直接替人决定什么**」——决定权、签字权、发布权始终属于人。把规则写清楚只能**提升输出质量**，不能改变这一边界；而且幻觉与概率性并不会因为规则写得清楚而消失。
- B ✅ 准确对应官方原文。大模型的角色是**产出候选与参考**：可以生成草稿、整理要点、给出建议；但"是否通过"属于**终局决定**，须由责任人作出。落到本题场景，正确设计应是：模型提取金额/事由/票据信息 → 标出与规则不符的疑点 → 输出"建议驳回（缺发票附件）" → **由审核人确认后生效**。
- C ❌ 混淆了微调的定位。微调的作用是**稳定行为、格式、风格、分类能力，或支持轻量模型部署**（官方 M5 原文），它**无法消除幻觉与概率性**，更不能把"最终责任"转移给模型。题干中"取消全部人工环节"的说法直接违反「高风险动作**必须人工确认**」。
- D ❌ 走向另一个极端。大模型**能够**理解和处理单据文本，做辅助整理、要点提取、异常提示正是它的强项。问题不在于"能不能读懂"，而在于"**能不能直接替人决定**"。

**举一反三**：
1. 若题干换成「**合同**：模型起草条款并标出风险点后，由法务决定是否签署」→ 应选**可行**，因为模型只做了**辅助整理与起草**，终局决定在人。
2. 若题干换成「**客服赔付**：模型直接向客户给出'赔 500 元'的终局答复并自动执行」→ 应选**不可行**，赔付金额属于对外承诺，必须**保留人工确认**。

**易错提醒**：最容易误选的是 **A** 或 **C**，因为"规则写清楚""微调过后"听起来很专业、很像解决方案。记住：**提示词与微调都只影响"输出质量"，不影响"责任归属"**——责任归属只由"是否有人确认"决定。同时别被 **D** 骗到，"不能替人决定"绝不等于"不能参与"。

**我错了吗**：☐

### Q002 [M1-K06] [A] 单选

客服同学问大模型"**本月初刚发布的产品退换货新政**有哪些变化"，模型给出了格式工整的答复，但与公司最新文件不符。技术同事建议把最新政策文件放进知识库，让模型基于检索到的资料回答。造成上述问题的原因是：

- A. 模型的**幻觉**：模型一定会因为缺乏自信而编造出不存在的政策条款
- B. 模型的**训练数据时间范围**限制：它的知识停留在训练数据截止时点，不了解此后新发布政策的真实内容
- C. 模型的**上下文限制**：政策文件字数太多，模型读不到后半部分
- D. 分词错误：政策中的术语被切成了错误的 Token，导致语义理解偏差

**答案**：B

**考点**：M1-K06 训练数据时间范围（工作方式见 M1-K04）

**官方依据**：官方原文「理解大模型**基于上下文生成内容**的基本方式，以及由此带来的**幻觉、训练数据时间范围和上下文限制**」。

**解析**：
- A ❌ 错在归因。题干的核心是"**本月初刚发布**"——信息在模型训练之后才产生，这是**训练数据时间范围**问题（"缺"），不是幻觉（"编"）。此外"一定会编造"表述过于绝对。⚠️ 注意两者关系：时间范围问题**常常以幻觉的形式表现出来**（不知道就去补），但**归因要归在"知识过期"，对策要落在"接知识库"**。
- B ✅ 完全对应官方原文。模型的知识来自训练时见过的数据，**停留在训练数据截止时点**，训练完成后**不会自动更新**，也不知道"今天"是什么时候，因此不知道此后新发生的事；若强行作答，就容易给出过时或与事实不符的答案。正确做法是**接入知识库**，让模型基于最新资料回答——这正是 M3 的定位。
- C ❌ 题干并未出现"超长文档""粘贴不进去""前面内容被忽略"等上下文受限特征；模型正常接收了提问并作答，症结在于**知识过期**而非**装不下**。区分要点：**不知道新发生的事 = 时间范围；一次塞不下 / 前面被忘 = 上下文限制**。
- D ❌ 分词属背景知识，且官方 M1 **未将其列为考点**（⚠️ 非官方明列考点）；即便个别术语切分不理想，也不会导致"整个政策都不知道"，与题干无关。

**举一反三**：
1. 若题干换成「问**今天的库存余量**，模型答了个大概数字」→ 答案选**训练数据时间范围**，且对策首选**调用工具**取实时数据（不是知识库——库存是会变的实时数据，不是文档资料）。
2. 若题干换成「问**公司去年的差旅标准**（知识库里已有文档），模型答错」→ 那更可能是**检索/切分质量问题**（属 M3），而不是时间范围。

**易错提醒**：最容易误选 **A**（幻觉）。两者确实容易缠在一起，口诀是：**「编的是幻觉，缺的是时间」**——看到"**刚发布 / 最新 / 实时 / 本月**"这类时间触发词，一律先判**训练数据时间范围**。

**我错了吗**：☐

### Q003 [M1-K07] [A] 单选

业务同学把一份约 50 万字的项目标书**一次性全部**粘贴给大模型，并要求"依据原文回答所有条款问题"。结果发现：对排在**开头**的条款能正常作答，对排在**中后部**的条款几乎无法回答。对此最合理的判断与处理是：

- A. 属于**训练数据时间范围**限制：标书写得太久远，模型没见过这些条款，只能通过微调注入
- B. 属于**上下文限制**：一次能处理的 Token 总量有上限，超长材料会被截断或不被同等重视；应先拆分处理，或通过知识库检索把相关片段放入上下文
- C. 属于**幻觉**：模型对中后部条款进行了编造，应要求它"再多检查两遍"即可解决
- D. 属于模型"拒绝回答"：只要在提问中加上"必须回答"的要求，就不会再遗漏

**答案**：B

**考点**：M1-K07 上下文限制（工作方式见 M1-K04）

**官方依据**：官方原文「由此带来的幻觉、训练数据时间范围和**上下文限制**」。

**解析**：
- A ❌ 错判。题干材料已经**提供给模型**了（模型能正常回答开头部分），问题不是"没见过"，而是"**装不下**"。此外知识过期问题首选**知识库**而非微调——微调喂进去的知识**同样会过期**。
- B ✅ 准确命中官方原文。模型**一次能处理的 Token 总量有上限**（输入 + 输出合计），超长材料要么被**截断**、要么超出部分不被有效处理（**能装下 ≠ 能同等重视每一段**）。可行处理办法：**拆分分段处理**（分段摘要再汇总）、**检索取相关片段**放入上下文、精简上下文并把关键信息放在当前问题附近。
- C ❌ 题干描述的是"**无法回答**"，并非"编造内容"，不属于幻觉；且让模型"再检查两遍"**不能突破上下文上限**，对自己的遗漏它同样可能自信地说"已全部处理"。
- D ❌ 这不是拒答问题，而是**输入容量**问题。加上强硬措辞既不能扩展上下文窗口，也不能保证输出可靠。

**举一反三**：
1. 若题干换成「长对话聊了 30 轮后，模型**忘了第 3 轮说过的客户预算**」→ 同样选**上下文限制**，对策是**精简对话、必要时开新会话并重给关键信息**。
2. 若题干换成「标书**只有 3 页**，但问到其中一条从未写过的承诺，模型编了出来」→ 那是**幻觉**，对策是**接知识库 + 要引用 + 人工核实**。

**易错提醒**：最容易误选 **A**。判据是看"**材料到底有没有被喂进去**"：已经喂进去了还答不出 → **上下文限制**（塞不下）；压根没喂过 → **训练数据时间范围**（不知道）。口诀：**「缺的是时间，塞不下的是上下文」**。

**我错了吗**：☐

### Q004 [M1-K05 / K06 / K07] [A] 单选

三个同事反馈了各自遇到的问题：① 用大模型做产品手册问答时，它给出了"该型号通过国家 XX 认证"的说明，但技术部门核查后确认**该认证从未存在过**；② 问"上一季度刚更新的内部售后标准"，模型给出的是**两年前的旧版本**；③ 一次性粘贴整本手册后提问，模型**完全没有读到最后三章的内容**。按官方对大模型局限的表述，三者依次对应：

- A. ① 幻觉　② 上下文限制　③ 训练数据时间范围
- B. ① 幻觉　② 训练数据时间范围　③ 上下文限制
- C. ① 训练数据时间范围　② 幻觉　③ 上下文限制
- D. ① 上下文限制　② 训练数据时间范围　③ 幻觉

**答案**：B

**考点**：M1-K05 幻觉 / M1-K06 训练数据时间范围 / M1-K07 上下文限制（三者辨析）

**官方依据**：官方原文「由此带来的**幻觉、训练数据时间范围和上下文限制**」。三项在官方原文中的**排列顺序**也正是：幻觉 → 训练数据时间范围 → 上下文限制。

**解析**：
- A ❌ ② 与 ③ 说反了。"给出两年前的旧版本"是知识**停在训练数据截止时点** → **训练数据时间范围**；"完全读不到最后三章"是**一次装不下** → **上下文限制**。
- B ✅ 三项全部对应正确，判据是官方原文的关键词：**① 编造出看似合理但与事实不符的内容（"该认证从未存在过"）= 幻觉**；**② 不了解训练截止之后新发生的更新（"两年前的旧版本"）= 训练数据时间范围**；**③ 一次性处理的总量有上限、超长材料不被处理（"没读到最后三章"）= 上下文限制**。
- C ❌ ① 与 ② 说反了。① 的特征是"**从未存在过 / 查无此项**"（编），不是"过期"；② 的特征是"**旧版本**"（缺最新）。
- D ❌ 三项全部错位。③ 的模型并非"编造"，而是"**压根没读到**"——这是容量问题，不是真实性问题。

**举一反三**：
1. 若①改成「模型说"该认证已于 20XX 年通过，证书编号 XXXX"，编号也查无此项」→ 仍是**幻觉**（编造细节越具体越典型）。
2. 若②改成「问的是**今天此刻的库存**，模型给了个昨天的数字」→ 仍归**训练数据时间范围**，但对策从知识库换成**调用工具**（实时数据靠工具）。

**易错提醒**：最容易误选 **C**，因为①里出现了"产品手册/认证"，容易联想到"模型没见过这份资料"。关键判据是"**从未存在过**"——**不存在的东西不可能靠'没见过'解释，只能是编的**。口诀：**「编的是幻觉，缺的是时间，塞不下的是上下文」**。

**我错了吗**：☐

### Q005 [M1-K04 / M1-K08] [A] 单选

下列四项任务中，按照官方关于**能力边界**的表述，**最适合直接交给大模型完成**（即直接由模型生成、总结、分析，不必额外接知识库或调用工具）的是：

- A. 查询公司仓库此刻的实际库存余量，并据此执行锁定库存操作
- B. 依据本月刚更新的内部价格表，向客户报出准确的新报价
- C. 把已提供的访谈记录整理成 500 字要点，并归纳出三个主要观点
- D. 核算某客户的本年度授信额度，并把结果写入业务系统

**答案**：C

**考点**：M1-K08 能力边界判断 ＋ M1-K04 基于上下文生成内容

**官方依据**：官方原文「掌握**能力边界判断**：什么时候适合**生成、总结、分析**，什么时候需要知识库、工具或人工确认」；工作方式原文「理解大模型**基于上下文生成内容**的基本方式」。

**解析**：
- A ❌ 既需要**实时数据**（此刻库存），又要**执行业务动作**（锁定库存）。官方判据：需要实时数据、确定性计算或**业务动作**时应**调用工具**，不应由模型凭生成完成。
- B ❌ 报价依赖"本月刚更新的价格表"——这是**训练数据时间范围之外的新信息**（M1-K06），且金额要求精确。应**接入知识库**取最新资料，必要时用**工具**完成确定性计算；直接让模型生成有出错风险。
- C ✅ 完全符合官方"适合**生成、总结、分析**"的情形：材料**已在上下文中**（访谈记录已提供 → 这正是 M1-K04「基于上下文生成」的典型条件），任务是**压缩提炼 + 归纳观点**，属于纯文字的总结与分析，不涉及外部事实、实时数据或执行动作。
- D ❌ 授信额度属于**高风险**决策（金融），且要**写入业务系统**（业务动作）。官方明确「AI 可以辅助整理和起草，但**不能替代最终责任人**」，此类结果应由工具/业务系统按规则计算，并**保留人工确认**。

**举一反三**：
1. 若 C 改成「把访谈记录整理成要点后**直接群发给客户**」→ 就要加**人工确认**（对外发布/对外承诺），不再是"直接交给模型完成"。
2. 若 C 改成「整理**尚未提供**、存放在公司内部系统中的访谈记录」→ 要先**接入知识库**，因为材料不在上下文里（模型不会主动去查）。

**易错提醒**：最容易误选 **B**，因为"报个价"看起来很像是"生成一段话"。关键看两点：**① 材料在不在上下文里？② 结果要不要精确、要不要对外负责？** 只要命中"最新资料"或"精确金额"，就**必须接知识库 / 调工具**。

**我错了吗**：☐

### Q006 [M1-K08] [A] 单选

某电商团队要上线"客户问价机器人"，需求包括：① 获取**当前实时**价格；② 按公司固定的**阶梯折扣规则算出精确金额**；③ 经确认后**写入报价单**。按照官方给出的能力边界方法，最合适的做法是：

- A. 只做提示词优化：把阶梯折扣规则写进提示词，由模型自己按规则生成最终金额
- B. 用微调把公司折扣规则训练进模型，由模型直接给出最终金额并写入报价单
- C. 由**工具**获取当前价格并完成确定性计算与写单动作，大模型负责理解意图、组织答复；规则性、确定性部分不交给概率生成
- D. 用上下文学习，每次提问时附上几个报价示例，模型就能保证金额与库存始终准确

**答案**：C

**考点**：M1-K08 能力边界判断（工具 / 知识库 / 微调 / 人工确认的选型）

**官方依据**：官方原文「什么时候需要**知识库、工具或人工确认**」；M3 原文「需要**实时数据、确定性计算或业务动作**时用工具」；M5 原文「**查知识用 RAG，做动作靠工具，稳行为才考虑微调**」。

**解析**：
- A ❌ 优化输入能改善表达与组织，但**不能替模型拿到实时价格、也不能保证精确算术**。金额属于**确定性计算**，交给逐 Token 的概率生成有误报风险。
- B ❌ 混淆了微调的定位。官方 M5 原文：微调适合**稳定行为、格式、风格、分类能力，或支持轻量模型部署**；它是"**稳行为**"手段，不是"补实时数据 / 做精确计算 / 替人执行动作"的手段。另外"由模型直接写入报价单"还绕过了**人工确认**。
- C ✅ 精准命中官方判据：**实时数据**（当前价格）、**确定性计算**（阶梯折扣金额）、**业务动作**（写入报价单）都应交给**工具 / 业务系统**；大模型负责擅长的部分——理解意图、组织语言、解释口径。这是官方「**做动作靠工具**」的典型应用。
- D ❌ 上下文学习（ICL）只是**在上下文里给示例做示范**，**不改参数、也不获取外部数据**；示例再多也不能保证实时金额与库存准确，且成本高、不可靠。

**举一反三**：
1. 若需求改成「回答客户'我们的退换货政策是什么'」→ 政策是**企业内部文档资料**，应选**接入知识库**，不是调工具。
2. 若需求改成「所有报价答复必须统一使用公司品牌话术与固定 JSON 结构」→ 这属于**稳定行为/格式/风格**，可考虑**使用微调**（并保留人工确认）。

**易错提醒**：最容易误选 **B**（微调），因为"把规则训练进模型"听起来最彻底。记住官方那句金句：**「查知识用 RAG，做动作靠工具，稳行为才考虑微调」** —— 本题三件事全是"**取实时数据 + 算准 + 执行动作**"，一个都不落在微调的射程内。

**我错了吗**：☐

### Q007 [M1-K01 / M1-K10] [A] 多选

关于大模型的基础概念与**技术发展脉络**，下列说法正确的有：（多选）

- A. "大"主要体现在**参数规模巨大、训练数据规模巨大、算力投入巨大**三个维度
- B. 技术发展脉络的方向是：Transformer 架构为模型的规模化训练奠定基础，应用侧从"能聊天"走向"能办事"——补知识靠知识库，做动作靠工具，多步骤流程靠 Agent
- C. 按官方"建议掌握的知识"，掌握技术发展脉络只需理解**方向与阶段特征**，不需要背诵具体论文标题、精确发布日期和参数规模
- D. 只要模型参数规模足够大，就能处理任意长度的输入、回答必然正确，且不受训练数据时间范围的影响

**答案**：A、B、C

**考点**：M1-K01 大模型定义与"大"的体现 ＋ M1-K10 技术发展脉络

**官方依据**：官方原文「大模型的基础概念、**技术发展脉络**、工作方式和典型应用场景」；官方声明「不要求考生编写代码，也不考模型训练和协议实现细节」；官方原文「由此带来的幻觉、训练数据时间范围和上下文限制」。

**解析**：
- A ✅ 官方虽未逐条定义"大"，但"参数 / 数据 / 算力"是行业与课程一致的三维度归纳，且与官方三大局限的表述不冲突：规模扩大**只拓宽能力边界**，不消除局限。
- B ✅ 两条方向性结论均成立：**架构可规模化 → 规模带来能力跃迁**；**应用侧靠知识库 / 工具 / Agent 补足模型的知识、动作与流程短板**。这也正是官方六选一手段（优化输入 / 知识库 / 工具 / 微调 / Agent / 人工确认）的由来。
- C ✅ 官方仅要求"了解技术发展脉络"，**未给出任何具体时间与技术清单**，且明确不考训练与实现细节 → 具体论文标题、精确发布日期、参数规模数字**均不要求**。
- D ❌ **过度外推，三处错误**：① "大"不意味着输入长度无上限——官方点明的局限之一就是**上下文限制**，一次能处理的 Token 总量有上限；② 规模增大只能**缓解**而非根除**幻觉**，不能保证"必然正确"；③ 模型知识仍受**训练数据时间范围**限制，不会因参数变大而自动获得最新信息。**把"规模大"等同于"没有边界"是标准错误项。**

**举一反三**：
1. 若把 B 改成「技术发展脉络的终点是模型越来越大」→ 应判**错**：脉络后段的重点在**知识库 / 工具 / Agent** 补足短板，不只在规模。
2. 若增加选项「开源模型一定可以免费商用」→ 应判**错**：商用要看**许可协议**，且这属 M1-K19 背景知识，非官方明列考点。

**易错提醒**：最容易**漏选 C**。考生常以为"技术发展脉络 = 要背大事年表"，于是看到"不需要背论文标题和发布日期"反而不敢选。记住官方口径：**脉络考方向，不考细节**。此外 D 是本模块最经典的"绝对化"陷阱项，见到"任意 / 必然 / 不受……影响"直接排除。

### Q008 [M1-K02 / M1-K03] [A] 多选

关于"大模型**能做什么**、**不能直接替人决定什么**"，下列说法正确的有：（多选）

- A. 适合承担**生成、总结、分析**类文本任务，产出草稿、候选方案与要点归纳
- B. 在医疗、金融、合同、对外发布等场景中，可以**辅助整理和起草**，但**不能替代最终责任人**
- C. 遇到高风险动作与最终决策时，应**保留人工确认**，不宜由模型自动生效
- D. 只要在提示词中写明"请务必准确，出错由你负责"，模型就可以承担最终责任并替人决定是否通过

**答案**：A、B、C

**考点**：M1-K02 能做什么 ＋ M1-K03 不能直接替人决定什么

**官方依据**：官方原文「理解大模型是什么，**能做什么，不能直接替人决定什么**」「什么时候适合**生成、总结、分析**」；M6 原文「AI 可以**辅助整理和起草**，但**不能替代最终责任人**」；M4 原文「**高风险动作必须人工确认**」。

**解析**：
- A ✅ 官方原文：掌握能力边界判断，明确"什么时候适合**生成、总结、分析**"。写文案、做纪要、归纳观点、给出候选方案，正是大模型最合适也最擅长的部分——它产出的是**候选与参考**。
- B ✅ 官方 M6 原文原句：「AI 可以**辅助整理和起草**，但**不能替代最终责任人**」。注意"**辅助**"与"**替代**"的分界——整理、起草可以做，最终拍板不行。
- C ✅ 官方 M4 原文：「**高风险动作必须人工确认**」。此外官方把"保留人工确认"列为可选手段之一，是能力边界判断的**兜底答案**。
- D ❌ 三个错误：① 提示词缓解不了**幻觉**与**训练数据时间范围**两类固有局限；② 大模型**没有责任主体**，"由你负责"在技术上和法律上都不成立；③ 是否通过、是否签署、是否发布的**决定权属于人**，这恰恰是官方"**不能直接替人决定什么**"所划的边界。

1. 若增加选项「模型可以给出'建议驳回（缺发票附件）'并附依据，由审核人确认后生效」→ 应**选**：这是**辅助**而非替代，符合边界。
2. 若把 A 改成「适合直接决定授信额度与诊断结论」→ 应**不选**：那是"决定"，不是"生成/总结/分析"。

**易错提醒**：最容易误选 **D**，因为"出错由你负责"看起来像是在做风险兜底。记住：**责任无法靠一句提示词转移**——模型既没有责任主体，也消除不了幻觉与概率性。另一头也别矫枉过正：本题 A/B/C 都在说"**可以做辅助**"，不要把"不能替人决定"读成"不能用"。

按照大模型的**典型应用场景划分**与**能力边界判断**，下列任务处理方式的对应关系，正确的有：（多选）

- A. 把一份 20 页的调研报告压缩成 300 字要点 → **文本摘要与信息提取**，原文提供后可直接交给模型完成
- B. 把中文版产品说明翻译成英文版 → **文本润色与转换**，可直接交给模型完成

- D. 从合同文本中提取甲乙方、金额、付款期限 → **文本摘要与信息提取**，原文提供后可直接交给模型完成

**答案**：A、B、D

**考点**：M1-K09 典型应用场景（4 类）＋ M1-K08 能力边界判断

**官方依据**：官方原文「大模型的基础概念、技术发展脉络、工作方式和**典型应用场景**」；官方原文「掌握**能力边界判断**：什么时候适合生成、总结、分析，什么时候需要**知识库、工具或人工确认**」。

- A ✅ "20 页 → 300 字"是典型的**长度压缩**，属于**文本摘要与信息提取**（不是"润色转换"——润色只改说法、不压缩内容）。材料已提供、无外部事实依赖 → 可直接交给模型完成。
- B ✅ 翻译属于已有内容**换一种形式**输出，归**文本润色与转换**（不是"生成创作"——创作是从无到有）。
- C ❌ 精确金额 + 本月刚更新的价格表，触发两条能力边界：一是信息在**训练数据时间范围**之外（M1-K06），二是**确定性计算**要求精确（金额不能靠概率生成）。应**接入知识库**取最新价格表，必要时用**工具**完成计算，并对关键结果**保留人工确认**；不能图省事直接让模型生成。
- D ✅ 从原文中**抽取已有字段**属于**文本摘要与信息提取**（不是"信息推理与表格解读"——推理要基于数据给出**新判断/新结论**；抽字段没有产生新结论）。原文已在上下文中时，可直接交给模型完成。

2. 若把 D 改成「判断该合同**是否应该签署**」→ **不属于**信息提取，属于高风险决策，必须**保留人工确认**。

## 五、⭐ 本模块必背清单（考前 10 分钟过一遍）

### 5.1 官方原文四句

1. 「理解大模型是什么，**能做什么，不能直接替人决定什么**。」
2. 「理解大模型**基于上下文生成内容**的基本方式，以及由此带来的**幻觉、训练数据时间范围和上下文限制**。」
3. 「掌握**能力边界判断**：什么时候适合**生成、总结、分析**，什么时候需要**知识库、工具或人工确认**。」
4. 「本认证**不要求考生编写代码，也不考模型训练和协议实现细节**。」

### 5.2 三个数字

- 本模块 **18%** → **9 题 = 6 单选 + 3 多选**，每题 2 分，满分 **18 分**
- 全局 **50 题 / 100 分 / 及格 80 分 / 60 分钟**
- 目标：本模块 **≥ 8/9 题**，失分 ≤ 2 分

### 5.3 三大局限口诀

> **「编的是幻觉，缺的是时间，塞不下的是上下文」**
> - **编**（幻觉）→ 知识库 + 要引用 + 人工核实
> - **缺**（训练数据时间范围）→ 知识库（查资料）/ 工具（取实时数据）
> - **塞不下**（上下文限制）→ 拆分分段 / 检索取片段 / 精简上下文

### 5.4 能力边界六选一

```
优化输入 → 接入知识库 → 调用工具 → 使用微调 → 协作 Agent ⋯ 或 → 保留人工确认
```

- **查知识用 RAG，做动作靠工具，稳行为才考虑微调。**
- **实时数据 / 确定性计算 / 业务动作 → 用工具。**
- **AI 可以辅助整理和起草，但不能替代最终责任人；高风险动作必须人工确认。**

### 5.5 判断三问

1. 要的事实**模型肚子里有吗**？没有 → **知识库 / 工具**
2. 要**做动作或算准**吗？要 → **工具**（多步骤 → **Agent**）
3. **错了谁负责**？高风险 → **人工确认**
4. 三问都否 → **直接生成 / 总结 / 分析**（效果不稳先**优化输入**）

### 5.6 场景四类

> **「造、改、抽、断」** = 造（生成创作）、改（润色转换）、抽（摘要与信息提取）、断（信息推理与表格解读，**断要人复核**）

| 1 | 「规模大 = 任意长度输入、必然正确、不受时间范围影响」 | 过度外推 | 三大局限依然存在（Q007-D） |
| 2 | 把「**编造不存在的认证/条款**」判成"知识过期" | 编 ≠ 缺 | "从未存在过 / 查无此项" → **幻觉**（Q004-①） |
| 3 | 把「**刚更新的政策答成旧版**」判成"装不下" | 不知道 ≠ 没读到 | "最新 / 刚发布 / 实时" → **时间范围**（Q002、Q004-②） |
| 4 | 「模型会**主动查资料 / 联网核实**」 | 原生模型不检索、不主动获取 | 要资料**接知识库**，要实时数据**调工具**（Q005-B） |
| 5 | 「效果不好就**微调**」 | 微调是稳行为 / 格式 / 风格 / 分类 | 补知识首选 **RAG**（Q006-B） |
| 6 | 知识库与工具**分工对调** | 一个查文档、一个做动作 | **查知识用 RAG，做动作靠工具**（Q006-C） |
| 7 | 「提示词写好 / 微调过就能**取消人工环节**」 | 消除不了幻觉与概率性 | 高风险**必须人工确认**（Q001-C、Q008-D） |
| 8 | 「**给了理由** = 结论可靠」「再检查两遍就能纠正」 | 理由本身也可能是生成的 | **要引用 + 抽检溯源 + 人工核实** |
| 9 | 把「不能替人决定」读成「**不能参与**」 | 走向极端 | 辅助整理、起草、归纳正是它的角色（Q001-D） |
| 10 | 在**注意力 / MoE / 分词 / 训练细节**上花时间 | ⚠️ 官方未提及且不考 | 时间投给**三局限 + 能力边界判断**（Q002-D） |

## 七、做题时的三条抓手（官方原文）

1. **「理解大模型是什么，能做什么，不能直接替人决定什么。」** → **决定权永远在人**（AI 出草稿，人签字）。
2. **「幻觉、训练数据时间范围和上下文限制。」** → **编的是幻觉，缺的是时间，塞不下的是上下文**。
3. **「优化输入、接入知识库、调用工具、使用微调、协作 Agent，或保留人工确认。」** → 场景题的标准答案池，**查知识用 RAG，做动作靠工具，稳行为才考虑微调**。
