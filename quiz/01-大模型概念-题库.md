### Q001 [M1-K02] [A] 单选

某团队拿到一个**基座模型**（已在海量文本上训练过、能续写但不太听指令），接下来希望它：① 能按用户指令、按指定格式回答；② 回答更符合人类的价值观与偏好（有用、无害）。这两个目标应按什么方式实现？

- A. 先做 RLHF 对齐偏好，再做 SFT 学习遵循指令
- B. 先做 SFT 学习遵循指令，再做 RLHF 对齐人类偏好
- C. 只需再做一次预训练，两个阶段都能一并达成
- D. 先做 RLHF 注入新业务知识，再做 SFT 精简输出格式

**答案**：B

**考点**：M1-K02 训练三阶段（预训练 → SFT → RLHF）

**解析**：
- A ❌ 顺序颠倒。SFT 必须在 RLHF 之前：模型得先"会按指令回答"，人类反馈才有可比较、可打分的回答对象。跳过 SFT 直接 RLHF，相当于让还没学会答题的人去接受评分。
- B ✅ 顺序正确且作用对应准确。**预训练**负责注入通用知识与语言能力（基座）；**SFT（监督微调）**用"指令-回答"示例教会模型**遵循指令、按格式输出**；**RLHF**再用人类偏好反馈调整**输出倾向**，使其更符合人类价值观与偏好。三阶段顺序不可颠倒。
- C ❌ 预训练解决的是"有没有知识"，不是"听不听话、讨不讨喜"。继续堆预训练无法让模型学会遵循指令格式，也不解决价值观对齐。
- D ❌ 两个错误：一是顺序错（RLHF 不在 SFT 之前）；二是**RLHF 不注入新知识**——它只调整输出倾向，新业务知识要靠预训练/继续预训练或微调数据。

**我错了吗**：☐

### Q002 [M1-K03] [A] 单选

某企业准备把一份 2 万字的产品文档交给大模型做问答，技术同学提醒："先关注一下这段文字会被切成多少 **Token**，以及模型的上下文长度是按什么算的。"关于 Token，下列说法正确的是：

- A. Token 就是字符数，中文按字算、英文按单词算，一个英文单词一定等于一个 Token
- B. Token 是模型处理文本的基本单位，中文和英文都会被切分，且一个英文单词可能被拆成多个 Token
- C. 分词只在训练阶段进行，模型上线推理时直接读原始文本，不需要分词
- D. Token 只影响模型的训练速度，与上下文长度限制、调用量统计无关

**答案**：B

**考点**：M1-K03 分词 Tokenization（V2.4 强化交互演示）

**解析**：
- A ❌ 三处错误：Token **不等于字符数**；不存在"中文按字、英文按词"这种简单规则（两种语言都会被切分）；一个英文单词**可能**被拆成多个 Token（尤其生僻词、专业词、长复合词），"一定等于一个"是常见误解。
- B ✅ 准确描述了分词的本质：**Token 是模型处理文本的最小基本单位**，训练与推理都要走同一套分词器，中英文都会被切分，且切分粒度由词表/分词器决定，英文单词常被拆成多个子词 Token。
- C ❌ 推理阶段同样必须分词，而且必须**使用与训练时相同的分词器和词表**，否则 ID 映射对不上、语义就会错乱。
- D ❌ 恰恰相反：Token 是模型"计数"的核心——**上下文长度以 Token 计、调用量与成本也按 Token 计**。题干里技术同学担心的问题正是由 Token 决定的。

**我错了吗**：☐

### Q003 [M1-K05] [A] 单选

用户与客服机器人连续对话：「那款**蓝牙耳机**支持退货吗？」→「**它**的退货期限是几天？」机器人正确理解了第二句中的"它"指的是前文的蓝牙耳机，并给出了对应答案。这一能力主要依赖大模型的什么机制？

- A. 分词机制，因为"它"被单独切分成了独立 Token
- B. 注意力机制，动态计算词与词之间的关联权重，把"它"与上下文中的"蓝牙耳机"关联起来
- C. RLHF 对齐机制，因为人类标注员教过模型代词指代规则
- D. MoE 路由机制，因为路由为这句话挑选了专门处理代词的专家网络

**答案**：B

**考点**：M1-K05 注意力机制（V2.4 强化：注意力溯源）

**解析**：
- A ❌ 分词只负责把文本切成 Token 并映射成 ID，它**不理解语义、也不建立词与词之间的关联**。切出"它"这个 Token 是前提，但解决指代靠的不是分词。
- B ✅ 这正是注意力机制的作用：处理某个 Token 时，通过 Query/Key 计算它与上下文中所有 Token 的相关性权重，再按权重汇总 Value，从而让"它"的表示里**混入真正相关的上下文信息**（即"蓝牙耳机"）。这就是长距离依赖得以解决的原因；V2.4 新增的**注意力溯源**演示正是把这种"生成时关注了输入的哪些部分"可视化出来，用于提升可解释性。
- C ❌ RLHF 调整的是**输出倾向**（是否有用、无害、符合偏好），不负责语言结构的理解。代词指代是模型架构层面的能力，不是对齐阶段教出来的。
- D ❌ 概念错配。MoE 的路由决定"**用模型里的哪些专家参数**"，解决的是**容量与推理开销**问题；注意力决定"**看输入里的哪些 Token**"。一个在模型结构侧，一个在输入侧，不能互换。

**我错了吗**：☐

### Q004 [M1-K07] [A] 单选

某大模型的介绍材料写道："模型总参数量非常大，但每次推理时只会根据输入**挑选并激活其中一部分专家网络**参与计算，从而在保持能力的同时控制算力开销。"这段描述指的是：

- A. 模型量化，通过降低数值精度来减少显存占用
- B. MoE（混合专家）架构，通过路由实现稀疏激活
- C. RLHF，通过人类反馈减少无效输出以节省算力
- D. 上下文学习，通过示例减少模型需要计算的参数

**答案**：B

**考点**：M1-K07 MoE 架构（V2.4 强化图文说明）

**解析**：
- A ❌ 量化是把权重从高精度降到低精度（如用更少的比特表示）来省显存、提速，**并不改变"用哪些参数参与计算"**。题干关键词是"挑选并激活一部分专家"，不是精度问题。
- B ✅ 完全对应 MoE（Mixture of Experts，混合专家）的核心特征：**多个专家子网络 + 路由/门控**，每次推理只由路由挑选少量相关专家参与，即**稀疏激活**。因此能做到"参数总量大（容量强）但单次推理开销可控"。
- C ❌ RLHF 是训练阶段用人类偏好反馈调整输出倾向，属于**对齐**手段，既不改模型结构，也不决定推理时激活哪些参数。
- D ❌ 上下文学习（ICL）是在输入里给示例来引导模型，**不更新参数，也不减少参与计算的参数量**，与"专家选择"无关。

**我错了吗**：☐

### Q005 [M1-K11] [B] 单选

法务同学用大模型查资料时遇到两个问题：① 模型给出了"《XX 管理办法》第 37 条规定……"的详细条款，但同事核查后发现**该条款根本不存在**；② 问"上周刚发布的新政策有什么变化"，模型**完全答不上来**。这两个问题分别属于：

- A. 两者都属于幻觉，都是模型编造内容导致的
- B. 前者是幻觉，后者是知识时效性限制
- C. 前者是知识时效性限制，后者是幻觉
- D. 两者都是上下文长度限制导致的，与模型能力无关

**答案**：B

**考点**：M1-K11 模型局限：幻觉 / 时效

**解析**：
- A ❌ 只对了第一个。② 中模型是"答不上来"，**并非编造内容**，不属于幻觉。把"不知道"和"瞎编"混为一谈是本考点最常见的失分点。
- B ✅ 判据清晰：**编造出看似合理但与事实不符的内容（不存在的条款/文献/数据）= 幻觉**；**知识停留在训练数据截止时点、不了解之后新发生的事件 = 知识时效性限制**。题干中"根本不存在"对应幻觉，"上周刚发布"对应时效。
- C ❌ 完全说反了。判断口诀：**"杜撰的"是幻觉，"最新的"是时效**。
- D ❌ 上下文长度限制指一次能处理的 Token 总量有上限（长文可能被截断），本题中模型已正常接收并作答，问题出在**内容不可信**和**知识过期**，与该限制无关。

**我错了吗**：☐

### Q006 [M1-K13] [A] 单选

运营同学拿到一份 30 页的产品说明书，希望大模型做两件事：把全文压缩成 300 字要点，并从原文中**提取出保修期限、适用型号两个字段**。按照大模型的典型应用场景划分，这属于哪一类？

- A. 文本生成与创作
- B. 文本润色与转换
- C. 文本摘要与信息提取
- D. 信息推理与表格解读

**答案**：C

**考点**：M1-K13 典型应用场景（课时2「大模型的典型应用场景」）

**解析**：
- A ❌ 文本生成与创作是**从无到有**产出内容（写文案、写故事、写代码）。本题的输入（说明书）已经存在，输出不是凭空创作，且长度被压缩，不符合"创作"。
- B ❌ 文本润色与转换是对已有文本做**形式上的改写**（润色语病、风格改写、翻译、格式转换），核心是"内容基本不变、说法变了"。本题把 30 页压成 300 字，内容量大幅减少，不是润色。
- C ✅ 两个动作都精准对应：**"压缩成要点"= 文本摘要**；**"提取保修期限、适用型号"= 信息提取**。这是课时2 典型应用场景中「文本摘要与信息提取」的标准例子。
- D ❌ 信息推理与表格解读强调**基于给定数据做出判断、推断或结论**（如读销售报表给出环比结论、对比多方案优劣）。本题只要求"抽出原文里已有的字段"，没有要求下结论，属于提取而非推理。注意：即使原文中有表格，只要任务是抽字段/做摘要，仍归 C。

**我错了吗**：☐

### Q007 [M1-K01] [A] 多选

关于大模型之"大"的体现，下列说法正确的有：（多选）

- A. 模型参数规模巨大
- B. 训练数据的规模巨大
- C. 训练所需的算力投入巨大
- D. 大模型的"大"意味着它能处理任意长度的输入，不受上下文长度限制

**答案**：A、B、C

**考点**：M1-K01 大模型定义与"大"的体现

**解析**：
- A ✅ 参数量是模型承载知识与模式的"容量"，是"大"的首要体现。
- B ✅ 训练数据规模巨大，模型才具备通用语言能力与广覆盖的世界知识。
- C ✅ 大规模参数和海量数据必然对应巨大的算力投入，这是"大"的成本面。三者共同支撑了模型的能力跃迁（也是涌现能力的前提）。
- D ❌ **过度外推**。"大"指的是**参数、数据、算力**三个维度，**不等于输入长度无限**。大模型的上下文长度有明确上限，且以 **Token** 计量（见 M1-K03）。这是把"能力大"误解为"没有限制"的典型干扰项。

**我错了吗**：☐

### Q008 [M1-K10] [C] 多选

某同事在内部培训材料中列举了以下关于"大模型特点"的说法。从大模型能力的常见归纳来看，合理的有：（多选）

- A. 具有较强的语言理解与生成能力，能理解复杂指令并生成连贯内容
- B. 具有较强的通用性与泛化能力，一个模型可应对写作、摘要、翻译、推理等多类任务
- C. 具备上下文学习能力，在输入中给出少量示例即可适配新任务，无需更新模型参数
- D. 参数规模足够大之后，模型就不会再产生幻觉，回答也必然正确且不受训练数据时间限制

**答案**：A、B、C

**考点**：M1-K10 大模型四大特点（含与 M1-K08 涌现、M1-K09 ICL 的辨析）

**解析**：
- A ✅ 语言理解与生成是大模型最基础也最突出的能力：能理解上下文、指代和复杂指令，并产出连贯自然的长文本。
- B ✅ 通用性与泛化能力是大模型区别于传统"一个模型一个任务"的关键：同一个模型可以跨写作、摘要、翻译、推理、代码等多类任务复用。
- C ✅ 这正是上下文学习（ICL，M1-K09）的含义：**不更新任何参数**，只在上下文中给出示例即可让模型"照样子"完成新任务。它也是提示词工程（M2）成立的前提。
- D ❌ **把"规模大"误当成"绝对可靠"**。参数规模增大只能**缓解**而无法根除幻觉；模型知识仍受**训练数据截止时点**限制，不因参数变大而自动获得最新信息（时效性问题需靠 RAG/插件等手段解决，属 M3/M4）。这类"规模越大越不会错"的说法是典型错误表述。

> 📌 补充：行业常见的"四大特点"还包括 **涌现能力**（M1-K08：规模跨过阈值后突然出现小模型不具备的能力）。
> ⚠️ **待与官方 V2.4 大纲 PDF 核对**：课时1「认识大模型」必然讲解大模型特点，但"四大特点"的**具体四项表述未获官方确认**，若官方表述不同，以官方为准；本题只需掌握"何为合理特点、何为夸大表述"的辨析方向。

**我错了吗**：☐

### Q009 [M1-K14] [A] 多选

公司计划在阿里云上做两件事：① 搭建一个基于大模型的文本问答应用；② 生成商品宣传图。关于阿里云相关产品的定位，下列说法正确的有：（多选）

- A. 通义千问 Qwen 是基础语言大模型，可用于文本理解与生成
- B. 通义万相是视觉生成模型，可用于文生图、图生视频
- C. 百炼是一站式大模型服务与应用开发平台，可用于模型调用和应用搭建
- D. 百炼平台只能用于模型训练，不能用来开发和搭建大模型应用

**答案**：A、B、C

**考点**：M1-K14 阿里云产品矩阵

**解析**：
- A ✅ 通义千问 **Qwen** 在阿里云产品体系中定位为**基础语言大模型**，承担文本理解与生成类能力，适合做问答、写作、摘要等文本任务（对应诉求①）。
- B ✅ 通义万相定位为**视觉生成模型**，能力包括**文生图 / 图生视频**（对应诉求②）。注意不要把它当成语言/对话模型。
- C ✅ 百炼平台定位为**一站式大模型服务与应用开发平台**，既提供模型服务，也支撑应用开发，适合用来搭建上述问答应用。
- D ❌ 与官方定位相反。百炼是**平台**，同时具备模型服务与应用开发能力，题干"只能训练、不能开发应用"的说法错误，容易与单纯"训练平台"混淆。

> ⛔ 备考边界：具体模型规格名称、版本号、上下文长度数值、价格、控制台菜单路径**均未核实，不考也不记**。本模块只要求产品**对得上号**：说话 → 千问，画图 → 万相，搭应用 → 百炼。

**我错了吗**：☐
