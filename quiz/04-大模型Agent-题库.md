# 一、单选题（6 题）

### Q001 [M4-K03] [A] 单选

阿里云认证大纲对「大模型 Agent」部分明确要求：**掌握如何给 Agent 明确目标、资料来源、工具边界和阶段检查点**。这里的「四要素」指的是？

- A. 感知、思考、行动、记忆
- B. **目标、资料来源、工具边界、阶段检查点**
- C. 目标、背景、角色、约束
- D. 数据、算法、算力、场景

**答案**：B
**考点**：M4-K03~K06 Agent 四要素（官方原文直接支持的 ⭐⭐ 主考点）
**解析**：
- A ❌ **感知、思考、行动**是 Agent 的**三大核心能力**（描述 Agent 自身由什么构成），不是下达任务时要明确的四要素。两者极易混淆：前者讲「Agent 有什么本事」，后者讲「你要把任务交代到什么程度」。此外「记忆」并不属于官方表述的三大能力。
- B ✅ **完全对应官方原文**：目标（交付什么、什么算做完）、资料来源（依据什么信息、查不到怎么办）、工具边界（能动哪些、禁止哪些、哪些要人确认）、阶段检查点（何时停下来核对、不通过怎么处置）。这四项是官方点名要求「明确」的内容，是本模块最高频考点。
- C ❌ **这是提示词要素（见 M2）**，不是 Agent 四要素。二者确实都含「目标」一词，但 M2 的七要素（目标、背景、角色、约束、示例、输出格式、评价标准）面向**单次输入优化**，M4 四要素面向**多步任务的任务委托书**。正确答案以官方对 Agent 部分的原文表述为准。
- D ❌ 数据/算法/算力/场景是描述大模型基础设施的维度，与 Agent 的任务下达无关，纯凑数干扰项。

> 📌 **速记**：`目标 → 交付什么？` `资料来源 → 依据什么？` `工具边界 → 能动哪些？` `阶段检查点 → 何时停下？`

### Q002 [M4-K04] [A] 单选

运营同学要让个人 AI Agent 完成《上月经营分析周报》。下列四种任务下达方式中，**最能完整体现**"给 Agent 明确目标、资料来源、工具边界和阶段检查点"的是？

- A. 「帮我写一份上月经营分析周报，尽量写得专业一点、数据准确一点。」
- B. 「按周报模板写上月经营分析，数据从 BI 取数工具里取，取完数之后你自己看着办就行。」
- C. 「先调用 BI 取数工具读取数据，然后生成周报；所有发邮件的操作都先生成草稿交我确认后再由我发送。」
- D. 「输出一份不超过 800 字的周报，含同比、环比两张表；数据只允许来自『经营数据/2026-08.xlsx』，不得使用其他来源，查不到的数据直接标注『未找到』；只允许调用『读取文件』与『生成图表』工具，禁止写入和删除任何文件；数据抓取完成后先输出字段口径交我确认，确认通过后再进入分析。」

**答案**：D
**考点**：M4-K04 资料来源 / M4-K05 工具边界 / M4-K06 阶段检查点（四要素场景综合，⭐⭐ 主考点）
**解析**：
- A ❌ 只有粗略方向，且「专业」「准确」是**没有判定门槛的形容词**——既不具体也不可核对。缺资料来源、工具边界、阶段检查点三项。
- B ❌ 虽指定了取数工具，但「**你自己看着办**」恰恰是**没有阶段检查点**的典型表现：中间步骤不受控，一旦口径取错，后续分析会建立在错误数据上一路跑到最后。
- C ❌ **本题最容易误选的干扰项**。它确实明确了工具调用，并把「对外发邮件」作为需确认的动作，但它**仍缺资料来源**（没限定数据从哪来、能否参考其他资料）与**阶段检查点**（没有中途停下核对的时点），目标也不够明确。覆盖不全 = 不是最佳答案。
- D ✅ **四项齐全且都达到"明确"标准**：① **目标**——一份 ≤800 字、含同比/环比两张表的周报（交付物 + 成功标准）；② **资料来源**——唯一指定文件，并规定其他来源禁用、查不到就标「未找到」（缺省行为，防止模型自行编造）；③ **工具边界**——白名单式授权（只读文件、生成图表）+ 明确禁止写入与删除；④ **阶段检查点**——数据抓取后先输出口径请人确认，通过才继续，这正是防「一步错步步错」的关键设计。

> 📌 **判断"够不够明确"的三问**：能不能被他人照着执行出同样的结果？（目标）｜出错后能不能追溯到依据？（资料来源）｜出事的代价能不能被事前限制住？（工具边界 + 阶段检查点）

**我错了吗**：☐

### Q003 [M4-K07] [A] 单选

小李为周报 Agent 设计了一份自检清单。按官方要求「**自检清单要具体、可核对、有证据**」，下列检查项中**最符合要求**的是？

- A. 「检查周报内容是否准确、表达是否专业。」
- B. 「核对周报是否达到合格标准，不合格就重新生成一遍。」
- C. 「周报中每个数字都必须能在『经营数据/2026-08.xlsx』的『华东』页签中找到同名行，并在清单中记录其所在行列位置；查不到的一律判为不合格并逐条列出。」
- D. 「让 Agent 一次性生成 3 个版本的周报，再从中挑一个最好的。」

**答案**：C
**考点**：M4-K07 自检清单三要求（**具体 / 可核对 / 有证据**）⭐⭐ 官方原话考点
**解析**：
- A ❌ **典型反例——不具体、不可核对**。「准确」「专业」是没有判定门槛的形容词，不同的人（或不同次的模型）会得出完全不同的结论，清单形同虚设。官方要求「具体」，即必须落到**哪个对象、满足什么条件**。
- B ❌ 「合格标准」本身没有被写清楚，等于没有标准；且「不合格就重新生成一遍」**缺少针对性反馈**（不说哪里不合格），大概率重犯同样的错，也没留下任何可复核的凭证。
- C ✅ **三条要求全部满足**：**具体**——检查对象是"周报中每个数字"，判定门槛是"能在指定页签找到同名行"；**可核对**——可逐条比对并打出通过/不通过的勾；**有证据**——要求记录源表的行列位置，第三方可据此复核查证，不合格项还要逐条列明以便修正。
- D ❌ **混淆了自检与 best-of-N 采样择优**。生成 N 个版本挑最好的只有"挑"，既没有针对发现的问题去修正，也不产生任何证据，还要成倍增加调用成本。官方口径是「具体、可核对、有证据」的清单驱动的自检，二者机制不同。

> 📌 另须记住：自检**不能保证 100% 正确**（标准本身可能有漏洞），且必须设**重试上限**，超限转人工。

**我错了吗**：☐

### Q004 [M4-K09] [A] 单选

小王把团队每周做「数据周报」的方法固化了下来：规定了"先取数 → 再与上周对比 → 按模板排版 → 最后检查数据口径"的先后顺序，规定了过程中要调用哪几个工具以及字段格式要求，之后同事换个会话也能直接套用。关于这一做法，下列说法正确的是？

- A. 这只是在对话框里写了一条很长的提示词，每次换会话仍需重新写一遍
- B. 这是用 **Skill 固化了一套重复工作方法**：把"流程 + 所需工具 + 约束与验收标准"沉淀为可复用资产
- C. 这只是调用了一个工具，因为过程中用到了取数工具
- D. 这是多个 Agent 分工协作的 Multi-Agent 架构

**答案**：B
**考点**：M4-K09 Skill——官方措辞「**固化重复工作方法**」⭐ V2.4 新增
**解析**：
- A ❌ Skill ≠ 长提示词。区别在于 Skill 还包含**所需工具集合、明确的约束与验收标准**，并被沉淀为**可复用资产**（换会话、换人都能直接套用），而一次性长提示词每次要重写、难以沉淀。
- B ✅ **完全对应 Skill 三要素与官方措辞**：流程步骤（先取数→对比→排版→校验）+ 所需工具（指定的取数等工具）+ 约束与验收标准（字段格式、口径一致），且具备可复用性。**注意官方用词是「固化重复工作方法」**——Skill 的价值正在于把反复做的工作方法固定下来，让执行过程稳定、可复现。若把多个这样的 Skill 按依赖关系串起来执行，即为 **Skill 编排**。
- C ❌ 调用工具只是其中的一个原子动作；Skill 的层次在**工具之上**，它规定"什么时候调哪个工具、按什么顺序调、什么算合格"。一句话：工具回答"能做什么"，Skill 回答"这件事该怎么干"。
- D ❌ Multi-Agent 强调的是**多个独立 Agent 角色分工、任务分发与结果汇总**（如检索 Agent、写作 Agent、检查 Agent）。题干是把一套方法固化下来，**没有角色间的任务分发**，不属于 Multi-Agent。

### Q005 [M4-K16] [A] 单选

关于「**工具**」「**MCP**」「**Function Calling**」「**Skill**」四者的概念与层级，下列说法正确的是？

- A. MCP 是一个功能强大的工具，可以直接替 Agent 完成查询库存、创建工单等具体动作
- B. Function Calling 是模型把"我要调用哪个工具、传入什么参数"表达为结构化调用的机制，真正的执行在模型之外完成
- C. 有了 MCP 之后，Function Calling 就不需要了，因为二者解决的是同一层的问题
- D. Skill 与提示词没有本质区别，都只是把一段话写给模型看

**答案**：B
**考点**：M4-K16 概念层级辨析 / M4-K10 工具调用 / M4-K11 MCP 定位（官方明示**不考协议细节**，主考点归属 M3）
**解析**：
- A ❌ **最高频陷阱之一**。MCP 的定位是让 Agent / 应用**把外部工具与数据源接进来的通用方式**（参见 M3 主考点），真正执行查询、下单、创建工单动作的是**接入进来的工具**。把连接方式当成工具本身，是层级混淆。
- B ✅ 准确复述了工具调用机制：模型**不执行**任何工具，只负责决定"要不要调、调哪个、参数填什么"，并输出**结构化的**调用请求（结构化才能被程序稳定解析），由模型之外的运行时真正执行，再把结果**回灌**给模型继续推理。「**执行在模型之外**」是本题的得分点。
- C ❌ **层级混淆的经典错误项**。Function Calling 位于**模型侧**（如何把调用意图表达成结构化请求），MCP 位于**连接侧**（工具与数据源如何接进来）。二者**不在同一层、通常共存**，不是互相替代关系。
- D ❌ Skill 的关键增值在于**所需工具集合 + 约束与验收标准 + 可复用**，它的官方定位是「**固化重复工作方法**」；而提示词偏"这次怎么说"。二者有本质区别。

> 📌 **类比速记**：MCP ≈ 接口标准，工具 ≈ 外接设备，Function Calling ≈ 发出的驱动调用，Agent ≈ 用电脑干活的人。
> ⛔ **官方明示不考 MCP 协议实现细节**（握手、报文格式、传输方式等），考试只考其作用与定位。

**我错了吗**：☐

### Q006 [M4-K12] [A] 单选

关于「桌面 Agent」与「云端 Agent」的差异，下列说法正确的是？

- A. 桌面 Agent 是另一种技术路线，不遵循感知—思考—行动的 Agent 范式
- B. 桌面 Agent 运行在本地设备上，可直接读写本地文件并在本地执行操作；因其具备本地操作权限，更需注意权限最小化与危险操作确认
- C. 桌面 Agent 由于运行在本地，天然具备比云端 Agent 更强的模型推理能力
- D. 桌面 Agent 的数据默认必须上传至云端处理，灵活性和隐私性都比云端 Agent 差

**答案**：B
**考点**：M4-K12 桌面 Agent（本地运行形态 + 权限风险）
**解析**：
- A ❌ 桌面 Agent 只是**部署形态**不同，走的仍是同一套 Agent 范式（感知—思考—行动）。把它理解成"另一种技术"是最常见的误读；四要素、Skill、自检清单、人工确认对桌面 Agent **同样适用**。
- B ✅ 准确命中两个考点：① **本地运行**使其能触及**本地文件系统与本地执行能力**，这正是它区别于云端 Agent 的关键（也解释了为什么适合整理本地文件、批量处理本地文档这类任务）；② 正因为拥有这些权限，误删、误覆盖本地文件、误执行本地命令等风险随之而来，必须配套**权限最小化**与**高风险动作人工确认**。
- C ❌ 推理能力由**底层模型**决定，与部署在本地还是云端无关。桌面形态改变的是**可达资源**，不是大脑。
- D ❌ 恰恰相反，本地运行的特点之一是数据可留在**本机**处理；"必须上传云端、隐私性更差"与桌面形态的定位相悖。

> ⚠️ **产品名称待核实**：具体产品名称、安装包获取方式、菜单路径**不在考证范围**，本模块只考**概念与定位**（本地运行、可操作本地文件与终端，区别于云端 Agent）。

### Q007 [M4-K08] [A] 多选

某公司上线了一个能读写文件、发送邮件、操作业务系统的个人 AI Agent。按照官方要求「**高风险动作必须人工确认**」，下列做法或认识**正确**的是？（多选）

- A. Agent 删除或覆盖本地/线上文件前，必须经人确认后再执行
- B. 向客户或外部联系人发送邮件前，先由 Agent 生成草稿，经人审阅确认后再发送
- C. 修改生产环境数据库、发起付款或退款等动作，应保留人工确认环节
- D. 只要自检清单写得足够完善，高风险动作就可以由 Agent 自主判断并执行，无需人工介入
- E. 人工确认环节会拖慢流程，可由 Agent 在事后补一条执行记录来代替事前确认
- F. 高风险动作的人工确认只需口头同意即可，不必记录确认人和确认内容

**答案**：A、B、C
**考点**：M4-K08 高风险动作必须人工确认（官方硬性规则，⭐⭐ 主考点）
**解析**：
- A ✅ **删除与覆盖属于不可逆动作**，一旦执行难以恢复，必须在工具边界中划为高风险并卡住等待人工确认。
- B ✅ 对外发送类动作**一旦发出无法撤回**，且直接影响公司形象；官方推荐的落地方式正是**Agent 生成草稿、人审阅确认后再执行**——这既保留了 Agent 的效率，又把拍板权留在人手里。
- C ✅ 改生产数据与付款/退款分别对应**系统性故障风险**与**资金损失风险**，是官方语境下最典型的高风险动作，必须保留人工环节（对应 M6 医疗、金融、合同、对外发布等高风险场景的治理要求）。
- D ❌ **本题核心干扰项，官方明确否定**。官方原文是陈述句规则「高风险动作**必须**人工确认」，不存在"足够完善即可免除"的例外。根本原因有三：① Agent 的错误是**有执行力**的，错了就是真做错了；② 自检清单是人写的，**拦不住清单之外的盲区**；③ 官方金句——**AI 可以辅助整理和起草，但不能替代最终责任人**。
- E ❌ 事后补记**只是留痕，不是确认**。确认的价值在于**事前拦住**尚未发生的不可逆动作，事后记录无法阻止损失发生。两者不能互换。
- F ❌ 合规要求确认过程**可追溯**：需记录谁确认的、确认了什么、依据是什么（详见 M6 审计追踪与来源留存）。只口头同意而无记录，等同于无确认。

**我错了吗**：☐

### Q008 [M4-K13] [A] 多选

某团队给已有的 Agent **接入了知识库**（内含公司产品手册、报价规则与售后政策），并**通过工具调用**让它具备了写文件与创建工单的能力。关于这一改动带来的效果与边界，下列说法**正确**的是？（多选）

- A. Agent 可以引用知识库内容作为作答依据，缓解"模型不知道就编一个"的问题，且结论可标注出处便于人工核查
- B. 产品手册更新后，Agent 在下次问答中即可用到新内容，无需重新训练模型
- C. 接入知识库后，Agent 的模型推理能力得到实质性提升，因为它已把这些文档内容永久写进参数、真正学会了
- D. Agent 获得写文件、创建工单的能力，是因为挂载了相应的工具；这与是否接入知识库是两回事
- E. 即便接入了知识库和工具，涉及删除客户数据、对外发布、发起付款等动作仍须人工确认
- F. 接入知识库与工具后，所有业务环节都可以放心交给 Agent 全自动完成，人不必再介入

**答案**：A、B、D、E
**考点**：M4-K13 Agent 接入知识库 / M4-K10 工具调用 / M4-K14 局限性 / M4-K15 协作使用方式
**解析**：
- A ✅ 接知识库后回答有据可依，直接针对 Agent 执行任务时最危险的问题——"凭想象编参数、编规则"；同时检索片段有明确出处，便于人工核查，这对报价、售后政策这类有合规要求的场景尤其关键。这也正是四要素中「**资料来源**」的落地。
- B ✅ 这是知识库相对微调的核心优势之一：**文档更新即刻生效**，改完文档下一次问答就能用到，无需重新训练、无需停机。
- C ❌ **最典型的陷阱**。检索是**外挂式**取用知识，文档内容并没有写进模型参数——「永久学会」描述的恰恰是**微调**的效果。接知识库改变的是**可用信息**，不改变模型本身的推理能力。
- D ✅ **知识 ≠ 能力**。能否写文件、创建工单取决于是否挂载了相应的**工具**（工具调用）；知识库只负责提供**依据**。二者职责不同、互不替代。Agent 的完整画像＝思考（模型）＋资料来源（知识库）＋行动（工具）＋方法（Skill）。
- E ✅ **这是本题最容易被漏选的正确项**。Agent 有执行力，恰恰是它相对普通问答的**最大局限**——错误会被真实执行出去。所以即便接入了知识库和工具，删除、外发、支付、改生产数据、对外发布这类高风险动作**仍须人工确认**（见 Q007）。
- F ❌ 与 E 直接对立。官方强调 Agent 的「**协作使用方式**」：人负责**定目标、设边界、拍板高风险、担最终责任**，Agent 负责检索、起草、批量执行低风险动作。此外，写不出验收标准的任务本就不该交给 Agent 全自动跑。

> 📌 **记忆锚点**：接知识库 → **有依据、可溯源、即时更新**，但**不提升智商、不等于微调**；接工具 → **有执行力**，但**高风险动作必须留人工确认**。

**我错了吗**：☐
