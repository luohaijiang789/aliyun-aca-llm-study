# 一、单选题（6 题）

### Q001 [M4-K01] [A] 单选

某公司基于大模型搭建了一个差旅助手，它的工作过程是：接收员工的出差申请 → 理解需求后把任务拆成「查航班、比价格、对照差旅标准、生成申请单」几步 → 依次调用机票查询接口、企业报销额度接口完成操作 → 最后输出一张申请单。**在整个过程中，"调用机票查询接口与报销额度接口"这一行为，对应 Agent 三大核心能力中的哪一个？**

- A. 感知（Perception）
- B. 行动（Action）
- C. 思考（Reasoning）
- D. 记忆（Memory）

**答案**：B
**考点**：M4-K01 Agent 三大核心能力（感知 / 思考 / 行动）
**解析**：
- A ❌ **感知**指的是接收并理解来自任务与环境的信息，包括用户指令、文件内容、检索结果，**以及工具返回的结果**。题干明确问的是"调用接口"这一主动动作，属于下游输出，不是接收。
- B ✅ **行动（Action）**就是真正调用工具 / API / 接口去执行，并对外部世界产生作用。题中的「调用机票查询接口、报销额度接口」是标准的行动环节；这也正是 Agent 区别于普通聊天机器人的关键——它不止"说"，它真的"做"。
- C ❌ **思考（Reasoning）**对应的是题干中「理解需求后把任务拆成几步」这一段——规划与决策，包括选哪个工具、下一步干什么。拆任务是思考，按拆好的步骤去调接口才是行动，两者不可混淆。若缺了思考能力，Agent 会走一步算一步、无法处理多步依赖任务。
- D ❌ **记忆**不属于 Agent 三大核心能力的标准表述。官方口径为**感知（Perception）、思考（Reasoning）、行动（Action）**三者的闭环循环。此外要注意：CoT（思维链）、ToT（思维树）只属于**思考**环节的策略，不是与三者并列的第四种能力。
**我错了吗**：☐

### Q002 [M4-K05] [A] 单选

关于大模型应用中的**工具调用（Function Calling）**，下列说法正确的是？

- A. 大模型在生成回答的过程中会直接执行被调用的外部程序，并将执行权交给该程序
- B. 大模型判断需要工具时，会输出结构化的调用请求（工具名与参数），由外部程序执行后把结果回灌给模型
- C. 工具调用是在大模型的参数内部完成的，因此调用结果天然可靠、不会出错
- D. 工具调用的作用是补充模型缺失的知识，让模型回答出原本不知道的事实

**答案**：B
**考点**：M4-K05 工具调用 / Function Calling ⭐ V2.4 新增（概念 + 流程）
**解析**：
- A ❌ 这是本考点**最高频的陷阱**。模型**不执行**任何工具，它只负责「决定要不要调、调哪个、参数填什么」，真正执行的是模型之外的 Agent 运行时。说"模型直接执行外部程序"把边界搞错了。
- B ✅ 完整复述了标准链路：事先向模型描述可用工具 → 模型输出**结构化的**调用请求（而不是随意的自然语言，结构化才能被程序稳定解析）→ 外部执行 → **把返回值回灌为新的上下文** → 模型继续推理或作答。这正是"让模型从只能说到真的能做"的机制所在。
- C ❌ 调用发生在模型**之外**，谈不上"在参数内部完成"；且结果远非天然可靠——工具可能超时失败、模型可能选错工具或填错参数，因此还需要异常处理与自检。
- D ❌ 混淆了**能力**与**知识**。工具调用提供的是**行动能力**（查出当日机票、发出一笔请求），它不是在给模型补知识。补充知识应走 **RAG / 知识库**（临时检索外挂）或**微调**（写入参数）。
**我错了吗**：☐

### Q003 [M4-K06] [A] 单选

某团队要为公司内部的 3 个 AI 助手分别接入日历、工单、文档 3 套内部系统。若**没有任何统一标准**，每个助手都为每套系统各写一套对接代码，共需编写 9 套适配器；引入**统一协议**后，每个助手和每套系统各按该协议适配一次即可互相联通。**题中描述的"统一协议"，其准确定位是？**

- A. 一个功能强大的 Agent，能替三个助手自动完成所有对接工作
- B. 一种替代 Function Calling 的新机制，让模型不再需要输出结构化的调用请求
- C. 一套标准化「模型与外部数据源、工具之间如何连接与交互」的开放协议（如 MCP），它本身不是工具
- D. 一个预先训练好的插件市场，里面封装了日历、工单、文档等各种现成工具

**答案**：C
**考点**：M4-K06 MCP 协议 / M4-K13 概念层级辨析 ⭐ V2.4 新增
**解析**：
- A ❌ 协议不是软件实体，更不是 Agent。Agent 是"干活的人"，协议是"接口标准"，二者完全不在同一层。
- B ❌ **层级混淆的经典错误项**。Function Calling 位于**模型侧**，解决"如何把调用意图表达成结构化请求"；而 MCP 这类协议位于**连接侧**，解决"外部数据源和工具如何被发现、描述、对接"。二者互补共存，不是替代关系。
- C ✅ 完全符合定义：它解决的是 N×M 集成碎片化（9 套 → 6 套乃至一次适配多处复用），且明确点出"**本身不是工具**"——执行具体动作的是日历/工单/文档这些工具，协议只负责把两者接起来。
- D ❌ 把协议等同于插件市场/工具集合。工具是被连接的**对象**，不是那条连接规则本身。
> 📌 **类比速记**：MCP ≈ Type-C 接口标准，工具 ≈ 外接设备，Function Calling ≈ 系统发出的驱动调用，Agent ≈ 使用电脑干活的人。
**我错了吗**：☐

### Q004 [M4-K09] [A] 单选

小王把团队每周的「数据周报」工作流程固化下来了：固定先取数、再核对比上周、然后按模板排版、最后检查数据口径是否一致，并在其中规定了要调用哪几个工具和字段格式要求，之后同事换个会话也能直接套用。**关于这一做法，下列说法正确的是？**

- A. 这只是在对话框里写了一条很长的提示词，每次换会话仍需重新写一遍
- B. 这是把「流程 + 工具 + 约束与验收标准」封装成了可复用的 **Skill**，固化的正是"工作方法"本身
- C. 这只是调用了一个工具，因为过程中用到了取数接口
- D. 这是多个 Agent 分工协作的 Multi-Agent 架构

**答案**：B
**考点**：M4-K09 Skill 与 Skill 编排 / M4-K13 概念层级辨析 ⭐ V2.4 新增
**解析**：
- A ❌ Skill ≠ 长提示词。区别在于 Skill 还包含**所需工具集合、明确的约束与验收标准**，并且被沉淀为**可复用资产**（换会话、换人都能直接套用），而一次性长提示词每次都要重写、难以沉淀。
- B ✅ 完全对应 Skill 的三要素：**流程步骤（先取数→核环比→排版→校验）+ 所需工具（指定的取数等工具）+ 约束与验收标准（字段格式、口径一致）**，且具备可复用性。这正是 V2.4「用 Skill 固化你的工作方法」这一课的核心。补充：若把多个这样的 Skill 按依赖关系串起来组合执行，就是**Skill 编排**。
- C ❌ 调工具只是过程中的一个原子动作；Skill 的组织层次在**工具之上**，它规定了"什么时候调哪个工具、按什么顺序调、什么算合格"。记住一句话：工具回答"能做什么"，Skill 回答"这件事该怎么干"。
- D ❌ Multi-Agent 强调的是**多个独立 Agent 角色分工、任务分发与结果汇总**（如检索 Agent、写作 Agent、检查 Agent）。题干是一个人把一套方法固化下来，**没有角色间的任务分发**，不属于 Multi-Agent。
**我错了吗**：☐

### Q005 [M4-K10] [A] 单选

一个 Agent 生成周报后，会先按预设标准核对「日报字段是否齐全、数据能否对齐模板」，发现缺失就带着具体问题重新生成，最多重试 3 次后仍不通过则转交人工。**下列对该"自检闭环"的理解，错误的是？**

- A. 自检闭环必须有可判定的校验标准，否则"自检"无从执行
- B. 自检闭环应当设置重试上限，以避免陷入无限循环并控制成本
- C. 自检闭环等同于让模型一次性生成多个候选答案再挑最好的那份
- D. 自检闭环不等同于人工审核，它是自动执行的「检查—修正」环节

**答案**：C
**考点**：M4-K10 自检闭环（四要素 + 三个"不等于"）⭐ V2.4 新增
**解析**：
- A ✅ 表述正确（不是错误项）：校验标准是自检闭环的**第一要素**，没有"什么叫合格"的判定依据，检查环节就形同虚设。
- B ✅ 表述正确：题干中的"最多重试 3 次"正是**重试上限**。缺少上限会让 Agent 陷入反复重试的失控循环，导致时延与调用成本飙升。
- C ❌ **本题答案，高频混淆点**。让模型生成 N 个候选再择优属于 **best-of-N 多次采样**——它只有"挑"，没有"针对发现的问题去修正"。自检闭环的核心价值恰恰在于**标准 + 检查动作 + 针对性反馈修正**，两者机制完全不同；且 best-of-N 会成倍增加调用成本却不保证命中正确答案。
- D ✅ 表述正确：人工审核是**人在环路上**，自检闭环是 Agent 自动完成的检查与修正，二者可以叠加使用，但不是一回事。题干"最多重试 3 次后转交人工"正是二者叠加的例子。
> 📌 另需记住：自检闭环**不能保证 100% 正确**——校验标准本身可能有漏洞、模型自评也可能不准，它提高的是**稳定性**。
**我错了吗**：☐

### Q006 [M4-K07] [A] 单选

关于「桌面 Agent」与「云端 Agent」的差异，下列说法正确的是？

- A. 桌面 Agent 是另一种技术路线，不遵循感知—思考—行动的 Agent 范式
- B. 桌面 Agent 运行在本地设备上，可直接读写本地文件并在本地执行操作；因其具备本地操作权限，更需注意权限最小化与危险操作确认
- C. 桌面 Agent 由于运行在本地，天然具备比云端 Agent 更强的模型推理能力
- D. 桌面 Agent 的数据默认必须上传至云端处理，灵活性和隐私性都比云端 Agent 差

**答案**：B
**考点**：M4-K07 桌面 Agent（本地运行形态 + 权限风险）⭐ V2.4 新增
**解析**：
- A ❌ 桌面 Agent 只是**部署形态**不同，走的仍是同一套 Agent 范式（感知—思考—行动）。把它理解成"另一种技术"是最常见的误读。
- B ✅ 准确命中两个考点：① **本地运行**使其能触及**本地文件系统与本地执行能力**，这正是它区别于云端 Agent 的关键价值（也解释了为什么适合整理本地文件、批量处理本地文档这类活）；② 正因为拥有这些权限，误删误改、误执行危险命令等风险随之而来，必须配套权限最小化与关键动作确认。
- C ❌ 推理能力由**底层模型**决定，与其部署在本地还是云端无关。桌面形态改变的是**可达资源**，不是大脑。
- D ❌ 恰恰相反，本地运行的特点之一是数据可留在**本机**处理；说"必须上传云端、隐私性更差"与桌面形态的定位相悖。

### Q007 [M4-K04] [B] 多选

下列场景中，**适合**采用 Agent（而非单纯的提示词优化、RAG 或微调）来实现的是？（多选）

- A. 用户提出「帮我把上个月的销售数据做成分析报表并发邮件给区域负责人」，需要取数、计算、生成图表、发送等多个步骤且后一步依赖前一步结果
- B. 客服只需要回答「公司差旅住宿标准是多少」，该标准写在公司内部的制度文档中
- C. 运维助手接到告警后，需要查询日志、判断可能原因、调用工单系统创建单据，并根据查询结果决定下一步处理方式
- D. 要求模型把所有客服回复统一成固定的三段式格式和品牌话术风格
- E. 用户问「请解释一下什么是检索增强生成」，这是一次性的常识问答

**答案**：A、C
**考点**：M4-K04 何时用 Agent / 何时不用（选型边界）
**解析**：
- A ✅ 典型的 Agent 场景：**多步骤 + 步骤间有依赖 + 需要调用外部能力**（数据库/图表/邮件）。这类任务无法用一次"输入→输出"完成，正是 V2.4 决策树中"任务复杂、多步执行、需调用外部 API/工具 → Agent"的标准画像。
- B ❌ **应选用 RAG / 知识库**。这是典型的"缺私域知识"问题：答案就在公司制度文档里，模型不知道而已，接上知识库检索即可，既成本低又可附出处、随时更新。不涉及任何多步执行动作，上 Agent 属于过度设计。
- C ✅ 标准 Agent 场景：不仅多步，还需**根据中间结果动态调整**下一步（ failover 式处置），且要调用日志系统与工单系统等外部能力，符合「查询 → 判断 → 决策 → 执行」的闭环。
- D ❌ **应选用微调**（或强约束的提示词）。题干说的是"统一输出格式与风格"，压根没有多步执行和外部调用需求，恰恰是 V2.4 决策树里明确指向**微调**的那一类。这是本题最容易误选的干扰项。
- E ❌ 单轮常识问答，最优解是**直接调用模型 + 优化提示词**。一句话就能答完的问题上 Agent，只会增加时延、调用成本和出错面。
> 📌 **记忆锚点**：不是"问题难"才上 Agent，而是"**任务需要多步执行与外部交互**"才上 Agent。
**我错了吗**：☐

### Q008 [M4-K08] [A] 多选

某团队给已有的 Agent **接入了知识库**（内含公司内部的产品手册、报价规则与售后政策）。关于这一改动带来的效果，下列说法**正确**的是？（多选）

- A. Agent 可以引用知识库中的内容作为作答依据，从而缓解"模型不知道就编一个"的幻觉问题
- B. Agent 处理私域业务时有了可追溯的事实依据，答案可标注来源便于人工核查
- C. Agent 的模型推理能力得到实质性提升，因为它把这些文档内容永久学会了
- D. 产品手册更新后，Agent 在下次问答中即可用到新内容，无需重新训练模型
- E. 接入知识库后，Agent 自动获得了写文件、发请求等执行外部动作的能力
- F. 接入知识库等同于对模型做了一次领域微调

**答案**：A、B、D
**考点**：M4-K08 知识库应用（Agent + RAG）⭐ V2.4 新增
**解析**：
- A ✅ 接知识库后，回答有据可依，直接针对Agent执行任务时最容易出问题的"凭自己想象编参数/编规则"，这是 Agent 接入知识库的首要价值。
- B ✅ 检索出来的片段有明确出处，答案可附来源、可核查，这对有合规要求的业务场景（如报价、售后政策）尤其关键。
- C ❌ **最典型的陷阱**。检索是**外挂式**取用知识，文档内容并没有写进模型参数，"永久学会"描述的恰恰是**微调**的效果。接知识库改变的是**可用信息**，不改变模型本身的推理智商。
- D ✅ 这是 RAG 相对微调的核心优势之一：**文档更新即刻生效**，改完文档下一次问答就能用到，无需重新训练、无需停机。
- E ❌ 混淆了**知识**与**能力**。能否写文件、发请求取决于是否挂载了相应**工具**（工具调用），与是否接了知识库是两回事。Agent 的完整能力 = 思考（模型）+ 知识（知识库）+ 手脚（工具）+ 方法（Skill）。
- F ❌ 二者是**不同的技术路径**：接知识库是外挂检索（知识不入参数、更新即时生效、可溯源），微调是写入参数（改变表达行为与风格、知识易过时、不可溯源）。不能混为一谈。
