# Lab 01 · 百炼平台搭建 RAG 问答

**对应**：RAG 全流程 / 文档切分 / 向量检索 / 评测归因
**模块**：增强大模型应用的能力（22%）
**V2.4 状态**：向量检索、RAG 评测归因为**新增考点**

---

## 目标

用百炼搭一个「基于我自己的文档回答」的问答应用，并**故意把它做坏一次**，练习归因。

---

## 步骤

1. 登录百炼控制台，创建知识库
2. 上传测试文档（10-30 页）
3. 观察/配置**切分策略**：chunk size、overlap
4. 创建应用，绑定知识库
5. 提问测试：
   - 文档里明确有的 → 应该答得准
   - 文档里没有的 → 应该答「不知道」而不是编
6. **归因练习**：问一个答错的问题，依次判断：
   - PDF 扫描件/表格中的关键内容是否成功**解析与入库**？没有则先查 OCR、提取；
   - 已入库但未召回？查结构切分、标题元数据、过滤条件与混合检索；
   - 正确候选被排到上下文之外？查重排序、top-k 与上下文预算；
   - 证据已给模型仍答歪？查生成约束、引用核验与无依据拒答。
7. 观察召回的 chunk 内容，理解「向量检索」实际在做什么

---

## 必须搞懂的考点

| 考点 | 要能回答 |
|---|---|
| RAG 解决什么 | 缺私域/最新知识 + 幻觉 |
| RAG 流程 | **解析** → 切分/向量化/入库 → 检索 → 重排 → 生成 → 评测与归因 |
| 向量检索是什么 | 把文本转向量，按相似度（余弦等）找最接近的片段 |
| chunk 切太大 | 噪声多，召回不精准 |
| chunk 切太小 | 语义断裂，上下文不完整 |
| 评测归因 | 先判断是**检索**问题还是**生成**问题，再对症下药 |
| RAG vs 微调 | RAG 补可更新知识；微调改善稳定行为，更新模型事实需重新训练与评估 |

## 常见坑

- 上传文档后直接问就答得不错 → 说明**没练到归因**。务必故意问一个刁钻问题。
- 只在意"能不能跑通"，忽略了 chunk 参数 → 考试会考切分策略的权衡。
